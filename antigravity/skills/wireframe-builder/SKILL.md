# HTML 인터랙티브 와이어프레임 제작 스킬

정책서와 기획 문서를 기반으로 단일 HTML 파일의 인터랙티브 와이어프레임을 생성합니다.

## 기본 원칙

1. **단일 HTML 파일**: HTML + CSS + JS를 하나의 파일에 포함
2. **외부 의존성 없음**: CDN 등 외부 리소스 사용하지 않음
3. **인터랙티브**: 사이드바 네비게이션, 페이지 전환, 드릴다운, 모달 등 동작
4. **그레이스케일**: 와이어프레임답게 흑백/회색 톤 기본
5. **반응형 불필요**: 데스크톱 기준 고정 레이아웃

## 와이어프레임 구조

### 전체 레이아웃
```html
<div class="layout">
  <aside class="sidebar">        <!-- 좌측 사이드바 -->
    <div class="logo">...</div>
    <nav class="nav">...</nav>
  </aside>
  <main class="main">
    <header class="topbar">      <!-- 상단바 -->
      <div class="breadcrumb">...</div>
      <div class="topbar-actions" id="topbar-actions">
        <!-- 검색, 다운로드 등 (필요한 화면에서만 노출) -->
      </div>
    </header>
    <div class="content">        <!-- 컨텐츠 영역 -->
      <div class="page" id="page-{name}">...</div>
    </div>
  </main>
</div>
```

### 페이지 전환 시스템
```javascript
function showPage(pageId) {
  // 1. 모든 페이지 비활성화
  document.querySelectorAll('.page').forEach(p => p.classList.remove('active'));
  // 2. 대상 페이지 활성화
  document.getElementById('page-' + pageId).classList.add('active');
  // 3. 네비게이션 활성 상태 업데이트
  // 4. 상단바 컨트롤 표시/숨김
  // 5. 브레드크럼 업데이트
}
```

## UI 컴포넌트 패턴

### 대시보드 페이지
```
┌─────────────────────────────────────┐
│ [기간 필터] [카테고리 필터] ...       │
├─────────────────────────────────────┤
│ [KPI 카드] [KPI 카드] [KPI 카드] ... │
├─────────────────────────────────────┤
│ [차트 영역]           [차트 영역]     │
├─────────────────────────────────────┤
│ [데이터 테이블]                       │
│  정렬 | 필터 | 페이지네이션           │
└─────────────────────────────────────┘
```

### 관리 페이지 (CRUD)
```
┌─────────────────────────────────────┐
│ [페이지 제목]           [+ 등록 버튼] │
├─────────────────────────────────────┤
│ [검색바] [상태 필터]                  │
├─────────────────────────────────────┤
│ [데이터 테이블]                       │
│  체크박스 | 이름 | 상태 | 액션 버튼   │
│  [페이지네이션]                       │
└─────────────────────────────────────┘
```

### 모달 (등록/수정)
```
┌─────────────────────────────────────┐
│ [모달 제목]                    [X]   │
├─────────────────────────────────────┤
│ [라벨]: [입력 필드]                   │
│ [라벨]: [셀렉트박스]                  │
│ [라벨]: [칩 선택 UI]                  │
├─────────────────────────────────────┤
│              [취소] [저장]            │
└─────────────────────────────────────┘
```

### 드릴다운 패턴
```
[목록 레벨 1] → 행 클릭 → [목록 레벨 2] → 행 클릭 → [목록 레벨 3]
```
- 뒤로가기 네비게이션 포함
- 브레드크럼으로 현재 위치 표시

## 화면 도출 규칙

정책서/기획 문서 기반으로 필요한 화면을 도출하는 규칙:

| 기획 요소 | 도출 화면 | 유형 |
|----------|----------|------|
| 엔티티 CRUD | 엔티티 관리 페이지 | 관리 |
| 대시보드/보고서 요구 | 대시보드 페이지 | 대시보드 |
| 데이터 처리/작업 관리 | 운영 관리 페이지 | 운영 |
| 사용자/권한 관리 | 설정 페이지 | 설정 |
| 커스텀 보고서/뷰어 | 보고서 페이지 | 보고서 |

## 상단바 컨트롤 규칙

- **대시보드/보고서 화면**: 검색바 + 다운로드 버튼 표시
- **관리/설정 화면**: 검색바 + 다운로드 숨김
- 판별 로직: dashboardPages 배열에 pageId 포함 여부

## 수정 시 주의사항

기존 와이어프레임을 수정할 때:
1. 반드시 최신 버전을 Read로 전체 확인
2. Edit 도구로 정확한 위치만 수정 (전체 재작성 지양)
3. showPage 함수의 dashboardPages 배열 동기화
4. 사이드바 nav-item과 page div의 ID 일관성 유지
5. 새 페이지 추가 시: nav-item + page div + showPage 로직 모두 업데이트

## 서브 에이전트 활용

대규모 와이어프레임 생성(5페이지 이상)은 서브 에이전트에 위임한다. 위임 시 전달할 정보:
- 정책서/기획 문서 경로 및 관련 섹션
- 페이지 목록 및 각 페이지 유형
- 기존 와이어프레임 파일 경로 (업데이트 시)
- 이 스킬의 레이아웃 구조 및 컴포넌트 패턴
