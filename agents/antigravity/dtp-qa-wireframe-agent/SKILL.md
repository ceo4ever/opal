# dtp-qa-wireframe-agent (폴백 모드)

## 실행 방식

Antigravity에서는 서브 에이전트가 지원되지 않으므로, 오케스트레이터가 이 스킬을 Read하여 직접 실행한다.

---

## 목적

wireframe-builder가 생성한 wireframe.md를 **UI 구현 전에 1차 검토**하여:
1. 사용자가 전체 문서를 읽지 않아도 되는 수준의 **핵심 요약** 제공
2. 와이어프레임 품질 체크리스트 기반 **검증 결과** 제공
3. 요구사항과의 **정합성 검증**
4. **Pass / Needs Revision 판정**으로 UI 구현 진행 여부 결정 지원

---

## 호출 시점

```
[wireframe.md 완료] → QA Agent 호출 → QA-WIREFRAME.md → 사용자 검토
                    → 승인 시 → dtp-wireframe-ui-agent가 UI 구현
```

---

## 입력

에이전트 호출 시 전달해야 하는 정보:

| 입력 | 설명 |
|------|------|
| `task_path` | 태스크 폴더 경로 |
| `wireframe_path` | 검토 대상 wireframe.md 경로 |
| `requirements_path` | 요구사항 문서 경로 (TASK.md 또는 정책서) |

에이전트는 `requirements_path`의 요구사항과 wireframe.md를 교차 참조한다.

---

## 실행 프로세스

### Step 1: 산출물 읽기

wireframe.md와 요구사항 문서를 모두 읽는다.

### Step 2: 핵심 요약 작성

와이어프레임의 핵심 내용을 **3~5줄**로 요약한다:
- 화면 구성 (몇 개의 페이지/뷰)
- 주요 UI 컴포넌트
- 핵심 인터랙션 흐름

### Step 3: 품질 체크리스트 검증

아래 검증 항목을 하나씩 확인하고 결과를 기록한다.

### Step 4: 교차 참조 검증

요구사항 문서와 비교하여 누락, 불일치, 정합성 문제를 찾는다.

### Step 5: 판정

검증 결과를 종합하여 판정한다:
- **Pass** — 지적 사항 없음 또는 경미한 수준. UI 구현 진행 가능.
- **Needs Revision** — 수정이 필요한 항목 존재. 지적 사항 해결 후 진행 권장.

---

## 와이어프레임 검증 기준

| # | 검증 항목 | 확인 내용 |
|---|----------|----------|
| W-1 | 요구사항 커버리지 | 요구사항의 모든 화면/기능이 와이어프레임에 반영되었는가? |
| W-2 | 화면 완전성 | 각 화면의 모든 구성 요소(헤더, 내비게이션, 컨텐츠, 푸터)가 명시되었는가? |
| W-3 | 인터랙션 정의 | 버튼 클릭, 폼 제출, 페이지 이동 등 주요 인터랙션이 명시되었는가? |
| W-4 | 데이터 구조 명세 | 화면에 표시될 데이터 구조와 필드가 정의되었는가? |
| W-5 | 상태 정의 | 로딩, 에러, 빈 상태 등 각 화면의 상태가 정의되었는가? |
| W-6 | 구현 가능성 | 정의된 UI가 선택한 기술 스택(React + shadcn/ui)으로 구현 가능한가? |
| W-7 | 일관성 | 컴포넌트 명칭, 스타일 가이드, 인터랙션 패턴이 화면 간 일관되는가? |
| W-8 | 접근성 고려 | 키보드 내비게이션, ARIA 레이블 등 접근성 요소가 고려되었는가? |

## QA 문서 출력 형식

### 파일명 규칙

```
tasks/{NNN}-{태스크명}/QA-WIREFRAME.md
```

### 문서 템플릿

```markdown
# QA: WIREFRAME — {태스크 제목}

> 검토일: YYYY-MM-DD | 판정: {Pass / Needs Revision}

## 1. 요약

{와이어프레임의 핵심 내용 3~5줄}
{화면 수, 주요 컴포넌트, 핵심 인터랙션 흐름}

## 2. 검증 결과

| # | 검증 항목 | 결과 | 비고 |
|---|----------|------|------|
| W-1 | 요구사항 커버리지 | Pass / Warning / Fail | {구체적 근거} |
| ...

## 3. 지적 사항

{Warning 또는 Fail 항목에 대한 상세 설명}
{없으면 "지적 사항 없음" 기재}

### 심각도 분류
- Critical: UI 구현 전 반드시 수정 필요
- Warning: 수정 권장, 사용자 판단에 따라 진행 가능
- Info: 참고 사항, 진행에 영향 없음

## 4. 교차 참조 검증

| 참조 문서 | 검증 내용 | 결과 |
|----------|----------|------|
| {요구사항 문서} | {확인한 정합성 항목} | Pass / Warning |

## 5. 판정

**{Pass / Needs Revision}**

{판정 근거 1~2줄}
```

---

## 판정 기준

| 판정 | 조건 |
|------|------|
| **Pass** | 모든 검증 항목 Pass, 또는 Info만 존재 |
| **Needs Revision** | Critical 1개 이상, 또는 Warning 3개 이상 |
