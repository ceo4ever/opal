# OPAL 프로젝트 에이전트 초기화

## 목적

프로젝트의 기술 스택, 구조, 규칙을 분석하여 프로젝트 전용 에이전트 정의(`{프로젝트}/.opal/AGENT.md`)를 생성한다.

## 실행 조건

- `{프로젝트}/.opal/AGENT.md`가 존재하지 않을 때
- 소유자가 프로젝트 에이전트 생성을 요청하거나 승인할 때

## 프로세스

### Step 1: 프로젝트 구조 분석

프로젝트 루트에서 다음 파일들을 자동 탐색한다:

| 탐색 대상 | 파악 정보 |
|----------|----------|
| `package.json` | Node.js 프로젝트, 프레임워크, 의존성 |
| `requirements.txt`, `pyproject.toml` | Python 프로젝트, 의존성 |
| `Cargo.toml` | Rust 프로젝트 |
| `go.mod` | Go 프로젝트 |
| `CLAUDE.md`, `.cursor/rules/`, `GEMINI.md` | 기존 AI 설정 |
| `docker-compose.yml`, `Dockerfile` | 컨테이너 환경 |
| `tsconfig.json` | TypeScript 설정 |
| `.env.example` | 환경 변수 구조 |
| 디렉토리 구조 (src/, app/, pages/ 등) | 프로젝트 아키텍처 |

### Step 2: 프로젝트 인터뷰 (필요 시)

자동 분석으로 파악되지 않는 정보는 소유자에게 질문한다:

| 질문 | 예시 |
|------|------|
| 이 프로젝트의 주요 목적은? | "커머스 관리 시스템" |
| 코드 컨벤션 특이사항? | "함수형 컴포넌트만 사용" |
| 브랜치 전략은? | "GitFlow / trunk-based" |
| 테스트 정책은? | "커버리지 80% 이상" |

### Step 3: 프로젝트 에이전트 생성

`~/.opal/templates/project-agent.md`를 Read로 읽어 템플릿으로 사용한다.
분석 결과와 인터뷰 내용을 반영하여 `{프로젝트}/.opal/AGENT.md`를 생성한다.

### Step 4: 확인 및 완료

생성된 프로젝트 에이전트 정의를 소유자에게 보여주고 확인을 받는다.

```
프로젝트 에이전트가 설정되었습니다!

- 프로젝트: {프로젝트명}
- 스택: {기술 스택}
- 저장 위치: {프로젝트}/.opal/AGENT.md

다음부터 이 프로젝트에서는 오케스트레이션 모드로 동작합니다.
수정할 부분이 있나요?
```

## 기존 설정과의 관계

프로젝트 에이전트는 기존 AI 플랫폼 설정을 대체하지 않고 보완한다:

- `.cursor/rules/` → Cursor가 직접 읽는 규칙 (유지)
- `CLAUDE.md` → Claude Code가 직접 읽는 설정 (유지)
- `GEMINI.md` → Antigravity가 직접 읽는 설정 (유지)
- `.opal/AGENT.md` → OPAL 에이전트가 오케스트레이션 시 참고 (신규)
