# OPAL 프로젝트 오케스트레이션

## 목적

OPAL 에이전트가 소유자와 프로젝트 에이전트 사이의 오케스트레이터로 동작한다.
소유자의 지시를 해석하고, 프로젝트 에이전트에게 전달하며, 결과를 검토하여 소유자에게 보고한다.

## 실행 조건

- `{프로젝트}/.opal/AGENT.md`가 존재할 때
- 소유자가 프로젝트 관련 작업을 지시할 때

## 프로세스

### Step 1: 프로젝트 에이전트 로드

`{프로젝트}/.opal/AGENT.md`를 Read로 읽어 프로젝트 컨텍스트를 파악한다.

### Step 2: 지시 해석

소유자의 지시를 분석하여 프로젝트 에이전트에게 전달할 프롬프트를 작성한다:

```
[프로젝트 에이전트 프롬프트 구성]
1. 프로젝트 에이전트 AGENT.md 내용 포함
2. 소유자의 지시 원문
3. 작업 범위와 기대 결과 명시
4. 완료 후 보고 형식 지정
```

### Step 3: 프로젝트 에이전트 실행

**Claude Code / Cursor** (서브에이전트 지원):

Task 도구를 사용하여 프로젝트 에이전트를 서브에이전트로 실행한다:

```
Task 도구 호출:
- prompt: Step 2에서 구성한 프롬프트
- description: "{프로젝트명} 에이전트 작업"
```

**Antigravity** (서브에이전트 미지원):

프로젝트 에이전트 AGENT.md의 규칙을 현재 컨텍스트에 적용하여 직접 실행한다.
실행 결과를 프로젝트 에이전트가 수행한 것처럼 구분하여 보고한다.

### Step 4: 결과 검토

프로젝트 에이전트의 실행 결과를 검토한다:

- 소유자의 원래 지시와 결과가 일치하는지 확인
- 코드 품질, 규칙 준수 여부 검토
- 잠재적 문제나 개선점 식별

### Step 5: 소유자 보고

검토 결과를 소유자에게 보고한다:

```
[{name} 오케스트레이션 보고]

{프로젝트} 에이전트가 작업을 완료했습니다.

- 지시: {소유자의 원래 지시 요약}
- 수행 결과: {핵심 변경 사항}
- 검토 결과: {품질/규칙 준수 여부}
- 특이 사항: {있으면 기재}

추가 지시가 있으신가요?
```

## 오케스트레이션 판단 기준

모든 작업을 오케스트레이션하지는 않는다. 다음 기준으로 판단한다:

| 상황 | 방식 |
|------|------|
| 간단한 질문, 설명 요청 | 직접 답변 (오케스트레이션 불필요) |
| 파일 1-2개 수정하는 단순 작업 | 직접 수행 |
| 프로젝트 규칙이 중요한 코딩 작업 | 오케스트레이션 |
| 다중 파일 변경, 아키텍처 영향 작업 | 오케스트레이션 |
| 테스트, 빌드, 배포 관련 작업 | 오케스트레이션 |

에이전트는 상황에 따라 유연하게 판단한다.
