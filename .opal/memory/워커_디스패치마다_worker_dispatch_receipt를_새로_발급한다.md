# 워커 디스패치마다 worker.dispatch receipt를 새로 발급한다

`dispatch-process.md` Step 0은 **[MUST] 매 워커 디스패치 직전에 새로 수행한다**이다. receipt 재사용은 금지다.

## 왜 재사용이 위험한가

태스크 124에서 18:05에 발급한 receipt 하나를 여러 디스패치에 돌려썼다. 19:37에 다른 세션이 install을 수행하면서 `~/.opal/references/events.json`의 manifest 해시가 바뀌었고, 그 시점 이후 디스패치 3건(W-8·TEST·컨벤션 진단)이 stale receipt를 받았다. 컨벤션 체커가 이를 신고하기 전까지 PM은 알지 못했다.

장기 실행 태스크일수록 위험이 크다. 배포는 태스크 진행 중에도 일어나며, 다른 세션이 수행할 수도 있다. receipt는 발급 시점의 manifest를 고정하므로 시간이 지날수록 실제와 어긋난다.

## 영향 판정 방법

stale이 발견되면 즉시 폐기하지 말고 **문서 집합과 변경 문서를 대조**한다. 124에서는 문서 4종 집합이 동일했고 `dispatch-process.md` 1건만 +437바이트 변경(PM 지침 문구)이라 워커 산출물의 실질에는 영향이 없었다. 워커가 소비하는 문서가 바뀌었다면 해당 디스패치를 다시 수행해야 한다.
