## 배경

037(브레인 질의 타임아웃 견고화)은 **증상**(fetch 타임아웃·Load failed)을 비동기 잡+폴링으로 해결했다. 이 후속 태스크는 **원인**(콜드 질의 자체가 ≈69초)을 줄인다.

## 핵심 인사이트 (정정된 모델)

- **프레임워크 로딩은 병목이 아니다.** `claude -p`가 CLAUDE.md를 컨텍스트에 둬도 자명 작업은 ~5초. Eager 부트스트랩 "파일 존재" 비용은 작다.
- **진짜 비용 = 인-에이전트 멀티턴 루프** (LLM이 brain-tool 검색→페이지 Read→합성을 각각 LLM 턴으로 왕복).
- **레버 = 검색을 LLM 밖(brain-tool, 결정론)에서 미리 끝내고 LLM은 합성 1턴만.** "부트스트랩 스킵"이 아니라 "멀티턴 압축"이 본질.
- 랭킹 지능은 이미 파이썬(brain-tool)에 있어 **밖으로 빼도 품질 손실 0**.

## 설계 결정 포인트 (후속 태스크에서 확정)

LLM이 검색 시점에 하는 실제 역할은 랭킹이 아니라 **① 질문→검색어 변환 ② 후보 페이지 선별**.
- ②는 score 상위 N 절단으로 충분.
- ①이 관건 — brain-tool 매칭이 리터럴(부분문자열)이라 키워드 품질이 중요(긴 문장 0매치, 핵심 토큰 7매치 실측). 선택지: (a) 질문 원문 검색(품질↓) (b) 키워드 추출 휴리스틱 (c) 경량 LLM 1콜로 키워드만 (d) 합성 LLM에 검색어 제안 겸임.

**권고**: opbr 스킬에 `--lite` 모드 신설 — Eager·멀티턴 스킵 + 검색 1패스 + 합성 1턴. BE 직접 우회(DRY 위배)보다 프레임워크 일관성 유지하며 같은 효과. PoC 산출물 참조(`/tmp/poc_prompt.txt` 등, 휘발성).
