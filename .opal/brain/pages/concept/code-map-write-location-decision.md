## 개요

워커가 새 헤더를 어디에 남길지 — 소스 파일 안인지 외부 지도인지 — 직접 고르지 않는다. 파일의 현재 상태(소속 영역이 읽기전용인지, 이미 인라인 헤더를 갖고 있는지, 아직 존재하지 않는 신규 파일인지)를 정해진 순서로 검사해 자리를 자동으로 정하고, 그 판정 결과를 도구가 알려준다(근거: task:077 PLAN§3.5.2).

## 결정 배경 (WHY)

기록 위치를 워커 재량에 맡기면 같은 성격의 파일이 워커마다 다른 자리에 기록되어, 나중에 "이 파일의 진짜 헤더가 어디 있는가" 자체가 불명확해진다. 이 설계는 그 이중화를 판정 로직으로 원천 차단하려는 의도다(근거: task:077 DONE.md §3 결정3).

## 결정 내용

판정은 다음 네 조건을 순서대로 검사한다.

| 순서 | 조건 | 기록 위치 |
|------|------|----------|
| ① | 소속 영역이 읽기전용으로 지정됨 | 외부 지도 |
| ② | 위 조건에 해당하지 않고, 파일에 이미 인라인 헤더가 있음 | 인라인 유지 |
| ③ | 파일이 아직 디스크에 존재하지 않는 신규 파일 | 인라인 |
| ④ | 그 외 (기존 파일 + 인라인 없음) | 외부 지도 |

이 순서를 바꾸면 읽기전용 영역의 신규 파일에 인라인 기록을 시도하는 등 규약을 위반하는 판정이 나올 수 있어, 순서 자체가 지켜야 할 계약이다(근거: task:077 PLAN§3.5.2 "이 순서를 바꾸면 규약 위반"). 외부 지도가 아예 없는 프로젝트에서는 이 판정 전체가 우회되어 항상 인라인만 돌려준다 — 지도 도입 이전의 기존 규칙과 결론이 같다(근거: task:077 PLAN§3.5.2).

## 영향 범위

헤더를 신규로 남기는 모든 작업 경로 — 워커의 직접 기록과, 세션 중 저장 시점에 기록 누락을 감지하는 후킹 양쪽.
