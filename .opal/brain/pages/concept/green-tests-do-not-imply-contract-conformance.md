## 개요

계약 테스트 26건이 전부 통과한 상태에서, 규약 문서와 세 구현을 항목별로 대조하는 정적 검사가 불일치 7건을 찾아냈고 그중 2건은 실제 결함이었다. 테스트 GREEN은 "테스트가 명시한 계약을 지켰다"는 뜻이지 "규약을 지켰다"는 뜻이 아니다.

## 결정 배경 (WHY)

- 규약에는 있으나 테스트로 표현되지 않은 항목 — 경로 간 로그 문구 동일성, 폴백 3동작의 완전 수행, 분기 기본값 존재 — 은 GREEN 상태에서도 미검증으로 남는다.
- 실제 결함 2건: (a) 체크섬 목록에서 항목을 고를 때 부분문자열 매칭을 써서, 상위문자열 항목이 먼저 오면 엉뚱한 줄의 해시를 기대값으로 채택할 수 있었다. (b) 체크섬 분기에 기본값이 없어 예상 밖 모드가 무음 통과했다 (근거: task:085 CONTRACT-CROSSCHECK.md D-2·D-6). 둘 다 현행 자산 구성에서는 발현하지 않지만 실패 시 닫히는 경계를 흔드는 잠재 경로였다.
- 나머지 불일치 다수는 **구현이 설계를 어긴 것이 아니라 설계 문서 내부가 서로 어긋난 것**이었다. 공통 규약 절은 3경로 동형을 지시하는데 경로별 상세 절이 축약 문구와 다른 위임 방식을 지시하고 있었다. 구현 담당은 지시를 충실히 따랐으므로 되돌릴 대상은 구현이 아니라 규약 문서였다.
- Windows 경로는 실행 환경이 없어 실행 검증 자체가 불가능했다. 그 경로에서는 정적 대조가 사실상 유일한 검증 수단이었고, 실제로 폴백 3동작 중 하나가 첫 폴백 경로에서 누락된 것을 이 대조가 잡았다.

## 결정 내용

- 같은 규약을 여러 언어·여러 파일에 복제 구현할 때는 실행 테스트와 **별개로** "규약 항목 × 경로" 대조표를 게이트로 둔다. 항목 전부 일치가 완료 기준이며, 부분일치가 남으면 단계를 닫지 않는다.
- 대조에서 나온 불일치는 **발원지를 구분해** 기록한다 — 구현 이탈인지, 규약 문서 자체의 내부 불일치인지. 발원지가 다르면 고칠 대상도 다르다.
- 대조 담당은 수정 권한 없이 기록만 남기고, 수정 여부·범위는 별도 판단으로 처리한다. 발견과 수정을 같은 손이 하면 "고치기 쉬운 것만 발견"하는 편향이 생긴다.
- 수정 반영 후에는 대조를 **재실행**해 회귀 0건을 확인한다. 이번에는 수정 5건 반영 후 재판정에서 8항목 전부 일치, 회귀 0건이 확인됐다.

## 영향 범위

다경로 동형 구현(설치기 여러 종, 언어가 다른 클라이언트, 동일 규약의 복제 구현)이 있는 모든 작업. 실행 검증이 불가능한 플랫폼이 포함될 때 특히 필수다.
