## 개요

장시간 실행되는 워커(agentic 구현 태스크)가 인프라 레벨 실패(API 연결 종료, 장시간 스톨)를 연속으로 겪을 때, 재시도만 반복하기보다 **모델 하향 + 전체 파일 통독 금지 + 함수 단위 저장 + 배치 분할**의 조합으로 대응하면 실패 재발이 해소된다.

## 결정 배경 (WHY)

078 EXECUTE 단계에서 워커 인프라 실패가 3연속 발생했다 — API 연결 종료 2회, 600초 스톨 1회. 매 실패 후 `git diff`로 산출물 유실이 없음을 확인했지만, 같은 방식(큰 파일 통째 작업)을 반복하면 또 실패할 위험이 있었다. (근거: task:078 DONE §8 특이사항)

## 결정 내용

아래 조합을 적용한 뒤로는 전량 성공했다.

- **모델 하향**: opus → sonnet으로 낮춰 단일 응답 부담을 줄인다.
- **전체 파일 통독 금지**: 대상 파일(예: `memory_tool.py`)을 처음부터 끝까지 한 번에 Read하지 않고, 수정이 필요한 함수 단위로 필요한 범위만 Read한다.
- **함수 단위 저장**: 큰 변경을 한 번의 Edit/Write로 몰아넣지 않고, 함수 단위로 쪼개어 저장한다 — 중간에 실패해도 이미 저장된 부분은 보존된다.
- **배치 4분할**: 전체 작업을 4개 배치로 나누어 순차 진행한다 — 각 배치가 독립적으로 완결되므로 한 배치의 실패가 전체를 되돌리지 않는다.

이 조합의 핵심은 "실패 단위를 작게 만드는 것"이다 — 큰 단일 트랜잭션으로 작업하면 인프라 실패 시 되돌아갈 지점이 멀어지고 검증 비용도 커진다.

## 영향 범위

향후 대형 파일(수백~수천 줄)을 다루는 EXECUTE 워커가 인프라 실패를 연속으로 겪을 때 우선 적용할 대응 순서로 재사용 가능하다.
