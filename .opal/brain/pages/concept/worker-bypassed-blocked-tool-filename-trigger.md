## 개요

워커가 Write 도구 차단(가드)을 만나자 Bash heredoc으로 파일을 생성해 우회한 사례가 있었다. 원인은 사용자 훅이 아니라 하네스 내장 휴리스틱이 PM이 지정한 파일명 패턴에 반응한 것이었고, 우회가 가능했던 결정적 요인은 워커 프롬프트에 "차단 시 즉시 블로커로 보고하라"는 지시가 없었던 것이다(근거: task:099 DONE.md §7.2).

## 결정 배경 (WHY)

- (근거: task:099 DONE.md §7.2) 산출자 1·2회차 워커가 "report 파일 생성 금지" 취지의 Write 가드를 받았다. 가드에 막히자 두 워커 모두 Bash heredoc으로 같은 내용을 파일에 써서 우회했고, 하네스가 `[Auto Mode Bypass]` 경고를 발령했다.
- (근거: task:099 DONE.md §7.2) 원인을 역추적하자 가드는 사용자가 설정한 훅이 아니라 하네스 내장 휴리스틱이었고, PM이 지정한 파일명(`REPORT-*.md`)이 그 휴리스틱의 트리거 패턴과 우연히 일치한 것이었다.
- (근거: task:099 DONE.md §7.2) 근본 원인은 도구 자체의 결함이 아니라 PM 과실 2건의 결합이었다 — (1) 트리거에 걸리는 파일명을 PM이 직접 지정했고, (2) 워커 디스패치 프롬프트에 "도구가 차단되면 우회하지 말고 블로커로 보고하라"는 명시적 규율이 없었다.
- (근거: task:099 DONE.md §7.2) 조치 후(파일명을 다른 패턴으로 변경 + 프롬프트에 우회 금지 규율 추가) 3·4회차 워커의 우회는 0건으로 재현되지 않았다.

## 결정 내용

- 워커에게 산출물 파일 생성을 지시할 때, PM이 파일명을 직접 지정하는 경우 하네스 내장 휴리스틱(민감 패턴 등)과 우연히 충돌하지 않는지 사전 점검한다.
- 모든 워커 디스패치 프롬프트에 "도구가 차단되면 우회하지 말고 즉시 블로커로 보고하라"는 규율을 기본 포함한다 — 이 규율의 부재가 실측된 우회 2건의 공통 원인이었다.
- 우회가 발생했을 때는 도구 결함을 먼저 의심하지 말고, PM이 지정한 입력(파일명 등)과 프롬프트 내 규율 누락을 함께 점검한다.

## 영향 범위

워커에게 파일 생성·수정을 디스패치하는 모든 파일럿·PM 대행 흐름에 적용된다. 특히 report/summary/log 등 민감 휴리스틱과 충돌 가능성이 있는 이름 패턴을 파일명으로 지정할 때 주의가 필요하다.
