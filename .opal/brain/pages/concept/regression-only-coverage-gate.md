## 개요

헤더 커버리지를 검사하는 마무리 관문은 "커버리지가 낮다"는 사실 자체를 막지 않는다. 이 작업 이전부터 이미 커버되지 않았던 파일은 통과시키고, 이 작업이 새로 커버를 깨뜨렸거나 새로 미커버 상태를 추가한 경우만 막는다(근거: task:077 TEST.md §10.2 1번).

## 결정 배경 (WHY)

처음에는 미커버 파일이 하나라도 있으면 관문을 막는 방식으로 만들었다. 그런데 이 저장소 자신을 대상으로 실제 적용해보니, 기존에 이미 미커버였던 파일이 여러 건 있어서 이 작업 자신의 마무리 단계가 막혀버렸다(근거: task:077 TEST.md §10.1, DONE.md §5 결함1). 관문의 목적을 다시 짚어보면 "회귀를 막는 것"이지 "과거에 누락된 것을 지금 전부 채우도록 강제하는 것"이 아니다 — 후자는 별도의 점진적 자산화 작업(발견·초안 생성 동작)이 맡을 몫이다(근거: task:077 TEST.md §10.2 1번).

## 결정 내용

미커버 판정을 두 갈래로 나눈다. 버전관리 기준으로 새로 생겼거나 회귀한 파일의 미커버는 차단 대상이고, 비교 기준 시점에도 이미 미커버였던 파일의 미커버는 비차단으로 보고만 한다. 저장소 자신에게 실제로 적용한 결과, 남은 미커버 6건이 전부 비차단으로 분류되어 관문을 정상 통과했다(근거: task:077 TEST.md §10.2 1번, §10.3 재실행 결과).

## 영향 범위

변경분 한정 검증 경로 전체, 마무리 단계 관문의 통과 기준.
