## 개념 요약

루프 액션 에이전트의 결과 파일 규약을 v2로 개정해 스트리밍 이벤트 로그를 편입시키고, 여기에 더해 "실행 중 창"(이벤트 로그)과 "판단 기록"(운행 일지)을 별도로 관측하는 이원 구조를 규약화했다. 실행 도중 상태를 보려면 이벤트 로그를, 왜 그런 판단을 내렸는지 보려면 운행 일지를 본다.

## 배경·문제 (WHY)

[[opal-agent-stream-json-passthrough]] 결정으로 비동기 축의 실행 도중 이벤트를 파일로 받을 수 있게 됐지만, 이것만으로는 부족했다 — 루프 액션 에이전트가 게이트 판단을 통과시켰는지, 왜 재시도를 했는지, 왜 특정 단계를 막았는지는 CLI 실행 바깥에서 벌어지는 판단이라 이벤트 로그에 담기지 않는다(근거: task:067 TASK.md 배경 분석). 이 공백을 메우기 위해 루프 액션 에이전트 자신이 직접 기록하는 append-only 일지가 필요했다.

## 결정 내용 (HOW)

- **결과 파일 규약 v2**: 비동기 축(생성자·Evaluator·test-agent 축)의 표준출력 캡처 슬롯이 단일 결과 파일에서 이벤트 로그 파일로 바뀐다. 동기 축(게이트·테스트·규칙검사 축)은 기존 방식(단일 JSON 결과 파일)을 그대로 유지한다 — 스트리밍의 가치는 장시간 걸리는 비동기 축의 실행 중 관측에 있고, 동기 축은 이미 반환값으로 즉시 수거되기 때문에 바꿀 이유가 없다(근거: task:067 PLAN§3.2.2). 디스패치 프롬프트 원문을 남기는 관행도 이번에 정식 규약으로 승격됐다(이전 태스크에서 비규약으로 자연 발생했던 산출물).
- **완료 마커 불변**: 종료코드 파일의 존재 여부가 여전히 유일한 완료 판정 기준이다. 이벤트 로그 파일의 존재/비존재로 완료를 판정하는 것은 여전히 금지된다([066계승], 근거: task:067 PLAN§3.2.2 H-10).
- **운행 일지(journal) 신설 — 이원 관측 구조**: 루프 액션 에이전트가 자신의 게이트 판단·재시도·단계 전환을 append-only로 직접 기록하는 표(시각·단계·이벤트·근거 4열)를 새로 규약화했다. 기록 시점은 각 단계 시작/종료, 게이트 판단(판정+근거), 재시도(회차+사유), 차단 사유다. 이벤트 로그가 "지금 무엇을 하고 있나"를 보여준다면, 운행 일지는 "왜 그렇게 판단했나"를 보여준다 — 두 관측 채널은 서로 대체할 수 없는 별개 축이다(근거: task:067 PLAN§3.2.2).
- **관측 질의는 파일 SSOT 경유 원칙**: 루프 액션 에이전트가 실행되는 도중 그 판단이나 진행 상황을 알고 싶을 때, 실행 중인 에이전트에게 직접 질의하지 않는다. 대신 이벤트 로그와 운행 일지라는 파일을 소유자(PM)가 직접 읽고 답한다. 이 원칙은 기존 관측성 경계 축소 결정([[oppl-internal-channel-opal-agent]] — 소유자가 Agent 도구로 디스패치하는 경우에만 행위주체 표시 규칙 적용)의 연장선이며, 내부 채널 디스패치는 파일 기반 자체 관측성으로 충분하다는 판단을 이번 태스크에서 실증했다(근거: task:067 DONE.md 특이 관찰 — 루프 액션 에이전트가 자율 재시드 판단을 운행 일지에 근거와 함께 남긴 실사례).

## 영향·관계

`opal/agents/opal-loop-action-agent/AGENT.md` §결과 파일 규약·§운행 일지가 규약 본체다. [[opal-action-monitor]]가 이벤트 로그·운행 일지 양쪽을 파싱해 단계×축 현황판을 렌더한다. [[opal-agent-stream-json-passthrough]]가 만든 이벤트 로그 산출물이 이 규약의 편입 대상이다.
