## 개요

자동 게이트(스크립트 exit code, assert 등)가 없어 사람이 직접 확인해야 하는 M3(수동) 시나리오는, "확인함" 같은 산문 서술이 아니라 **실제 실행 출력 원문**을 결과란에 그대로 남겨야 한다. 자동 게이트가 없는 자리를 산문이 대신하면 검증이 자기선언으로 퇴화한다. (근거: task:079 DONE §4 TS-024, §8 특이사항)

## 결정 배경 (WHY)

079의 TS-024는 "배포된 CLI로 078의 실제 히스토리 오기재를 실사용 정정한다"는 목표-달성 실증 시나리오였다 — 자동화된 assert로 판정할 수 없는, PM이 직접 수행하는 M3 시나리오였다(task:079 PLAN H-10, TEST-SCENARIO M3 분류). 이런 시나리오는 실행 여부를 "정정을 확인함" 같은 문장으로만 남기면, 그 문장이 실제로 정정이 일어났다는 증거가 되지 못한다 — 검증이 도구가 아니라 작성자의 자기 진술에 의존하게 된다.

## 결정 내용

- **M3(수동) 시나리오의 결과란에는 CLI 응답 JSON 원문·`git diff` 원문 등 실제 산출물을 그대로 인용한다.** 079의 DONE.md는 TS-024 결과에 배포본 CLI의 JSON 응답 전문과 `git diff .opal/MEMORY.json`의 실제 hunk를 그대로 첨부했다(근거: task:079 DONE §4 TS-024).
- **평가자(Evaluator) 권고를 실제로 수용한 사례**: "확인함"류 산문을 원문 증거로 교체하라는 권고가 실제 산출물 작성에 반영됐다(근거: task:079 DONE §8 특이사항).
- **효과**: 원문 증거는 사후에 제3자(리뷰어, 다음 태스크의 PM)가 "정말 그 값이 그렇게 바뀌었는가"를 재검증할 수 있게 하며, 서술이 정확했는지 자체를 검증 가능하게 만든다.

## 영향 범위

자동 게이트를 걸 수 없는 모든 수동(M3) 검증 시나리오 — 실사용 데이터 정정, 배포 후 실환경 확인, 실렌더 스크린샷 등 — 의 결과 기록 방식에 재사용 가능한 규율이다. TEST-SCENARIO.md·DONE.md 작성 시 M3 항목을 만나면 이 규율을 적용한다.
