## 개요

같은 워킹트리에서 두 태스크가 동시에 EXECUTE 단계를 진행하며 같은 파일(예: 규범 문서)의 서로 다른 절을 각자 수정해야 할 때는, `Write`(전체 덮어쓰기)를 금지하고 `Edit`(부분 치환) 전용으로 한정하며, 편집 위치를 줄번호가 아니라 **헤딩 앵커**로 잡고, 편집 후 상대방이 담당하는 영역의 diff가 0줄인지 확인하는 규율로 상호 변경을 보존한다.

## 결정 배경 (WHY)

078과 077이 같은 워킹트리에서 동시에 `tools.md`를 EXECUTE했다 — 077은 code-scan 절(당시 `tools.md:202-289`)을, 078은 memory-tool 절(당시 `tools.md:542-639`)을 각자 수정했다. 의미상 충돌은 없었지만(서로 다른 절), 한쪽이 파일을 통째로 저장하면 다른 쪽이 진행 중이던 변경이 덮여 사라질 위험이 있었고, 상대방의 편집으로 줄 번호가 이동하면 줄번호 기준 편집은 엉뚱한 위치를 건드릴 위험이 있었다(H-10). (근거: task:078 PLAN.md H-10, D-4)

## 결정 내용

- **`Write` 금지, `Edit` 전용**: 공유 파일에는 전체 파일을 다시 쓰는 도구를 쓰지 않는다 — 부분 치환만 허용해, 자신이 손대지 않은 영역은 물리적으로 건드릴 수 없게 한다.
- **헤딩 앵커 편집**: 줄번호가 아니라 `## memory-tool` 같은 헤딩 텍스트를 앵커로 삼아 편집 위치를 잡는다 — 동시 편집으로 줄번호가 밀려도 앵커는 유효하다.
- **대기 금지**: 상대 태스크의 완료를 기다리지 않는다. 대신 **편집 직전에 파일 전문을 재-Read**해 최신 상태를 확인한 뒤 편집한다.
- **상대 영역 diff 0줄 검증**: 자신의 편집이 끝난 뒤, 상대방이 담당하는 절(code-scan 절 등)의 diff가 0줄임을 확인해 상호 보존을 실증한다(TS-047).
- **결과**: 두 태스크 모두 완료 시점까지 상호 변경 충돌 0건.

## 영향 범위

향후 여러 태스크가 동일 워킹트리에서 병렬로 진행되며 같은 공유 문서(규범 문서, 인벤토리 파일 등)의 서로 다른 절을 각자 갱신해야 하는 모든 상황에 재사용 가능한 협업 규율이다.
