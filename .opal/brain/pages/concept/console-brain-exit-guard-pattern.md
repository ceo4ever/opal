## 개념 요약

콘솔 브레인이 "휘발성 단일 세션"으로 전환되면서 화면을 벗어나면 진행 중이던 대화가 그대로 소멸하게 되었다. 이 소멸을 사용자가 의도치 않게 겪지 않도록, 대화가 진행 중일 때 세션이 사라지는 4가지 이탈 경로 모두에서 동일한 확인 대화상자를 띄우는 가드 패턴이다.

## 배경·문제 (WHY)

- [[console-brain-volatile-single-session]] 설계는 "재오픈·타 브라우저 접속 시 백지"를 의도된 동작으로 확정했지만, 이는 동시에 "화면을 실수로 벗어나면 진행 중이던 대화가 경고 없이 사라진다"는 부작용을 낳는다.
- 이 가드는 최초 설계 범위에는 없었고, 검증(TEST) 단계가 진행되던 중 소유자가 추가로 요구해(추가작업, R-8) 반영되었다.
- 이탈 경로는 하나가 아니라 네 갈래(콘솔 메뉴 전환·브라우저 새로고침/탭 닫기·프로젝트 전환·"새 대화" 클릭)이며, 각 경로가 화면 프레임워크 상에서 감지되는 방식이 서로 달라 단일 장치로는 전부 막을 수 없었다는 점이 설계의 핵심 난점이었다.
- 특히 "새 대화" 버튼은 처음에는 사용자의 명시적 의도 행위로 보아 가드 대상에서 제외했으나, 다른 3경로와의 일관성 및 "돌이킬 수 없는 대화 손실을 막는다"는 목적에 비추어 소유자가 뒤늦게 포함을 요청해 4번째 경로로 추가되었다.

## 결정 내용 (HOW)

대화 내역(turns)이 1개 이상 있을 때만 가드가 발동한다 — turns가 비어 있으면 경고 없이 즉시 진행한다. 4경로는 각기 다른 장치로 막는다.

1. **콘솔 메뉴 전환**: 화면 라우팅 전환을 가로채는 내비게이션 블로킹 훅으로 경로 이동을 감지해 확인 대화상자를 띄운다(`dashboard/frontend/src/pages/brain/BrainPage.tsx:306` `useBlocker`, pathname 변경만 감지해 같은 화면 내 쿼리 파라미터 변경과 구분).
2. **브라우저 새로고침·탭 닫기**: 브라우저 표준 이탈 확인 이벤트를 사용한다(`BrainPage.tsx:317-318` `beforeunload`) — 이 경로만 브라우저 기본 문구가 뜨며 커스텀 문구를 넣을 수 없다.
3. **프로젝트 스위처 변경**: 내비게이션 블로킹 훅은 같은 화면 내에서 프로젝트 컨텍스트만 바뀌는 전환을 잡지 못한다. 그래서 전역 UI 상태 저장소에 "브레인 대화가 더러워졌다(dirty)"는 플래그를 노출하고(`dashboard/frontend/src/store/ui-store.ts:24,52,64` `brainDirty`), 프로젝트 스위처를 보유한 상위 셸 컴포넌트가 이 플래그를 확인해 전환 자체를 가로챈다(`dashboard/frontend/src/components/app-shell/AppShell.tsx:119-147` `ProjectSwitcher`).
4. **"새 대화" 버튼**: 같은 화면 내 세션 교체이므로 ①③과 마찬가지로 라우팅으로는 잡히지 않는다. 별도 진입점에서 turns가 있으면 확인 대화상자를 띄우고, "확인"을 눌렀을 때만 실제 새 세션 발급 로직을 수행한다(`BrainPage.tsx:331` `pendingNewSession`, `:533` `handleNewSessionClick`).

4경로 모두 동일한 확인 대화상자 컴포넌트를 재사용해 사용자 경험을 통일했다 — "취소" 시 잔류·세션 유지, "확인/나가기" 시 진행(①②③은 실제 이탈, ④는 새 세션 발급으로 진행).
