# UI 분석·설계 스킬

정책서와 요구사항 문서를 분석하여 구조화된 **wireframe.md**를 생성합니다.

> **마이그레이션 안내**: HTML 와이어프레임 직접 생성 기능은 **ui-designer 스킬**로 이관되었습니다.
> 이 스킬은 UI 분석·설계에 집중하며, 산출물(wireframe.md)을 ui-designer에 전달하면 React + shadcn/ui 기반 UI를 생성할 수 있습니다.

```
파이프라인:
  wireframe-builder → wireframe.md → ui-designer → UI (프로토타입 또는 프로덕션)
```

---

## 스킬 프로세스 (4단계)

### Phase 1: 입력 분석

1. 정책서/요구사항 문서를 읽고 핵심 정보를 식별한다:
   - **핵심 기능**: 시스템이 제공하는 주요 기능 목록
   - **엔티티**: 관리 대상이 되는 데이터 객체 (사용자, 주문, 상품 등)
   - **사용자 역할**: 시스템을 사용하는 역할 유형 (관리자, 일반 사용자 등)
   - **비즈니스 규칙**: 화면 동작에 영향을 주는 정책/제약
2. 입력이 부족하면 interview 스킬을 참조하여 구조화된 질문으로 보완한다.
3. 서비스 유형을 판별한다: 관리자 대시보드, SaaS, 공개 웹사이트, 모바일 앱 등.

### Phase 2: 화면 도출

1. **화면 도출 규칙 테이블**을 적용하여 필요한 화면을 식별한다.
2. 각 화면에 **ID**(`SCR-NNN`), **유형**, **경로**, **메뉴 그룹**을 부여한다.
3. 화면 간 **네비게이션 흐름**을 정의한다 (진입점, 이동 관계).

### Phase 3: 화면별 상세 설계

1. 화면 유형에 맞는 **기본 ASCII 레이아웃**을 적용한다.
2. **구성 요소 테이블**을 작성한다: 영역 | UI 요소 | shadcn 컴포넌트 | 데이터/설명.
3. **화면 유형별 shadcn 기본 매핑**을 자동 적용한 뒤, 구체적 요구사항에 맞게 조정한다.
4. **인터랙션 목록**을 정의한다: 이벤트 → 동작 → 결과.

### Phase 4: 산출물 생성

1. wireframe.md 스키마에 따라 구조화된 마크다운을 생성한다.
2. version-mgr 규칙에 따라 버전을 관리한다.
3. 산출물 경로: `{태스크 폴더}/wireframe.md` 또는 사용자 지정 경로.

## 화면 도출 규칙

정책서/기획 문서의 요소에서 필요한 화면을 도출하는 매핑 규칙:

| 기획 요소 | 도출 화면 | 화면 유형 |
|----------|----------|----------|
| 엔티티 CRUD 요구 | 엔티티 관리 페이지 (목록 + 등록/수정) | `crud` |
| 대시보드/현황 요구 | 대시보드 페이지 | `dashboard` |
| 보고서/분석 요구 | 보고서 페이지 | `report` |
| 데이터 상세 보기 요구 | 상세 보기 페이지 | `detail` |
| 독립 입력 폼 요구 | 입력 폼 페이지 | `form` |
| 사용자/권한/시스템 설정 | 설정 페이지 | `settings` |
| 인증/회원가입 요구 | 인증 페이지 | `auth` |
| 실시간 상태 모니터링 | 모니터링 페이지 | `monitor` |

### 도출 보조 규칙

- 엔티티 1개당 최소 1개 화면 (CRUD 관리 페이지)
- 엔티티 간 관계가 있으면 상세 보기(detail) 화면 추가 고려
- 역할이 2개 이상이면 권한 설정(settings) 화면 추가
- 대시보드 요구가 없어도, 3개 이상 엔티티가 있으면 현황 대시보드 제안

## 화면 유형 분류

| 유형 코드 | 설명 | 대표 레이아웃 |
|----------|------|-------------|
| `dashboard` | 현황/통계 대시보드 | KPI 카드 + 차트 + 테이블 |
| `crud` | 엔티티 관리 (목록+등록/수정) | 검색/필터 + 테이블 + 모달/페이지 폼 |
| `detail` | 상세 보기 | 정보 카드 + 탭 + 관련 데이터 |
| `form` | 독립 폼 (등록/수정 전용 페이지) | 섹션별 필드 그룹 + 액션 버튼 |
| `settings` | 설정 | 탭 메뉴 + 섹션별 토글/입력 |
| `report` | 보고서/분석 | 필터 + 차트 + 데이터 테이블 |
| `auth` | 인증 (로그인/회원가입) | 중앙 정렬 카드 폼 |
| `monitor` | 실시간 모니터링 | 상태 카드 + 실시간 차트/로그 |

## 화면 유형별 ASCII 레이아웃 패턴

### 대시보드 (dashboard)
```
┌─────────────────────────────────────┐
│ [기간 필터] [카테고리 필터] ...       │
├─────────────────────────────────────┤
│ [KPI 카드] [KPI 카드] [KPI 카드] ... │
├─────────────────────────────────────┤
│ [차트 영역]           [차트 영역]     │
├─────────────────────────────────────┤
│ [데이터 테이블]                       │
│  정렬 | 필터 | 페이지네이션           │
└─────────────────────────────────────┘
```

### 관리 (crud)
```
┌─────────────────────────────────────┐
│ [페이지 제목]           [+ 등록 버튼] │
├─────────────────────────────────────┤
│ [검색바] [상태 필터]                  │
├─────────────────────────────────────┤
│ [데이터 테이블]                       │
│  체크박스 | 이름 | 상태 | 액션 버튼   │
│  [페이지네이션]                       │
└─────────────────────────────────────┘
```

### 상세 보기 (detail)
```
┌─────────────────────────────────────┐
│ [← 뒤로] [제목]        [편집] [삭제] │
├─────────────────────────────────────┤
│ [정보 카드]                          │
│  필드: 값 | 필드: 값 | 필드: 값      │
├─────────────────────────────────────┤
│ [탭: 관련 데이터A] [탭: 관련 데이터B] │
│ [탭 콘텐츠 — 테이블/리스트]           │
└─────────────────────────────────────┘
```

### 모달 폼 (crud/form 공용)
```
┌─────────────────────────────────────┐
│ [모달 제목]                    [X]   │
├─────────────────────────────────────┤
│ [라벨]: [입력 필드]                   │
│ [라벨]: [셀렉트박스]                  │
│ [라벨]: [칩 선택 UI]                  │
├─────────────────────────────────────┤
│              [취소] [저장]            │
└─────────────────────────────────────┘
```

### 설정 (settings)
```
┌─────────────────────────────────────┐
│ [설정 제목]                          │
├──────────┬──────────────────────────┤
│ [탭 메뉴] │ [섹션 제목]              │
│ 일반      │ [라벨] [토글/입력]        │
│ 알림      │ [라벨] [토글/입력]        │
│ 보안      │                          │
│          │ [섹션 제목]               │
│          │ [라벨] [토글/입력]         │
└──────────┴──────────────────────────┘
```

### 인증 (auth)
```
┌─────────────────────────────────────┐
│                                     │
│         ┌───────────────┐           │
│         │  로고/서비스명  │           │
│         │  [이메일 입력]  │           │
│         │  [비밀번호 입력] │          │
│         │  [로그인 버튼]  │           │
│         │  링크: 회원가입  │          │
│         └───────────────┘           │
│                                     │
└─────────────────────────────────────┘
```

### 드릴다운 패턴
```
[목록 레벨 1] → 행 클릭 → [목록 레벨 2] → 행 클릭 → [상세 보기]
```
- 뒤로가기 네비게이션 포함
- Breadcrumb으로 현재 위치 표시

## 화면 유형별 shadcn 기본 매핑

화면 유형을 결정하면 아래 기본 매핑을 자동 적용하고, 구체적 요구사항에 따라 조정한다.

| `form` | FieldGroup, Field, Input, Select | Button, Combobox, Textarea, Switch |
| `settings` | Tabs, Switch | Input, Select, Button, Separator |
| `report` | Chart, Table | Select(필터), Button(다운로드), DatePicker |
| `auth` | Card, Input, Button | FieldGroup, Field, Checkbox |
| `monitor` | Card, Badge | Chart, Table, ScrollArea, Alert |

## wireframe.md 산출물 스키마

아래 스키마에 따라 wireframe.md를 생성한다. ui-designer 스킬이 이 스키마를 파싱하여 UI를 구현하므로, 구조를 정확히 준수해야 한다.

### 전체 구조

```
wireframe.md
├── 헤더 (서비스명, 작성일, 버전)
├── 1. 서비스 개요
│   ├── 서비스명, 유형, 대상 사용자
│   └── 핵심 기능 목록
├── 2. 전체 구조
│   ├── 2.1 레이아웃 유형 + 설명
│   ├── 2.2 네비게이션 구조 (메뉴 트리)
│   └── 2.3 화면 흐름도 (화면 간 이동)
├── 3. 화면 목록 (마스터 테이블)
│   └── ID | 화면명 | 유형 | 경로 | 메뉴그룹 | 설명
├── 4. 화면별 상세 설계
│   └── (화면 수만큼 반복)
│       ├── 메타 정보 (유형, 경로, 진입점)
│       ├── 레이아웃 (ASCII 다이어그램)
│       ├── 구성 요소 테이블 (영역 | UI 요소 | shadcn 컴포넌트 | 데이터/설명)
│       ├── 기능 목록
│       └── 인터랙션 목록 (이벤트 → 동작 → 결과)
├── 5. 공통 컴포넌트
│   └── 컴포넌트 | shadcn 기반 | 사용 화면 | 설명
└── 6. shadcn 설치 목록
    └── 컴포넌트 | 사용 화면 + 설치 명령
```


```markdown
- **대상 사용자**: {역할1, 역할2, ...}
- **핵심 기능**:
  1. {기능1}
  2. {기능2}
  ...
```

```markdown
  - {메뉴항목3} → SCR-003

{화면 간 주요 이동 관계를 ASCII로 표현}
```

#### 3. 화면 목록

```markdown

|---------|-----------|----------|------|
```

### 화면 ID 규칙

- `SCR-{NNN}` 형식 (예: SCR-001, SCR-002)
- 3자리 순번, 도출 순서대로 부여
- 화면 목록(섹션 3)과 상세 설계(섹션 4)에서 동일 ID 사용

### 구성 요소 테이블 규칙

- **영역**: 화면 내 위치 (`header`, `filter`, `content`, `sidebar`, `footer`, `modal` 등)
- **UI 요소**: 사용자에게 보이는 요소 (검색바, 데이터 테이블, 등록 버튼 등)
- **shadcn 컴포넌트**: 해당 요소를 구현할 정확한 shadcn 컴포넌트명
- **데이터/설명**: 표시할 데이터 필드명이나 동작 설명

## 서브 에이전트 활용

대규모 설계(5화면 이상)는 서브 에이전트에 위임한다.

### 위임 전략

- **메인 에이전트**: Phase 1(입력 분석), Phase 2(화면 도출), Phase 4(산출물 통합)
- **서브 에이전트**: Phase 3(화면별 상세 설계)를 화면 단위로 분배

### 위임 시 전달 정보

1. 정책서/기획 문서 경로 및 관련 섹션
2. 담당 화면의 ID, 유형, 경로, 설명
3. 전체 구조 정보 (레이아웃 유형, 네비게이션 구조)
4. 이 스킬의 ASCII 레이아웃 패턴 및 shadcn 기본 매핑
5. 구성 요소 테이블 형식 및 인터랙션 목록 형식

### 위임 결과 통합

메인 에이전트가 서브 에이전트의 화면별 설계를 수집하여:
- 공통 컴포넌트(섹션 5) 추출
- shadcn 설치 목록(섹션 6) 집계
- 전체 wireframe.md로 통합
