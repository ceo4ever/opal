# TODO 단계 상세 가이드 (실행 체크리스트 + QA)

> **Full Task 전용**: 이 가이드는 Full Task 모드의 TODO 단계에서 사용된다.
> Short Task에서는 TODO 단계가 없으며, 실행 체크리스트는 PLAN.md에 통합된다.

> **실행 컨텍스트**: 이 가이드는 워커 에이전트의 컨텍스트에서 실행된다.
> 오케스트레이터가 워커를 디스패치하면, 워커가 이 가이드를 읽고 프로세스를 따른다.
> 서브 에이전트 사용이 불가능한 플랫폼에서는 오케스트레이터가 직접 이 가이드를 따른다.

PLAN.md의 구현 계획을 실행 가능한 세부 작업 단위로 분해하고, QA 체크리스트를 작성한다.
TODO.md는 "구현 단계에서 따라가는 작업 목록"이자 "사용자가 진행 상황을 추적하는 대시보드"이다.

---

## Part A: 작업 분해 원칙

### 분해 규칙

- **1파일 = 1작업**: 하나의 작업은 하나의 파일 또는 하나의 논리적 단위를 대상으로 한다
- **독립 테스트 가능**: 각 작업은 독립적으로 테스트 가능해야 한다
- **의존성 순서**: 작업 간 의존성 순서를 명시한다 (하위 레이어 먼저)
- **완료 기준 명확**: 각 작업에 "완료 기준"을 달아서, 끝났는지 모호하지 않게 한다

### Step 형식

```markdown
### Step {N}: {작업 제목}
- [ ] 완료
- **파일**: {대상 파일 경로}
- **작업 내용**: {무엇을 할지 구체적으로}
- **완료 기준**: {이것이 되면 완료}
- **테스트**: {어떻게 검증할지}
- **실행 방법**: {direct | sub-agent}
- **의존**: {선행 Step}
```

### 필드 설명

| 필드 | 설명 |
|------|------|
| 파일 | 대상 파일 절대/상대 경로 |
| 작업 내용 | 구체적인 구현 내용 (함수 추가, 필드 변경 등) |
| 완료 기준 | 검증 가능한 완료 조건 |
| 테스트 | 검증 명령어 또는 방법 |
| 실행 방법 | `direct` (메인 에이전트 직접) 또는 `sub-agent` (서브 에이전트 위임) |
| 의존 | 선행 Step 번호. 없으면 "없음" |

### 실행 방법 규칙

- `direct` -- 메인 에이전트가 직접 실행 (단순 모드 기본값)
- `sub-agent` -- 복잡 모드에서 워커 내부의 서브 에이전트에 위임 (Part C 토폴로지에 따라 결정)
- 단순 모드에서는 모든 Step이 `direct`
- 복잡 모드에서는 Part C의 에이전트 토폴로지가 각 Step의 실행 방법을 결정

## Part B: QA 체크리스트

### B-1. 기능 테스트

TASK.md의 요구사항이 모두 충족되는지 확인한다.
각 요구사항에 대응하는 테스트 항목을 작성한다.

### B-2. 회귀 테스트

기존 기능이 깨지지 않는지 확인한다.
기존 테스트 스위트 실행, 영향 범위의 기능 동작 확인을 포함한다.

### B-3. 코드 품질

프로젝트 코드 컨벤션(CLAUDE.md 등)을 준수하는지 확인한다:
- 타입 힌트, 주석, 포매터, 네이밍 규칙 등
- 린트/타입 체크 통과 여부

### B-4. 보안

민감 정보가 노출되지 않는지 확인한다:
- .env, 인증 파일이 .gitignore에 포함되어 있는가
- 코드에 하드코딩된 토큰/시크릿이 없는가

## 복잡도 판별 기준

Part A 작성 완료 후, 아래 기준으로 실행 모드를 결정한다:

| 기준 | 단순 모드 | 복잡 모드 |
|------|----------|----------|
| Step 수 | 5개 이하 | 6개 이상 |
| 변경 파일 수 | 3개 이하 | 4개 이상 |
| 모듈 범위 | 단일 모듈 | 다중 모듈/레이어 |
| 작업 유형 | 오류 수정, 단순 기능 수정 | 신규 개발, 대규모 개선 |
| 외부 의존성 | 없음 | 새 API, 새 패키지, 새 도구 필요 |

**하나라도 "복잡 모드" 기준에 해당하면 복잡 모드를 적용한다.**

---

## Part C: 실행 아키텍처 (복잡 모드 전용)

**이 파트는 복잡 모드에서만 생성된다.** Part A + B 작성 완료 후 복잡도 판별을 거쳐, 복잡 모드로 판정되면 워커가 Part C를 직접 생성한다.

Part C는 다음을 포함한다:
- **C-1. 에이전트 토폴로지** -- Step 간 의존성 DAG 기반 에이전트 그룹핑 및 실행 순서
- **C-2. 스킬 요구사항** -- 기존 스킬 매칭 + 신규 스킬 필요 여부
- **C-3. 도구 요구사항** -- CLI, MCP, 패키지 설치/설정 필요 사항
- **C-4. 테스트 전략** -- op-dev-test-agent 에이전트의 실행 계획

상세 형식은 `references/execute-plan-guide.md`를 참조한다.

## 상태 표시 규칙

체크박스로 완료 상태를 관리한다:
- `- [ ] 완료` -- 미완료
- `- [x] 완료` -- 완료

블로커 발생 시:
- 체크박스는 미완료 상태로 유지
- Step 아래에 `> 블로커: {설명}` 인라인 메모 추가
- 즉시 사용자에게 보고

## 품질 체크리스트

- [ ] PLAN.md의 모든 구현 항목이 Step으로 분해되었는가?
- [ ] 각 Step의 완료 기준이 명확하고 검증 가능한가?
- [ ] Step 간 의존성 순서가 올바른가?
- [ ] 각 Step의 실행 방법(direct/sub-agent)이 지정되었는가?
- [ ] QA 체크리스트가 TASK.md의 모든 요구사항을 커버하는가?
- [ ] 회귀 테스트와 보안 체크가 포함되어 있는가?
- [ ] 복잡도 판별 기준에 따라 실행 모드가 올바르게 결정되었는가?
- [ ] 복잡 모드일 경우 Part C가 포함되어 있는가?

## 사용자 보고

TODO.md 작성 완료 후, 워커가 결과를 오케스트레이터에 반환한다:
- `artifact_path`: TODO.md 경로
- `summary`: 작업 요약 (Step 수, 실행 모드, 주요 작업)
- `status`: 완료/블로커
- `complexity`: 단순/복잡 + 판별 근거

오케스트레이터가 사용자에게 보고하고, 승인을 받으면 EXECUTE 단계로 진행한다.
QA 에이전트 호출 없음.
