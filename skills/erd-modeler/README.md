# erd-modeler (erm)

개념(Mermaid) → 논리(Mermaid) → 물리(DBML→DDL) 3단계로 DB ERD를 모델링하는 스킬.

> **[DEPRECATED]** 이 스킬은 `op-data-model` / `op-data-ddl`로 분해 이관되었습니다. `//erm`은 `op-data-model` 단독 호출 alias로 하위호환을 위해 유지되고 있습니다. 신규 데이터 설계 파이프라인은 `//opdd`(opal-pilot-data-design)를 사용하는 것이 권장됩니다.

## 개요

엔티티/속성/관계 정의가 필요한 작업에서, 비즈니스 관점의 개념 모델부터 속성·FK가 상세화된 논리 모델, DBMS에 특화된 물리 모델(DDL 포함)까지 단계적으로 만들어 줍니다. 표준사전(단어/도메인/코드) 자체의 CRUD는 `data-dictionary` 스킬이 전담하며, 이 스킬은 사전을 읽기 전용으로 참조만 합니다.

## 언제 쓰나

- "ERD 만들어줘", "데이터 모델링", "테이블 설계", "논리 모델링", "물리 모델링", "DDL 생성", "스키마 설계" 요청을 받았을 때
- 엔티티·속성·관계 정의가 필요한 모든 작업

## 사용법

호출: `//erm`

| 모드 | 트리거 | 설명 |
|------|--------|------|
| `model` | ERD 모델링 | 개념→논리→물리 단계별 모델링 |
| `ddl` | DDL 추출 | DBML → 지정 DBMS용 CREATE TABLE 스크립트 |

모드가 불명확하면 사용자에게 확인합니다. 출력 경로도 사용자 지정 경로 → 기존 산출물 경로 → 사용자 확인 순으로 결정합니다.

### 표준사전 참조 (3단계 폴백)

| 단계 | 조건 | 처리 |
|------|------|------|
| 1 | 사용자가 사전 파일 경로 제공 | 해당 경로를 Read하여 로드 |
| 2 | 사전 없음(소규모/신규 프로젝트) | 내부 분류어 약어표를 기반으로 진행하고 "표준사전 없이 내부 기본 규칙으로 진행합니다" 안내 |
| 3 | 외부 표준이 필요한 경우 | 웹 검색으로 해당 도메인 표준 참조 |

## 동작 흐름

### model 모드

```
개념 모델링 (Mermaid)          비즈니스 관계, 카디널리티, M:N 허용, FK 없음
  ↓
논리 모델링 (Mermaid)          속성/FK/데이터타입 상세화, 식별·비식별 관계, M:N 해소, 표준용어사전 기반 속성명
  ↓
물리 모델링 (DBML)             DBMS 특화 타입/인덱스/제약조건, DDL 자동 추출
```

- 개념 모델링: 관계명은 한글 동사형("운영한다"), 카디널리티는 1:1/1:N/M:N, FK는 표현하지 않습니다.
- 논리 모델링: 모든 속성은 표준용어사전 등록 용어를 사용하고(미등록 시 먼저 등록), 식별/비식별 관계를 판단하여 표시합니다.
- 물리 모델링: 명명규칙(`{스키마}_{주제영역}_{엔티티}_{유형}`)을 적용해 테이블명을 정하고, 도메인사전에서 DBMS별 컬럼 타입을 매핑합니다.

### ddl 모드

`dbml2sql` CLI로 DBML을 원하는 DBMS(MySQL/PostgreSQL/MSSQL 등)의 CREATE TABLE 스크립트로 변환합니다. CLI가 없으면 도메인사전의 타입 매핑을 참조해 직접 DDL을 생성합니다. 기존 DB에서 역으로 DBML을 뽑아낼 때는 `sql2dbml`을 사용합니다.

## 산출물

권장 폴더 구조(프로젝트 상황에 따라 조정 가능)는 다음과 같습니다.

```
{출력경로}/
├── 개념모델링/
│   ├── ERD_SA{N}_{영역명}.mermaid
│   └── ERD_SA{N}_{영역명}.md
├── 논리모델링/
│   ├── ERD_SA{N}_{영역명}_논리.mermaid
│   └── ERD_SA{N}_{영역명}_논리.md
└── 물리모델링/
    ├── {프로젝트명}_전체.dbml
    └── ddl/
        └── {DBMS명}/{프로젝트명}_DDL_{DBMS명}.sql
```

DDL에는 CREATE TABLE(컬럼·타입·NOT NULL·DEFAULT), PRIMARY KEY, FOREIGN KEY(ON DELETE/ON UPDATE), INDEX/UNIQUE INDEX, 테이블/컬럼 COMMENT(한글명)가 포함됩니다.

## FAQ

### 표준사전이 없는 프로젝트에서도 쓸 수 있나요?
네. 사전이 없으면 내부 기본 명명규칙(분류어 약어표)으로 진행하며, 그 사실을 안내합니다.

### 어떤 DBMS를 기본으로 하나요?
물리 모델링 시 대상 DBMS를 명시하지 않으면 MySQL 9을 기본으로 합니다.
