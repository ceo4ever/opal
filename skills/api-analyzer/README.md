# api-analyzer

외부 서비스의 API 공식 문서를 7단계 프레임워크로 분석하여 표준 명세서를 산출하는 스킬.

## 개요

새로운 외부 서비스와 연동을 검토하거나 기존 연동을 점검할 때, API 문서를 인증·엔드포인트·요청/응답·페이징·제한사항·에러·연동전략 순서로 체계적으로 훑어 표준 형식의 명세서(Markdown)로 정리해 줍니다.

## 언제 쓰나

- 새로운 외부 API를 연동하기 전에 공식 문서를 분석해야 할 때
- 기존 연동의 인증 방식, 레이트 리밋, 에러 처리 방식을 다시 점검하고 문서화해야 할 때
- 여러 서비스의 API를 한 번에 비교 검토해야 할 때

## 사용법

호출 트리거(자연어): "API 분석해줘", "API 명세서 작성", "API 검토", 새로운 서비스 연동 검토, API 공식 문서 분석, API 스펙 정리, 외부 API 조사.

전용 alias는 없습니다. 분석하고 싶은 API의 공식 문서(URL 또는 텍스트)와 함께 위 트리거 문구로 요청하면 됩니다.

| 입력 | 설명 |
|------|------|
| API 공식 문서 | URL, 붙여넣은 텍스트 등 |
| (선택) 프로젝트 표준 필드 정보 | 있으면 섹션 9 필드 매핑에 활용 |

## 동작 흐름

아래 7단계를 순서대로 수행합니다.

1. **인증 방식 분석**: OAuth2 / API Key / HMAC / Service Account / Bearer Token 중 어떤 방식인지, 필요한 인증 정보와 토큰 발급/갱신 절차를 확인합니다.
2. **엔드포인트 분석**: Base URL, API 버전, 주요 엔드포인트 목록, HTTP 메서드, URL 패턴과 파라미터를 정리합니다.
3. **요청/응답 구조 분석**: 요청/응답 스키마, 데이터 타입과 단위(특히 금액·비율·날짜), 프로젝트 표준 필드와의 매핑 가능성을 확인합니다.
4. **페이징/대량 데이터 처리**: offset / cursor / token-based / 스트리밍 등 페이징 방식과 대용량 조회 전략을 확인합니다.
5. **레이트 리밋 및 제한사항**: 분당/시간당/일당 요청 제한, 동시 요청 제한, 리밋 초과 시 대응 전략을 확인합니다.
6. **에러 처리**: HTTP 상태 코드, 서비스 고유 에러 코드, 재시도 가능 여부를 정리합니다.
7. **프로젝트 연동 전략**: 수집 대상 범위, 수집 주기, 정규화 시 주의점, 데이터 정합성 검증 포인트를 도출합니다.

여러 서비스를 동시에 분석해야 하는 경우, 서브 에이전트를 병렬로 띄워 각각 이 7단계 프레임워크를 적용합니다.

## 산출물

아래 9개 섹션으로 구성된 `{서비스명} API 명세서` Markdown 문서입니다.

| 섹션 | 내용 |
|------|------|
| 1. 개요 | 서비스 소개, 주요 특징, 적용 범위 |
| 2. 인증 방식 | 인증 유형, 필요 정보, 발급 방법, 헤더 구성, 코드 예시 |
| 3. 엔드포인트 | 엔드포인트 목록 테이블, 상세 설명 |
| 4. 요청/응답 구조 | 엔드포인트별 요청 파라미터, 응답 필드 상세 |
| 5. 페이징 및 대량 데이터 | 페이징 방식, 전략 |
| 6. 레이트 리밋 | 제한 사항 테이블, 대응 전략 |
| 7. 에러 처리 | 에러 코드 테이블, 재시도 전략 |
| 8. 연동 전략 | 수집 범위, 주기, 설계 포인트 |
| 9. 필드 매핑 | 프로젝트 표준 대비 Dimension/Metric 매핑 테이블 |
