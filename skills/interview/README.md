# interview

요구사항이 불명확할 때 의사결정트리 기반으로 한 번에 한 질문씩 물어 요구사항을 완결시키는 인터뷰 스킬.

## 개요

새로운 요구사항이나 정책 변경 요청을 받았지만 세부 사항이 불명확할 때, 무작정 여러 질문을 한꺼번에 던지지 않고 직전 답변에 따라 다음 질문을 결정하는 방식으로 요구사항을 좁혀 나갑니다. 기존 산출물(정책서, 설계서 등)이 있으면 이를 참조해 이미 답이 나온 항목은 질문 없이 스킵합니다.

## 언제 쓰나

- 새로운 요구사항을 정의해야 하는데 세부 사항이 부족할 때
- 정책 변경 요청을 받았지만 영향 범위가 불명확할 때
- "검토해줘", "확인해줘", "궁금한 거 물어봐" 같은 요청을 받았을 때
- 다른 스킬(wireframe-builder, html-mockup 등)이 입력 부족으로 이 스킬을 참조해 부족분만 물어야 할 때

## 사용법

전용 alias는 없습니다. 위 트리거 상황에서 자연어로 요청하면 다른 작업의 일부로, 또는 단독으로 호출됩니다.

| 항목 | 내용 |
|------|------|
| 입력 | 사용자의 초기 요청 + (있으면) 기존 산출물 |
| 진행 방식 | AskUserQuestion 도구로 매 콜당 질문 1개만 전달 |
| 출력 | 의사결정 기록 (결정 사항 요약 + 영향 범위) |

## 동작 흐름

1. **초기 분석**: 요청 내용에서 명시적 요구사항을 추출하고, 기존 산출물이 있으면 읽어 갭·충돌을 식별한 뒤 불명확한 점을 의사결정트리로 구조화합니다. 루트(상위 결정)부터 리프(세부 결정)까지 배치합니다.
2. **질문 1개 전달 (반복)**: 트리의 현재 노드 하나만 질문합니다. 짧은 header, 배경 설명이 담긴 question, 장단점을 포함한 2~4개의 구체적 options로 구성합니다. 컨텍스트나 기존 산출물에서 이미 답이 나오는 노드는 질문 없이 "{항목}은 {추론값}으로 자동 결정. 변경하시려면 알려주세요." 1줄 통지 후 스킵합니다.
3. **답변 분석 및 분기**: 답변이 기존 규칙/산출물과 일관되는지 검증한 뒤, 답변에 따라 다음 가지를 선택합니다(불필요한 가지는 쳐냅니다). 미해결 노드가 남아 있으면 2단계로 돌아갑니다.
4. **의사결정 기록**: 트리를 끝까지 타고 나면 "[결정 사항 요약]"과 "[영향 범위]"(영향받는 산출물, 필요한 업데이트) 형식으로 정리합니다.

인터뷰 중에는 변경 영역에 따라 관련 기존 산출물(정책서, DB 설계서, 와이어프레임, 표준 지표 정의 등)과 교차 검증합니다.

## 산출물

채팅 응답 형태의 의사결정 기록입니다. 별도 파일을 생성하지 않으며, 결과는 다음 형식으로 정리됩니다.

```
[결정 사항 요약]
1. {질문 주제}: {결정 내용} — {근거/맥락}
...

[영향 범위]
- 영향받는 산출물: {목록}
- 필요한 업데이트: {목록}
```
