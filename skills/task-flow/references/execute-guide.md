# EXECUTE 단계 상세 가이드 (실행 관리)

TODO.md의 승인을 받은 후, 실제로 코드를 작성하고 검증하는 단계이다.
실행 모드(단순/복잡)에 따라 실행 방식이 달라진다.

---

## 실행 모드별 동작

### 단순 모드 (Simple Mode)

메인 에이전트가 Step 순서대로 직접 실행한다.

```
Step 1 → Step 2 → ... → Step N → 인라인 테스트 → QA → 완료 보고
```

**실행 규칙:**
1. Part A의 Step을 의존성 순서대로 하나씩 실행
2. 각 Step 실행 시:
   - 대상 파일 Read → 내용 파악
   - Edit/Write로 코드 작성/수정
   - Step의 테스트 기준에 따라 인라인 테스트 실행
   - TODO.md 체크박스 갱신
3. 블로커 발생 시:
   - 즉시 사용자에게 보고
   - 사용자 지시 대기
4. 모든 Step 완료 후:
   - Part B QA 체크리스트를 인라인으로 검증
   - QA 에이전트 호출 → QA-EXECUTE.md 생성
   - 사용자에게 완료 보고

### 복잡 모드 (Complex Mode)

Part C 토폴로지에 따라 서브 에이전트를 배치하여 실행한다.

```
Batch 1: [Agent-1, Agent-2 병렬] → Batch 2: [Agent-3] → ... → Test Agent → QA → 완료 보고
```

**실행 규칙:**
1. Part C-1의 에이전트 토폴로지에 따라 배치(batch) 구성
2. 각 배치 실행 시:
   - 배치 내 에이전트를 **병렬로** Task 도구로 실행
   - 각 서브 에이전트에 전달할 정보:
     - 담당 Step 목록 + 상세 내용
     - 필요 컨텍스트 (PLAN.md 참조 섹션, 기존 파일 등)
     - 프로젝트 CLAUDE.md 코드 컨벤션
     - 필요 스킬 (있으면 스킬 경로 전달)
   - 배치 완료 시 진행 보고
3. 전체 에이전트 완료 후:
   - task-flow-test 에이전트 호출 → TEST-REPORT.md 생성
   - QA 에이전트 호출 → QA-EXECUTE.md 생성
   - 사용자에게 완료 보고

### Short Task 모드

PLAN.md 기반으로 실행한다:

1. PLAN.md 실행 체크리스트(섹션 3)를 순서대로 실행
2. 각 Step 완료 시: PLAN.md 체크박스 갱신
3. 블로커 발생 시 즉시 사용자에게 보고
4. 모든 Step 완료 후:
   - QA 체크리스트(섹션 4)를 인라인으로 검증
   - QA 에이전트 호출 → QA-EXECUTE.md 생성
   - 사용자에게 완료 보고

## 서브 에이전트 프롬프트 구성

복잡 모드에서 각 서브 에이전트에 전달하는 프롬프트 구조:

```
## 역할
{Agent-N}: {역할명}

## 담당 작업
{Part A에서 해당 Step들의 전체 내용 복사}

## 컨텍스트
- 프로젝트 루트: {경로}
- 참조 파일: {PLAN.md §N, 기존 파일 경로 등}
- 코드 컨벤션: {CLAUDE.md 핵심 규칙}

## 스킬 (필요 시)
{스킬 경로 또는 인라인 지침}

## 실행 규칙
1. 각 Step을 순서대로 실행
2. Step마다: Read → Edit/Write → 테스트
3. 완료 시 변경 파일 목록 반환
4. 블로커 발생 시 즉시 보고
```

---

## 체크리스트 갱신 규칙

EXECUTE 중 각 Step 완료 시 즉시 체크박스를 갱신한다.

### Full Task
TODO.md Part A의 각 Step:
- `- [ ] 완료` → `- [x] 완료`

### Short Task
PLAN.md 실행 체크리스트(섹션 3)의 각 Step:
- `- [ ] Step N: ...` → `- [x] Step N: ...`

---

## 블로커 처리

블로커가 발생하면:

1. **즉시 중단** — 추측으로 해결하지 않는다
2. **사용자 보고**:
   ```
   🚫 [EXECUTE] 블로커 발생

   📍 Step {N}: {제목}
   ❌ 문제: {구체적 에러/상황}
   💡 가능한 원인: {추정}
   🔧 제안: {해결 방안}

   어떻게 진행할까요?
   ```
3. **사용자 지시 대기** — 지시에 따라 재개 또는 건너뛰기

## 진행 보고 형식

### 배치 완료 보고 (복잡 모드)

```
📋 [EXECUTE] 배치 {M}/{K} 완료

진행 상황:
- ✅ Agent-1 ({역할명}): Step 1, 2 완료
- ✅ Agent-2 ({역할명}): Step 3, 4 완료
- 전체: {완료 Step}/{전체 Step} ({백분율}%)

다음 배치 진행합니다.
```

### EXECUTE 최종 보고

```
📋 [EXECUTE] 완료 보고

📎 산출물: {변경 파일 목록}
📎 테스트: tasks/{NNN}-{태스크명}/TEST-REPORT.md (복잡 모드)
📎 QA 리뷰: tasks/{NNN}-{태스크명}/QA-EXECUTE.md

[실행 요약]
- 전체 Step {N}개 중 {완료}개 완료
- 변경 파일 {M}개
- 테스트: {결과}
- QA 판정: {✅ Pass / ⚠️ Needs Revision}
```

## QA 에이전트 호출 (EXECUTE 단계)

EXECUTE 완료 후, QA 에이전트를 호출하여 QA-EXECUTE.md를 생성한다.

**호출 정보:**
- stage: `EXECUTE`
- task_path: 태스크 폴더 경로
- artifact_path: TODO.md (상태 갱신 완료된 버전)
- 추가 참조: TEST-REPORT.md (복잡 모드), 변경 파일 목록

## 동적 스킬 사용 (복잡 모드)

Part C-2에서 스킬이 필요한 에이전트가 있을 때:

### 기존 스킬 사용
- 서브 에이전트 프롬프트에 스킬 경로를 전달
- 서브 에이전트가 해당 스킬의 SKILL.md를 Read하고 프로세스를 따름

### 신규 생성 스킬 사용
- `tasks/{NNN}/skills/{name}/SKILL.md`에서 읽기
- 서브 에이전트 프롬프트에 포함

### 인라인 지침
- Part C-2에서 인라인 지침으로 분류된 경우
- 에이전트 프롬프트의 "스킬" 섹션에 직접 포함
