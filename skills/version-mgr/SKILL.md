# 산출물 버전 관리 스킬

산출물의 버전을 체계적으로 관리하여 변경 이력을 추적하고, 이전 버전을 보존합니다.

## 버전 넘버링 규칙

### 버전 형식: `v{Major}.{Minor}`

| 변경 수준 | 버전 변경 | 예시 | 기준 |
|-----------|----------|------|------|
| **구조적 변경** | Major 증가 | v1.0 → v2.0 | 섹션 추가/삭제, 엔티티 신규, 아키텍처 변경 |
| **내용 수정** | Minor 증가 | v1.0 → v1.1 | 기존 섹션 내용 수정, 오류 수정, 보강 |

### 판단 기준 상세

Major 변경 (v1.x → v2.0):
- 새로운 주요 개념이나 구조가 추가될 때
- 문서 구조(섹션) 자체가 추가되거나 대폭 변경될 때
- 기존 규칙이 근본적으로 바뀔 때

Minor 변경 (v1.0 → v1.1):
- 기존 섹션 내 설명 보강, 테이블 데이터 추가
- 오탈자, 수치 수정
- 기존 규칙의 세부 조정

## 파일 관리 프로세스

### 1단계: 기존 버전 확인
해당 폴더에서 동일 문서의 최신 버전을 확인한다.

### 2단계: 새 파일 생성 (이전 버전 보존)
기존 파일을 절대 덮어쓰지 않는다. 새 버전은 새 파일로 생성한다.

### 3단계: 변경이력 업데이트
문서 하단의 변경이력 테이블에 새 버전 항목을 추가한다. 이전 버전의 변경이력도 모두 포함해야 한다.

### 4단계: 헤더 메타정보 갱신
```
> 작성일: {오늘 날짜} | 작성자: {에이전트명} | 버전: v{새 버전}
```

## 변경이력 테이블 형식

```markdown
| 버전 | 날짜 | 작성자 | 변경내용 |
|------|------|--------|---------|
| v1.0 | YYYY-MM-DD | {작성자} | 초기 작성 |
| v1.1 | YYYY-MM-DD | {작성자} | {핵심 변경 1줄 요약} |
```

변경내용은 1줄로 핵심만 기술한다. 상세 내용은 문서 본문에서 확인한다.

## HTML/바이너리 파일 버전 관리

코드 내부에 변경이력 섹션이 없는 파일(HTML, 바이너리 등):
- 파일명으로 버전 관리 (예: `wireframe_v3.0.html`)
- 부분 수정은 기존 파일을 직접 Edit (Minor: 파일명 유지)
- 대규모 변경은 새 파일 생성 (Major: 새 파일명)

## 버전 관리 시 주의사항

산출물 업데이트 요청을 받으면:
1. 반드시 최신 버전 파일을 Read로 먼저 확인
2. 변경 범위를 파악하여 Major/Minor 결정
3. 이전 버전의 모든 내용을 새 버전에 계승 (누락 방지)
4. 변경된 부분만 정확히 수정 (관련 없는 부분 변경 금지)
