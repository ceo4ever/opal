# TEST-SCENARIO.md 작성 가이드

> **실행 컨텍스트**: 이 가이드는 워커 에이전트의 컨텍스트에서 실행된다.
> PLAN(Short) 또는 TODO(Full) 완료 후, EXECUTE 전에 워커가 이 가이드를 읽고 TEST-SCENARIO.md를 작성한다.
> 작성된 TEST-SCENARIO.md는 사용자 검토 게이트를 거친 후, EXECUTE 완료 시 op-dev-test-agent가 실행 결과를 채운다.

---

## 목적

TEST-SCENARIO.md는 두 가지 역할을 수행한다:

1. **설계 검증** -- 테스트 시나리오를 구체화하는 과정에서 PLAN/TODO의 빈틈을 발견
2. **테스트 계획 + 결과 통합** -- 단일 파일에 시나리오(계획)와 실행 결과를 함께 관리

---

## 작성 프로세스

### Step 1: 컨텍스트 확인

PLAN.md(Short) 또는 TODO.md(Full)에서 아래 정보를 확인한다:
- 변경 파일 목록
- 핵심 설계 (함수/클래스 시그니처, 변경 포인트)
- QA 체크리스트 (기능 테스트, 회귀 테스트 항목)
- TASK.md의 요구사항

### Step 1-b: 도구 사전 확인

테스트 도구를 사전에 결정하여 시나리오의 "도구" 필드를 기입한다.

1. `{project}/.opal/test-tools.yaml` 존재 여부 확인
2. **있으면**: `stack` 및 `tools` 섹션을 읽어 사용 가능한 도구 목록 파악
3. **없으면**: 프로젝트 설정 파일(`package.json`, `pyproject.toml` 등)에서 추론
   - `package.json`의 `devDependencies`에 vitest/jest 있으면 → unit: vitest/jest
   - `pyproject.toml`에 pytest 있으면 → unit: pytest
4. 아래 시나리오 유형 → 도구 매핑 테이블을 참조하여 각 시나리오에 사용할 도구 결정
5. TEST-SCENARIO.md의 각 시나리오 "도구" 필드에 결정된 도구를 기입

**시나리오 유형 → 도구 매핑 테이블:**

| 시나리오 유형 | 대응 카테고리 | 예시 도구 (TypeScript) | 예시 도구 (Python) |
|-------------|------------|----------------------|------------------|
| 함수/클래스 단위 검증 | unit | vitest, jest | pytest |
| API 엔드포인트 검증 | e2e 또는 unit | playwright, supertest | pytest + httpx |
| 브라우저 UI 검증 | e2e | playwright, cypress | playwright |
| 린트/포맷 | lint, format | eslint, prettier | ruff, black |
| 타입 안전성 | typecheck | tsc | mypy |
| 시크릿/보안 | security | gitleaks (global) | gitleaks (global) |

### Step 2: 시나리오 도출

TASK.md의 각 요구사항에 대해 시나리오를 도출한다:

1. **기능 시나리오**: 각 요구사항의 정상 동작을 검증하는 시나리오
2. **에지 케이스**: 경계값, 에러 입력, 빈 값 등
3. **통합 시나리오**: 여러 요구사항이 함께 동작하는 시나리오 (해당 시)

**시나리오 ID 규칙**: S-1, S-2, ... S-N (순번)

### Step 3: 시나리오 작성

각 시나리오에 대해 아래 4가지를 작성한다:
- **대상**: 어떤 기능/변경점을 테스트하는지
- **조건**: 입력 데이터, 사전 상태, 환경 조건
- **기대 결과**: 성공 기준 (구체적으로, 검증 가능하게)
- **도구**: Step 1-b에서 결정한 도구 기입 (예: `vitest`, `playwright`, `gitleaks`)

나머지 필드(실행 명령, 결과, 상세)는 비워둔다 -- op-dev-test-agent가 채운다.

### Step 4: 문서 전용 태스크 확인

변경 파일이 모두 `.md` 파일이면:
- 시나리오 목록 섹션에 "문서 전용 변경 -- 코드 테스트 대상 없음" 명시
- 코드 품질/보안/회귀 섹션은 템플릿 그대로 유지 (op-dev-test-agent가 스킵 판단)
- 시나리오는 문서 품질 관련 항목만 작성 (내용 정합성, 참조 링크 유효성 등)

### Step 5: 설계 검증

시나리오를 작성하면서 발견한 설계 빈틈이 있으면:
- TEST-SCENARIO.md 하단 "설계 피드백" 섹션에 기록
- 심각한 빈틈이면 오케스트레이터에 보고하여 PLAN 수정을 제안

---

## 시나리오 수 가이드

| 태스크 규모 | 시나리오 수 | 기준 |
|------------|-----------|------|
| Short Task (소규모) | 2~5개 | 핵심 기능 + 주요 에지 케이스 |
| Full 단순 | 3~8개 | 요구사항별 1~2개 |
| Full 복잡 | 5~15개 | 요구사항별 2~3개 + 통합 |
