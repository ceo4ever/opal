# 외부 API 분석 스킬

외부 서비스의 API 공식 문서를 체계적으로 분석하여 표준 명세서를 산출합니다.

## 7단계 분석 프레임워크

모든 API 분석은 다음 7단계를 순서대로 수행한다:

### Step 1: 인증 방식 분석
```
확인 항목:
- 인증 유형: OAuth2 / API Key / HMAC / Service Account / Bearer Token
- 필요한 인증 정보 (키, 토큰, ID 등)
- 토큰 발급/갱신 프로세스
- 인증 헤더 구성 방식
- 만료 정책 및 갱신 전략
```

### Step 2: 엔드포인트 분석
```
확인 항목:
- Base URL 및 API 버전
- 주요 엔드포인트 목록 (프로젝트에 필요한 것 중심)
- HTTP 메서드 (GET/POST/PUT/DELETE)
- URL 패턴 및 경로 파라미터
- 필수/선택 쿼리 파라미터
```

### Step 3: 요청/응답 구조 분석
```
확인 항목:
- 요청 본문 스키마 (JSON/Form/GraphQL)
- 응답 본문 스키마 (필드, 타입, 설명)
- 데이터 타입 및 단위 (특히 금액, 비율, 날짜)
- 프로젝트 표준 필드와의 매핑 가능성
```

### Step 4: 페이징/대량 데이터 처리
```
확인 항목:
- 페이징 방식: offset / cursor / token-based / 스트리밍
- 한 페이지 최대 레코드 수
- 전체 데이터 조회 전략
- 대용량 데이터 조회 방식 (비동기 보고서, 스트리밍 등)
```

### Step 5: 레이트 리밋 및 제한사항
```
확인 항목:
- 분당/시간당/일당 요청 제한
- 동시 요청 제한
- 데이터 조회 기간 제한
- 리밋 초과 시 응답 및 대응 전략
```

### Step 6: 에러 처리
```
확인 항목:
- HTTP 상태 코드별 의미
- 서비스 고유 에러 코드 체계
- 에러 응답 구조
- 재시도 가능 여부 판단 기준
- 공통 예외로의 변환 전략
```

### Step 7: 프로젝트 연동 전략
```
확인 항목:
- 수집 대상 데이터 범위
- 수집 주기 권장 사항
- 정규화(Normalization) 시 주의점
- 데이터 정합성 검증 포인트
- 기존 연동과의 공통점/차이점
```

## 명세서 출력 구조

```markdown
# {서비스명} API 명세서

> 작성일: YYYY-MM-DD | 작성자: {작성자명} | 버전: v1.0

## 1. 개요
[서비스 소개, 주요 특징, 적용 범위]

## 2. 인증 방식
[인증 유형, 필요 정보, 발급 방법, 헤더 구성, 코드 예시]

## 3. 엔드포인트
[엔드포인트 목록 테이블, 상세 설명]

## 4. 요청/응답 구조
[엔드포인트별 요청 파라미터, 응답 필드 상세]

## 5. 페이징 및 대량 데이터
[페이징 방식, 전략]

## 6. 레이트 리밋
[제한 사항 테이블, 대응 전략]

## 7. 에러 처리
[에러 코드 테이블, 재시도 전략]

## 8. 연동 전략
[수집 범위, 주기, 설계 포인트]

## 9. 필드 매핑 (프로젝트 표준 대비)
[Dimension 매핑 테이블, Metric 매핑 테이블]
```

## 인증 유형별 참고 패턴

다양한 인증 방식의 일반적인 특성:

| 인증 유형 | 특징 | 주의점 |
|-----------|------|--------|
| OAuth 2.0 | 토큰 기반, 권한 스코프 | 토큰 갱신 자동화, 권한 범위 확인 |
| API Key | 키 기반, 간단 | 키 노출 방지, Rate Limit 확인 |
| HMAC | 요청 서명, 보안 높음 | timestamp 정확도, 서명 순서 |
| Service Account | 서버-서버, 키 파일 | JSON 키 관리, 권한 할당 |
| Bearer Token | 헤더 토큰 전달 | 만료 시간, 갱신 메커니즘 |

## 병렬 실행 전략

여러 서비스를 동시에 분석해야 할 경우, 서브 에이전트를 활용하여 병렬로 분석한다. 각 서브 에이전트에게 이 스킬의 7단계 프레임워크와 명세서 출력 구조를 전달한다.
