# 표준 기술 문서 작성 스킬

프로젝트의 모든 기술 문서가 일관된 표준을 따르도록 보장합니다.

## 핵심 원칙

1. **언어 규칙**: 프로젝트의 CLAUDE.md 또는 코드 컨벤션 문서에 정의된 언어 규칙을 따른다. 별도 규칙이 없으면 본문은 한국어, 코드/변수/필드명은 영어를 기본으로 한다.
2. **문서 형식**: Markdown(.md) 기본, 필요 시 .docx/.xlsx/.pptx
3. **파일명 규칙**: 프로젝트 규칙을 따른다. 별도 규칙이 없으면 `{내용}_{버전}.{확장자}` 형식을 사용한다.
4. **저장 위치**: 프로젝트 구조에 맞춰 저장한다.

## 문서 템플릿

모든 기술 문서는 반드시 아래 구조로 시작한다:

```markdown
# [문서 제목]

> 작성일: YYYY-MM-DD | 작성자: [작성자명] | 버전: v{X.Y}

---

## 1. 개요
[문서 목적, 대상, 범위]

## 2. 상세 내용
[본문]

## 3. 참고사항
[관련 문서, 제약사항]

---

변경이력:

| 버전 | 날짜 | 작성자 | 변경내용 |
|------|------|--------|---------|
| v1.0 | YYYY-MM-DD | [작성자명] | 초기 작성 |
```

## 문서 유형별 가이드

| 문서 유형 | 필수 섹션 | 비고 |
|-----------|----------|------|
| **분석서** | 개요, 분석 대상, 분석 결과, 종합 평가 | 데이터 기반 |
| **명세서** | 개요, 인증, 엔드포인트, 요청/응답, 에러, 제한사항 | API 중심 |
| **정책서** | 개요, 용어정의, 각 정책 영역, 변경이력 | 비즈니스 규칙 |
| **설계서** | 개요, 아키텍처, 상세 설계, 인터페이스, 제약사항 | 기술 중심 |
| **계획서** | 개요, 목표, 범위, 일정, 산출물, 리스크 | 작업 계획 |

## 테이블 작성 규칙

- 모든 테이블에는 헤더 행과 구분선이 있어야 한다
- 테이블 내 데이터는 좌측 정렬 기본
- 빈 셀은 `-` 또는 `N/A`로 표시
- 테이블이 5개 컬럼을 초과하면 분리 검토

## 작업 보고 규칙

문서 작성 완료 시 반드시 다음을 제공한다:
- 산출물 파일 경로
- 주요 변경 사항 요약 (3줄 이내)
- 관련 문서 영향 분석 (다른 문서에 영향이 있는지)
