## 체크리스트 검토

### R1 — search 커맨드 정규식 전환

- [x] `search "auth.*service"` 실행 시 `auth`와 `service`를 모두 포함하는 파일만 반환된다 — 검증 가능. `new RegExp('auth.*service', 'i').test(JSON.stringify(r.header))` 로 확인되며, 단독 포함 파일 제외 여부는 fixture 데이터로 확인 가능
- [x] `search "opal"` 실행 시 기존 v1.1.0과 동일한 결과 집합이 반환된다 (리터럴 하위 호환) — 검증 가능. v1.1.0과 결과 집합 비교 또는 육안 확인
- [x] `search "OPAL"` (대문자) 실행 시 `opal` 포함 파일이 반환된다 (case-insensitive 동작) — 검증 가능. `i` 플래그 효과 확인
- [x] `--domain`/`--layer` 필터와 조합 시 정상 동작 — 검증 가능. 코드 스케치의 재필터링 로직이 그대로 유지되므로 확인 가능

### R2 — exports 커맨드 정규식 전환

- [x] `exports "^get[A-Z]"` 실행 시 `get` + 대문자로 시작하는 exports를 가진 파일만 반환된다 — 검증 가능. `^` 앵커가 각 배열 항목 전체 문자열에 적용되는 특성상 정확히 판정 가능
- [x] `exports "parse"` 실행 시 `parse`를 포함하는 exports를 가진 파일이 반환된다 (리터럴 하위 호환) — 검증 가능. `parseArgs`, `parseHeader` 등 실데이터로 확인 가능
- [x] exports 필드가 없거나 배열이 아닌 파일은 결과에서 제외된다 — 검증 가능. 코드 스케치에 `!r.header.exports || !Array.isArray(r.header.exports)` 가드가 명시되어 있으며 Pass/Fail 판정 가능
- [x] `--domain`/`--layer` 필터와 조합 시 정상 동작 — 검증 가능. R1과 동일한 방식

### R3 — 잘못된 정규식 에러 처리

- [x] 위 실행의 exit code가 1이다 — 검증 가능. `echo $?` 로 즉시 확인
- [x] `exports "[invalid"` 실행 시 동일하게 처리된다 — 검증 가능. search와 동일한 에러 처리 코드 구조 확인
- [x] `search "("` (닫히지 않은 괄호) 등 다른 종류의 잘못된 정규식도 동일한 방식으로 처리된다 — 검증 가능. V8 `SyntaxError` catch 범위 내의 모든 정규식 오류 포함
