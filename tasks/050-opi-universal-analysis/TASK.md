# TASK: opi 범용 프로젝트 분석 개선

## 작업 목표

opi(opal-project-init)의 Phase 1 소스 분석을 개선하여 어떤 프로젝트 구조에서도 정확한 docs/ 문서를 생성할 수 있도록 한다.

## 배경

현재 opi Phase 1-1은 프로젝트 루트의 표준 파일(package.json, src/, app/ 등)만 스캔한다. 다음과 같은 프로젝트 유형에서 분석이 불완전하거나 실패한다:

- **FE 단독 / BE 단독**: 부분적으로 동작하지만 모노레포와 구분 못함
- **풀스택 (모노레포)**: `frontend/` + `backend/`로 분리된 구조에서 루트에 config 파일이 없으면 기술 스택을 못 찾음
- **기획+개발 혼합**: `100.기획/` + `workspace/backend/` 같은 비표준 구조에서 기획 폴더를 인식 못함
- **일반 프로젝트 (빈 프로젝트 포함)**: 코드가 없는 프로젝트에서 분석할 대상이 없음. 기획만, 문서만, 빈 프로젝트 모두 포함

049에서 워커 에이전트가 docs/를 자율적으로 읽도록 개선했으므로, opi가 정확한 docs/를 만드는 것이 전체 파이프라인의 전제 조건이다.

## 요구사항

- [ ] Phase 1-1을 2단계로 분리한다: (1) 프로젝트 레이아웃 탐색 → (2) 기술 스택 분석
- [ ] 레이아웃 탐색: 프로젝트 루트의 디렉토리 트리를 depth 2~3으로 스캔하여 실제 구조를 파악한다
- [ ] 발견된 디렉토리를 분류한다. 판별 우선순위: (1) config 파일 존재 여부 → (2) 파일 유형 → (3) 폴더명은 보조 힌트만
  - 코드: config 파일(package.json, pyproject.toml 등) 존재 → 폴더명 무관 (front/, server/, workspace/backend/ 등 모두 인식)
  - 문서: .md/.docx/.pdf 등 문서 파일 존재
  - 태스크: tasks/ 패턴
  - 기타: 미분류 → 인터뷰에서 캡틴에게 용도 확인
- [ ] 기술 스택 분석: 루트뿐 아니라 발견된 코드 디렉토리에서도 config 파일을 탐색한다
- [ ] 기존 문서 탐색: docs/ 외에 발견된 문서 디렉토리도 스캔한다
- [ ] 분석 결과를 캡틴에게 보여주고 확인받는다 (미분류 폴더 용도 질문)
- [ ] Phase 1-2 카테고리 판별을 확장한다: 개발(FE 단독/BE 단독/풀스택/기획+개발) + 일반(기획, 문서, 빈 프로젝트 통합)
- [ ] 빈 프로젝트도 초기화 가능하다: 아무것도 없어도 인터뷰 기반으로 docs/ 생성, 이후 최신화로 채워감
- [ ] Phase 3 개발 문서 작성 시, 발견된 코드 디렉토리 기반으로 분석한다 (루트 고정 아님)
- [ ] 기존 표준 구조 프로젝트에서도 동일하게 동작한다 (하위 호환)
