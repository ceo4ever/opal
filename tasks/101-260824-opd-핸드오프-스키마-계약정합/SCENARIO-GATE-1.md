## 3. 쟁점 독립 판정

### 쟁점 1 — L3 존폐: PLAN §C-4("L3 불요") vs TEST-SCENARIO(L3 3건 유지)

**판정: TEST-SCENARIO.md가 옳다. PLAN §C-4의 "L3 불요"는 기각한다.** 근거 4건 중 (a)가 결정적이다.

**(a) 시점 근거 — 실증 사례가 성립할 수 없다 [E1 실행 관측]**
PLAN §C-4가 대체 근거로 든 "본 태스크의 ANALYSIS.md·PLAN.md가 실증 사례"는 사실 전제부터 성립하지 않는다. 개정 대상 6파일은 **현재 전건 무변경**이다.
- 관측 스코프: 6파일(`op-dev-analysis/SKILL.md`, `op-dev-plan/references/plan-guide.md`, `harness/analysis-core.md`, `opal-pilot-dev/references/pipeline.json`, `op-dev-qa/SKILL.md`, `qa-dev-guide.md`)
- 실행 명령: `git status --short <6파일>` → 출력 0줄(전건 무변경)
- 대조: `sed -n '27p;84p' opal/skills/op-dev-analysis/SKILL.md` → 현행 규범은 여전히 **구형 4값**(`유효 / 승계 / 수정필요 / 사실오류`)을 지시하고, `sed -n '97,99p'` → §1.1 헤더는 여전히 **구형 4열**(`파일 | 역할 | 변경 필요 | 근거(줄번호)`)이다.

즉 ANALYSIS.md·PLAN.md는 **개정 전 규범이 배포된 상태에서** 생성됐다. 그럼에도 PLAN.md §확정 입력 판정 표가 2계열 값(`해당없음(결정)`·`유효(대조 확인)`)을 쓰고 있는 것은 규범 유도의 증거가 아니라 PM 주입의 증거다 — PLAN.md 스스로 "본 표는 `op-dev-analysis/SKILL.md` 개정안(R-4)의 2계열 판정값 스킴을 **선적용**했다"고 명시한다. 존재하지 않는 규범을 선적용한 산출물은 그 규범의 재현성 증거가 될 수 없다.

**(b) self-confirming 구조** — 개정안을 프롬프트로 주입받아 만든 산출물로 "규범만으로 재현되는가"를 증명하는 순환 논증이다(헌법 §4, `scenario-gate.md` §4 Producer≠Evaluator). TEST-SCENARIO §조기 경보의 지적이 정확하다.

**(c) L3 기준 오적용** — PLAN §C-4의 사유는 "런타임·동시성·외부 시스템 개입 없음"으로, 코드 태스크의 L3 정의를 규범 태스크에 적용했다. 본 태스크에서 규범이 구동하는 런타임은 **워커의 행동**이며, task:100 R-12가 확립한 검증 형태는 지시 없는 표준 프롬프트 재생성 대조다(`tasks/100-.../DONE.md` §5).

**(d) 회귀 실증이 이미 존재** — task:100은 L1 정적 검사를 통과하고도 재생성본에서 판정값이 `유효` 16건 일괄로 회귀했다(`ANALYSIS-REGEN.md:13`, TASK.md 배경 분석 (3)). "문서는 고쳤는데 행동은 그대로"가 실측된 사건이며, 본 태스크는 **그 회귀를 고치려고 존재한다**. L3를 제거하면 태스크가 자신의 재발을 탐지할 수단을 잃는다 — S-20이 겨눈 task:100 후속 이월 5가 정확히 이 지점이다.

> 결론: 목표달성 축을 실제로 검증하는 것은 L3 3건(S-19·S-20·S-21)이다. PLAN §C-4의 "L2 상당(TS-006·TS-008)" 대체는 ①축을 충족하지 못한다. **L3 3건은 축소·삭제 대상이 아니다.**
