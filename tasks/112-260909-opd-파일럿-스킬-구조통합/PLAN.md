# PLAN: 파일럿 전용 스킬 내부화와 Dev Pilot 통합

> 입력: [TASK.md](TASK.md), [ANALYSIS.md](ANALYSIS.md)

## Approach

활성 소스와 활성 문서만 변경한다. SDD 단계 스킬은 `opal-pilot-sdd/internal-skills/`로 소유권을 옮기고 stale `op-sdd-verify`는 삭제한다. Dev Pilot은 `opal-pilot-dev` 단일 구현에서 Full/Short profile을 선택하게 하며, `//opds`와 `skill=opds`는 logical compatibility layer로 보존한다. code-scan 선조회는 `code-scan scan .opal-worktrees/task_112/opal/skills/opal-pilot-dev --brief`와 `code-scan search "opal-pilot-dev-short|op-sdd|track-routing" --json`으로 수행했으나 worktree가 허브 `.opal/code-scan.json` exclude 대상이라 결과는 `No files found`/`{}`였고, 이후 `rg` fallback으로 활성 참조를 선별했다.

- 적용 순서: P1에서 active 구조 이동과 canonical Dev profile을 먼저 만들고, P2에서 stale verify 삭제와 worktree 설정을 닫고, P3에서 registry/state/install/docs를 새 구조에 맞춘 뒤, P4에서 oppd 하위 Pilot 탐색 경로를 정합하고, P5에서 문서 표준의 이력 계약과 컨벤션 포인터를 맞춘 다음, P6에서 통합 검증과 잔여 참조 점검을 수행한다.
- 검증 범위: 결정론 검증은 `state-tool spec-validate`, `state-tool validate`, `skill-registry validate/match`; 회귀 검증은 state-tool/skill-registry Node·Python 테스트; 실제 연동 검증은 임시 HOME 또는 스크립트 지원 격리 옵션 기반 설치로 구분한다.
- 실측 경계: 설치 검증은 기존 사용자 `~/.opal/`을 직접 수정하지 않는 방식이 우선이며, 지원 옵션이 없으면 PLAN 기준 H-1을 남기고 소스 수준 archive/install 테스트로 대체한다.
- 실패 시: source worktree 변경만 되돌리거나 수정하고 재검증한다. 이미 격리 설치 경로에 쓴 파일은 해당 임시 경로만 삭제한다. 사용자 설치본이나 과거 task/brain/dashboard historical fixture는 복구 대상으로 삼지 않는다.
