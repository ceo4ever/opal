## 작업 목표

서비스 기획 프로세스의 기술 산출물을 **논리적 네트워크**로 관리하는 오케스트레이터 스킬 `otp-write-tech`를 개발한다. 산출물 간 논리적 연결 관계를 인지하여, 작성/수정 시 연결된 문서의 정합성을 함께 유지한다.

## 배경

### 현재 OPAL의 문서 작성 커버리지

| 스킬 | 커버 범위 | 한계 |
|------|----------|------|
| otp-write | 단일 독립 문서 (PRD, 보고서, 가이드 등) | 문서 간 연결성 없음 |
| opdp | 프로젝트 파일럿 (PRD/TRD -> 로드맵 -> 태스크) | 코드 구현까지 포함, 기획 산출물 전용이 아님 |
| otp-wf | 와이어프레임 -> UI 구현 | 기획 문서가 아니라 UI 구현 |

### 갭: "기술 산출물 간 논리적 연결"

참조: [서비스 기획 산출물 톺아보기](docs/web-captures/it-ist-tistory-com-277.md)

서비스 기획 산출물은 서로 **논리적으로 연결된 네트워크**를 형성한다:

```
순서 체인 (기본 흐름):
  PRD → TRD → 서비스 정책서 → IA (기능 포함)
  → 와이어프레임은 //otp-wf로 별도 수행 (정책서 + IA를 근거로)

논리적 연결 (양방향):
  - 뒤에서 앞으로도 참고 가능 (IA 먼저 쓰고 PRD를 나중에 써도 됨)
  - 수정 시 연결된 문서 연쇄 업데이트
  - 선택 산출물은 필수 산출물과 연결
```

**논리적 연결의 의미:**
- **순서 체인 존재** — 기본 흐름은 PRD → TRD → 서비스 정책서 → IA → 와이어프레임
- **역방향도 가능** — IA를 먼저 쓰고 PRD를 나중에 쓸 수도 있음 (있으면 참고, 없으면 없는 대로)
- **수정 시 연쇄 업데이트** — 한 문서를 수정하면 논리적으로 연결된 다른 문서도 영향 분석 후 함께 수정

현재 otp-write로 PRD를 따로 쓰고, 기능 정의서를 따로 쓰면 **문서 간 정합성이 관리되지 않는다**. otp-write-tech는 이 논리적 연결을 인지하고, 작성/수정 시 연결된 문서의 정합성을 함께 관리한다.

## otp-write-tech 커버 범위

### 기술 산출물과 논리적 연결 관계

**필수 산출물** — 서비스 기획의 뼈대. 이것들이 논리적 네트워크의 코어.

| 산출물 | 설명 | 논리적으로 연결된 문서 |
|--------|------|---------------------|
| PRD | 왜 만드는가, 목표, 타깃 유저, 핵심 요구사항 | TRD, 서비스 정책서, IA |
| TRD | 기술 요구사항, 아키텍처, 기술 스택, 제약 | PRD, IA |
| 서비스 정책서 | 용어 정의, 회원/결제/환불 등 공통 비즈니스 정책 | PRD, IA, 운영 정책서 |
| IA (기능 포함) | 정보구조도 + 기능 정의 통합 (메뉴 구조, 기능별 동작/데이터). 엑셀(.xlsx) 추천 | PRD, TRD, 서비스 정책서 |

**선택 산출물** — 프로젝트 규모/필요에 따라 추가.

| 산출물 | 설명 | 논리적으로 연결된 문서 |
|--------|------|---------------------|
| 기능도 | 기능 계층 구조 시각화 | IA |
| 순서도(Flowchart) | 기능별 흐름 도식화 | IA |
| 운영 정책서 | CS 처리, 환불 프로세스, 개인정보 파기 등 | 서비스 정책서, IA |
| 서비스 매뉴얼 | 서비스 개요, 주요 기능, 사용법 설명 | IA, 운영 정책서 |

> **IA**: 엑셀(.xlsx) 형식 추천 — 기능 목록 + 정보구조를 스프레드시트로 관리 (anthropics/xlsx 커뮤니티 스킬 연동)
> **와이어프레임**: otp-write-tech 범위 밖 — 서비스 정책서 + IA를 근거로 `//otp-wf`로 별도 수행

### 논리적 연결의 동작 방식

1. **작성 시**: 연결된 문서가 이미 존재하면 Read하여 참고. 없으면 없는 대로 작성.
2. **수정 시**: 수정 대상 문서의 연결 문서를 스캔하여 영향 분석. 영향 있는 문서를 함께 업데이트 제안/수행.
3. **순서 자유**: 어떤 문서든 먼저 작성 가능. 기능 정의서를 먼저 쓰고 PRD를 나중에 쓸 수도 있음.

### otp-write-tech가 아닌 것

- 단일 독립 문서 (연결 관리 불필요) -> otp-write
- 프로젝트 전체 파일럿 (PRD+TRD+로드맵+태스크 실행) -> opdp
- 코드 구현 수반 -> otp-dev / otp-dev-short
- 와이어프레임/UI -> otp-wf
- 외부 API 분석 -> api-analyzer
