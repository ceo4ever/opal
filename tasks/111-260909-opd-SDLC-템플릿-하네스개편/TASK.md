# TASK: SDLC 템플릿과 하네스 수행 기준 개편

## Problem

사용자는 OPAL을 적용한 실제 개발 사이클이 과거 2시간 이내에서 최근 3시간 이상으로 늘었고, 문서가 방대해 읽고 판단하기 어렵다고 보고했다. 현행 템플릿은 분석·설계·검증 정보를 여러 절에서 반복하도록 요구한다. MAMS 사례에서는 문서 증가 외에도 설계 변경과 실제 연동 가정 오류가 재작업으로 이어졌다. 근거: [사전 검토](templates/README.md), [MAMS 대입 검토](templates/MAMS-178-REVIEW.md).

## Proposed outcome

사용자가 문제·설계 결정·완료 여부를 빠르게 판단하고, 에이전트는 각 단계에 필요한 조사·결정·검증만 수행한다. TASK·ANALYSIS·PLAN·TEST-SCENARIO를 새 형식으로 연결하여 반복 작성과 불필요한 추론을 줄이고, 실제 개발에서 2시간 이내 사이클 달성을 검증한다.

## Affected users and systems

- 사용자: OPAL 적용 프로젝트의 개발 책임자·검토자, PM·구현·검증 에이전트.
- 시스템: 개발 pilot(opd), 네 단계 스킬·가이드, 문서를 소비하는 실행·검증·상태 관리 도구.
- 포함: 새 템플릿과 수행·종료 기준, 문서 간 정보 소유권, 게이트·소비자 정합, `docs/PROJECT.md` 레지스트리 기반 문서 선별·주입·갱신 판단, MAMS 사례 검토와 시간·품질 측정 방법, 새 계약을 공유하는 opds 정합, 중복·미호출 스킬 제거. 이번 태스크의 산출물부터 새 형식을 사용한다.
- 제외: MAMS 업무 코드·운영 데이터 변경, 과거 태스크 문서의 일괄 변환, 관련 없는 pilot 전면 개편, 기존 문서 변경이력의 일괄 삭제.

## Constraints

- C-1: 요구 결과·영향 경계·실패 처리·검증 증거를 삭제하거나 검사를 생략해 시간을 맞추지 않는다.
- C-2: 같은 정보는 한 문서에서 정의하고 후속 문서는 참조한다. 현재 유효한 설계로 본문을 갱신하며 폐기안·정정 우선순위를 누적하지 않는다.
- C-3: 목표 검증·독립 평가·RED 선행·실제 연동 확인을 보존한다. 대역 성공을 실제 연동 증거로 대신하지 않는다.
- C-4: 새 형식 지원과 기존 태스크 조회·재개 호환성을 함께 설계한다. 기존 검사기의 거부를 임의 PASS로 처리하지 않는다.
- C-5: 변경은 프로젝트 원본에 적용하고 설치본은 정식 배포로 갱신한다. 코드 변경 범위·검증은 PLAN에서 구체화한다.
- C-6: 사용자 요청에 따라 산출물은 `tasks/111-260909-opd-SDLC-템플릿-하네스개편/`에서 관리한다. 기존 제안은 `templates/`로 이관한다.
- C-7: 프로젝트 문서·기획·설계 산출물은 `docs/PROJECT.md`의 프로젝트 문서 레지스트리를 기준으로 선별한다. 고정 `docs/ARCHITECTURE.md`·`docs/CONVENTIONS.md` 목록은 최소 폴백이며, 모든 문서 전문을 매번 복제하거나 무조건 수정하지 않는다.
- C-8: 워커가 사용할 스킬·MCP·도구는 PM이 디스패치 시점에 실제 런타임 capability를 확인해 주입한다. 스킬·reference·agent 문서의 고정 capability 카탈로그를 사용 가능성의 근거로 삼지 않는다.
- C-9: 문서 변경이력 제거 원칙은 `opal-doc-standard.md`에서만 확정한다. 기존 문서의 변경이력 일괄 삭제와 생성·검사·설치 로직 정리는 별도 태스크에서 수행한다.

## Acceptance criteria

- AC-1: 네 문서가 새 형식으로 작성되고 각 정보의 원본·입력·수행·종료 조건이 명확하다. 이전 양식의 중복 표를 별도로 채우라는 지시가 적용 경로에 남지 않는다.
- AC-2: 새 TASK에서 요구한 결과·제약이 PLAN 작업과 TEST-SCENARIO에 연결되고, 누락·필수 미검증·실패는 완료로 판정되지 않는다.
- AC-3: 스킬·pilot·도구가 새 형식을 실제로 소비한다. 정상 입력은 다음 단계로 진행하고, 필수 정보 누락은 거부한다. 기존 태스크 조회·재개가 정한 호환 정책대로 동작한다.
- AC-4: MAMS 대표 사례에 새 형식을 대입하여 원래 요구사항과 핵심 검증의 보존을 확인한다. 남은 상세 계약·실행 미확인은 명시하고 동등성 확인 전 완료로 주장하지 않는다.
- AC-5: 시간·품질 측정의 시작·종료·대기·범위변경 기준을 정하고, 실제 적용 결과와 재작업 사유를 기록한다. 2시간 달성은 실제 측정으로 판정하며, 사례 문서 재작성만으로 달성 처리하지 않는다.
- AC-6: 수정 대상 스킬과 내부 reference 문서가 `docs/PROJECT.md` 레지스트리 기반 문서 주입·문서 갱신 후보 판단을 같은 계약으로 설명한다. MAMS처럼 `100.기획/`, `200.개발/`, `docs/CONVENTIONS-*`를 Glob으로 찾는 프로젝트에서도 고정 docs 목록 때문에 누락되지 않는다.
- AC-7: opd 실행 경로의 고정 “활용 스킬/MCP” 목록과 중복 실행 산문을 제거한다. PM dispatch는 실제 사용 가능한 capability와 용도를 명시하고, 워커는 주입된 capability만 소비한다. state-tool·test-tool처럼 단계가 구조적으로 요구하는 명령은 실행 계약으로 유지한다.
- AC-8: `opal-doc-standard.md`는 git 관리 Markdown의 수기 변경이력을 기본 생성하지 않는 원칙을 단일 기준으로 명시하고, 기존 문서 일괄 삭제는 이번 변경에 포함하지 않는다.
- AC-9: `op-dev-todo`와 `opal-next` 소스가 제거되고 활성 레지스트리·에이전트·프로젝트 문서·사용자 안내에 호출 가능한 항목으로 남지 않는다. 과거 태스크와 brain 기록은 사료로 보존한다.
