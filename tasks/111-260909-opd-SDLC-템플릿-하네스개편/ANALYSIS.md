| 프로젝트별 `docs/PROJECT.md` 레지스트리 스키마는 완전히 동일하지 않을 수 있다. | OPAL과 MAMS 모두 "프로젝트 문서" 표를 갖지만, OPAL은 `적용 범위` 컬럼을 쓰고 MAMS는 기획/설계 산출물과 개발 운영 문서를 나눠 `참조 시점`과 Glob 규칙을 둔다. | 스킬은 특정 컬럼 하나에 고정되면 안 된다. 최소 공통 입력은 문서 경로, 용도/설명, 참조 시점이며, 적용 범위·도메인 값은 있으면 사용하고 없으면 TASK/PLAN의 변경 대상·검색 패턴으로 보강해야 한다. |
| 고정 capability 목록을 지워도 필수 workflow는 유지할 수 있다. | state-tool·test-tool 명령과 scenario evaluator 호출은 단계 진입·판정 절차 안에 직접 연결돼 있고, 단순 “활용 목록”과 구분된다. | PM dispatch가 런타임 capability 주입 필드를 실제로 채우지 않으면 선택형 보조 도구 활용은 줄 수 있다. 빈 목록 의미와 미제공 시 처리 규칙을 dispatch 계약에 명시해야 한다. |

## Handoff

- PLAN 결정 1: 새 TASK 형식 판별을 `헤딩 감지`로 할지 `명시 메타(template/schema_version)`로 할지 정한다. 필수 잠금 요소는 구형 4요소와 맞춰 `Proposed outcome/Affected users and systems/Constraints/Acceptance criteria`로 보는 것이 최소 변경이고, `Problem`은 배경 필드로 남기는 편이 호환성이 높다.
- PLAN 결정 2: 새 PLAN의 `Work items`를 EXECUTE와 code-scan citation gate의 공식 실행 입력으로 승격한다. 이때 `op-dev-execute`, `opal-pilot-dev` 디스패치, `state-tool` `_collect_plan_target_files()`를 함께 바꿔야 한다.
- PLAN 결정 3: `op-scenario-gate` Step 2에서 새 AC/C/W/H/S를 정규화 JSON으로 변환하는 규칙을 정한다. `AC`는 requirements, `H`는 hypotheses로 자연 매핑되고, `C`는 requirements 포함 또는 별도 의미 검사 중 하나를 선택해야 한다. `W`와 `F`는 의미가 다르므로 F가 없을 때 features를 비울지 W로 대체할지 명시해야 한다.
- PLAN 결정 4: 빈 분모 거짓 통과 방지는 `op-scenario-gate` 변환 단계에 두고, MAMS·2시간 검증 한계도 PLAN/TEST에 남긴다. 원본 TASK/PLAN에 AC/C/H 또는 W/F가 있는데 정규화 분모가 비면 `scenario-coverage-check` 호출 전에 블로커로 처리한다. MAMS-178은 회고 대입 자료라 원 요구·핵심 검증 완전 동등성은 미확인이고, 2시간 시작/종료·대기 산정 및 실제 적용 대상도 성능 완료 판정 전 확정해야 한다.
- PLAN 결정 5: 프로젝트 문서 주입은 `docs/PROJECT.md` 레지스트리 우선으로 통일한다. OPAL 기본 docs 4종은 최소 보장 또는 부재 폴백일 뿐이고, MAMS 같은 프로젝트의 기획 정책서·ERD·매체 API 명세·운영 스킬 문서는 레지스트리의 참조 시점과 경로 패턴으로 선별해야 한다. 구현으로 내용이 달라지는 문서는 PLAN `Work items`에 포함하고, 참조 전용 문서는 산출물에 복제하지 않는다.
- PLAN 결정 6: 고정 capability 카탈로그는 제거하고 `dispatch-process.md`를 capability 선택·주입 SSOT로 둔다. 역할·도메인 지식은 agent/persona에 남기되, 특정 스킬/MCP 함수명의 사용 가능성은 런타임에서 확인된 경우에만 워커 프롬프트에 넣는다. 구조적 state/test/gate 도구는 각 단계 workflow에 남긴다.
- PLAN 결정 7: `opal-doc-standard.md`만 변경이력 미생성 원칙으로 정리한다. 기존 문서의 변경이력 절, creator/checker 규칙, installer strip 로직은 별도 태스크에서 한 번에 전환한다.
- PLAN 결정 8: `op-dev-todo`와 `opal-next`는 삭제한다. 활성 레지스트리와 안내 문서에서 제거하고, PLAN Work items·부트스트랩·help·doctor를 각각의 대체 경로로 둔다.
