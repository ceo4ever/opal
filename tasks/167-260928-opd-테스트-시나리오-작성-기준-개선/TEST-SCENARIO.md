# TEST-SCENARIO: 테스트 시나리오 작성 기준 개선 — 중복·과잉 시나리오 억제와 advisory 응답 게이트

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: 워크트리 소스(`/Volumes/Data/AIStudio/workspace/ai-framework/.opal-worktrees/task_167`)의 `opal/tools/test-tool`·`opal/tools/state-tool`을 `~/.opal/.venv/bin/python`으로 실행한다. 설치본(`~/.opal/`)은 쓰지 않고 install도 하지 않는다.
- 공통 데이터: 각 테스트가 임시 디렉터리에 sdlc-v2 TASK·PLAN·TEST-SCENARIO fixture, pipeline fixture(`pipeline-pm.json`·`pipeline.json`·`pipeline-short.json`)로 초기화한 `state.json`, evaluator 결과 JSON fixture를 만든다. 실제 저장소의 태스크 폴더는 건드리지 않는다.
- 대역 사용과 한계: 독립 evaluator 에이전트의 판단 대신 계약 형식의 결과 JSON fixture를 쓴다. 이 대역은 두 기록 도구가 advisory·응답·refinement를 올바르게 검사·전이하는지 확인할 때만 쓴다. 실제 evaluator가 의미상 중복을 advisory로 찾아내는지는 대신하지 못하며, merge 후 허브에서 install한 뒤 설치본 evaluator 1회 실행으로 확인한다(PLAN Release and recovery).
- 실행 조건: 자동 실행. 사람 조치 없음.
