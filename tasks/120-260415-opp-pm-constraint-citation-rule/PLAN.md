현재 예시 나열 이후에 다음 규칙 단락을 삽입한다.

**삽입 위치**: `### Step 3. 문서 Read + 핵심 제약 추출` 예시 블록 다음 (§ Step 4 시작 전)

**삽입 내용 (설계안)**:

```
#### 인용 의무 규칙

핵심 제약을 워커에게 주입할 때 다음 기준으로 **원문 인용 vs 요약**을 구분한다:

| 구분 | 기준 | 처리 방법 |
|------|------|----------|
| 원문 인용 필수 | 금지사항, 아키텍처 강제 규칙, 재해석 여지가 있는 정책·명세·도메인 규칙 | `[MUST] <문서명> §N: <규칙 원문>` 형식으로 직접 인용 |
| 요약 허용 | 선호사항, 가이드라인, 스타일 가이드 | 요약 형태로 전달 가능 |

**인용 포맷**: `[MUST] <문서명> §N: <규칙 원문>`

예:
- `[MUST] BE-FRAMEWORK.md §3: BaseMedia를 반드시 상속하라. 직접 Model 상속 금지.`
- `[MUST] ARCHITECTURE.md §2: 미들웨어 체계를 준수하라. 커스텀 미들웨어 삽입 금지.`

> **이유**: 경로 나열과 요약 수준의 제약 전달은 워커가 자체 판단으로 규칙을 우회할 수 있다.
> 원문을 직접 인용해야 워커가 동일한 기준을 적용한다.
```

#### Step 2: 워커 컨텍스트 주입 템플릿 변경 설계

현재 `## 핵심 제약` 섹션:

```markdown
## 핵심 제약
- {제약 1}: {설명}
- {제약 2}: {설명}
```

변경 후:

```markdown
## 핵심 제약
- [MUST] <문서명> §N: <규칙 원문>  ← 원문 인용 필수 항목
- {선호사항 또는 가이드라인}: {설명}  ← 요약 허용 항목
```

기존 형식을 완전히 대체하지 않고, 원문 인용 포맷 라인을 첫 번째 예시로 추가하여 **하위 호환** 유지.

#### Step 3: opal-pilot-dev 디스패치 템플릿 변경 설계

**ANALYSIS/PLAN/EXECUTE** 세 곳 모두, 기존 `**참조 문서**: {경로}` 필드 다음에 `**핵심 제약**:` 필드를 추가한다.

추가 필드:
```
**핵심 제약**: {[MUST] <문서명> §N: <인용문> 형식으로 원문 인용. 요약 허용 항목은 일반 목록으로}
```

#### Step 4: opal-pilot-sdd 디스패치 템플릿 변경 설계

**Phase 1(SPEC)/Phase 3(DESIGN)** 두 곳 모두, 동일한 방식으로 `**참조 문서**:` 다음에 `**핵심 제약**:` 필드 추가.
