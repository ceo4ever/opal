### R3. network-guide.md §1 산출물 유형 정의 추가 — PMO 그룹 + 개발 WBS

**위치**: network-guide.md §1, "프로젝트 특화 선택 타입" 블록(27~35행) 뒤, `---` 구분선(37행) 앞

**추가할 텍스트**:

```markdown
### PMO

> 프로젝트 관리 목적의 산출물. 기획 산출물을 입력으로 받아 관리 도구를 생성한다.

| 유형 | 설명 | 입력 | 출력 형식 | 수량 |
|------|------|------|----------|------|
| **개발 WBS** (Work Breakdown Structure) | 기획 산출물(IA, 기능 목록, 배치기능, 부가기능 등)을 입력으로 개발 항목을 MECE 원칙(누락·중복 없이)으로 구조화한 목록. 일정·완료여부 등 개발 관리 도구로 활용한다. | IA(주입력), PRD(보조), TRD(기술 컴포넌트 참조) | Markdown 표 (일정·완료여부 컬럼 포함) | 보통 1개 |

#### 개발 WBS Level 분해 구조

| Level | 명칭 | 설명 | 예시 |
|-------|------|------|------|
| 0 | 프로젝트 전체 | 프로젝트 단위 | 프로젝트명 |
| 1 | 개발 영역 | BE / FE / 인프라 / 공통 | Backend, Frontend |
| 2 | 기능 모듈 | IA 메뉴 구조 기준 기능 묶음 | 회원관리, 결제, 대시보드 |
| 3 | 작업 패키지 | 실제 개발 단위 (8~80시간) | 회원가입 API, 결제 UI 등 |
```

**변경 요약**: "프로젝트 특화 선택 타입" 뒤에 "### PMO" 서브섹션 신규 추가. 유형 테이블 + Level 분해 구조 테이블로 구성.

### R4. network-guide.md §2 연결 맵 추가 — 개발 WBS 연결 관계

**위치**: network-guide.md §2, "유형 간 양방향 참조" 코드 블록(43~83행) 내부, 외부 API 명세서 연결 블록 마지막(82행) 뒤, 코드 블록 닫는 ``` 앞

**추가할 텍스트** (코드 블록 내부에 삽입):

```
개발 WBS ↔ IA (핵심 연결)
  IA → 개발 WBS: 메뉴 구조 + 기능 정의 → Level 2(기능 모듈) 및 Level 3(작업 패키지) 분해 기준
  개발 WBS → IA: 작업 분해 과정에서 기능 누락 발견 → IA 기능 보완

개발 WBS ← PRD (보조 참조)
  PRD → 개발 WBS: 핵심 요구사항 우선순위 → WBS 항목 우선순위 반영

개발 WBS ← TRD (보조 참조)
  TRD → 개발 WBS: 기술 스택·아키텍처 → Level 1(개발 영역) 분류 및 기술 컴포넌트 반영
```

**추가로**, §2 "각 연결의 참조 항목" 테이블(95~104행)에 아래 행 추가:

```
| IA > 메뉴 구조 + 기능 정의 | Level 2/3 분해 기준 | 개발 WBS |
| PRD > 핵심 요구사항 | WBS 항목 우선순위 반영 | 개발 WBS |
| TRD > 기술 스택·아키텍처 | Level 1 분류 및 기술 컴포넌트 반영 | 개발 WBS |
```

**변경 요약**: 양방향 참조 블록에 개발 WBS 연결 3건(IA 핵심, PRD 보조, TRD 보조) 추가 + 참조 항목 테이블에 3행 추가.

## 3. 핵심 설계: network-guide.md §2 연결 맵 초안

아래는 §2 양방향 참조 코드 블록에 삽입할 최종 텍스트 초안이다.

```
개발 WBS ↔ IA (핵심 연결)
  IA → 개발 WBS: 메뉴 구조 + 기능 정의 → Level 2(기능 모듈) 및 Level 3(작업 패키지) 분해 기준
  개발 WBS → IA: 작업 분해 과정에서 기능 누락 발견 → IA 기능 보완

개발 WBS ← PRD (보조 참조)
  PRD → 개발 WBS: 핵심 요구사항 우선순위 → WBS 항목 우선순위 반영

개발 WBS ← TRD (보조 참조)
  TRD → 개발 WBS: 기술 스택·아키텍처 → Level 1(개발 영역) 분류 및 기술 컴포넌트 반영
```

설계 근거:
- **IA가 주입력**: TASK.md 합의 사항 — IA의 메뉴 구조가 Level 2(기능 모듈) 분해의 직접 기준. 양방향(누락 발견 피드백)
- **PRD는 보조**: 요구사항 우선순위만 참조. 단방향(PRD → 개발 WBS)
- **TRD는 보조**: 기술 스택/아키텍처가 Level 1 영역 분류(BE/FE/인프라/공통)에 영향. 단방향(TRD → 개발 WBS)
- 서비스 정책서와의 직접 연결은 불필요 — 정책 내용은 IA를 경유하여 간접 반영됨
