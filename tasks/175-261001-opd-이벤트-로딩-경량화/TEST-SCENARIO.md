# TEST-SCENARIO: 이벤트 로딩 경량화 1차

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: macOS, 이 워크트리(`feat/OP-TASK-175`), `~/.opal/.venv/bin/python3`(`unittest`·`pytest`), `node`. 결정론 시나리오는 소스 실행(`opal/tools/event-loader/event_loader.py`)과 임시 폴더·임시 프로젝트 루트만 쓰고 `~/.opal`·이 태스크의 `state.json`을 수정하지 않는다. 구형 호출 원장은 환경변수 `OPAL_EVENT_LOADER_LEDGER`로 임시 파일을 가리킨다.
- 공통 데이터: 매니페스트와 문서는 이 저장소의 실제 `opal/core/references/events.json`·`agents.md`다. 프로젝트 에이전트 덮어쓰기는 임시 프로젝트 루트의 `.opal/agents/opal-be-agent/AGENT.md`에 만든 사본이다.
- 대역 사용과 한계: 사용하지 않는다. event-loader·state-tool·정적 검사는 모두 실제 코드를 실행한다. 실제 에이전트 디스패치는 S-14·S-15에서만 하며 나머지는 결정론이다.
- 실행 조건: 자동 실행(사람 협업 없음). S-14·S-15·S-16은 EXECUTE 뒤 `scripts/install-mac.sh` 배포가 끝난 설치본에서만 실행하고, 배포 시각을 전환 기준 시점으로 기록한다. 실호출이 불가능하면 `blocked`로 반환한다.
- 병렬 그룹: S-1, S-2, S-3, S-4, S-5, S-6, S-7, S-8, S-9, S-10, S-11, S-12 — 서로 선행 관계가 없고 각자 임시 폴더·임시 원장만 쓰며 공유 자원을 쓰지 않는다. 나머지는 순차 실행한다.
