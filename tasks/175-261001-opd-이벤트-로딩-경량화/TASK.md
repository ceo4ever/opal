# TASK: 이벤트 로딩 경량화 1차

## Problem

현재 이벤트 응답은 동일 문서 본문을 두 번 전달하고, 워커 디스패치마다 대상과 무관한 에이전트 항목까지 전달해 PM의 입력량과 반복 비용을 늘린다. 기존 검증은 문서 최신성만 확인하므로 다른 대상·역할·호출에 receipt가 재사용되는 것을 구분하지 못한다([제안서 §2·§4](../../docs/proposals/opal-event-loading-economy.md)).

## Proposed outcome

필수 규칙과 실행 결과를 보존하면서 이벤트 응답의 중복 본문을 없애고, 디스패치에는 대상에게 필요한 공통 규칙과 에이전트 항목만 전달한다. 검증은 실제 대상·역할·호출과 반환 본문에 연결되어 잘못된 receipt 재사용을 거부한다. 기존 실행 중 세션은 명시적인 구형 호환 경로로 보호하며, 새 계약의 검증이 생략되는 조용한 다운그레이드는 허용하지 않는다. 전달량 감소와 기능·준수 결과, 비용·시간을 구분해 확인할 수 있는 결과를 남긴다.

## Affected users and systems

PM 및 직접·하위 워커를 호출하는 파일럿과 에이전트, event-loader와 state-tool 검증 소비자가 영향을 받는다. 포함 범위는 승인된 [제안서 §1의 1차 작업 및 §3.1·§3.2·§4.1~§4.3·§5](../../docs/proposals/opal-event-loading-economy.md)다. P2 조건부 문서 분리와 P3 지연 절 로딩은 제외한다. 디스패치 식별자 발급 주체와 계약 버전 선언 위치, 게이트 문장 공통화 여부는 PLAN에서 결정한다.

## Constraints

- C-1: 필수 규칙의 선택은 매니페스트와 도구가 결정하며, 모델의 자의적인 선택이나 이전 컨텍스트에 대한 의존으로 생략하지 않는다.
- C-2: 플랫폼 공통 어댑터 규칙은 전문을 유지한다. 다른 워커의 담당을 배정하는 역할에는 필요한 전체 에이전트 항목을 보존한다.
- C-3: 코드 펜스 내부의 헤딩은 절 경계가 아니다. 프로젝트 예시와 미래 에이전트 템플릿이 실제 공통 지시로 유출되어서는 안 된다.
- C-4: 설치 전 실행 중이던 세션을 갑자기 차단하지 않는다. 호환 종료의 구형 호출 0건은 누적 총량이 아닌 명시된 전환 기준 시점 이후의 관측 구간으로 판정하며, 종료는 제안서의 소스 전환·직접/하위 검증·기존 세션 전환 조건을 모두 만족해야 한다.

## Acceptance criteria

- AC-1: 새 형식 이벤트 응답에서 문서 본문은 한 번만 전달되며, 같은 이벤트에 적용되는 필수 규칙과 기능·준수 결과가 보존된다.
- AC-2: 대상별 디스패치는 공통 규칙과 해당 대상의 항목을 제공하고 무관한 항목·예시·추가 가이드를 제외한다. 담당 배정 역할의 전체 항목 제공 예외를 보존하며, 일반 대상의 실제 문서 본문 합계가 기존 전체 로드보다 줄어든다.
- AC-3: PM·워커 진입·하위 디스패치 모두 동일한 새 호출 계약을 적용한다. 대상·역할·디스패치 식별자 불일치, 반환 본문 변조, 실제 선택 문서의 경로·해시·출처 변경과 필수 인자 누락은 거부된다.
- AC-4: 전환 중 구형 호출은 전체 전송·경고·구형 검증 표시와 추적이 가능하고, 새 계약 요청은 구형으로 자동 전환되지 않는다. 지원하지 않는 계약 버전과 호환 종료 뒤 구형 호출은 명시적으로 거부된다.
- AC-5: 결과 자료에서 문서 본문 합계·실제 JSON 응답량·비용·시간을 구분해 확인할 수 있고, 재검증을 로드량에 중복 합산하지 않는다.
