## 발견 사항

### [마이너] `[WORKER]` 마커 적용 형태 불일치

PLAN §3 Step 2를 보면 스킬마다 적용 방식이 다르다:

- **opd(opal-pilot-dev)**: 코드 블록 내 키-값 프롬프트의 **첫 줄**에 `[WORKER]` 리터럴 삽입 (2-a)
- **opds / opp / opdw / oppd**: "디스패치 서술에 `[WORKER]` 마커 포함 지침 추가" — 서술형 문장으로만 지침이 존재하며 실제 프롬프트 형태 미정의 (2-b~f)
- **opwt**: "워커 프롬프트 첫 줄에 `[WORKER]` 포함" 지침만 제시 — 실제 프롬프트가 `references/` 파일 참조형이어서 마커 삽입 위치가 모호

AGENT.md 규칙은 "디스패치 프롬프트의 **첫 줄**에 `[WORKER]`"라고 명시하지만, 서술형 프롬프트(opds·opp·opdw)와 Agent 도구 파라미터형(oppd)에서 "첫 줄"의 의미가 달라 현장 적용 시 해석 여지가 발생한다.

### [마이너] Harness 폴백 현황 표 불완전 (PLAN §1)

§1 "스킬 Harness 폴백 현황" 설명에 "모든 opal-pilot-* 스킬에 폴백 존재"라고 서술하나, 실측 확인 결과 `opal-pilot-project-dev`(oppd)와 `opal-pilot-dev-wireframe`(opdw) 두 스킬도 동일 폴백 문구를 보유하고 있음을 §1 워커 디스패치 현황 표에서는 별도 언급하지 않았다. 결론(변경 불필요)에는 영향 없으나 근거 표의 완전성이 낮다.

기존 `[CRITICAL]` 경고("하네스 미로드 → 구현 금지 원칙 무효화")를 Lazy 설계 근거로 교체하는 접근은 구조적으로 타당하다. opal-harness.md가 Eager로 올라가므로 기존 경고의 핵심 우려(하네스 미로드)가 근본적으로 해소된다. 각 스킬의 Harness 폴백이 워커 레벨에서 2중 안전망 역할을 하는 점도 실측 확인됨.
