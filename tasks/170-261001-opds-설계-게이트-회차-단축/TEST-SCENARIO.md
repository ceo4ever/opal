## Setup

- 환경: 이 워크트리(`/Volumes/Data/AiStudio/workspace/opal/.opal-worktrees/task_170`)의 `opal/tools/state-tool/state_tool.py` 소스를 직접 import하거나 `~/.opal/tools/state-tool/run.sh`로 실행. `opal-evaluator-agent` 실제 디스패치가 필요한 시나리오는 `worker.dispatch` 경로를 그대로 사용하되, W-5·S-6의 디스패치는 PM이 직접 수행한다(워커에게 위임하지 않음 — PLAN Decisions 참조).
- 공통 데이터: 결정론 실패를 안정적으로 재현하는 전용 fixture — `tasks/170-.../run/eval-set/fixture-deterministic-fail/`에 TASK.md(AC-1·AC-2 포함)와 PLAN.md(Work item이 AC-1만 연결하고 AC-2는 어느 Work item에도 연결하지 않음)를 새로 작성해 `uncovered requirement AC-2`를 결정론적으로 재현한다(과거 태스크 164는 이미 pass해 재사용 불가 — 3회차 지적으로 확인). S-6용 round-trip fixture 태스크는 `tasks/170-.../run/fixture-task/`에 `state-tool init --skill opds --mode agentic --actor coordinator --rows-from <pipeline-pm.json 경로>`로 새로 만든다.
- 대역 사용과 한계: W-5의 평가 세트(pass 3건·결함 5건)는 대체(substitute)가 아니다 — pass 3건은 각 태스크의 `passed_bundle_hash`와 일치하는 git 커밋/작업트리 스냅샷에서 가져온 실제 파일이고, 결함 5건은 과거 `run/design-gate-i*.json`의 `gaps` 원문이 가리키는 문제를 재현하는 합성 최소 fixture(원본 근거를 파일 상단에 주석으로 병기)다. 두 경우 모두 실제 `opal-evaluator-agent` 재디스패치(real-usage)로 측정하며, 통계적 근사는 쓰지 않는다.
- 실행 조건: W-5(S-9)는 PM이 실행 전 `ListAgents`로 활성 피어 세션 유무를 확인하는 조건을 Setup에서 한 번에 요청한다(H-1) — 다른 세션이 `design-gate start`를 호출하지 않는 시간대인지 캡틴에게 1회 확인.
