# PLAN: PM 직접 수행 모델 — actor 축 신설과 L2 대체

> 입력: [TASK.md](TASK.md) · 설계 원천 `docs/proposals/opal-pm-direct-execution.md`(§1~§12)

## Approach

`--pm`을 **actor 축**이라는 독립 owner 문서로 신설하고, `--wt`(워크스페이스 축)가 이미 확립한 4개 서술 패턴을 그대로 복제한다 — (i) 전용 owner 문서, (ii) `pilot.start` required doc 등재, (iii) `modes.md` 라우팅 계약의 "모드 플래그 개수에 포함하지 않는다" 조문, (iv) `state-tool init` 선택 인자 + 미지정 시 키 미생성. 이 대칭이 TASK AC-1·AC-4·C-3을 동시에 만족시키는 유일한 검증된 경로다.

범위는 제안서 §12의 1·2·3·5단계다. Dev Pilot 1종(`opd`/`opds` = canonical `opal-pilot-dev`)에만 수직 접합하고, `opal-self-pm`을 신설하며, GC 3종은 **호출 연동만** 한다. 4단계(타 Pilot 확산)·6단계(전 Pilot 회귀)는 TASK `Affected users and systems` §범위 제외가 확정했다.

L2 제거는 "조용한 치환"이 아니라 **규범 본문 제거 + grep 실측**으로 수행한다.

## Decisions and contracts

| 결정 | 변경 후 계약 | 선택 이유·근거 |
|---|---|---|
| D-1. actor 축은 전용 owner 문서 `harness/actor.md`가 소유한다 | 신규 `opal/core/references/harness/actor.md`(frontmatter `module: actor` / `role` / `load: pilot.start`)가 actor 축 정의·지원 Pilot 폐쇄 목록·`--pm` 실행 계약·독립 검증 경계·GC 호출 지점의 **원문 단일 SSOT**다. 다른 문서는 포인터만 둔다 | `--wt`가 `harness/worktree.md`를 별도 module 문서로 소유하고 `events.json` `pilot.start` `required_docs`에 등재된 구조와 동형. C-6([MUST] owner 1곳) 준수 |
| D-2. `--pm` 파싱 owner는 정규식 trigger가 아니라 actor.md 라우팅 계약이다 | 레지스트리 `triggers`는 손대지 않는다. `--pm`은 `pilot.start`에서 전 Pilot이 로드하는 actor.md 조문에 따라 Pilot alias 다음 토큰으로 해석된다 | 레지스트리 `triggers`는 커맨드 토큰만 매칭한다(`opal-pilot-dev-short.triggers == ["^opal-pilot-dev-short$","^opds$"]`). 기존 `--interactive`·`--agentic`·`--wt`·`--rev` 중 trigger로 표현된 것이 0건이며 중앙 CLI 파서도 없다. 레지스트리에서 배제한 결과 `--pm`의 **사용자 대면 노출 owner는 `harness/skill-commands.md` §쌍슬래시 커맨드의 커맨드 문법 블록**(`:35-39`)이며, 해석 규칙 원문은 actor.md가, 문법 노출은 그 블록이 소유하도록 분리한다(W-21) |
| D-3. actor 축은 모드 축과 직교한다 | `modes.md` §라우팅 계약에 조항 8 신설: "`--pm`은 모드가 아니라 별도 실행 주체(actor) 축이므로 모드 플래그 개수에 포함하지 않는다. 해당 축의 원문은 `harness/actor.md`가 소유한다." | 조항 5(`--wt`)와 동형 서술. 구조적으로도 안전하다 — `state-tool init`은 `--mode {interactive,semi-agentic,agentic}` enum 단일 인자를 받으므로 별개 인자인 `--actor`가 `mode_flag_conflict` 개수 판정에 물리적으로 들어갈 수 없다(`state_tool.py` `p_init` 인자 정의) |
| D-4. actor는 `state.json` 최상위 선택 키이며 **미지정 시 키를 생성하지 않는다** | `state-tool init`에 `--actor {pm}` 선택 인자 추가. 지정 시에만 `state["actor"] = "pm"`. `task_steps[]` 행 구성·key·순서·STATE 렌더는 **전부 무변경**이며 `pipeline.json`·`pipeline-short.json`을 손대지 않는다 | `state_tool.py:1422-1425`의 `--worktree` 조건부 영속화("미지정 시 state.json에 키를 생성하지 않는다")를 그대로 재사용. actor를 행으로 만들지 않으므로 AC-2(행 구성 동일)·AC-4(기본 경로 키 미추가)·C-3(바이트 수준 현행 유지)이 동시에 성립한다 |
| D-5. 미지원 Pilot의 `--pm`은 2중으로 막는다 | (a) actor.md가 지원 Pilot **폐쇄 목록**(`opal-pilot-dev` 하나 — alias `opd`·`opds`)을 소유하고 "[MUST] 목록 밖 Pilot이 `--pm`을 수신하면 조용히 무시하지 않고 미지원임을 1행으로 통보한 뒤 기본 actor 진행 여부를 확인한다"를 규정한다. (b) `state-tool init --actor pm --skill <목록 밖>`은 `actor_unsupported_for_skill`로 exit 1 거부한다 | 산문만으로는 집행되지 않는다([MUST] PRINCIPLES §Core Stance). actor.md는 `pilot.start` required doc이므로 **모든** Pilot이 첫 작업 전에 읽고, state 기록 경로는 도구가 결정론적으로 막는다. `modes.md` 조항 7의 "폐쇄된 라우팅 표" 패턴과 동형 |
| D-6. 디스패치 의무 원칙을 actor-aware로 재서술한다 | `guards.md` §디스패치 의무 원칙 본문을 다음으로 교체한다 — "**오케스트레이터 SKILL.md에 \"워커 디스패치\"로 정의된 단계는 `actor=worker`(기본)에서 반드시 서브에이전트를 디스패치한다. PM이 임의 판단으로 직접 실행하여 대체하지 않는다.** `actor=pm`은 사용자가 명시한 `--pm`으로만 성립하는 예외이며, 이때 PM이 해당 단계 스킬을 직접 읽고 입력·출력·검증 계약을 적용한다. 임의 판단에 의한 직접 실행은 actor 축과 무관하게 여전히 금지다. 어느 actor에서도 **독립 검증 행**(§독립 검증 경계)은 서브에이전트 디스패치를 생략할 수 없다." + 하위 절 §독립 검증 경계 신설 | TASK가 지목한 정면 충돌의 해소 형식이다. "누가 결정하는가"(사용자 명시 vs PM 임의)로 예외를 좁혀 원칙의 방어 대상(PM의 자의적 우회)을 보존한다. 제안서 §5 "actor-aware 계약으로 바꾼다"의 구체화 |
| D-7. self-confirming 방지는 **기존 tool-gated 행**이 그대로 담당한다 | `actor=pm`에서도 다음 3행은 서브에이전트 산출 증거 없이 통과 불가다 — `plan.scenario_gate`(`op-scenario-gate` verdict `pass` 필요), `test.run_tests`+`test.pm_gate`(`test-scenario.json` 전 시나리오 PASS + 실제 실행 증거), CLOSE 첫 행(`--auto-pass` 거부, `--owner user` 필수). `worker.dispatch` load·verify는 **이 독립 검증자를 호출하는 시점에만** 발생한다 | 새 게이트를 만들지 않고 `pipeline-short.json` `task_steps[]`의 `plan.scenario_gate`·`test.pm_gate` `gate.checklist`가 이미 집행 중인 구조를 재사용한다. AC-3·C-2·C-5 충족. TEST-SCENARIO 작성자도 이미 PLAN 워커와 분리되어 있다(`opal-pilot-dev/SKILL.md` STEP 3.5 "self-confirming 방지를 위해 PLAN 워커와 다른 작성자") |
| D-8. `opal-self-pm` 경량 기록은 신규 `self-pm-tool`이 `{task_root}/.opal/self-pm/{run_id}.json`에 쓴다 | 3서브명령(`init`/`update`/`show`)만 갖는 최소 CLI. 제안서 §7의 8필드(`objective`·`status`·`decisions`·`open_questions`·`approved_scope`·`changed_files`·`validation`·`knowledge_impact`)를 필수 스키마로 **도구가 검증**하고, 누락·미지 `status` 값은 JSON 에러로 거부한다. `state.json`·`test-scenario.json`·`backlog.json` 경로를 읽지도 쓰지도 않는다 | 대안 2개를 폐기했다 — (i) 손으로 쓰는 JSON은 8필드 보장이 산문이 되어 [MUST] PRINCIPLES §Core Stance 위반, (ii) `state-tool` 확장은 3-SSOT 소유권 경계를 흐려 AC-10이 보호하려는 바로 그 속성을 깬다. 신규 도구는 현재 요구(AC-10)의 최소 구현이며 조회·집계 기능을 만들지 않아 PRINCIPLES §2를 지킨다. 규모 선례: `improve-tool` 442행 + `run.sh` 12행 |
| D-9. GC 3종은 **호출만** 하고 스킬 본체를 변경하지 않는다 | actor.md와 `opal-self-pm/SKILL.md`가 호출 지점·입력 구성 책임만 규정하고, 파라미터·finding 스키마·판정은 각 스킬 §입력과 `harness/gc-finding-schema.md`를 참조한다 | `op-gc-security/SKILL.md` §1의 입력(`project_root`·`target_files`·`output_dir`·`timestamp`)과 `op-gc-report/SKILL.md` §입력과 책임(`findings_inputs`·`baseline`)이 이미 caller-neutral이다. TASK C-8이 고정한 실명 3종이며 태스크 120에서 분리 완료 — 재분리 금지 |
| D-10. L2 제거 대상은 **규범 본문**으로 한정하고 grep으로 실측한다 | 제거·대체 대상 5곳: `README.md` §L2 경량 트랙(:262-275), `opal-pm.md` §12 하위 L2 블록(:218-253), `harness/state.md`(:81), `harness/header-rules.md`(:41), `docs/architecture-diagram/opal_framework_architecture.html`(:451,:468,:615-616,:637-638). **제외**: 이력·버전 표 행(`header-rules.md:187`, `opal-brain/SKILL.md:596-597`, `opal-cli/lib/update.sh:27`), `.opal/brain/`, `docs/proposals/`, `tasks/` | 이력 행 수정은 [MUST] `.opal/AGENT.md` §금지사항(이력은 git·태스크 기록 소유)과 충돌한다. brain은 과거 결정 기록이므로 현재 사실 갱신 대상이 아니다. ## Release and recovery

- **적용 순서**: P1(actor.md·state-tool·self-pm-tool) → P2(events.json·modes·guards·capability·dispatch-process·opal-self-pm) → P3(Dev Pilot 접합·L2 대체·레지스트리·install) → P4(사용자 대면 문서 4종 + 다이어그램) → P5(install 실행 + source→installed 실측). P1~P4는 **소스만** 수정하며 `~/.opal/` 배포본을 직접 편집하지 않는다([MUST] `.opal/AGENT.md` §금지사항).
- **검증 범위**:
  - *결정론(도구 실행)* — `state-tool` 테스트 3건, `self-pm-tool` 테스트, `state-tool init --actor pm --skill opwt` exit 1, `event-loader load --event pilot.start` required 5종, `code-scan validate --changed` exit 0.
  - *회귀(문서 실측)* — AC-4는 `--actor` 미지정 `state.json`의 `actor` 키 부재 + `task_steps[]` 11행 동일로 확인한다. AC-12는 제외 집합을 인자로 명시한 grep 실측으로 확인한다(W-20 (5)).
  - *실제 연동* — `//opds --pm`으로 태스크 1건을 TASK→PLAN까지 실제 실행해 `plan.scenario_gate`가 `op-scenario-gate` 디스패치를 여전히 요구하는지, `Work items` `담당`이 `PM`으로 기록되는지 확인한다(AC-2·AC-3). 이 실연동은 TEST 단계가 소유하며 PLAN은 대상만 지정한다.
  - *문서 검증으로 충분한 항목* — W-5~W-9·W-11·W-12·W-15~W-19는 규칙 문서·서술 갱신이므로 owner 중복 없음·포인터 정합만 확인한다.
- **실측 경계**: 없음 — 시간·품질 수치 목표를 두지 않는다.
- **실패 시**: install은 `clean_dirs`(`skills`/`agents`/`references`/`templates`/`tools`)를 지우고 소스에서 다시 채우는 멱등 배포이므로, 소스를 `git revert`(또는 해당 커밋 이전으로 체크아웃)한 뒤 `./scripts/install-mac.sh`를 재실행하면 배포본이 이전 상태로 완전히 되돌아간다. 배포 후 진행 중 태스크가 `pilot.start` receipt stale로 차단되면(H-2) 롤백이 아니라 `event-loader load --event pilot.start` 재수행 후 `state-tool event-verify`로 복구한다. `self-pm-tool` 기록(`{task_root}/.opal/self-pm/`)은 사용자 런타임 데이터이므로 롤백 대상이 아니며 install이 건드리지 않는다.
