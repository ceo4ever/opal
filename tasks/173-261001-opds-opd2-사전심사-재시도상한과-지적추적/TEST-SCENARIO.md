# TEST-SCENARIO: opd2 PLAN 사전심사 — 재검증 절차 정합·회차 상한·지적 해소 추적

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: 이 워크트리(`/Volumes/Data/AiStudio/workspace/opal/.opal-worktrees/task_173`)의 `opal/skills/opal-pilot-dev2/scripts/lifecycle.py`를 실제 CLI(`lifecycle.py <command> <task>`)로 호출한다. 기존 테스트 하네스(`opal/skills/opal-pilot-dev2/tests/test_lifecycle.py`)처럼 임시 Git 저장소와 실제 형제 도구 `state-tool`(opd2 `pipeline.json` 행)을 쓴다. 실행 명령은 `python3 -m unittest discover -s opal/skills/opal-pilot-dev2/tests`다. 기준선은 36건 통과다.
- 공통 데이터: PLAN 단계까지 INTENT·DESIGN을 통과한 임시 태스크. AC가 2개인 intent, `ac_coverage`가 모두 덮는 plan, `reviewer: r1`·`builder: b1`. 사전심사 기록은 `review --call A|B --actor r1 --verdict ... --reason ... [--findings '<JSON>'] [--resolutions '<JSON>']`로 만든다. 지적 예: `[{"id":"A-1","location":"plan.json files","remaining_choice":"app.py 외 테스트 파일 포함 여부"}]`.
- 대역 사용과 한계: Reviewer 에이전트는 실제로 디스패치하지 않고 테스트가 Reviewer 역할로 CLI를 직접 호출한다(역할 판정은 fixture이며 실제 독립 에이전트 평가가 아니다 — `references/validation.md`와 같은 구분). 사용자 해제는 실명 actor와 reference 문자열을 가진 CLI 호출로 재현한다.
- 변경 전 원장 재현: `Store.state()`로 꺼낸 state의 `plan_reviews`에 `findings` 키가 없는 기록을 직접 넣고 `Store.save(state, 'plan_review', report)`로 저장한다.
- 설치 후 검증 환경: `scripts/install-mac.sh`에서 `install_dir`·`strip_deploy_md_recursive` 정의를 sed로 잘라 임시 스크래치 루트에 적용한다. 스크래치 루트는 `skills/opal-pilot-dev2`(그 함수로 복사)와 `tools/`(`opal/tools` 전체 복사)를 형제로 둔다. 공유 `~/.opal/`은 읽지도 쓰지도 않는다.
