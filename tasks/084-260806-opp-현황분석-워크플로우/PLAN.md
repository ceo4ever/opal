**(2) 미보유 5종(N-1~N-5)을 소스 검색으로 재확인했다.**

- N-1 헤더 블록 우선 읽기 — `opal/core/references/` 전체에 "파생/SSOT 판별을 위해 문서 헤더를 먼저 읽는다" 취지의 규칙 없음.
- N-2 인용 시점 stale 재확인 — `citation-rules.md:11`은 "상상·추정·기억 기반 기재 금지"까지만 규정하고, **이미 확보한 인용이 현행인지 재확인**하는 시점 규율은 없음.
- N-3 산출물 거처 선판정 — `memory-learning.md:44-60`은 임시(메모리)→영구(docs/brain) **졸업(promote)** 만 규정하고, 산출 시점의 최초 거처 판정은 없음.
- N-4 기존 분석 산출물 재사용 분기 — `opal-brain/SKILL.md:439-441`은 답변 품질 평가 후 **신규 파일링 여부**만 판정하며, 동일 질의의 기존 synthesis 페이지를 먼저 찾는 단계가 없음.
- N-5 PM(대화) 수집 팬아웃 — `opal-pm.md:148` PM(대화) 행의 동작이 "PM이 직접 수행"이며, 워커 디스패치는 PM(태스크) 행에만 있음.

**(3) 인프라 확인 결과 — 신규 배선 불필요.**

- 배포: `install-mac.sh:1384`가 `opal/core/references/`를 하위 디렉토리째 재귀 복사하므로, 신규 파일을 등록할 매니페스트가 없다. Step 추가 불필요.
- brain 기본 페이지 타입: `brain_tool.py:31` `DEFAULT_PAGE_TYPES = ["entity", "concept", "flow", "synthesis"]` — TASK §규모 실측의 "분석 23건"은 `synthesis` 타입에 대응한다. R-7의 "기존 분석 페이지 조회"는 `--type synthesis`로 실현된다.
- `synthesis`는 `brain_tool.py:922`에서 `sources` 없으면 lint 위반(`unsourced`)이므로, 재사용 분기에서 근거 원문 추적 경로가 이미 보장된다.

## 6. 설계 피드백 (판단이 갈린 지점과 선택 근거)

### FB-1. `opal-pm.md` 절 배치 — 말미 §18 vs §3 인근 삽입

- **갈림**: AS-IS 분석은 성격상 §3(디스패치 전 프로세스)·§7(문서/코드 불일치) 인근이 의미적으로 자연스럽다.
- **선택**: 말미 §18.
- **근거**: 실측(`grep -rn "opal-pm.md §" opal docs`) 결과 §3·§4·§5·§6·§7·§9·§10·§11·§15 **9개 절**이 외부 문서에서 절 번호로 역참조된다. 중간 삽입은 이 역참조를 전부 깨뜨리고, 수정 범위가 계획 대상 4파일을 넘어선다. 의미적 인접성보다 **참조 무결성**을 우선했다 (Simplicity First — 요구되지 않은 리팩터 회피).

### FB-2. R-5 반영 위치 — §12 표 셀 수정 vs 인접 문단 추가

- **갈림**: AC는 "해당 표(또는 인접 문단)"를 허용한다. 표의 PM(대화) 행 "동작" 셀을 "PM이 직접 수행 (수집 워커 예외 있음)"으로 고칠 수도 있다.
- **선택**: 표 불변 + 인접 문단(`##### PM(대화)의 읽기 전용 수집 예외`) 추가.
- **근거**: 해당 표의 축은 **하네스 적용 여부**이지 디스패치 허용 여부가 아니다. 셀에 예외를 욱여넣으면 표의 축이 흐려지고, 예외의 3가지 조건(허용 범위·위임 불가 범위·여전히 불가 범위)이 셀 한 칸에 들어가지 않는다.

### FB-3. R-4 규율 3종의 단계 배정

- **갈림**: N-1(헤더 블록 우선 읽기)은 실제로는 2단계 수집에서도 매 문서마다 발생한다. 0단계와 2단계 중 어디에 둘지 갈렸다.
- **선택**: **0단계 단독 배치**.
- **근거**: N-1의 목적은 "이 문서가 SSOT인가 파생본인가"를 판별해 **좌표를 고정**하는 것이다. 좌표가 고정된 뒤의 2단계는 이미 확정된 SSOT를 좁혀 읽을 뿐이다. 두 단계에 중복 기재하면 "어느 단계 소유인가"가 흐려져 R-4 AC(단계 식별 가능)를 약화시킨다. 2단계에서는 참조 1줄로 연결한다.
- **부수 효과**: N-2(stale 재확인)는 인용 근거가 실제로 만들어지는 2단계에, N-3(거처 선판정)은 산출이 발생하는 4단계에 각각 단독 배치되어 TASK가 지정한 0·2·4 배치와 정확히 일치한다.

### FB-4. R-7 재사용 조회의 삽입 위치 — 0.5 vs 5번 확장

- **갈림**: 기존 5번(답변 품질 평가)에서 파일링 직전에 중복 조회를 넣는 방안도 가능하다.
- **선택**: **질의 절차 앞단(0.5)**.
- **근거**: 뒤에 두면 이미 전체 검색·Read·합성을 마친 뒤에야 중복을 발견한다. 앞단에 두면 "재사용" 분기에서 후속 절차 자체를 건너뛸 수 있어 토큰과 지연을 아낀다. N-4의 문제 정의("query 모드가 매 호출 신규 생성")도 조회 이전 시점의 결함이다.

### FB-5. 폴백 F-3(code-scan)의 서술 수준

- **갈림**: 폴백 매트릭스가 자기완결이 되도록 3분기(매칭 0건/저커버리지/정상)를 표에 옮겨 적을 수 있다.
- **선택**: **위임만 하고 옮기지 않는다.**
- **근거**: [MUST] PRINCIPLES §Governance "Lower docs reference these principles; they don't restate them." 3분기 기준(예: 커버리지 30%)은 `header-rules.md`가 소유하며 값이 바뀔 수 있다. 복제하면 두 문서가 다른 임계값을 말하는 이중 SSOT가 된다.

### FB-6. 축 매트릭스의 결측 표기 기호

- **갈림**: 미보유와 결측을 한 기호로 통합할지.
- **선택**: `-`(해당 축 미보유 — 프로젝트가 그 축 SSOT를 선언하지 않음)와 `?`(축은 있으나 확인 실패·부분 커버)를 분리.
- **근거**: 두 상황의 다음 행동이 다르다. `-`는 "축 SSOT 신설 제안", `?`는 "재수집·커버리지 개선"으로 이어진다. 갭 목록의 "다음 행동"이 결정 가능하려면 구분이 필요하다.

### FB-7. `docs/PROJECT.md` 미갱신

- **판단**: 갱신하지 않는다.
- **근거**: `PROJECT.md:164-172` 문서 레지스트리는 프로젝트 레벨 문서(`AGENT.md`·`PROJECT.md`·`ARCHITECTURE.md`·`CONVENTIONS.md`·`MEMORY.json`·`README.md`)만 등재하며 `opal/core/references/` 하위 문서는 1건도 없다. 또한 신규 컴포넌트(스킬·도구·에이전트)가 추가되지 않으므로 컴포넌트 표 대상도 아니다. PM Gate에서 이 판단이 뒤집히면 Step 6에 행 1개를 추가하면 된다.

### FB-8. 규모 실측 수치의 문서 반영 여부

- **판단**: `pm/asis-analysis.md`에 규모 수치·사례를 **기재하지 않는다.**
- **근거**: TASK.md §규모 실측은 특정 사용처 프로젝트 1건의 관측이며, 프레임워크 문서에 옮기면 프로젝트 중립성 [MUST]에 저촉될 위험과 수치 진부화 위험이 동시에 발생한다. 팬아웃이 필요한 이유는 "단일 컨텍스트 통독 불가 규모에서"라는 조건 서술로 일반화한다.
