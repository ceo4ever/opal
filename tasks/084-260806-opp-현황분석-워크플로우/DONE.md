## 3. 설계 핵심

### 3.1 5단계 — 순서만 소유하고 규칙은 상속한다

| 단계 | 하는 일 | 상속 대상 |
|------|---------|----------|
| 0 좌표 고정 | 질의 경계 확정 + 축 SSOT 지목 + docs 프리로드 | `opal-pm.md` §2 |
| 1 기존 지식 확인 | brain 조회 + 재사용/갱신/신규 판정 결과 소비 | `pm/dispatch-process.md` §Step 1.5 |
| 2 4축 수집 | 정책·화면·데이터·코드를 좁혀서 구간 Read | `pm/dispatch-process.md` §code-scan |
| 3 정합 판정 | 축 간 대조 후 3분류 판정 | `harness/doc-code-mismatch.md` |
| 4 보고·환류 | 레이아웃 판정 + 축 매트릭스·갭 목록 + 거처 판정 | `opal-brain/SKILL.md` §답변 구조 |

### 3.2 신규 규율 3종 — 이번 세션의 실패에서 도출

- **N-1 헤더 블록 우선 읽기(0단계)** — 문서 본문 통독 전에 상단 헤더로 SSOT인지 파생본인지 판별하고, 파생본이면 원천으로 좌표를 옮긴다.
- **N-2 인용 시점 stale 재확인(2단계)** — 확보한 지식을 근거로 인용하는 시점에 원문을 재확인한다. brain은 스냅샷이고 코드가 SSOT다.
- **N-3 산출물 거처 선판정(4단계)** — 보고 산출 **전에** 거처를 판정한다. 같은 내용이 이미 있으면 신규 생성이 아니라 갱신을 택한다(이중 SSOT 금지).

### 3.3 읽기 전용 수집 워커 예외

PM(대화)는 원칙적으로 워커를 디스패치하지 않으나, **2단계 수집에 한해** 읽기 전용 워커 팬아웃을 허용했다.

- 워커 권한은 읽기 도구로 한정하고, **판정·해석·권고 반환을 금지**했다.
- 3단계 정합 판정과 4단계 보고 합성은 PM이 직접 수행한다 — 판단 주체를 단일하게 유지한다.
- 변경·실행 계열 디스패치는 여전히 불가하며, 필요하면 PM(태스크)로 전환한다.

### 3.4 자산 부재에서도 멈추지 않는다

폴백 5종(brain 부재 · term 미채택 · code-scan 미보급 · 축 SSOT 부재 · 기획 산출물 부재) 어느 것도 동작이 "중단"이 아니다. 축소 실행하되 **결측을 침묵하지 않는다** — 축 매트릭스 셀(`-` 미보유 / `?` 확인 실패)과 갭 목록에 반드시 명시한다.

### 3.5 재서술 금지의 실제 적용

`header-rules.md`의 폴백 임계값(30%)을 문서에 옮겨 적지 않고 **분기 판정 자체를 위임**했다. 값이 바뀌면 SSOT 한 곳만 바뀐다. 보고 레이아웃(관측 축 6종 → 후보 5종) 역시 참조만 하고 재정의하지 않았다.
