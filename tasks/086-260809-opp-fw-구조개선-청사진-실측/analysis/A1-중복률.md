## §1. 측정 방법

### 1.1 측정 단위

SKILL.md의 헤딩 블록(`##`/`###`)을 측정 단위로 한다. **블록 경계 운영 정의(본 문서의 명시적 해석)**: PLAN §2 N-1 "헤딩 줄 ~ 다음 동급/상위 헤딩 직전 줄" 규칙을 배타적 파티션으로 성립시키기 위해, 문서에 등장하는 `##`/`###` 헤딩을 레벨 구분 없이 **줄번호 순으로 나열**하고 각 블록을 "자신의 헤딩 줄 ~ 다음(레벨 무관) 헤딩 직전 줄"로 정의한다. 이렇게 하면 `##` 블록에 `###` 자식이 있을 때 `##` 자신의 몫은 도입부(자식 헤딩 이전)만 남고, 자식 `###`는 별도 블록이 되어 **줄 중복 없이 정확히 1회씩** 전체 분모를 partition한다 (§3 검산이 이를 실증). [E] 이 해석은 PLAN 원문이 명시하지 않은 세부 규칙이며, 배타 할당(C-1 방향 원칙)을 만족시키기 위한 저자 판단이다.

### 1.2 분모 정의

```
분모줄수 = 총줄수 − frontmatter줄수 − 전문(前文)줄수(H1 제목~첫 '##' 직전) − '## 변경이력' 블록줄수
```

전문(前文, H1 제목 + 공백줄)은 frontmatter와 마찬가지로 파이프라인 정의와 무관한 문서 메타데이터이며 `##`/`###` 측정 단위에 속하지 않으므로 분모에서 제외한다(제외 시에만 블록 총합이 분모와 정확히 일치함 — §3 검산 실측). [E] "전문 제외"는 PLAN §2 N-1이 명시한 "frontmatter+변경이력 제외"를 넘어선 확장 해석이나, 배타적 파티션을 위해 불가피하다.

### 1.3 3분류 기준 및 경계 규칙

PLAN §2 N-1 표 그대로 적용(WHAT/ENFORCE/WHY 정의, 경계 규칙 1~4). 요약:
- 혼재 블록 → 줄수 과반으로 배타 할당, `혼재=Y` 표기
- `## Harness` → ENFORCE 고정
- 판정 불가(정보 없는 헤딩 전용 블록 등) → WHY 보수 할당

### 1.4 WHAT-D / WHAT-P 판정

WHAT 분류 블록에 대해 pipeline.json의 `task_steps[].stage/item/key`, `pm_gate[].stage/artifacts/checklist`, `meta.stages`와 대조. 블록 내용이 이미 그 필드에 구조화되어 있으면 **WHAT-D**, 없으면 **WHAT-P**. 블록이 D/P 혼재이면 D/P도 줄수 과반으로 단일 값 배타 할당한다(§2 표의 "WHAT-D·P" 열은 블록 전체에 대한 단일 값).

### 1.5 재현 명령

```
grep -n '^#\{1,4\} ' <SKILL.md 경로>
```

집계 스크립트는 스크래치패드(`/private/tmp/claude-501/...`)에서만 실행했으며 태스크 폴더/FW 소스에 남기지 않았다(C-3).

### 4.1 즉시 절단 대상 (WHAT-D, pipeline.json에 이미 존재)

**절단 효과(추정)**: 위 4개 유형만 제거해도 pilot당 30~40줄(전체 WHAT-D의 60~80%)이 즉시 산문에서 빠진다. `[E]` 추정 근거: §2 표에서 STATE.md+PM Gate 두 블록의 줄수 합이 pilot별 WHAT-D 줄수의 대부분을 차지함(opp 39/43, opd 48/72, opds 42/66, opdw 40/40)을 관찰했으나, 정확한 "제거 후 잔여 줄수"는 P2 실제 편집 후에만 확정 가능하므로 추정으로 표기한다.

### 4.2 P2 스키마·데이터 확장 대상 (WHAT-P)

공통적으로 4 pilot 모두에서 다음 유형이 WHAT-P로 반복 등장한다 — pipeline.json 스키마에 필드를 추가하면 데이터화·절단 가능:
1. **디스패치 템플릿 필드 목록** (스킬 경로/태스크 폴더/이전 산출물/프로젝트 컨텍스트/Scope 제한/핵심 제약 등) — `task_steps[]`에 `dispatch_template` 필드 신설 후보
2. **모드 플래그 표** (`### 명시 모드`: 호출→모드 매핑) — `meta`에 `mode_flags` 필드 신설 후보
3. **자율 게이트 흐름 속성** (`### 자율 게이트 흐름`: 단계별 사용자승인/PM자율 여부) — `task_steps[].gate_autonomy` 필드 신설 후보
4. **AGENTIC-LOG 생성 시점 규칙** — `meta.agentic_log_trigger` 필드 신설 후보
5. **에스컬레이션 임계값 표**(opds 전용) — `meta.escalation_thresholds` 필드 신설 후보

### 4.3 잔존 WHY 최소 골격 (경량 발동층 산문 유지 대상)

절단 후에도 산문으로 남아야 하는 블록(판단이 실제로 개입하는 서술):
- `## Harness`(고정 ENFORCE — 로드 지시 자체는 도구가 대신할 수 없음, 세션 초기 Read 강제)
- `### 기본 모드` / Agentic 섹션 도입부 — 모드 간 차이·해석 서술
- opd `### 4-3. FE/BE 병렬` — "독립적이면 병렬/의존 있으면 순차" 판단 기준
- opdw `### 3-1. 라우팅 결정` — FE 단일 라우팅 근거·폴백 조건
- opds `### 조기 에스컬레이션`/`### PLAN 결과 에스컬레이션` 서술부(표 제외) — 판별 불확실 시 처리 방침
- 각 PM Gate 체크리스트의 "설계 피드백 섹션에 미해결 빈틈이 없는가" 류 판단 항목(열거된 형태이나 내용은 판단) — WHAT으로 분류했으나 실질은 판단 서술이므로 P2에서 형식 변경(체크리스트→가이드 문장) 시 WHY로 재분류 검토 필요
