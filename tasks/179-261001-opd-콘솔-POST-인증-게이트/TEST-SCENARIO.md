# TEST-SCENARIO: OPAL Console 상태 변경 API 인증 게이트와 구형 Brain 실행 차단 (Gateway 제안 Phase 0)

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: 이 리포지토리의 워크트리 루트. 백엔드는 `~/.opal/.venv/bin/python -m pytest`(이하 `pytest`), 프런트엔드는 `dashboard/frontend`에서 `npx vitest run`(이하 `vitest`), CLI는 `bash`, SUT E2E는 `opal/tools/test-tool`의 `e2e run`이 임대 포트 위에 기동한 실제 uvicorn·vite를 쓴다. 사용자 Console(127.0.0.1:7823)·사용자 `~/.opal`·설치본은 실행하거나 수정하지 않는다.
- 공통 데이터: 모든 백엔드·CLI·E2E 실행은 임시 `HOME`과 `OPAL_HOME=<임시 HOME>/.opal`을 쓰고, 프로젝트·태스크 fixture는 기존 `test_e2e_sut_http_surfaces.py`의 `_Isolated` 방식을 따른다. 인증이 필요한 백엔드 테스트는 `dashboard/backend/tests/auth_helpers.py`의 `authed_client(app)`로 세션을 만든다.
- 대역 사용과 한계:
  - 대체 대상: 실제 `claude -p` 프로세스. 이유: 구독 토큰 소모·부수효과 방지(기존 H-8). 방법: 모든 Brain 관련 테스트는 autouse 가드 fixture로 실제 `subprocess.run`·`subprocess.Popen` 호출을 즉시 실패시키고, spawn 검증은 `subprocess.Popen` 대체 객체의 호출 횟수·인자로 단언한다. 한계: 켜진 구형 Brain의 실제 LLM 응답 품질은 검증하지 않는다. 이 태스크의 AC-3는 "꺼짐일 때 프로세스 0회"와 "켜짐일 때 허용 경로 동작·`legacy` 표시"이므로 대체 호출 횟수가 곧 증거이며, 실제 `claude`와의 연동은 Phase 2 새 Brain 검증의 몫이다.
  - 대체 대상 없음: 인증·세션·CSRF·진입 token·E2E 교환은 모두 실제 코드 경로를 실행한다(S-15는 실제 uvicorn 소켓).
- 실행 조건: 자동 실행. S-17은 브라우저 driver가 필요하며 가용하지 않으면 도구가 `executor_unavailable`로 기록하고 pass로 승격하지 않는다(대체 manual 없음, PM Gate에서 사용자에게 그대로 보고).
- RED 안전: `구현 전 RED` 시나리오는 구현 전에 실행해도 사용자 환경·실제 `claude`를 건드리지 않는다(위 가드 fixture, 임시 HOME).
