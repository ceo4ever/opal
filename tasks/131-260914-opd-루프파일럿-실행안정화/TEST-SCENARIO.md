# TEST-SCENARIO: OPPL 실행 안정화 — 상한·완료판정 도구 집행

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: macOS(darwin), Python 3.10+ 표준 라이브러리 전용. 작업본 `/Volumes/Data/AIStudio/workspace/ai-framework/.opal-worktrees/task_131`. 테스트 실행은 `pytest opal/tools/<도구>/tests/`. process group 검증은 실제 `subprocess` + `os.killpg` + `os.kill(pgid, 0)` 생존 확인으로 수행한다.
- 공통 데이터: W-1이 고정하는 stream fixture 6종(`opal/tools/opal-agent/tests/fixtures/`). 태스크 123 실행 증거 3파일에서 프롬프트 본문·절대경로·토큰·PID·타임스탬프를 비식별 치환한 것이며, 원본은 `/Volumes/Data/AIStudio/workspace/ai-framework/.opal-worktrees/task_123/tasks/123-260912-oppl-태스크-실행로그-표준화/tasks/` 하위 `T01-채널-관측-능력-실측/.oppl-run/t1.events.jsonl`, `T03-기록코어-스키마-멱등-순번/.oppl-run/t3.events.jsonl`, `T02-워킹-스켈레톤-CLI-관통/.oppl-run/t3.a2.events.jsonl`이다.
- 대역 사용과 한계: LLM provider CLI(`claude`)는 호출하지 않는다. 대체 대상은 provider 프로세스이며, 이유는 실 호출이 비용·rate limit·비결정성을 도입해 상한·타임아웃 판정을 재현 불가능하게 만들기 때문이다. **한계: 실제 provider의 stream 스키마 변화는 이번 태스크에서 검출되지 않으며 이 한계를 닫는 시나리오는 없다.** S-24는 배포본의 CLI 계약 성립만 확인하고 provider stream을 통과시키지 않는다. 완화 수단은 W-1 fixture가 추정이 아니라 태스크 123 실측 증거에서 파생됐다는 점 하나뿐이며, provider 스키마 변경 시 adapter 판정이 깨질 위험은 잔존 위험으로 남긴다. **프로세스 수명주기·PGID·파일 lock·직렬화는 대역을 쓰지 않는다** — 무출력 `sleep` 및 손자 프로세스를 fork하는 실제 스크립트를 띄워 검증한다.
- 실행 조건: 자동 실행. 사용자 협업이 필요한 시나리오는 없다. S-24는 `./scripts/install-mac.sh` 실행으로 사용자 홈 배포본을 갱신하므로 다른 시나리오 완료 후 마지막에 1회만 수행한다.
