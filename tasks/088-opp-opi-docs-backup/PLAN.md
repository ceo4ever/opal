## 2. 구현 계획

### 2-1. SKILL.md에 추가할 내용

#### A. 공통 백업 프로토콜 섹션 (신규)

**삽입 위치**: `## 설계 원칙` 아래, `## 모드 판별` 위에 새 섹션 삽입

```markdown
## docs/ 백업 프로토콜

docs/ 하위 문서를 수정(Write/Edit)하기 직전에, 해당 파일이 이미 존재하면 백업을 수행한다.

**백업 규칙**:
- **대상**: `docs/` 하위의 기존 파일을 수정할 때만 적용 (신규 생성은 백업 불필요)
- **위치**: `docs/backup/`
- **파일명**: `{원본파일명}_{YYYYMMDDHHMM}.md` (예: `PROJECT_202604061530.md`)
- **타이밍**: 파일 수정(Write/Edit) 직전
- **폴더 생성**: `docs/backup/` 가 없으면 자동 생성
- **중복 방지**: 동일 세션 내 같은 파일에 대해 이미 백업이 존재하면 재백업하지 않는다

**절차**:
1. docs/ 하위 파일을 수정하기 전에 해당 파일이 이미 존재하는지 확인한다
2. 존재하면 `docs/backup/` 디렉토리를 확인하고, 없으면 생성한다
3. 현재 파일을 `docs/backup/{파일명}_{YYYYMMDDHHMM}.md` 형식으로 복사한다
4. 백업 완료 후 원본 파일을 수정한다
```

#### B. 초기화 모드 Phase 2 수정

**위치**: `### Phase 2: 공통 문서 작성 + 검토` > `**2-2. 작성 프로세스**`

**변경**: 작성 프로세스 절차에 백업 단계 삽입

현재:
```
1. 참조 가이드의 구조에 맞춰 초안을 작성한다
```

변경 후:
```
1. 참조 가이드의 구조에 맞춰 초안을 작성한다
   - 기존 파일이 있으면 **docs/ 백업 프로토콜**에 따라 백업 후 수정한다
```

#### C. 초기화 모드 Phase 3 수정

**위치**: `### Phase 3: 개발 문서 (개발 프로젝트만)` > `**3-3. 작성 프로세스**`

**변경**: Phase 2와 동일한 백업 참조 추가

현재:
```
Phase 2와 동일한 프로세스를 따른다:
1. docs-guide.md 구조에 맞춰 초안 작성
```

변경 후:
```
Phase 2와 동일한 프로세스를 따른다:
1. docs-guide.md 구조에 맞춰 초안 작성
   - 기존 파일이 있으면 **docs/ 백업 프로토콜**에 따라 백업 후 수정한다
```

#### D. 최신화 모드 Phase 3 수정

**위치**: `### Phase 3: 변경 사항 정리 + 사용자 검토`

**변경**: 사용자 승인 후 업데이트 절차에 백업 단계 삽입

현재:
```
4. 사용자 승인 → 해당 섹션만 업데이트
```

변경 후:
```
4. 사용자 승인 → **docs/ 백업 프로토콜**에 따라 백업 후 해당 섹션만 업데이트
```

#### E. .gitignore 업데이트 권장 (SKILL.md 외)

SKILL.md 수정과 별도로, `docs/backup/`을 `.gitignore`에 추가하는 것을 권장한다. 이는 opi 스킬이 아닌 프로젝트 설정 변경이므로 TASK 실행 시 함께 처리한다.
