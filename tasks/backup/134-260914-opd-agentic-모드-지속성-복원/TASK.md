# TASK: agentic 모드 지속성 복원

## Problem
agentic 모드로 시작한 Pilot이 사용자 검토 왕복 또는 세션 재시작 뒤 기존 모드를 일관되게 복원하지 못해, 이미 위임된 진행 중에도 사용자 확인을 반복 요청한다. 같은 단절이 중첩 Pilot 호출, 트랙 전환, 작업 재개 경로에서도 발생할 수 있어 사용자 의도와 실제 하네스 동작이 어긋난다.

## Proposed outcome
명시적으로 선택한 agentic 모드가 작업 상태의 단일 기준으로 유지되고, 사용자 검토 왕복·세션 재시작·기존 작업 재개·중첩 Pilot·트랙 전환 뒤에도 동일하게 적용된다. 사용자가 모드를 명시적으로 바꾸지 않는 한 불필요한 확인 요청은 재발하지 않으며, CLOSE 진입 확인처럼 모드와 무관한 필수 경계는 유지된다.

## Affected users and systems
OPAL Pilot을 interactive·semi-agentic·agentic 모드로 실행하거나 재개하는 사용자와 PM이 영향받는다. 범위는 Dev Pilot의 호출·재개·중첩·트랙 전환, 상태 도구, 세션 프로젝트 브리프, 공통 하네스 문서와 회귀 테스트다. 개별 제품 기능과 OPAL 외부 플랫폼 자체의 세션 저장 방식은 범위에서 제외한다.

## Constraints
- C-1: 모드의 최종 판정은 결정론적 도구와 `state.json`을 단일 기준으로 사용하고, 산문 지시만으로 복원 여부를 결정하지 않는다.
- C-2: 사용자의 명시적 모드 선택이 기존 저장 모드보다 우선하며, 모드를 명시하지 않은 재개는 저장 모드를 상속한다.
- C-3: agentic 모드에서도 CLOSE 진입 사용자 확인과 안전·권한 경계는 완화하지 않는다.
- C-4: 기존 interactive·semi-agentic 동작과 레거시 태스크 호환성을 유지한다.
- C-5: 프로젝트 소스만 변경하고 배포본 `~/.opal/`은 직접 수정하지 않으며, 기존 작업 트리의 사용자 변경을 보존한다.
- C-6: 모드 복원 계약은 지원 플랫폼에 공통으로 적용되고 플랫폼별 하드코딩을 추가하지 않는다.

## Acceptance criteria
- AC-1: agentic 작업에서 사용자 검토 왕복 뒤 다음 단계 진입 시 비-CLOSE 사용자 확인이 자동 승인되고 추가 확인 요청이 발생하지 않음을 자동 테스트로 검증한다.
- AC-2: agentic 작업의 세션을 종료한 뒤 모드 플래그 없이 재개해도 저장된 agentic 모드가 복원됨을 자동 테스트로 검증한다.
- AC-3: 기존 작업을 모드 플래그 없이 재호출하거나 중첩 Pilot·Dev 트랙 전환으로 이어갈 때 원래 모드가 상속됨을 자동 테스트로 검증한다.
- AC-4: 사용자가 재개 시 모드를 명시하면 저장 모드보다 명시값이 우선하고 상태에 일관되게 반영됨을 자동 테스트로 검증한다.
- AC-5: 모드가 없거나 손상된 레거시 상태는 문서화된 안전한 기본값으로 결정되며, 호출 경로별 상이한 암묵 기본값이 남지 않음을 자동 테스트로 검증한다.
- AC-6: 프로젝트 브리프 또는 동등한 재개 정보에 활성 태스크의 모드가 포함되어 세션 복원 시 하네스가 이를 소비할 수 있음을 자동 테스트로 검증한다.
- AC-7: interactive·semi-agentic의 기존 확인 경계와 agentic의 CLOSE 진입 확인 경계가 유지됨을 기존 및 신규 회귀 테스트로 검증한다.
- AC-8: 관련 하네스·Pilot 문서가 구현된 단일 모드 판정 및 상속 계약과 일치하고, 설치 검증으로 배포 대상 반영 가능성을 확인한다.
