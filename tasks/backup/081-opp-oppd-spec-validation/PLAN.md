### 1-2. 현재 상태

**oppd Phase 1 현재 흐름 (SKILL.md 141~188행)**


opwt 자체 Phase 4(정합성 검증)는 PRD↔TRD 간 커버리지·용어·범위 일관성을 검증하지만,

**network-guide.md 7-3 신규 프롬프트 현재 상태 (351~387행)**

```
2. {type} 유형의 표준 구조에 맞춰 문서를 작성한다.
```

PRD 유형에 대해 "표준 구조"가 무엇인지 명세되지 않아, 워커가 Non-goals·AC·Open Questions 없이도 작성을 완료할 수 있다. 사실상 비명세 상태.

#### 2-3-A. network-guide.md 7-3 PRD 섹션 명세 추가 (삽입 위치: "수행 작업" 2번 항 확장)

현재 7-3 "신규" 프롬프트의 "수행 작업" 2번:
```
2. {type} 유형의 표준 구조에 맞춰 문서를 작성한다.
```

변경 후:
```
2. {type} 유형의 표준 구조에 맞춰 문서를 작성한다.

   **PRD 유형의 경우, 아래 섹션을 반드시 포함한다:**

   | 섹션 | 필수/선택 | 작성 기준 |
   |------|----------|-----------|
   | 제품 목표 | 필수 | 달성하고자 하는 결과 (측정 가능한 표현 권장) |
   | **Non-goals** | **필수** | 이번 버전에서 명시적으로 제외하는 범위를 열거한다 |
   | 타깃 유저 | 필수 | `As a {역할}, I want {목적}, so that {이유}` 형식, 최소 1개 |
   | 핵심 요구사항 | 필수 | Must/Should/Nice-to-have 3단계로 분류하여 작성한다. 모호한 표현 금지 ("빠르게" → "응답 3초 이내") |
   | **Acceptance Criteria** | **선택 (핵심 서비스 시나리오 단위)** | GIVEN {상태} / WHEN {행위} / THEN {기대 결과} 형식. 핵심 Must 기능당 최소 1개 작성 |
   | **Open Questions** | **필수** | 미결 사항을 열거한다. 없으면 "없음"으로 명시한다 |

   **TRD 유형의 경우, 아래 섹션을 반드시 포함한다:**

   | 섹션 | 필수/선택 | 작성 기준 |
   |------|----------|-----------|
   | 기술 스택 | 필수 | 주요 라이브러리/프레임워크 버전을 명시한다 (`React 18.3.x` 형태) |
   | 아키텍처 설계 | 필수 | 시스템 구성도 또는 레이어 설명 |
   | **비기능 요구사항** | **필수** | 성능(응답시간 N초 이내), 가용성(SLA %), 보안(인증/인가 방식)을 수치로 명시한다. 수치화 불가 시 "[미결: 수치 확정 필요]"로 표시 |
   | API/인터페이스 계약 | 필수 (API 포함 시) | 주요 엔드포인트 목록, 인증 방식, 핵심 요청/응답 필드 |
   | **Open Questions** | **필수** | 미결 기술 사항을 열거한다. 없으면 "없음"으로 명시한다 |
```

#### 2-3-B. oppd SKILL.md Phase 1 삽입 섹션 전체 초안 (1-1과 1-2 사이)

```markdown
### 1-1b. SDD 명세 검증 (PM 직접 수행)

opwt 완료 후, PM이 PRD·TRD를 직접 읽어 명세 완성도를 검증한다.
**이 단계를 통과하지 않으면 1-2 사용자 확정으로 진행하지 않는다.**

#### PRD 검증 체크리스트

`docs/PRD.md`를 Read하여 아래 항목을 1:1 판정한다.

| # | 항목 | 검증 기준 | 판정 |
|---|------|-----------|------|
| P1 | Non-goals 섹션 존재 | 섹션이 있고 내용이 비어 있지 않음 | Pass / Fail |
| P2 | 타깃 유저 시나리오 형식 | `As a ... I want ... so that ...` 형식, 최소 1개 | Pass / Fail |
| P3 | 핵심 요구사항 Must 분류 | Must/Should/Nice-to-have 구분이 명시됨 | Pass / Fail |
| P4 | Acceptance Criteria 존재 | Must 핵심 기능당 최소 1개, GIVEN/WHEN/THEN 형식 | Pass / Fail |
| P5 | 모호한 표현 없음 | "빠르게", "쉽게", "적절히" 등 수량화 불가 표현 없음 | Pass / Fail |
| P6 | Open Questions 섹션 존재 | 섹션이 있고 "없음" 또는 구체적 항목이 기재됨 | Pass / Fail |

> **PRD 통과 기준**: P1~P6 전항 Pass. 1개라도 Fail이면 PRD Fail.

#### TRD 검증 체크리스트

`docs/TRD.md`를 Read하여 아래 항목을 1:1 판정한다.

| # | 항목 | 검증 기준 | 판정 |
|---|------|-----------|------|
| T1 | 기술 스택 버전 명시 | 주요 라이브러리/프레임워크에 버전이 명시됨 | Pass / Fail |
| T2 | 성능 요구사항 수치화 | 응답시간, 처리량 등이 수치로 명시됨 (미결 허용, "[미결: 수치 확정 필요]"로 표시된 경우 Pass) | Pass / Fail |
| T3 | 보안 요구사항 명시 | 인증/인가 방식이 구체적으로 기술됨 | Pass / Fail |
| T4 | PRD Must 기능 커버리지 | PRD의 Must 기능이 모두 TRD에 반영됨 | Pass / Fail |
| T5 | Open Questions 섹션 존재 | 섹션이 있고 "없음" 또는 구체적 항목이 기재됨 | Pass / Fail |

> **TRD 통과 기준**: T1~T5 전항 Pass. 1개라도 Fail이면 TRD Fail.

#### 판정 결과 처리

| 판정 | 처리 |
|------|------|
| PRD Pass + TRD Pass | 1-2 사용자 확정으로 진행 |
| PRD Fail | opwt "수정" 모드 재호출 — Fail 항목을 `이슈`로 전달 |
| TRD Fail | opwt "수정" 모드 재호출 — Fail 항목을 `이슈`로 전달 |
| PRD+TRD 모두 Fail | opwt "수정" 모드 재호출 — 두 문서의 Fail 항목을 통합 전달 |

#### Fail 시 opwt 재호출 형식

```
//opwt 수정
- 대상 문서: {PRD | TRD | PRD, TRD}
- 이슈:
  - [P{번호}] {항목명}: {Fail 사유}
  - [T{번호}] {항목명}: {Fail 사유}
- 참조 문서: docs/PROJECT.md, docs/ARCHITECTURE.md
```

opwt 재작성 완료 후 1-1b 검증을 재수행한다. (무한루프 방지: 최대 2회)
2회 Fail 시 미통과 항목을 사용자에게 보고하고 판단을 요청한다.
```

#### 2-3-C. PM 직접 수행용 검증 체크리스트 (요약 대조표)

**PRD 검증 체크리스트 (6항목)**

| # | 항목 | 빠른 확인 방법 |
|---|------|---------------|
| P1 | Non-goals 섹션 | 섹션 제목 검색 → 내용 비어있지 않은지 확인 |
| P2 | 타깃 유저 형식 | "As a" 텍스트 검색 → 최소 1개 존재 여부 |
| P3 | Must 분류 | "Must" / "Should" / "Nice-to-have" 키워드 존재 여부 |
| P4 | AC 형식 | "GIVEN" / "WHEN" / "THEN" 키워드 존재 여부 + Must 기능별 1개 이상 |
| P5 | 모호 표현 | "빠르게", "쉽게", "적절히", "충분히", "용이하게" 검색 |
| P6 | Open Questions | 섹션 제목 검색 → "없음" 또는 항목 기재 여부 |

**TRD 검증 체크리스트 (5항목)**

| # | 항목 | 빠른 확인 방법 |
|---|------|---------------|
| T1 | 버전 명시 | 각 기술 스택 항목 옆 버전 숫자 존재 여부 |
| T2 | 성능 수치 | "초", "ms", "TPS", "RPS", "%" 또는 "[미결:" 존재 여부 |
| T3 | 보안 방식 | "JWT", "OAuth", "세션", "RBAC", "인증" 등 구체적 방식 명시 여부 |
| T4 | PRD Must 커버리지 | PRD Must 기능 목록 vs TRD 구현 방식 항목 1:1 대조 |
| T5 | Open Questions | 섹션 제목 검색 → "없음" 또는 항목 기재 여부 |
