# TEST-SCENARIO: OPAL 범용 E2E 하네스 구현 (제안서 태스크 3~9)

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- **환경**: worktree `task_127`(브랜치 `feat/OP-TASK-127`, main 병합 완료). test-tool 단위 테스트 인터프리터는 `~/.opal/.venv/bin/python`. Console FE는 `dashboard/frontend`(vite), BE는 `dashboard/backend`(uvicorn). 사용자 소유 Console이 `127.0.0.1:7823`에서 상시 가동 중이다.
- **공통 데이터**: `surfaces.json` 40표면(cli 7 · driver-op 8 · executor-op 8 · http 17)을 커버리지 분모로 쓴다. 이 파일은 읽기 전용이다(C-8).
- **대역 사용과 한계**: 브라우저 실행 후보는 실측상 Orca 번들 `agent-browser 0.27.0` 하나뿐이고 standalone `agent-browser`·`cmux` 바이너리는 이 머신에 없다(ANALYSIS Q5). S-8·S-9는 실제 후보로 실행하며, 가용 후보가 0이면 **substitute로 대체해 pass로 올리지 않고 `blocked` 사유를 구조화 기록한다**(H-2). 단위 테스트의 `subprocess` 대역은 계약 형태 검증에만 쓰고 AC-4·AC-5의 실행 증거로 인정하지 않는다.
- **실행 조건**: 자동 실행. 단 S-11(사람 협업 재개)은 구조화 submission 입력이 필요하며 verifier가 최종 판정한다 — 사람의 완료 선언만으로는 pass가 되지 않는다. **모든 시나리오는 격리 `OPAL_HOME`과 임대 포트에서만 수행하고 사용자 `~/.opal`·7823 Console에 `start`/`stop`/`kill`을 실행하지 않는다(C-2).** 각 시나리오 전후로 7823 health 200을 확인한다.

### 표면 전수 conformance (S-29~S-60)

> **왜 필요한가**: `scenario-conformance`는 `surfaces.json` 40표면 각각에 대해 `surface_ref`가 일치하는 **통과 시나리오 1건 이상**을 요구하며 `surface_ref`는 단수 필드다. S-1~S-28은 검증 **행위** 단위라 8표면만 참조하므로 나머지 32표면이 `surface_unverified`로 남고 S-25의 `all_surfaces_green`이 도달 불가능해진다. `CONTRACT.md` §B.5가 40표면 전수를 커버리지 게이트 분모로 확정했고 `surfaces.json`은 읽기 전용이므로(C-8), 분모를 줄이는 대신 표면 단위 엔트리로 검증을 채운다.
>
> **형식 충족 방지**: 충실도 문턱을 표면 종류로 고정한다. 이 규칙은 S-29~S-60뿐 아니라 **표면을 참조하는 전 시나리오에 동일하게 적용한다** — S-7(`api-executor-capture`)이 `real-usage`, S-13(`console-stop`)이 `profile: api`인 이유다(게이트 3회차 권고 반영). — `driver-op`·`executor-op`는 `real-usage`(실 driver/executor 관통), `http`·`cli`는 `real-http`(실 SUT 호출). 대역·substitute 실행은 이 절의 어떤 표면도 green으로 만들지 못한다.
>
> **RED 대상에서 제외된 2건 (S-14·S-16)**: 두 시나리오는 `red-first.md` §1.5의 RED 대상에서 빠지고 구현 후 회귀 가드로 검증한다. S-14는 최초 문언이 비공개 헬퍼의 단위 왕복을 겨냥해 §2 검증 경계("내부 private 구현 대신 반환값·exit code·API 응답을 검증한다")를 위반했고, 공개 표면인 `console stop`으로는 현재 구현에서 두 기대가 자명하게 참이라 실패를 관측할 수 없었다 — 공개 관측 가능한 형태로 재정의했다. S-16은 AC-16이 선행 커밋으로 이미 충족되어 RED가 성립하지 않는다(`git status --porcelain` 매치 0건 실측). 두 건 모두 §2의 "자동 우회 금지"에 따라 워커가 BLOCKED로 반환했고 PM이 실측 재검증 후 재정의했다.
