## 4. 규정-도구 불일치 4건 — 구조적 발견

「규정·도구·자산 3층 일관」을 목표로 내건 태스크에서 **규정과 도구가 네 번 어긋났다.** 규정을 쓴 주체와 도구를 짠 주체가 **같은 태스크 안에 있었는데도** 그랬다.

|---|---|---|---|
| 1 | **도구가 못 봄** | 원칙은 「어느 필드에도」인데 적용 범위가 5필드 → `changelog`가 양쪽을 빠져나감 | Step 1b(범위를 블록 전체로) + 6c(감지 축 추가) |

## 7. 하네스·프레임워크 발견 (회고 입력)

1. **「태스크 시점 사실」을 영구 회귀 단언으로 고정하면 후속 태스크가 구조적으로 걸린다** — 3연속 발생: `VERSION` 상수 핀 / 테스트 파일 **개수** 핀(`=== 11`) / 파일 **diff** 핀(TS-045 `git diff --numstat`가 빈 문자열). 전부 한 태스크의 관측을 영구 계약으로 굳힌 것
2. **`--wt` 축은 `tasks/` 픽스처 의존 테스트를 구조적으로 통과 불가로 만든다** — 워크트리 계약(§2.5 (3))상 `tasks/`는 허브 고정. state-tool 3건 + console BE 31건 = **34건**이 워크트리에서만 실패한다. R-5 AC의 절대 수치는 허브 기준이라 워크트리에 그대로 적용하면 영구 미달
3. **서브에이전트 `Write` 차단** — 이 세션에서 워커가 산출물 파일을 직접 쓰지 못해 전 워커에 heredoc 우회를 주입해야 했다. 첫 ANALYSIS 워커는 이 때문에 blocked로 반환
4. **선작성 트랙에 「Block A 원문 보존」 규약이 없다** — G-7이 지적한 감사 불가능성. `test-scenario-guide.md`에 보존 의무를 추가할 후보
5. **PLAN 체크박스 설계 결함** — Step 16~22가 7개 하위 Step을 **하나의 체크박스**로 묶어 진행 추적 불가. 워커 3명이 연달아 「단독 완료로 체크하면 타 담당자 미완을 오표기」라며 손대지 않았다
6. **테스트 실행 위치가 결과를 바꾼다** — console BE를 `cd dashboard/backend`에서 돌리면 `ModuleNotFoundError`로 134 errors, 저장소 루트에서 돌리면 정상. 워커 3명이 서로 다른 기준선을 보고했다. 실행 위치를 스위트별로 문서화할 필요
7. **감지기의 구조적 한계** — 태스크번호 패턴은 **표기**를 본다. 태그를 지우면 이력이 남아도 통과한다(Step 7 실측). 안전망은 L3 [SUPERVISOR] 하나뿐
