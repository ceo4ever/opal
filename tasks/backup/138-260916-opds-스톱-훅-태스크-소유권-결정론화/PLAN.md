# PLAN: `--wt` 전용 세션·Stop 훅 태스크 소유권 결정론화

> 입력: [TASK.md](TASK.md) (ANALYSIS 없음 — `opds` Short profile)

## Approach

Stop 판정을 "가장 최근 `updated_at` 태스크 추측"에서 "registry canonical + 세션 lease 대조"로 바꾸고, 그 판정을 inline `python -c`가 아니라 테스트 가능한 모듈이 소유하게 한다. 새 실행 축(전용 worktree 세션)은 기존 `worktree-tool` registry 위에 `execution_ownership` 한 축을 얹어 표현하며, 별도 lifecycle 파일을 만들지 않는다.

범위를 13개 실행 그룹으로 나누고, **P1~P4만 완료돼도 현재 관측된 Task 132 오탐이 종결**되도록 앞단을 배치한다. 허브 루트 cwd의 이 세션에서 Stop hook이 허브 `tasks/132-260914-opd-oppb-프로젝트빌드-파일럿-신설/state.json`(`in_progress`·`updated_at 2026-09-15 10:39`·`transition_action=continue`)을 15회 연속 지목한 사실이 P1~P4의 완료 기준이자 첫 회귀 fixture다 — registry `.opal-worktrees/.meta/task_132.json`의 canonical `task_path`는 워크트리이고 `attribution_state` 키가 부재(=active)이므로 허브 사본은 `worktree_owned_shadow`다.

기존 코드에 없는 것만 새로 만든다. `state-tool`에는 `activate`/`heartbeat`/`resume` 서브명령을 신설하지 않고(현재 grep 0건, Non-goals의 `state-tool resume`은 후속 태스크), 자동 claim을 기존 `init`/`advance`/`mark` 경로 안쪽 경계에 넣는다. `run-log` CONTRACT.md:58에 이미 정의돼 있으나 전 이벤트가 `null`로 기록되는 `actor.session_id`(`state_tool.py:1036`·`:1452`·`:1530`·`:2674`)를 새 필드 추가 없이 채운다.

  - launch/prompt 실패로 registry가 중간 상태에 남는 경우: W-11의 원자 복귀가 `generation` 증가와 함께 `hub_owned` + `attribution_state` 키 부재로 되돌린다. 복귀 자체가 실패하면 `worktree-tool ownership-set --state hub_owned --generation <현재+1>`을 허브 `--project-root`와 함께 수동 호출한다.
  - lease·세션 registry 오염: 3개 경로 모두 추적 제외 런타임 파일이므로 디렉터리 삭제가 안전한 복구다. 삭제 후 전 태스크는 무소유로 분류되어 PM 판단 입력으로 올라올 뿐 파이프라인 상태(`state.json`)는 영향받지 않는다.
  - 체크포인트 커밋 오적용: W-16은 `amend`·`rebase`·`reset`을 수행하지 않으므로 보정 커밋을 추가하고 `checkpoint_shas[]`에 이어 기록한다. 이력 재작성이 필요하면 사용자 승인 경계로 올린다(C-20).
