# TASK: task-flow 워커 에이전트 실행 모델

> 작성일: 2026-03-14 | 작업 유형: 기능 개선

## 작업 목표

task-flow의 전체 파이프라인을 워커 서브 에이전트 기반으로 전환하여, 메인 에이전트(알투)는 오케스트레이터(감독/중계/보고)만 수행하고, 실제 분석·계획·실행은 워커 서브 에이전트가 담당하도록 한다. 이를 통해 알투의 컨텍스트 윈도우를 절약하고, 다중 태스크 동시 실행을 가능하게 한다.

## 배경

현재 task-flow는 알투(메인 에이전트)가 모든 단계를 직접 수행한다:
- TASK: 알투가 직접 작성
- RESEARCH: 알투가 코드를 읽고 분석
- PLAN: 알투가 설계
- TODO: 알투가 분해
- EXECUTE: 알투가 코드 작성/수정 (단순 모드) 또는 서브 에이전트 디스패치 (복잡 모드)

문제점:
1. **컨텍스트 윈도우 폭발**: 알투가 분석·계획·실행을 모두 수행하면, 코드를 대량으로 읽고 수정하며 컨텍스트가 급격히 커진다. 특히 RESEARCH에서 코드 분석, EXECUTE에서 코드 수정이 컨텍스트를 가장 많이 소모한다.
2. **동시 실행 불가**: 알투가 한 태스크를 직접 수행하는 동안 다른 태스크를 병렬 처리할 수 없다.
3. **역할 혼재**: 오케스트레이터(감독)와 워커(실행)의 역할이 분리되지 않아, 실행 중 판단이 필요한 상황에서 전체 맥락을 이미 잃은 상태가 된다.

해결 방향: 알투는 오케스트레이터로서 워커를 디스패치하고, 게이트 체크포인트에서 사용자와 중계하는 역할만 수행. 실제 코드 읽기/분석/작성은 워커 서브 에이전트의 격리된 컨텍스트에서 수행한다.

## 요구사항

### R1. 오케스트레이터-워커 아키텍처

- [ ] R1.1 알투(오케스트레이터)의 역할: 태스크 수신, 워커 디스패치, 게이트 체크포인트에서 사용자 중계, 상태 추적, 최종 보고
- [ ] R1.2 워커(서브 에이전트)의 역할: 코드 읽기/분석, 산출물 작성, 코드 구현/수정, 테스트 실행, 결과 반환
- [ ] R1.3 알투는 코드를 직접 읽거나 수정하지 않는다 — 워커의 결과를 수신하여 사용자에게 전달
- [ ] R1.4 알투는 여러 태스크의 워커를 동시에 디스패치할 수 있다 (다중 태스크 병렬 실행)

### R2. 단계별 워커 위임 범위

- [ ] R2.1 TASK 단계: 알투가 직접 수행 (사용자 지시 구조화는 오케스트레이터 역할)
- [ ] R2.2 RESEARCH 단계: 워커에게 위임 (코드 읽기/분석이 컨텍스트를 많이 소모)
- [ ] R2.3 PLAN 단계: 워커에게 위임 (RESEARCH 결과를 이어받아 설계)
- [ ] R2.4 TODO 단계: 워커에게 위임 (PLAN 결과를 이어받아 분해)
- [ ] R2.5 EXECUTE 단계: 워커에게 위임 (코드 작성/수정이 컨텍스트를 가장 많이 소모)
- [ ] R2.6 Short Task: PLAN(통합) + EXECUTE를 워커에게 위임

### R3. 워커 연속성 (컨텍스트 이어받기)

- [ ] R3.1 같은 태스크의 연속 단계는 동일 워커가 이어서 수행할 수 있어야 한다 (RESEARCH → PLAN 등)
- [ ] R3.2 워커 연속성이 불가능한 경우 (플랫폼 제약 등), 이전 단계 산출물(.md)을 다음 워커에 전달하여 컨텍스트 복원
- [ ] R3.3 게이트 체크포인트(사용자 검토)에서 워커는 결과를 반환하고 대기, 승인 후 이어서 진행 또는 새 워커 디스패치

### R4. 워커 프롬프트 설계

- [ ] R4.1 단계별 워커 프롬프트 템플릿 정의
- [ ] R4.2 프롬프트에 포함할 항목: 역할, 현재 단계, 태스크 컨텍스트(TASK.md 등), 참조 가이드(research-guide.md 등), 프로젝트 컨벤션(CLAUDE.md), 산출물 저장 경로
- [ ] R4.3 워커 결과 반환 형식 정의 (산출물 경로, 요약, 블로커 정보)

### R5. 다중 태스크 동시 실행

- [ ] R5.1 알투가 태스크 A의 사용자 검토 대기 중에 태스크 B를 시작할 수 있다
- [ ] R5.2 각 태스크의 워커는 독립된 컨텍스트에서 실행 (태스크 간 간섭 없음)
- [ ] R5.3 알투가 여러 태스크의 상태를 추적하고 사용자에게 통합 보고

### R6. 기존 호환성 유지

- [ ] R6.1 task-flow-qa: 기존 QA 호출 구조 유지 (워커가 QA 호출, 또는 오케스트레이터가 QA 호출)
- [ ] R6.2 task-flow-planner: Full Task 복잡 모드에서 Part C 생성 역할 유지
- [ ] R6.3 task-flow-test: Full Task 복잡 모드에서 TEST-REPORT.md 생성 역할 유지
- [ ] R6.4 체크리스트 갱신 규칙 유지 (Full: TODO.md, Short: PLAN.md)
- [ ] R6.5 게이트 체크포인트 보고 형식 유지
