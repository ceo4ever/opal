# TEST-SCENARIO: PM 보고·활동 이벤트·정지 판정 관측 배선

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: macOS, 이 워크트리(`.opal-worktrees/task_147`) 단독. Python은 `~/.opal/.venv/bin/python`(훅이 실제로 쓰는 인터프리터)과 각 도구의 `run.sh` 래퍼를 쓴다. 저장소 상태는 `feat/OP-TASK-147` 브랜치.
- 공통 데이터: 검증용 태스크 캡슐은 `state-tool init --run-log-mode shadow`로 매 시나리오가 tmp 경로에 새로 만든다. 이 태스크 자신의 캡슐(`tasks/147-.../`)은 읽기 참조용이며 시나리오가 그 상태를 전이시키지 않는다. 비밀값 검사용 fixture 문자열 4종은 각 시나리오가 자기 tmp 캡슐 안에서만 생성한다.
- 대역 사용과 한계: S-1·S-2·S-13·S-14를 제외한 전 시나리오에서 대역을 쓰지 않는다. S-2가 만드는 Stop 봉투 fixture는 **실제 캡처본**이므로 대역이 아니다. 훅 판정 경로에 monkeypatch·mock을 쓰지 않으며, 훅 동작은 반드시 `stop_hook.py`를 subprocess로 실행해 관찰한다 — 인프로세스 `evaluate()` 직접 호출은 단위 계약 검증(S-8)에만 쓰고 AC-4·AC-6의 근거로 삼지 않는다.
- 실행 조건: S-2만 사용자 협업이 필요하다(실제 Stop을 발생시킬 새 세션 1회). 나머지는 자동 실행한다. S-2는 `.claude/settings.local.json`을 임시 변경하므로 **캡틴 승인 후에만** 착수하며, 백업·원복·바이트 동일성 대조를 같은 시나리오 안에서 판정한다.
