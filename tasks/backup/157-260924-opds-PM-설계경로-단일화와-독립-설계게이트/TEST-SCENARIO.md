# TEST-SCENARIO: PM 설계 경로 단일화와 독립 설계 게이트

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: macOS, 태스크 worktree `/Volumes/Data/AIStudio/workspace/ai-framework/.opal-worktrees/task_157`(브랜치 `feat/OP-TASK-157`), OPAL venv `~/.opal/.venv/bin/python`(pytest 포함), git CLI.
- 공통 데이터: 도구 테스트는 `tempfile`로 만든 임시 태스크 폴더에 sdlc-v2 TASK/PLAN/TEST-SCENARIO 픽스처를 쓰고 실제 `state-tool` CLI로 `init --rows-from`을 실행해 만든다. 저장소의 실제 `tasks/`·`.opal/`은 쓰지 않는다. run-log 검증 픽스처는 `init --run-log-mode shadow`로 만든다.
- 대역 사용과 한계: 사용하지 않는다. `design-gate start`의 coverage 검사는 실제 `test-tool` 프로세스를 호출한다. `design-gate record`에 넘기는 evaluator 결과 JSON은 픽스처 파일이며, 이는 기록 도구의 판정·거부를 검증할 뿐 evaluator 판단 품질의 증거가 아니다. evaluator 판단은 S-4에서 실제 `opal-evaluator-agent` 디스패치로 따로 확인한다.
- 실행 조건: 자동 실행. S-4는 PM이 설치본 `opal-evaluator-agent`를 `phase: design-rubric`으로 실제 디스패치하고 반환 JSON을 `run/test-evidence/`에 저장한 뒤 opal-test-agent가 판정한다. S-12는 `scripts/install-mac.sh` 실행 뒤 설치본 `~/.opal/`을 대상으로 한다.
- 증거 보관: 각 명령의 stdout/stderr와 exit code를 태스크 `run/test-evidence/`에 저장한다. 거부 시나리오는 호출 전후 `state.json` sha256도 함께 남긴다.
