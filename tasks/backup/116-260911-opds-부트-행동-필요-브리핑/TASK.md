# TASK: 부트스트랩 행동 필요 브리핑

## Problem
프로젝트 세션 부트에서 메모리를 읽고도 사용자에게 표시할 요약과 다음 행동이 제공되지 않는다. 현재 진행 중인 작업이나 검토가 필요한 기억을 놓쳐 세션 재개 비용이 발생한다.

## Proposed outcome
세션 첫 응답에 진행 재개가 필요한 작업과 우선 검토가 필요한 메모리만 조건부로 간결하게 표시된다. 표시할 항목이 없으면 기존의 짧은 부트스트랩 응답을 유지한다.

## Affected users and systems
프로젝트 인지 세션을 시작하는 사용자와 Codex·Claude·Cursor·Gemini 부트스트래퍼, `state-tool`, `memory-tool`에 영향을 준다. 일반 비서 세션과 작업 산출물의 저장 형식은 범위에서 제외한다.

## Constraints
- C-1: 진행 중인 작업의 판정은 `state.json`/`state-tool`, 메모리의 검토 우선순위 판정은 `MEMORY.json`/`memory-tool`의 각 SSOT를 따른다.
- C-2: 부트 컨텍스트의 전체 출력 크기와 기존 `memory-tool --boot-brief`의 1KB 상한을 유지한다.
- C-3: 완료 이력과 일반 참고 기억은 행동 필요 항목이 없을 때 자동 표시하지 않는다.
- C-4: 기존 세션 이벤트, `show` 응답 키, 비-worktree 동작과 플랫폼별 설치 parity를 보존한다.
- C-5: 파이프라인 상태는 `state-tool`로만 갱신하고, 코드·설정 변경은 워크트리에서 수행한다.

## Acceptance criteria
- AC-1: 진행 중 또는 차단된 최신 작업이 있을 때 세션 첫 응답에 작업 제목·현재 단계·다음 행동이 최대 1건 표시된다.
- AC-2: 검토가 필요한 메모리가 있을 때 후보·이슈·개선·피드백 우선순위에 따라 최대 2건이 표시된다.
- AC-3: 진행 작업과 검토 메모리가 모두 없으면 추가 브리핑 없이 기존 부트스트랩 응답이 출력된다.
- AC-4: 부트스트랩 브리핑의 직렬화 출력이 1024 bytes 이하이고 본문·긴 작업 결과를 포함하지 않는다.
- AC-5: Codex·Claude·Cursor·Gemini 설치 산출물에서 동일한 브리핑 계약이 확인된다.
- AC-6: 기존 memory-tool·state-tool·부트스트랩 회귀 테스트가 통과하고, 새 미완료 작업 및 우선 메모리 사례가 독립 테스트로 검증된다.
