## Critical assumptions

| 가정 | 확인 방법·결과 | 남은 한계 |
|---|---|---|
| LLM이 "Read 도구" 전문 로드를 실제로 수행했는지 도구가 외부에서 완전히 감지할 수 있다 | 현재 저장소에는 Read 호출 자체를 기록하는 범용 hook/receipt가 보이지 않는다. `state-tool`은 state 전이를, `opal-agent`는 프롬프트 marker를 제어하지만 Read 관측은 별도 구조가 없다. | "전문 로드" 강제는 loader CLI가 파일 전문+hash+receipt를 출력하고, 산출물/프롬프트가 receipt를 소비하는 방식으로 구현 가능하다. LLM 내부 컨텍스트 적재 여부 자체는 플랫폼 API 한계가 있어 receipt 기반 계약으로 정의해야 한다. |

## Handoff

- PLAN에서 결정할 것: event manifest 스키마, `event-loader` CLI 공개 계약, `opal-harness.md`를 어떤 owner 문서들로 분해할지, pilot/worker가 receipt를 어디서 요구할지, cold-start 측정 명령과 설치 parity 검증 명령.
- 착수 차단: 없음. 단, "Read 호출 자체"의 플랫폼 내부 관측은 불가능하므로 AC-5는 loader receipt 계약으로 구현 범위를 명확히 해야 한다.
