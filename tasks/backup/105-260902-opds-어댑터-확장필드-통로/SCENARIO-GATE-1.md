## 3. 미검증 이월(S-14)의 정직성 판정

**정당한 환경 제약 처리로 인정한다** — 부당한 회피가 아니다. 근거 4가지:

1. **제약이 실측 근거로 기재**됨 — "본 환경에 `pwsh` 미설치(실측)로 M2 자동화 불가". 추정이 아니라 확인된 사실을 사유로 든다.
2. **대체 검증이 실제로 설계**됨 — 런타임을 못 돌리는 대신 정적층으로 내려 S-5(두 스크립트 센티넬 구간 스펙 JSON 블록 **바이트 diff 공집합**)와 S-6(PS 7 전용 구문 스캔 0건 + `Get-AgentFrontmatter` 기존 4키 유지 하위호환)을 세웠다. 미러 규약(`windows.ps1:93`)의 핵심인 "두 언어 스펙 표현이 갈리지 않음"은 기계 검증된다.
3. **이월 사실의 공표 의무가 문서에 박힘** — "본 태스크는 이 항목을 미검증 상태로 이월합니다 — 완료 보고에 미검증 사실을 명시합니다", §4 매핑 표 비고 `**이월** (pwsh 미설치)`, H-4·H-5 검증 계층 `L1 + L3(이월)`. 3곳에서 중복 표기되어 은닉 여지가 없다.
4. **책임 이양 경로가 실행 가능**하게 남음 — [SUPERVISOR] PM 표준 요청 양식이 4단계 절차로 구체화되어 있어, 소유자가 Windows 머신을 확보하면 즉시 집행 가능하다.

**잔존 리스크(차단 사유 아님)**: R-4 AC 중 "Windows 런타임 정합"만은 여전히 미검증이며, 정적 미러 일치가 런타임 동치를 보장하지는 않는다(H-5의 `ConvertFrom-Json` → `PSCustomObject` 인덱싱 실패는 정적 스캔으로 완전히 배제되지 않는다). 완료 보고 시 이 한 줄을 명시할 것을 권고한다.
