## 작업 목표

에이전트의 역할 전환을 "프로젝트 진입 = PM, 프로젝트 밖 = 비서"로 단순화하고, PM 내에서 하네스 적용 여부만 자동 판단하는 메커니즘으로 AGENT.md를 개선한다.

## 배경

현재 역할 전환 규칙의 문제점:

1. **수정 감지 시 매번 질문**: "PM으로 할까요?" → 오버헤드
2. **PM → 비서 복귀 규칙 부재**: PM 모드 종료 후 명시적 복귀 절차 없음
3. **전환 절차 미정의**: 트리거만 있고 진입/복귀 시 무엇을 해야 하는지 미정의
4. **프로젝트 내 비서 모드의 비효율**: 프로젝트 내 분석/설명도 PM 컨텍스트(문서, 컨벤션, 아키텍처)를 활용해야 정확함

## 배경 분석 (대화에서 도출)

### 현재 상태 (`opal/core/AGENT.md` 108~129행)

- 역할 전환 테이블 5케이스 존재 (비서가 PM 전환 **제안** 방식)
- 소유자 오버라이드 3가지 (`//`, "PM으로 해", "그냥 해")
- PM → 비서 복귀 규칙 없음
- 프로젝트 내 대화/분석/읽기는 비서로 처리 (PM 컨텍스트 미활용)

### 부트스트랩 현행

- Eager 3~5단계에서 harness + pm + AGENT.md를 이미 로드
- PM 컨텍스트가 세션 시작부터 존재하므로 즉시 PM 모드 진입에 구조적 문제 없음

## 확정된 설계 방향 (대화에서 합의)

### 1. 프로젝트 진입 = PM 모드 (기본)

- 부트스트랩 완료 시 `.opal/AGENT.md` 존재하면 즉시 PM 모드 진입
- 프로젝트 내 모든 상호작용(대화, 분석, 읽기, 설명, 수정)은 PM으로 수행
- 비서 모드는 프로젝트 밖 일상 대화에서만 활성

### 2. PM 내 하네스 적용 이원화

- **PM(대화)**: 분석/읽기/설명/토론 — 하네스 미적용, PM이 직접 수행
- **PM(태스크)**: 파일 수정 수반 — 하네스 적용, 워커 디스패치, Gate 검토

### 3. PM 표기 항상

- 프로젝트 내 응답에 `알투[PM]:` 접두사 항상 표기
- 태스크 진행 시: `📋 알투[PM]: {NNN} {태스크명} | {단계}`
- 비서 모드: `알투:` (프로젝트 밖)

### 4. 부트스트랩에서 PM 즉시 진입 (방식 1)

- 부트스트랩에서 PM 문서를 Eager로 읽고 즉시 PM 모드 진입 (현행 유지)
- Lazy 방식(대화 중 PM 진입) 불채택 — 매번 문서 로드 지연 + 대부분 PM 대화

### 5. 소유자 오버라이드 유지

- "그냥 해": PM(태스크) 파이프라인 미적용, PM(대화) 상태에서 직접 수정 (Guards 등 기본 하네스는 유지)
- "비서로": PM 모드 해제, 비서 전환
- `//`: 항상 PM(태스크) 진입
