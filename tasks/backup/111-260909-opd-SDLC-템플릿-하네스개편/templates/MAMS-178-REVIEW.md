## 1. TASK.md 대입

### Problem

구글 성과는 PMAX만 대상으로 합의했지만, 성과 화면의 캠페인유형에 SEARCH가 나타났다. 수집 대상 제외가 실제 수집·적재에 적용되지 않았고, 매핑에 실패한 원본 유형명이 코드값으로 저장됐다. 근거: 원본 DONE §1 「발단」.

### Proposed outcome

운영자가 구글 PMAX 성과만 조회하고, 비PMAX 성과가 재수집으로 다시 섞이지 않는다. 캠페인 정보는 유형과 관계없이 보존하여 향후 대상 확대의 근거로 사용한다.

### Affected users and systems

- 사용자: 매체 성과를 조회하는 운영자, 수집 배치 담당자.
- 시스템: 구글 캠페인 정보·성과 수집, 원시·집계 데이터, 성과 화면.
- 포함: 비PMAX 성과 수집 제외·기존 데이터 정리, 매핑 실패 시 원문 보존, 대상 확대 정책 기록.
- 제외: 타 매체 변경, 캠페인 정보 전량 수집 중단, 코드사전 사용 여부 변경, 화면 조회 API에 별도 제외 필터 추가.

### Constraints

- C-1: 기존 PMAX 성과와 타 매체 데이터·수집 동작을 보존한다.
- C-2: 캠페인유형을 정리하기 전에 원본 유형을 보존한다.
- C-3: 애플리케이션 SQL 호출은 Repository 계층을 따른다. 데이터 변경은 승인된 환경에서 수행한다.
- C-4: 대상 확대는 화면 기획 확정 → 코드사전 사용 설정 → 수집 개시 순서다.

### Acceptance criteria

- AC-1: 구글 성과 수집을 다시 실행해도 PMAX 외 성과가 새로 적재되지 않는다.
- AC-2: 기존 비PMAX 성과가 원시·관련 집계 테이블에서 제거되고, 동일 환경·동일 기준 시점의 PMAX 행과 금액은 정리 전후 동일하다.
- AC-3: 매핑 실패 유형은 미분류로 저장되고 원본값은 보존된다. 기존 잘못된 유형값도 정리되며, 재수집 후 같은 정책을 유지한다.
- AC-4: 기존 문제를 재현하는 조회 기간에서 성과 화면의 구글 유형 목록에 PMAX만 표시된다.
- AC-5: 프로젝트 확정 기준에 PMAX 대상 정책과 C-4 확대 순서가 기록된다.

### Open questions

최종 유효 기준 재구성이므로 신규 질문은 없다. 최초 착수 때에는 정리 대상 테이블 범위·정리 방식·기존 값 갱신 계약을 ANALYSIS/PLAN에서 확인해야 했다. 이 설명은 사례 검토용이며 실제 TASK에는 해당 시점의 미결 질문만 남긴다.
