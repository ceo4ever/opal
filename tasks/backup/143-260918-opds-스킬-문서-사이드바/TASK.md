# TASK: OPAL Docs 스킬 문서 사이드바·README 렌더

## Problem
태스크 140이 만든 스킬 문서 상세 화면이 비어 있다. 파서가 `## Usage`·`## Arguments` 같은 영어 표준 heading을 전제하는데 실제 `SKILL.md` 55개는 `## 입력 분기`·`## STEP 1: TASK` 같은 다른 구조를 쓴다. 전수 측정 결과 `quick_start` 0/55, `usage_markdown` 0/55, `arguments` 0/55, `options` 0/55, `examples` 0/55이며 값이 있는 것은 `pipeline` 10/55와 `related_skills`뿐이다 (`dashboard/backend/parsers/skill_parser.py`, `feat/140-opdw-스킬-문서-화면` 브랜치). 목록 화면도 55개를 3열 카드로 평면 나열해 그룹 경계가 시각적으로 없고 스크롤로만 탐색한다.

## Proposed outcome
사용자가 좌측 사이드바에서 그룹별로 묶인 스킬 전체를 한눈에 보고, 항목을 클릭하면 우측에 그 스킬의 `README.md`가 그대로 렌더되어 개요·사용법·파이프라인·예시를 읽을 수 있다. 55개 스킬 전부가 첫 화면부터 내용이 채워진 상태로 보인다.

## Affected users and systems
OPAL을 도입하거나 적합한 `//` 스킬을 고르려는 사용자와 숙련 사용자가 영향을 받는다. 변경 범위는 OPAL Console 프론트엔드의 Docs 화면과 라우팅, 상세 응답에 README 본문을 싣는 읽기 전용 백엔드 표면이다. 기존 7개 화면(대시보드·프로젝트·태스크·메모리·환경·프로젝트 브레인·설정)과 그 API의 동작 변경은 범위에서 제외한다. 스킬 `README.md` 54건은 커밋 `4724340`으로 이미 main에 반영되어 이 태스크의 작성 범위가 아니다.

## Constraints
- C-1: 기존 Console의 React·TypeScript·Vite·Tailwind·shadcn/ui 구조와 전역 색상 토큰을 재사용하고 신규 런타임 의존성을 추가하지 않는다 (`docs/PROJECT.md` §주요 컴포넌트 (OPAL Console)).
- C-2: 스킬 메타데이터를 프론트엔드에 하드코딩하지 않고 레지스트리와 각 스킬 폴더의 파일에서 읽기 전용으로 파생한다.
- C-3: 본문은 파싱해 슬롯으로 쪼개지 않고 Markdown 원문 그대로 렌더한다. `README.md`가 없으면 `SKILL.md` 본문으로 폴백해 어떤 스킬도 빈 화면이 되지 않는다.
- C-4: 사용자가 직접 호출하지 않는 내부 단계 스킬(`op-*` 21건)과 `opal-pilot-dev-short`는 사이드바에 노출하지 않는다. 파일럿·오퍼레이터 문서에서 참조로만 연결한다.
- C-5: 기존 Console의 읽기 전용 원칙을 유지하고 이 화면에서 스킬 실행·파일 수정·설치를 수행하지 않는다.
- C-6: 기존 Markdown 렌더 안전 정책(raw HTML 플러그인 미사용)을 그대로 재사용한다.
- C-7: 소스 변경은 프로젝트 경로에서 수행하고 `~/.opal/` 배포본을 직접 편집하지 않는다 (`docs/CONVENTIONS.md` §배포 경계).
- C-8: 데스크톱과 모바일에서 탐색·열람이 가능하고 키보드 포커스와 접근 가능한 이름을 제공한다.

## Acceptance criteria
- AC-1: `/docs/skills` 진입 시 좌측 사이드바에 파일럿·오퍼레이터·독립 세 그룹으로 묶인 스킬 33개가 표시되고, 각 항목에 alias가 함께 보인다.
- AC-2: 사이드바 항목을 클릭하면 우측에 해당 스킬 문서가 렌더되고 URL이 `/docs/skills/{skill}`로 바뀌어 공유·새로고침이 가능하다. 현재 선택 항목은 사이드바에서 시각적으로 구분된다.
- AC-3: 우측 본문이 `README.md`를 Markdown으로 렌더한다. 제목·문단·목록·표·코드 블록·인용문이 원문 구조대로 표시된다.
- AC-4: `README.md`가 없는 스킬은 `SKILL.md` 본문으로 폴백해 렌더하고, 폴백 사실을 사용자에게 알린다. 두 파일이 모두 없을 때만 부재 상태를 표시한다.
- AC-5: 내부 단계 스킬 21건과 `opal-pilot-dev-short`가 사이드바에 나타나지 않는다. 다만 URL로 직접 접근하면 문서를 읽을 수 있다.
- AC-6: 검색 입력과 그룹·도메인 필터가 화면에서 제거된다.
- AC-7: 목록·상세 조회 실패, 존재하지 않는 스킬 id, 본문 부재에 대한 로딩·빈 상태·오류 상태가 제공된다.
- AC-8: 프론트엔드 빌드·린트·타입 검사와 관련 테스트, 백엔드 관련 테스트가 통과하고 기존 Console 7개 화면에 회귀가 없다.
- AC-9: 설치 스크립트 경유 배포 후 브라우저에서 사이드바 탐색과 문서 열람이 데스크톱·모바일 뷰포트 모두에서 동작한다.
