## 워커의 정직한 관측 보고 1건 (PM 승인)

**c2·c3는 독립 판별면이 아니다** — 워커가 명세와 다른 관측을 기대에 맞추지 않고 그대로 보고했다.

- 파일별 단독 실행으로 분리하면 교정 전에도 c2(문자 8432)·c3(문자 8295)는 둘 다 `pre_existing` · exit 0이다. 교정 전 문자 창문 8192에도 포함되지 않기 때문이다.
- 두 케이스가 RED에서 함께 실패한 것은 c1과 **하나의 `validate --changed` 실행을 공유**해 c1의 거짓 차단이 공유 exit code를 2로 만들기 때문이다.
- **판별면은 c1 단독**이고, c2·c3는 교정 전후 `sub` 분류가 불변인 **경계 대조군**(창문 밖 종료 / 절단 U+FFFD가 `}`로 오인되지 않음)이다.
- PM 판정: **정확한 보고이며 설계도 타당하다.** 각 케이스의 핵심 단언인 `sub` 분류는 이미 독립이고, 케이스별 CLI 분리 실행은 2회 → 4회로 늘어 메타 3건의 시간 예산만 키운다. 현행 유지.
