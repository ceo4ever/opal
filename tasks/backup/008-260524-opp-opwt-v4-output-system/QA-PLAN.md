## 3. 발견 사항

### 3.1 Critical (반드시 수정)

### 3.2 Normal (개선 권장)

**N-1: Step 1 완료 기준 — "HH:mm" 플레이스홀더 실행 중 갭**

Step 1 §작업 내용 3번 변경이력 행 형식에 `2026-05-24 HH:mm`이 명시되어 있음. 이는 EXECUTE 워커가 실제 작업 시각을 KST로 기록해야 한다는 의미인데, 워커 지침에 "작업 완료 시점의 KST 현재 시각으로 치환한다"는 명시적 안내가 없음. (→ `PLAN.md` §3 Step 1 작업 내용 3번)

완료 기준에는 `grep "v4.0"` 테스트가 있으나, `HH:mm`이 그대로 남아있어도 grep 통과가 가능한 구조임.

**권장 조치**: Step 1 작업 내용 3번에 "HH:mm은 EXECUTE 워커가 작업 완료 시점 KST 시각으로 치환한다" 한 줄 추가.

---

**N-2: Step 3 테스트 — grep 패턴 불정확**

Step 3 완료 기준 테스트:
```
grep -A 12 "PRD 유형의 경우" ... | grep -c "필수" ≥8
```
이 grep 패턴은 network-guide.md의 현 텍스트와 매핑되지 않을 가능성이 있음. "PRD 유형의 경우"라는 문자열이 §7-3 PRD 가이드 헤더로 실제 사용될지 불확실함. EXECUTE 워커가 헤더 문구를 다르게 작성하면 grep이 0을 반환해 테스트 실패로 오인될 수 있음. (→ `PLAN.md` §3 Step 3 테스트 항목 1번)

**권장 조치**: grep 패턴을 보다 안정적인 문자열로 교체. 예: `grep -c "필수\|선택" network-guide.md` 또는 명확히 삽입될 헤더 문구를 Step 3 작업 내용에 먼저 확정하고 테스트에 그 문자열 사용.

---

**N-3: R-6 AC — "기존 TASK 전용 확인 항목 4개 재구성 확인" 검증 방법 불명**

TASK.md R-6 AC 5번: "기존 '`TASK 전용 확인 항목`' 4개가 인터뷰 라운드로 재구성됨"
PLAN.md §4 R-6 체크리스트 마지막 항목에 동일 내용이 포함되어 있으나, EXECUTE QA에서 이를 어떻게 검증할지 구체적인 grep/검증 명령이 Step 1 테스트 섹션에 없음. (→ `PLAN.md` §3 Step 1 테스트)

**권장 조치**: Step 1 테스트에 `grep -c "TASK 전용 확인 항목\|모드 결정\|대상 문서 유형" SKILL.md` 결과 0을 추가하여 구 항목 제거 검증을 포함.

---

**N-4: §6 디스패치 권장 방식 — "Phase 1 완료 확인" 메커니즘 미명시**

§6의 디스패치 권장 방식에 "Phase 1 완료 확인 후 Phase 2: Step 3 워커 1개 디스패치"라고 명시되어 있으나, 오케스트레이터가 Phase 1 완료를 어떻게 확인하는지(예: state-tool 조회, Task 도구 결과 대기 등)가 명시되어 있지 않음. (→ `PLAN.md` §6 디스패치 권장 방식)

**권장 조치**: "Phase 1 Step 1·2·4 Task 완료 응답 수신 후 Phase 2 진입"과 같이 구체적인 완료 신호 기준 1줄 추가.

### 3.3 Minor (선택 사항)

**m-1: PLAN.md §1.1 D-5 참조 경로 — 슬래시 프리픽스 불일치**

**m-2: §1.2 관련 파일 표 — F-4와 F-5 번호 불일치**

§2.2 구현 순서 표에 "5 | F-4 MEMORY.md 갱신"이 나오는데, §2.1 수정 파일 목록에서 F-4는 `.opal/MEMORY.md`로 4번째 파일임. §2.2에서 "5번째 순서"로 표기되는 것은 문맥상 혼란 없으나, §2.3 아래 문장 "F-5(MEMORY 갱신)는 CLOSE 단계…"에서 `F-5`를 사용하는 것은 F-4를 가리키는 오타임. (→ `PLAN.md` §2.2 하단 "F-5(MEMORY 갱신)는 CLOSE 단계" — F-4가 맞음)

**m-3: §5 리스크 표 — R-N 번호와 요구사항 R-N 충돌 가능성**

리스크 표의 `#` 컬럼이 R-1~R-7을 사용하는데, TASK.md 요구사항도 R-1~R-8을 사용함. 동일 문서(PLAN.md)에서 리스크 R-1과 요구사항 R-1이 혼동될 여지 있음. (→ `PLAN.md` §5 리스크 표 `#` 컬럼)

**권장 조치**: 리스크 번호를 RISK-1~RISK-7으로 변경하여 충돌 회피.
