## 작업 목표

PM이 기획(신규 기능·개선) 대화 중 AS-IS를 분석할 때, 프레임워크 도구와 프로젝트 산출물을 **어떤 순서로 읽고·분류하고·대조해 보고하는지**를 PM 행동 프로세스로 명문화한다. 새 스킬·새 `//` 커맨드는 만들지 않는다.

## 배경

AS-IS 분석은 기획 단계에서 상시 발생하는 작업이나, 현재 프레임워크에는 이를 위한 **순서**가 없다. 개별 규칙(`code-scan` 우선 호출, brain 사전 조회, 코드=SSOT 판정, 인용 의무)은 각기 다른 문서에 흩어져 있고, PM은 매 세션 즉흥적으로 조합한다. 그 결과 탐색 누락·파생 문서 오판·이중 SSOT 생성이 반복 발생했다.

## 확정된 설계 방향 (대화에서 합의)

1. **신규 스킬·`//` 커맨드를 만들지 않는다.** PM(대화) 행동 프로세스로 정의한다.
2. **5단계 워크플로우** — 0 좌표 고정 / 1 기존 지식 확인 / 2 4축 수집 / 3 정합 판정 / 4 보고·환류.
3. **수집 4축** — 정책·화면·데이터·코드. 각 축은 위치 특정 후 구간 Read(통독 금지).
4. **읽기 전용 수집 워커 허용** — 2단계에 한해 PM(대화)에서 병렬 수집 워커를 허용한다. 판정·합성·보고는 PM이 직접 수행한다.
5. **규모 분기** — 단일 축 질의는 0→1→4로 축약, 다축 질의만 2·3단계를 전개한다.
6. **자산 부재 시에도 작동한다** — brain·code-scan·축 SSOT·기획 산출물이 없어도 중단 없이 축소 실행하고, 결측을 보고서에 명시한다.
7. **보고 레이아웃은 재정의하지 않는다** — 기존 query 모드의 판정 규칙을 참조하고, 축 매트릭스·갭 목록 2블록만 추가한다.
