| 가정 | 확인 방법·결과 | 남은 한계 |
|---|---|---|
| 내부 SDD skill이 `opal/skills` 1-depth validation에 걸리지 않는다. | validator가 `opal/skills`와 `skills`의 1-depth 항목만 순회하고, 각 entry 바로 아래 `SKILL.md`만 검사함을 확인했다 (`opal/tools/skill-registry/skill-registry.js:390`, `opal/tools/skill-registry/skill-registry.js:397`, `opal/tools/skill-registry/skill-registry.js:399`). | 실제 테스트로 새 내부 경로가 unregistered로 나오지 않는지 확인해야 한다. |

## Handoff

- PLAN에서 결정할 것: SDD는 `opal-pilot-sdd/internal-skills/{op-sdd-spec,op-sdd-plan,op-sdd-action-plan}`로 이동하고 `op-sdd-verify`는 삭제, S-1~S-6 SSOT는 `opal-pilot-sdd/references/verify-guide.md`로 확정하는 안을 기본안으로 둔다.
- PLAN에서 결정할 것: Dev는 `opal-pilot-dev` 단일 SKILL에 Full/Short profile 절을 두고, Short pipeline은 `opal-pilot-dev/references/pipeline-short.json`로 이동하며, registry의 `opds` logical entry는 canonical path를 가리키게 한다.
- PLAN에서 결정할 것: 승격 규칙 포인터는 제거될 `opal-pilot-dev-short/SKILL.md`가 아니라 canonical SKILL 내 "Short profile escalation" 절 또는 별도 `references/track-escalation.md`로 옮긴 뒤 `track-routing.md`를 갱신한다.
- 착수 차단: 없음. 단 EXECUTE 검증에는 `skill-registry validate`, state-tool spec/init 회귀, pipeline row count, 설치 dry-run 또는 임시 HOME 설치 확인이 포함되어야 한다.
