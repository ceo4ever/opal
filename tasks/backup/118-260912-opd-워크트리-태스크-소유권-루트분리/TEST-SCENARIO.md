# TEST-SCENARIO: 워크트리 태스크 소유권 — cone 착지 실측과 허브 루트 보정 제거

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: macOS / git 2.x(worktree·sparse-checkout cone 지원) / Python 3.14 / Node.js. 허브 `/Volumes/Data/AIStudio/workspace/ai-framework`, 코드 작업본 `.opal-worktrees/task_118`(브랜치 `feat/OP-TASK-118`, base `e8b6c4f`).
- 공통 데이터: disposable Git fixture는 `git clone --local <허브>` 후 `git worktree add` + `git sparse-checkout init --cone` + `set <repos> tasks .opal`로 만든다. 생성 위치는 `/private/tmp/` 하위를 기본으로 하되, Console BE 검증(S-2)만 `scan_roots` 기본값 제약 때문에 `$HOME/workspace/` 하위 전용 임시 디렉터리를 쓰고 측정 종료 즉시 삭제한다.
- 대역 사용과 한계: 사용하지 않음. 루트 판정·cone 착지·거부 게이트는 전부 실제 git 저장소와 실제 CLI 실행으로 검증한다. `.opal/MEMORY.json`·`.opal/brain`에 대한 쓰기 검증은 운영 파일이 아니라 fixture 사본에서만 수행한다.
- 실행 조건: 자동 실행. 단 S-2는 `$HOME/workspace` 하위 쓰기 권한이 필요하고, S-17의 install 검증은 `~/.opal/` 배포본을 갱신하므로 다른 세션이 동시 실행 중이 아닐 때 수행한다.
- 동시 세션 주의: 태스크 117 세션이 `event_loader.py`·`docs/PROJECT.md` 등을 미커밋 수정 중이다. 허브에서 `git status` 기반 판정을 하는 시나리오(S-11)는 이 태스크의 판정 대상 경로(`.opal/brain/**`, `.opal/MEMORY.json`)로 범위를 한정해 실행한다.
