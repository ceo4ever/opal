# 메모리 압축 스킬 (context-compactor)

## 입력 파라미터
- mode: memory | history | document
- level: brief | compact | dense
- source: 파일 경로 또는 디렉토리

## 3단계 파이프라인
### Step 1: CLASSIFY
### Step 2: COMPRESS
### Step 3: VERIFY

## 모드별 동작

### history 모드
### document 모드

## 레벨별 압축 기준

### compact (~50%, 기본값)
### dense (~70%)

## 출력물 (COMPACTED.md) 포맷

## 에이전트 부트스트랩 연동

## 스킵 조건
```

#### 3단계 파이프라인 상세 동작

**Step 1: CLASSIFY (유형 분류)**
- 입력 콘텐츠를 다음 유형으로 분류:
  - `[decision]` — 기술적 결정 + 이유 (예: "JWT 선택, 이유: ~")
  - `[fact]` — 외부 사실 (API 제한, 환경 정보 등)
  - `[preference]` — 작업 선호도 (테스트 방식, 코딩 스타일 등)
  - `[issue]` — 미해결 문제 (open/resolved 상태 포함)
  - `[history]` — 완료된 작업 이력 (태스크 번호, 날짜)
  - `[ephemeral]` — 일시적 정보 (삭제 가능)
- **삭제 불가 마킹**: `[decision]` + `[issue:open]` + `[preference]`는 절대 삭제 금지
- **모순 탐지**: 동일 주제에 상반된 정보 → 양쪽 보존 + `[conflict]` 태그

**Step 2: COMPRESS (유형별 압축)**

| 유형 | brief (~20%) | compact (~50%) | dense (~70%) |
|------|-------------|----------------|-------------|
| `[decision]` | 1줄 + WHY 보존 | 원문 ~50% | 원문 ~70% |
| `[fact]` | 핵심값만 | 원문 ~50% | 원문 ~70% |
| `[preference]` | 1줄 요약 | 원문 ~50% | 원문 ~70% |
| `[issue:open]` | 1줄 + 상태 | 원문 ~50% | 원문 ~70% |
| `[issue:resolved]` | 1줄 결과만 | 1줄 결과만 | 원문 ~70% |
| `[history]` | 태스크명+날짜만 | 태스크명+결과 | 원문 ~70% |
| `[ephemeral]` | 삭제 | 삭제 | 삭제 |

- **WHY 보존 원칙**: 이유/배경이 있는 결정은 압축 후에도 WHY를 1줄 이상 유지
- **포인터 유지**: 원본 파일 참조 가능한 경우 `[→ memory/파일명.md#섹션]` 형태로 남김
- **시간축 보존**: 순서가 중요한 이력은 날짜 마커 유지 (`YYYY-MM-DD` 또는 태스크 번호)

**Step 3: VERIFY (검증)**
- 압축 전후 유형별 항목 수 대조 (삭제 불가 유형 누락 여부 확인)
- 목표 압축률 달성 여부 확인 (±10% 허용)
- `[conflict]` 태그 항목 확인 (양쪽 보존되었는지)
- 에러 시: 검증 실패 항목을 열거하고 중단 (부분 출력 방지)

#### 모드별 입출력 상세

**memory 모드**
```
입력:  {프로젝트}/.opal/memory/*.md (전체 또는 지정)
       + {프로젝트}/.opal/MEMORY.md (인덱스)
출력:  {프로젝트}/.opal/memory/archive/COMPACTED.md
용도:  에이전트 부트스트랩 시 경량 컨텍스트 로드
```

**history 모드**
```
입력:  대화 히스토리 파일 또는 로그 (경로 직접 지정)
출력:  지정 경로 또는 stdout (--output 파라미터)
용도:  대화 이어가기 전 컨텍스트 주입
```

**document 모드**
```
입력:  임의 마크다운 문서 (경로 직접 지정)
출력:  {원본 파일명}.compacted.md (원본과 같은 디렉토리)
용도:  긴 참조 문서 경량화
```

#### 레벨별 압축 기준 상세

| 레벨 | 목표 압축률 | 적용 기준 | 권장 상황 |
|------|-----------|----------|----------|
| `brief` | ~20% (80% 삭제) | 핵심 결정/사실/미결 이슈만 보존 | 컨텍스트 윈도우 극히 부족 |
| `compact` | ~50% (기본값) | WHY 포함 핵심 내용 보존 | 일반 부트스트랩 |
| `dense` | ~70% (30% 삭제) | ephemeral + resolved issues만 삭제 | 최대한 보존 필요 |

#### 출력물(COMPACTED.md) 포맷

```markdown
---
type: compacted
source: ["memory/arch.md", "memory/preferences.md", ...]
mode: memory
level: compact
created: 2026-03-22
tokens: ~2400 (원본 ~8600)
---

# Project Context (compacted)

## Decisions
- **{결정 주제}: {선택값}** — {WHY 1줄} [→ memory/파일명.md]

## Preferences
- {선호도 1줄} [→ memory/파일명.md]

## Active Issues
- [open] {이슈 설명} [→ memory/파일명.md]

## Facts
- {사실 1줄} [→ memory/파일명.md]

## Recent History
- {태스크번호}: {작업명} 완료 ({날짜})

---
*Generated by context-compactor | level: compact | {날짜}*
```

**섹션 생략 규칙**: 해당 유형의 항목이 없으면 섹션 자체를 생략한다.

#### 에이전트 부트스트랩 연동 흐름

SKILL.md 내 "에이전트 부트스트랩 연동" 섹션에 아래 로직을 정의한다:

```
부트스트랩 시 메모리 로드 우선순위:
1. {프로젝트}/.opal/memory/archive/COMPACTED.md 존재 → 이것만 로드
2. COMPACTED.md 없음 → MEMORY.md + memory/*.md 직접 로드

COMPACTED.md 갱신 시점 (권장):
- memory/*.md 파일 누적이 5개 이상
- 총 토큰 추정치 5,000 이상
- 신규 태스크 시작 전 (선택)
```

이 흐름은 `~/.opal/AGENT.md`의 부트스트랩 섹션에 반영되어야 한다. 스킬에서 AGENT.md 수정 가이드를 제공한다.

#### 스킵 조건

아래 조건에 해당하면 압축을 건너뛴다:
- 입력 콘텐츠가 200단어 미만 또는 50줄 미만
- 법률/의료/금융 관련 중요 문서 (명시적 `--force` 플래그 없으면 스킵)
- 이미 `type: compacted` frontmatter가 있는 파일
