# TEST-SCENARIO: E2E 테스트 환경 설정 체계

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: worktree `/Volumes/Data/AIStudio/workspace/ai-framework/.opal-worktrees/task_159`, macOS. test-tool은 소스 경로를 `~/.opal/.venv/bin/python opal/tools/test-tool/test_tool.py`로 실행한다. `dashboard/frontend`는 `npm ci`까지 끝난 상태다.
- 기준선 증거: `evidence/baseline-login-to-dashboard.json`·`.exit`에 변경 전 `login-to-dashboard` 판정이 기록돼 있다. `blocked`/exit 19, run.json 상세 `fragment_value_ref_missing`, 선택 driver agent-browser orca-managed, `urls` 키 `backend`·`frontend`다. 회귀 스위트는 변경 전 41 failed·3 errors다. 원인은 태스크 127 fixture 경로 부재로 확정됐다(PLAN §Approach).
- 공통 데이터: 저장소 밖 임시 프로젝트는 OS 임시 폴더에 만든다. 표준 라이브러리 HTTP 서버 스크립트 1개(`GET /health` → `{"status":"ok"}`, `GET /items` → JSON 배열)와 `test-scenario.json`(api profile 1건, schema_version 2.0)을 둔다. 검토 탐지용 `package.json`(vite 의존성·`dev` 스크립트)과 `.env.example`(`E2E_TOKEN=` 이름만)은 S-2에서만 추가한다.
- RED 테스트 위치: 구현 전 RED 행은 `opal-test-agent`가 `opal/tools/test-tool/tests/test_red_s159_env.py`에 공개 인터페이스(CLI stdout JSON·exit, 파일 트리, 프로세스 잔존) 기준으로 작성한다. 구현 워커는 이 파일의 기대 계약을 약화하지 않는다.
- 대역 사용과 한계: 데스크톱 앱 실행기는 범위 밖이다. 그래서 데스크톱 표면은 "실행기 없음" 판정까지만 검증하고 실행 성공은 검증하지 않는다. 그 밖의 서비스 기동·health·driver 확인은 실제 프로세스와 실제 HTTP로 수행한다.
- 실행 조건: 전부 자동 실행한다. 사람 협업은 필요 없다. 설치본(`~/.opal`) 재배포는 수행하지 않는다(PLAN D-14).
