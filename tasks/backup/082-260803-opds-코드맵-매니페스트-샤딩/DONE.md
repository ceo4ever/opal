## 1. 무엇을 했나

`code-scan`은 "소스 디렉토리 1개 = 매니페스트 1개"를 고정 규칙으로 삼아 매니페스트가 무한정 비대해졌다. 실사용 프로젝트에서 단일 매니페스트가 86.4KB / 292 엔트리까지 커졌고, 이를 열람한 워커가 모델 턴 1회에 600초 워치독을 초과해 강제 종료되는 사고가 났다.

이번 태스크는 **한 디렉토리의 매니페스트를 예약 폴더 `_shards/` 아래 의미 단위 샤드로 분산**할 수 있게 하고, **매니페스트 파일당 바이트 상한을 도구가 비차단으로 감지·열거**하게 했다.

## 3. 설계 핵심 — 봉인 1곳 + 옵트인

```
베이스 매니페스트 (진입점, 무변경) : .opal/code-map/{scope}/{mirrorRel}.json
샤드                               : .opal/code-map/{scope}/{mirrorRel}/_shards/{label}.json
```

- **진입 경로 무변경** — `mirrorPathForDir()` 산출 경로가 곧 베이스 매니페스트다. 새 경로 계산 규칙을 추가하지 않고, 샤드 경로는 그 절대 경로에서 순수 문자열로 파생한다.
- **`resolveShards` 1곳 봉인** — 샤드 로딩·`byKey` 합집합·중복 판정이 이 함수 밖에 존재하지 않는다. 태스크 080이 `resolveHeaderSource`·`isInScope`를 각 1곳에 봉인한 선례를 따랐다. 소비처 4곳은 전부 이 헬퍼를 호출한다.
- **`null` 반환 4조건 = 옵트인의 구조적 보증** — 그중 하나가 `ctx.headerSource !== 'manifest'`(inline 무영향 게이트)다. 샤드 미선언 자산에서는 헬퍼가 `null`을 돌려 **오늘과 동일한 코드 경로**를 탄다. 이것이 골든 바이트 동일성의 근거다.
- **스키마 추가는 키 1개** — 베이스에 `shards`(라벨 문자열 배열)뿐. 샤드 파일은 베이스와 동일한 형태를 재사용해 신규 스키마 0개.
- **`CODE_MAP_VERSION`은 1 고정** — 상향하면 기존 전 자산이 `unsupported_version`으로 즉시 차단된다.

## 7. 사고 1건 — `git stash`로 미커밋 구현 424줄 유실

EXECUTE 중 워커가 검증 목적으로 `git stash` → `stash drop`을 실행해 **동시 작업 중이던 다른 워커의 미커밋 구현 424줄이 워킹트리에서 소실**됐다(48/55 → 13/55). 워커가 자진 신고한 dangling commit 해시를 PM이 `rescue/082-code-scan` 태그로 고정한 뒤, 구현본 복원 + Step 11 메타 패치 재적용으로 완전 복구했다.

**판정: 하네스 구멍이 지배 원인.** 하네스·헌법·컨벤션 전수에서 파괴적 git 명령 금지 규칙이 **0건**이었다. 존재하는 것은 커밋 규칙("새 이력을 만들지 마라")뿐이며, "기존 미커밋 작업을 파괴하지 마라"는 정반대 방향이 무방비였다. 게다가 커밋 금지 + 병렬 디스패치 + Bash 무제한이 겹쳐 **한 워커의 실수가 전원 작업을 파괴하는 구조**를 하네스가 스스로 만든다. Scope 제한 계약은 파일 단위인데 git은 저장소 단위라 워커가 자기 폭발반경을 알 수단도 없었다.

→ FW 개선으로 등재 완료 (§8).
