# TEST-SCENARIO: PM 직접 수행 모델 — actor 축 신설과 L2 대체

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: macOS · 워크트리 `/Volumes/Data/AIStudio/workspace/ai-framework/.opal-worktrees/task_122`(branch `feat/OP-TASK-122`) · Python 3(state-tool·self-pm-tool 테스트) · Node.js(skill-registry) · 배포 루트 `~/.opal`
- 공통 데이터: 임시 태스크 폴더는 `$TMPDIR` 하위에 만들고 워크트리 `tasks/`를 오염시키지 않는다. `state-tool init` 회귀 비교의 기준 스냅샷은 **변경 전 소스**로 생성한 `state.json`이다(W-2 적용 전에 미리 떠 둔다).
- 대역 사용과 한계: **S-9·S-10·S-11에 한해 대역을 쓴다** — `opal-self-pm`의 대화 루프는 사람 발화가 입력이므로 PM이 사용자 역할을 대행하는 대화 리허설로 검증한다. 이는 실제 사용자와의 세션 증거를 대신하지 못하며, 검증 범위는 "스킬 문서가 규정한 절차를 따를 때 규정된 산출·거부가 실제로 발생하는가"까지다. 나머지 시나리오는 대역 없이 실제 명령·실제 파일로 검증한다.
- RED 대상 판정: `시점 = 구현 전 RED`인 행만 `test-tool scenario-init`의 `red_required: true`로 변환한다. **S-1은 RED 대상이 아니다** — W-2 적용 전에도 통과하고 적용 후에도 통과해야 하는 무변경 회귀 잠금이므로, 실패를 관찰할 수 있는 시점이 존재하지 않는다(`harness/red-first.md` §1 「나머지는 실제 검증 시점을 TEST-SCENARIO에 적는다」).
- 실행 조건: S-1~S-8·S-12~S-22는 자동 실행. S-9~S-11은 PM이 대화 리허설을 수행하고 `self-pm-tool` 기록 파일을 증거로 남긴다. S-16(install)은 배포본 `~/.opal`을 실제로 덮어쓰므로 다른 시나리오보다 뒤에 실행한다.
