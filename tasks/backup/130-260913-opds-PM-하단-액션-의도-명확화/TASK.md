# TASK: PM 하단 액션 의도 명확화

## Problem

PM 결과 보고의 하단에서 같은 `다음` 표지가 어떤 때는 PM이 이어서 할 일을, 어떤 때는 사용자가 승인하거나 결정해야 할 일을 뜻한다. 사용자는 보고를 읽고도 답해야 하는지 기다리면 되는지, 무엇을 판단해야 하는지 알기 어렵고, 의사결정 요청에는 판단 대상·선택 영향·PM 권고가 빠지는 경우가 반복된다.

## Proposed outcome

모든 PM 결과 보고가 하단에서 행동 주체와 사용자 입력 필요 여부를 즉시 드러낸다. 사용자 결정이 필요한 보고는 결정할 한 가지, 선택지 또는 답변 범위, PM 권고와 이유, 선택에 따른 다음 작업, 답해야 할 정확한 질문을 함께 제시한다.

## Affected users and systems

- 영향 사용자: OPAL을 통해 PM 결과 보고를 받는 소유자와 해당 보고를 생성하는 PM
- 포함: 일반 PM 보고의 공통 하단 액션 계약, PLAN·EXECUTE·CLOSE 사용자 게이트 보고 예시, 관련 검증 시나리오
- 제외: 세션 부트 브리핑, 보고 본문 전체 형식의 재설계, 파이프라인 단계·승인 상태 전이, 비서 tier 보고 형식, 전역 설치·배포

## Constraints

- C-1: 하단 액션의 의미와 행동 주체를 소유하는 규범은 한 곳만 두고 게이트 문서는 이를 참조해야 한다.
- C-2: 사용자 입력이 필요 없는 PM 행동과 사용자 입력이 필요한 결정 요청은 배타적인 두 형태로 유지해야 한다.
- C-3: `opal/core/AGENT.md`에 제거된 대규모 보고 형식을 다시 도입하지 않아야 한다.
- C-4: `opal/core/references/opal-pm.md`의 보고 형식 절은 기존 35줄 상한과 문장 추가 대신 기존 조 교체 원칙을 지켜야 한다.
- C-5: 게이트 본문의 단계별 정보 계약과 실제 승인·상태 전이 규칙은 변경하지 않아야 한다.
- C-6: 프로젝트 소스만 수정하고 `~/.opal/` 배포본은 별도 승인 없이 변경하지 않아야 한다.

## Acceptance criteria

- AC-1: 공통 하단 액션 계약만 읽어도 두 형태 각각의 행동 주체와 사용자 입력 필요 여부를 구분할 수 있다.
- AC-2: 사용자 결정 요청 계약이 결정할 한 가지, 선택지 또는 답변 범위, PM 권고, 권고 이유와 주요 영향, 답변 후 다음 작업, 한 개의 명시적 질문을 요구한다.
- AC-3: PLAN·EXECUTE·CLOSE 게이트 예시가 사용자 입력 필요 사실과 결정 대상을 직접 표시하며, 승인 요청을 `다음 진행 사항`으로만 표현하는 예시가 0건이다.
- AC-4: 일반 PM 보고와 게이트 보고가 동일한 하단 액션 의미를 사용하고, 게이트 문서가 별도의 상충 정의를 만들지 않는다.
- AC-5: 사용자 입력이 불필요한 사례와 필요한 사례를 포함한 독립 보고 재현 검증에서 사용자가 해야 할 행동이 전건 단일하게 판별된다.
- AC-6: `opal/core/AGENT.md`에 보고 형식 본문이 다시 생기지 않고 기존 게이트 단계·승인 상태 계약 관련 회귀 검증이 통과한다.
