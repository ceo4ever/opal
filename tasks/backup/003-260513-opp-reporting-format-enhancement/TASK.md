# TASK: 보고 형식 양식 보강 — 결론/근거 번호화 + 이모티 prefix + 다음 블록 2갈래

> 작성일: 2026-05-13 | 작업 유형: 개선 | 적용 스킬: opp | 모드: semi-agentic
> 입력: 캡틴 보고 양식 보강 지침 (세션 대화)
> 출력: `opal/core/references/harness/reporting-template.md` 갱신 + 변경이력 추가

## 작업 목표

보고 형식 SSOT(`reporting-template.md`)에 캡틴이 제안한 양식 보강 규칙 3가지(번호화·이모티 prefix·다음 블록 2갈래)를 정식 등재하여, 모든 응답에서 일관된 시각 구분과 가독성을 보장한다.

## 배경

현행 SSOT는 3블록 구조(결론·근거·다음)와 ASCII 박스 금지(§3), 결론 카드 양식(§2)만 정의되어 있다. 캡틴이 실제 운용 중 다음 미정의 영역에서 알투 응답의 일관성 부족과 가독성 저하를 지적했다:

1. 결론·근거 블록의 항목 번호화(1, 2, 3...) — 한눈에 항목 수 파악
2. 블록 헤딩 이모티 prefix — 시각 구분 강화
3. 다음 블록 2갈래 — 의사결정 필요 시 / 단순 진행 시 양식 분리

## 배경 분석 (대화에서 도출)

### 직전 보고 SSOT 위반 4건 (캡틴 지적)

| # | 위반 항목 | 근거 (SSOT 조항) |
|---|----------|-----------------|
| 1 | ASCII 박스(`┌──┬──┐`) 4개 사용 | §3 일목요연 원칙: "ASCII 박스 사용 금지 (마크다운 헤딩 + `---` 구분선만)" |
| 2 | 결론 1~2줄 초과 (3줄+) | §3: "결론 길이 1~2줄" |
| 3 | 결론 카드 첫 줄 양식 부재 | §2: "결론 첫 줄 — 캡틴 결정이 필요합니다 — N개 옵션 중 알투 권고는 X번" |
| 4 | Q1/Q2 옵션이 본문 끝 독립 영역으로 분리 | §2: "옵션 제시 — 근거 블록 안의 표·리스트로 흡수 (별도 블록 만들지 않음)" |

### 현행 SSOT 미정의 영역 (캡틴 보강 지침)

- 결론·근거 블록 내 항목 번호 매기기 규칙 없음 — 응답마다 표/리스트/산문이 임의로 혼용
- 블록 헤딩이 굵은 텍스트(`**결론**`)만으로 정의 — 이모티 prefix 미정의
- 다음 블록이 단일 형식 — 의사결정 요청과 단순 진행 안내가 구분되지 않음

## 확정된 설계 방향 (대화에서 합의)

### D-1. 결론·근거 블록 번호화

- 결론·근거 블록 내 항목은 `1)`, `2)`, `3)` 번호 매기기로 표현 (한눈에 항목 수 파악)
- 결론 항목 수: 1~3개 권고 (현행 "결론 1~2줄"은 항목 수 기준으로 재정의)
- 근거 항목 수: 3개 이내 (현행 §3 유지)

### D-2. 블록 헤딩 이모티 prefix

| 블록 | 이모티 | 헤딩 형식 |
|------|--------|----------|
| 결론 | 🎯 | `🎯 결론` |
| 근거 | 🔍 | `🔍 근거` |
| 다음 (의사결정) | ❓ | `❓ 의사 결정해 주세요?` |
| 다음 (진행) | ▶️ | `▶️ 다음 진행 사항입니다.` |

- 굵은 텍스트(`**결론**`) → 이모티 + 텍스트(`🎯 결론`)로 대체

### D-3. 다음 블록 2갈래 분기

| 갈래 | 헤딩 | 양식 |
|------|------|------|
| 의사결정 필요 | `❓ 의사 결정해 주세요?` | `Q1) ... (a-권고 / b)` 형식. 각 옵션에 권고/이유 짧게 첨부 |
| 단순 진행 | `▶️ 다음 진행 사항입니다.` | 번호 + 들여쓰기 리스트 (`1) ... - 세부 항목`) |

- §2 결론 카드는 이 분기 양식에 흡수 (의사결정 필요 시 `❓` 블록 사용)

### D-4. 시각 구분 보강

- 항목/문장 사이 빈 줄로 분리 (말이 길어지는 경우)
- 블록 헤딩 이모지를 시각 단위로 활용

### D-5. 적용 범위

- PM(태스크), PM(대화), 비서 모드 모든 응답 (§6 적용 범위 그대로 유지)
- 비보고(자유 형식, §7) 예외도 그대로 유지
