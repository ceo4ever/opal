# OPAL AI 에이전트 시스템 — 리서치

> 작성일: 2026-03-09 | 작성자: R2 | 버전: v1.0

## 1. 플랫폼별 시스템 프롬프트 로드 메커니즘

### Claude Code

- **로드 파일**: `~/.claude/CLAUDE.md` (글로벌) + `{프로젝트}/CLAUDE.md` (로컬)
- **자동 탐색**: `~/.claude/skills/*/SKILL.md`, `~/.claude/agents/*/AGENT.md`
- **Read 도구**: 세션 중 임의 경로의 파일을 Read 도구로 읽을 수 있음
- **부트스트래퍼 동작**: CLAUDE.md에 "~/.opal/AGENT.md를 Read로 읽어라"고 지시하면, 첫 사용자 메시지 처리 시 AI가 Read를 호출하여 파일을 로드할 수 있음

### Cursor

- **로드 파일**: `~/.cursor/rules/*.mdc` (alwaysApply: true면 항상 활성)
- **자동 탐색**: `~/.cursor/agents/*.md` (에이전트 자동 탐색)
- **Read 도구**: 세션 중 임의 경로의 파일을 Read 도구로 읽을 수 있음
- **부트스트래퍼 동작**: `000-opal-agent.mdc`에 지시하면, 세션 시작 시 규칙이 자동 로드되고, AI가 AGENT.md를 Read로 읽음

### Antigravity

- **로드 파일**: `~/.gemini/GEMINI.md` (글로벌) + `{프로젝트}/GEMINI.md` (로컬)
- **자동 탐색**: `~/.gemini/antigravity/skills/*/SKILL.md`
- **Read 도구**: 세션 중 임의 경로의 파일을 Read할 수 있음
- **부트스트래퍼 동작**: GEMINI.md에 지시하면 동작

### 결론

**모든 플랫폼에서 부트스트래퍼 패턴이 동작한다.** AI가 `~/.opal/AGENT.md`를 Read로 읽는 것은 기본 기능이며, 부트스트래퍼가 이를 지시하면 세션 시작 시 로드된다.

## 2. 부트스트래퍼 설계 검증

### 현재 방식 (100줄+ 스니핏)

```
# === R2 START ===
너의 이름은 알투(R2)다...
(약 100줄의 정체성, 성격, 역할, 보고 형식)
# === R2 END ===
```

문제: 내용 변경 시 3개 플랫폼 모두 재설치 필요

### OPAL 방식 (3줄 부트스트래퍼)

```
# === OPAL START ===
세션 시작 시 ~/.opal/AGENT.md를 Read로 읽어 AI 에이전트로 활성화한다.
파일이 없으면 ~/.opal/skills/onboarding/SKILL.md를 읽어 온보딩을 시작한다.
# === OPAL END ===
```

장점:
- 에이전트 정의 변경 시 `~/.opal/AGENT.md`만 수정하면 3개 플랫폼에 즉시 반영
- 부트스트래퍼 자체는 거의 변경할 일이 없음
- 설치 후 사용자가 직접 커스터마이징 가능

### 마커 전환 처리

기존 `# === R2 START ===` / `# === R2 END ===` 마커가 설치된 경우:
- install-mac.sh에서 R2 마커를 먼저 제거 → OPAL 마커로 교체
- 또는 R2 마커도 인식하여 자동 교체 (하위 호환)

**결정**: install-mac.sh에서 R2 마커와 OPAL 마커 모두 인식하도록 구현. 기존 R2 섹션이 있으면 OPAL 섹션으로 교체.

## 3. 온보딩 인터뷰 설계

### 기존 interview 스킬 패턴 분석

- **한 번에 3~4개 질문** (AskUserQuestion 도구 사용)
- **선택지 제공**으로 의사결정 부담 감소
- **2~3라운드** 이내 완료 목표
- **의사결정 기록** 형식으로 결과 정리

### 온보딩 항목 설계

**Round 1: 기본 정체성** (필수)

| 항목 | 설명 | 예시 |
|------|------|------|
| `name` | 에이전트 이름 | 알투, 메듀사, 자비스 |
| `alias` | 짧은 별칭 | R2, MDS, JVS |
| `owner_name` | 소유자 호칭 | 캡틴, 보스, 사장님 |
| `owner_alias` | 소유자 이름 | 루카스, 민수 |
| `personality_summary` | 성격 한 줄 요약 | "까칠하지만 일처리 똑부러짐" |

**Round 2: 성격 디테일** (선택, 확장 가능)

| 항목 | 설명 | 예시 |
|------|------|------|
| `tone` | 대화 톤 | 존댓말+친근, 반말+직설, 격식체 |
| `role_summary` | 역할 한 줄 | "자비스 같은 AI 비서" |
| `traits` | 성격 특성 목록 | ["솔직함", "주도적", "꼼꼼함"] |
| 사용자 추가 항목 | 자유 정의 | 원하는 항목 자유 추가 |

## 4. 프로젝트 에이전트 오케스트레이션 패턴

### 기존 패턴: task-flow → task-flow-qa

```
task-flow SKILL.md:
  1. 탐색 경로에서 AGENT.md를 찾아 Read
  2. Task 도구로 서브에이전트 실행
  3. 서브에이전트에게 입력 전달 (stage, task_path, artifact_path)
  4. 서브에이전트가 QA 문서 생성
  5. 결과를 사용자에게 보고
```

### OPAL 프로젝트 오케스트레이션 패턴

```
OPAL 에이전트 (AGENT.md):
  1. 사용자 지시 수신
  2. {프로젝트}/.opal/AGENT.md 확인
     ├─ 없음: 직접 수행 (또는 project-init 스킬로 생성 제안)
     └─ 있음: 오케스트레이션 모드
  3. 오케스트레이션:
     a. 사용자 지시를 해석하여 프로젝트 에이전트용 프롬프트 작성
     b. Task 도구로 프로젝트 에이전트 실행
        - 프로젝트 에이전트 AGENT.md를 프롬프트에 포함
        - 작업 내용과 컨텍스트 전달
     c. 결과 수신 및 검토
     d. 사용자에게 보고
```

### 플랫폼별 오케스트레이션 지원

| 플랫폼 | 서브에이전트 메커니즘 | 지원 여부 |
|--------|---------------------|----------|
| Claude Code | subprocess (Task 도구) | O |
| Cursor | Task 도구 (subagent_type) | O |
| Antigravity | 스킬 체이닝 (서브에이전트 없음) | △ (동일 컨텍스트 실행) |

**Antigravity 대안**: 서브에이전트 미지원이므로, 오케스트레이터 스킬이 프로젝트 에이전트 AGENT.md를 직접 Read하여 컨텍스트로 활용하고, 동일 컨텍스트에서 실행.

## 6. 핵심 발견사항

1. **부트스트래퍼 패턴은 모든 플랫폼에서 동작한다** — AI의 Read 도구가 기본 기능이므로, 부트스트래퍼가 경로를 지시하면 파일을 읽을 수 있다.

2. **3줄 부트스트래퍼로 충분하다** — 현재 100줄+ 스니핏의 내용이 모두 `~/.opal/AGENT.md`로 이동하므로, 부트스트래퍼는 "읽어라"는 지시만 있으면 된다.

3. **온보딩은 interview 스킬 패턴을 그대로 활용** — 기존 interview 스킬의 AskUserQuestion 패턴과 라운드 구조를 온보딩에 적용.

4. **오케스트레이션은 기존 task-flow-qa 호출 패턴과 동일** — Task 도구로 서브에이전트를 실행하고, 결과를 검토하여 보고하는 패턴을 재활용.

5. **R2 → OPAL 마커 전환은 install-mac.sh에서 자동 처리** — 기존 R2 설치 사용자도 재설치 시 자동으로 OPAL로 전환.
