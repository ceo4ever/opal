## 2. 신규 발견 — 수정 과정에서 생긴 취약점

### GC-101 (high, blocking) — 예측 가능한 임시 파일명 + 심볼릭 링크 추종 → 임의 파일 덮어쓰기

- 위치: `opal/tools/state-tool/state_tool.py:468`
- rule_id: `SECURITY.md §1 (CWE-377)` / CWE-59 / OWASP A01 · source_tier **T0**
- 관측: `_atomic_write_state_json()`이 tmp 경로를 `state.json.tmp.{os.getpid()}`로 **예측 가능하게** 만들고, `open(tmp_path, "w")`로 연다 — `O_EXCL`도 `O_NOFOLLOW`도 없다.
- 재현: task 디렉터리에 `state.json.tmp.<pid>` → `/tmp/gcsec4/VICTIM_TMP.conf` 심볼릭 링크를 미리 심고 `_atomic_write_state_json()` 호출. **victim 파일 내용이 state JSON으로 교체됨**(`trusted=yes` → `{"schema_version":"1.2","attacker":"PWNED"}`). 추가로 `os.replace()`가 심볼릭 링크 자체를 옮겨 이후 `state.json`이 victim을 가리키는 심볼릭 링크로 남는다 → **후속 모든 상태 쓰기가 victim으로 흐른다**.
- 영향: 쓰기 권한을 가진 로컬 공격자가 임의 경로를 공격자 영향 하의 JSON으로 덮어쓰고, 상태 SSOT를 영구 리다이렉트한다.
- 이 취약점은 **이번 수정이 도입했다** — GC-001/D-F 대응으로 추가된 신규 writer이며, GC-005가 조각에 적용한 `O_EXCL|O_NOFOLLOW` 방어가 여기에는 적용되지 않았다.
- 조치: `tempfile.mkstemp(dir=state_file.parent)` 또는 `os.open(tmp, O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW, 0o600)`로 생성한다.
- 검증: 위 재현 절차에서 victim 원문이 불변이고 봉투 오류가 반환되면 닫힘.

### GC-102 (high, blocking) — 락 파일 심볼릭 링크 추종 + 임의 chmod

- 위치: `opal/tools/run-log-tool/run_log_core.py:215,217`
- rule_id: CWE-59 / CWE-367 / OWASP A01 · source_tier **T1**
- 관측: `_acquire_lock()`의 `os.open(lock_path, O_CREAT|O_RDWR, 0o600)`에 `O_NOFOLLOW`가 없고, 뒤따르는 `os.chmod(lock_path, 0o600)`는 `lchmod`가 아니라 **링크 대상에 적용**된다.
- 재현: `.opal-task.lock` → `/tmp/gcsec2/VICTIM_LOCK.txt`(0644) 심볼릭 링크 선점 후 `init()` 호출. **victim 권한이 0644 → 0600으로 변경됨**, 링크는 그대로 유지, `init`은 `ok:true` 반환.
- 영향: (a) 임의 파일 권한 강제 변경 — 다른 사용자·서비스가 읽던 파일을 소유자 전용으로 만들어 서비스 거부, (b) `flock`이 공격자가 지정한 엉뚱한 inode에 걸려 **D-4 단일 배타 락 보장이 무력화**된다(서로 다른 대상을 가리키는 두 프로세스가 동시에 "락 획득" 성공 → 조각 동시 쓰기·순번 충돌).
- (b)는 GC-004가 도입한 `chmod`가 (a) 원시요소를 새로 만든 것이므로, 이번 수정이 공격면을 넓혔다.
- 조치: `O_NOFOLLOW`를 추가하고 `chmod`는 열린 fd 기준 `os.fchmod(fd, 0o600)`로 바꾼다.
- 검증: 위 재현에서 victim 권한 불변 + `ELOOP` 계열 오류 봉투면 닫힘.

### GC-103 (medium, blocking) — `run/` 디렉터리 심볼릭 링크로 조각이 태스크 밖에 기록됨

- 위치: `opal/tools/run-log-tool/run_log_core.py:341-343` (+ 우회되는 방어 `:141-155`)
- rule_id: CWE-22 / `SECURITY.md §6 path 정규화(CWE-22)` · source_tier **T0**
- 관측: `run_dir.mkdir(parents=True, exist_ok=True)`는 `run/`이 디렉터리 심볼릭 링크여도 성공하고, `os.chmod(run_dir, 0o700)`가 링크 대상에 적용된다.
- 재현: `t3/run` → `/tmp/gcsec2/OUTSIDE_DIR`(0755) 심볼릭 링크 선점 후 `init()`. 외부 디렉터리 권한이 **0755 → 0700**으로 바뀌고 조각 `run-log-run_s3-0001.jsonl`이 **태스크 폴더 밖에 생성**됨.
- **GC-003이 넣은 `_resolved_segments()` 포함 관계 확인은 이 공격을 잡지 못한다** — `run_dir.resolve()`가 심볼릭 링크를 따라간 결과를 기준으로 삼기 때문에 조각이 항상 "포함"으로 판정된다(재현에서 `validate_run` → `verdict:"pass"`).
- 영향: 실행 로그(향후 마스킹 대상 원문 포함)가 추적 제외·0700 경계 밖으로 유출되고, 외부 디렉터리 권한이 임의 변경된다.
- 조치: `run_dir`을 `O_NOFOLLOW` 계열로 열어 `os.path.islink()` 검사 후 사용하거나, 포함 관계 기준을 `run_dir.resolve()`가 아닌 `task_dir.resolve()/"run"`으로 고정한다.
- 검증: 심볼릭 링크 `run/`에서 `init()`이 거부되고 외부 디렉터리 권한이 불변이면 닫힘.

### GC-104 (medium, advisory) — redact 초크포인트가 state.json writer 전체를 덮지 않음 (GC-001 잔여)

- 위치: `opal/tools/state-tool/state_tool.py:484`
- rule_id: OWASP A09 / D-9 계약 · source_tier T1
- 관측: 초크포인트는 `_atomic_write_state_json()` 안에만 있다. `save_state_json()`은 동일한 `state` 딕셔너리(=`run_log.pending_events` 포함)를 디스크에 쓰면서 `redact()`를 타지 않으며, 호출처가 6곳이다.
- 재현: state.json에 `pending_events:[{"secret":"UNREDACTED-TOKEN"}]`를 심고 `status --set blocked` 실행 → state.json 재기록 확인, `redact()` 호출 0회, 값 그대로 잔존.
- 영향: 현재 T02에서는 `pending_events` 생성자가 `_cmd_init_run_log()` 하나뿐이고 `redact()`가 pass-through라 **실 유출은 없다**. 그러나 D-9 "모든 writer가 공통 경로를 통과한다"는 구조적으로 미성립이며, T06이 `redact()` 본문을 채우는 순간 이 경로로 스테이징되는 사건은 조용히 마스킹을 건너뛴다. 지금은 pass-through라 회귀 테스트로도 잡히지 않는다.
- 조치: 초크포인트를 `save_state_json()`에도 적용하거나, 두 함수를 단일 직렬화 진입점으로 합친다.

### GC-105 (low, advisory) — outbox(state.json)가 0644, 조각은 0600 (GC-004 잔여)

- 위치: `opal/tools/state-tool/state_tool.py:468`
- rule_id: CWE-732 / OWASP A05 · source_tier T1
- 관측: 실제 init 실행 후 `state.json` 0644, 조각 0600, 락 0600, `run/` 0700. `_atomic_write_state_json()`이 tmp를 기본 umask로 만들고 `os.replace()`가 그 mode를 그대로 승계한다.
- 영향: GC-004가 조각을 0600으로 좁혔지만 **동일한 사건 payload가 보관함(state.json)에도 실린다** — 같은 데이터에 두 가지 권한 경계가 공존해 마스킹 전 원문이 world-readable 경로로 남는다.
- 참고: state.json 자체의 0644는 기존 관례이므로, 최소 조치는 `pending_events`가 비어 있지 않은 동안만 0600으로 좁히는 것이다.
