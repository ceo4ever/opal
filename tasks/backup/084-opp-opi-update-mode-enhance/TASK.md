# TASK: opi 최신화 모드 정밀도 개선

## 작업 목표

opi 최신화 모드가 프로젝트 생성 시점의 기준으로만 변경을 감지하여, 이후 축적된 실질적 변화(구조 변경, 내용 변경, 새 문서/모듈 추가)를 형식적으로만 훑고 넘어가는 문제를 해결한다. **형식(구조)과 내용(설계 사상) 모두를 정밀 분석하여 문서화 품질을 높이고**, 이를 통해 PM이 정확히 지시하고 워커가 정확히 일할 수 있는 기반을 만든다.

## 배경

실제 프로젝트 최신화 수행 시 다음 문제가 반복되고 있다:

**형식(구조) 측면**:
- `app/main.py → app/mams/main.py` 이동, 중간 레이어 추가 등 코드 구조 변경을 depth 2~3 스캔으로는 감지 불가
- 작업 히스토리에 기록된 변경 이력을 활용하지 않아 PM이 처음부터 전수 분석해야 함
- "아키텍처 변경"이라는 모호한 기준만 존재하여 구체적 비교 프로세스 부재
- 문서 단위 "업데이트 필요" 판단만 있고, 어떤 섹션이 어떻게 틀린지 drill-down 없음

**내용(설계 사상) 측면**:
- `framework/` 같은 중요 구조가 만들어져도 사상을 분석하지 않고 형식만 보고 넘어감
- 프레임워크 대폭 확장 시 새 문서(FRAMEWORK.md 등) 필요성을 감지/제안하는 로직 부재
- 결과적으로 문서가 실제 프로젝트를 반영하지 못해 PM 지시와 워커 작업의 정확도가 떨어짐

**이 문제는 개발/일반 프로젝트 모두에 해당한다.** 개발 프로젝트는 코드+문서, 일반 프로젝트는 문서 중심이지만, "변화를 정밀하게 감지하고 문서에 반영"해야 하는 본질은 동일하다.
