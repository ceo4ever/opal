### ① 목표 달성 — 2점

앵커 2점("사용자·운영 계층에서 목표를 직접 검증")에 부합한다.

- 태스크 목표는 "릴리즈 태그 설치·업데이트 시 다운로드 대상과 체크섬 발행 대상을 일치시켜
  하드 실패 2건(`opal-cli update`·`install.ps1`)과 무음 스킵 1건(`install.sh`)을 해소"다(TASK.md §작업 목표).
- **S-9**가 목표 그 자체를 L2 실행으로 검증한다 — `opal-cli update --to v0.6.11 --force` 실 CLI 실행,
  기대 결과가 `"체크섬 검증 완료" 출력 후 exit 0` + `캡틴이 최초 신고한 하드 실패가 재현되지 않는다`.
  단위·정적 검사의 대체물이 아니라 실 프로세스 관통이다.
- **S-7**이 무음 스킵 1건을 L2 실행으로 검증한다 — `"항목 미매칭 스킵 경고 0건"`이라는 **부재 증명**을
  기대 결과에 포함시켜, "검증 통과 출력"만으로는 잡히지 않는 결함 클래스를 직접 겨냥한다.
- **RED-first 트랙(§0)이 self-confirming을 구조적으로 차단한다** — RED 증거가 사변이 아니라 실측
  (`1ae94e27…` 기대 / `463a5842…` 실제)이고, S-7·S-9를 **불변 대상**으로 못박아 구현 중 판정 기준 완화를 금지했다.
  "시나리오는 통과했는데 목표는 미달"(070 사건)의 역패턴이다.
- 검증이 정적 검사로 대체되고 있지 않다 — 정적 검사(S-3·S-4·S-17)는 §0에서 명시적으로 RED 대상에서
  **제외**되어 목표 달성의 근거로 쓰이지 않는다.

> Windows 경로(F-3/S-16)의 L3 처리는 아래 §2 관찰①에서 별도 평가했다. ① 점수를 낮추지 않았다 —
> 해당 사안은 요구 커버(②) 성격이며 결정론축이 이미 통과 판정했다. 여기서 재감점하면 축 이중 계상이 된다.

### ⑤ 채택/잔존 — 2점 (교체형 목표)

앵커 2점("구형 잔존0·신형 채택 모두 검증")에 부합한다. 교체형 관점을 적용해 양방향을 각각 확인했다.

**구형 잔존 0 (S-3, "구형 경로 잔존 0건 (교체 완결성)")** — 5개 독립 검사로 분해되어 있다:
① `archive/refs/tags`가 각 파일에서 **폴백 분기 내부 1회씩만** 등장 ② `install.sh`에 `opal.tar.gz` 리터럴 0건
③ 비고정문자열 매칭(`grep "${tarball_name}"`) 0건 ④ 무조건 `--strip-components` 고정 인자 0건
⑤ 3파일 헤더 `DL-CONTRACT (085)` 각인 존재.
"URL 문자열 0건"에 그치지 않고 **결함을 만든 구형 관용구 자체**(정규식 매칭·고정 strip·하드코딩 파일명)를
잔존 대상으로 열거한 점이 이 축의 핵심 요건을 충족한다. 대상도 3파일 전부(`install.ps1` 포함)다.

**신형 채택 (S-9·S-7·S-2·S-13)** — 선언이 아니라 실행 결과로 증명된다:
- 발행 자산과 자동 아카이브는 해시가 원천적으로 다르므로(`1ae94e27…` vs `463a5842…`),
  S-7·S-9의 **"체크섬 검증 통과"는 릴리즈 자산을 실제로 내려받았을 때만 성립한다**.
  즉 채택 여부가 통과 조건에 구조적으로 내장되어 있어 위조 불가능한 채택 증거다.
- S-2가 자산명을 `sha256sums.txt` 파일명 컬럼에서 파생(DL-CONTRACT D-B)했음을 확인해, 하드코딩 회귀를 차단한다.
- S-13이 신형(prefix 없음)·구형(prefix 있음) 양 형식의 추출 사후조건(`VERSION`·`opal/` 존재, 각인값 `v0.6.11`)을 확인한다.
- S-12가 **구형 잔재의 오작동**(폴백 후에도 받아둔 sha 파일로 비교 → 100% 불일치)이 재현되지 않음을 로그 부재로 확인한다.

### ⑥ 경계/부정 — 2점

앵커 2점("경계·부정 경로 시나리오 존재")에 부합한다. 정상 경로 편중이 아니며, 부정 경로가 결함 클래스별로 분리되어 있다.

| 부정/경계 유형 | 시나리오 | 기대 |
|---|---|---|
| 체크섬 항목 부재 · 빈 기대값(무음 통과 클래스) | S-5 | 양쪽 모두 exit≠0, 경고 후 통과 경로 부재 |
| 해시 도구 미탑재 | S-6 | `shasum` 폴백, 둘 다 없으면 실패 반환(무음 통과 없음) |
| 손상 tarball | S-8 | exit≠0, 추출·설치 단계 미도달 |
| 릴리즈 자산 부재 → 폴백 | S-10 | 중단 없이 자동 아카이브 완료 + 사유 로그 |
| 비대화형 + 자산 부재(fail-closed) | S-11 | exit≠0 + 옵트인 안내, `OPAL_ALLOW_UNVERIFIED=1`은 경고 후 진행 |
| 폴백 시 잘못된 비교 금지 | S-12 | 불일치 오류 부재, UNVERIFIED로 수렴 |
| 아카이브 형식 경계(prefix 유/무) | S-1·S-13 | strip 판정 `0/1/1`, 양 형식 사후조건 충족 |
| 회귀 경계(main 브랜치 · DRY-RUN) | S-14·S-15 | 배너·구조 무변경, 네트워크 접근 0 |

특히 강한 지점 2가지:
- **fail-closed 보존이 부정 경로로 검증된다**(S-11) — 무결성 검증을 우회하는 방향의 해소를 금지한
  TASK §제약과 R-2·GC-001이 시나리오 수준에서 집행된다.
- **"무음 통과"를 부재 증명으로 검증한다**(S-5·S-7) — 실패를 유도해 exit≠0을 확인하는 통상 부정 경로에
  더해, "경고 후 통과하는 경로가 존재하지 않는다"는 강한 형태의 기대를 걸었다.

## 2. 관찰 사항 (advisory — gaps 아님, 게이트 차단 요인 아님)

> scenario-gate.md §5-1 및 AGENT.md Phase 1-S에 따라 `gaps[]`는 **0점 축에 한해** 산출된다.
> 아래 3건은 어느 축도 0점이 아니므로 `gaps[]`에 포함하지 않는다. PM 재량 반영 사항으로만 남긴다.

**관찰① — Windows 경로의 이중 스킵 가능성 (F-3 / H-7)**
S-16이 L3 [SUPERVISOR] + 환경 부재 시 대체 검증 허용이고, 대체 검증 3종 중 하나인 S-4의 PowerShell 구문
파싱도 `pwsh 미설치 시 사유 기록 후 Skip`이다. 두 스킵이 동시에 성립하면 `install.ps1`에 남는 증거는
정적 grep(S-3)과 규약 대조표뿐이다. H-7이 지목한 리스크는 `tar 인자 배열 전개 오류 → 추출 실패`라는
**런타임 동작**인데, 구문 파싱으로는 이를 검출할 수 없다. `install.ps1`은 목표 문장이 지목한 하드 실패 2건 중
하나이므로 잔여 위험이 0은 아니다.
- 판정에 미반영한 이유: TASK.md F-6 AC가 "사유 + 대체 검증 방법 명시"를 명시적으로 허용하고,
  PLAN §9 R-5가 이를 사전 식별·수용했다. 요구 커버(②)는 결정론축이 이미 통과시켰다.
- 권고(선택): macOS/Linux의 `pwsh`로 `Get-DlStripComponents` + 조건부 인자 배열을 **실 픽스처에 대해 tar까지 실행**하면,
  Windows 없이도 H-7의 런타임 리스크를 대부분 회수할 수 있다. 현재 대체 검증 3종에는 이 실행이 없다.

**관찰② — 네트워크 순단 오판(H-1)의 직접 재현 부재**
PLAN의 H-1 시나리오 후보는 `sha URL만 차단 후 install 실행`이었으나, S-10은 "릴리즈 자산이 없는 태그"를
사용해 **자산 부재**를 재현할 뿐 **순단 오판**을 재현하지 않는다.
- 판정에 미반영한 이유: PLAN §9 R-1이 이 리스크를 **수용**으로 처리했고("fail-closed라 보안 회귀 없음"),
  그 수용의 전제인 fail-closed 동작 자체는 S-11이 검증한다. 즉 잔여 위험이 안전한 방향으로 닫혀 있다.

**관찰③ — 폴백 진입 조건 중 2개 분기가 L2 미도달**
DL-CONTRACT D-C 의사코드 기준 폴백 진입 경로는 4가지다 — (a) sha 다운로드 실패 (b) 자산명 파생 공백
(c) 자산 tarball 다운로드 실패 (d) 폴백 후 재다운로드마저 실패 → `hard_error`.
S-10이 (a), S-12가 (c)를 덮지만, (b)는 S-2의 단위 반환값 확인에 그치고 호출자 폴백까지 이어지지 않으며,
(d)의 하드 실패는 어느 시나리오에도 기대 결과로 명시되지 않았다.
- 판정에 미반영한 이유: ⑥축 앵커는 "경계·부정 경로 시나리오 존재"이며 부정 경로가 8종 이상 실재한다.
  (b)(d)는 커버리지 세밀도 사안이지 축 미달 사안이 아니다.
