## 1. 무엇을 해결했나

릴리즈 태그로 설치·업데이트할 때 **체크섬이 발행된 파일과 실제로 내려받는 파일이 서로 달라** 검증이 구조적으로 성립할 수 없던 결함을 3경로 전부에서 해소했다.

릴리즈 워크플로우는 `git archive` 산출물(`opal-{tag}.tar.gz`)에 대해 체크섬을 발행하는데, 설치·업데이트 스크립트는 GitHub이 자동 생성하는 별개 아카이브를 내려받고 있었다. 두 파일은 압축 방식과 디렉토리 구조가 달라 해시가 일치할 수 없다.

| 경로 | 종전 동작 | 현재 |
|------|----------|------|
| `opal-cli update` | 해시 불일치 하드 실패 | 릴리즈 자산 수신 → 검증 통과 |
| `install.ps1` (Windows) | 예외 throw로 설치 중단 | 동일 규약 적용 (런타임 미검증 — §5 참조) |
| `install.sh` (mac/linux) | 항목 미매칭으로 **검증 무음 스킵** | 항목 부재는 하드 실패 |

이 결함은 릴리즈 워크플로우 도입(태스크 139) 이후 계속 존재했으나, 소유자 환경이 main 브랜치 기반 설치여서 체크섬 분기 자체를 우회해 왔다. v0.6.11이 릴리즈 태그로 업데이트를 시도한 첫 사례였다.

## 3. 설계 — DL-CONTRACT (3경로 공통 규약)

코드 공유는 불가로 판정했다. `install.sh`는 curl-pipe-bash 단일 파일 자기완결이 보안 계약이고(`scripts/install.sh:53-57`), 세 파일 모두 **소스를 내려받기 전에** 실행되어 공유 런타임 위치가 없다. 대신 규약을 단일화하고 헤더 각인 + 정적 대조로 드리프트를 막았다.

| # | 규약 |
|---|------|
| 1 | 릴리즈 자산 존재 판정은 `sha256sums.txt` 다운로드 성공 여부 단일 신호 — 워크플로우가 두 자산을 같은 스텝에서 올리므로 존재가 동치이며, 추가 왕복이 0이다 |
| 2 | 자산명은 하드코딩하지 않고 `sha256sums.txt` 파일명 컬럼에서 파생 — 다운로드 대상과 검증 대상이 **구조적으로** 같아진다 |
| 3 | 로컬 저장명 = 발행 자산명 (verify 모드) |
| 4 | 폴백 3동작 동시 수행 — URL 재지정 + 로컬명 분리(`-archive` 접미) + sha 파일 폐기 |
| 5 | 체크섬 3모드 `verify` / `unverified` / `branch`, 모드 이상값은 하드 실패(fail-closed) |
| 6 | strip 판정 = 루트 직속 0 AND 최상위 세그먼트 1종 → 1, 그 외 0 |
| 7 | 추출 후 `VERSION`·`opal/` 사후조건, 위반 시 하드 실패 |

3파일 헤더에 `DL-CONTRACT (085)` 각인을 남겨 후속 유지보수자가 규약 존재를 인지하게 했다.

**HEAD 프로브 미채택 근거**: 존재하지 않는 릴리즈 자산을 `curl -I`로 조회하면 exit 22가 아니라 **56**을 반환해 네트워크 실패와 구분할 수 없다(실측).

**`release.yml --prefix` 미채택 근거**: 이미 발행된 v0.6.7~v0.6.11이 전부 prefix 없음이라 호환 분기가 어차피 필수다. 추가해도 이득 없이 재릴리즈만 유발한다.

## 5. 검증 결과

### 자동 테스트 (RED-first)

RED 기준선 **PASS 2 / FAIL 24** → 최종 **PASS 26 / FAIL 0**. 작성자(test-agent)와 구현자를 분리했고, 테스트 파일은 GREEN 루핑 중 미수정이다. 네트워크 0회 — 아카이브 픽스처를 `git archive`로 로컬 생성해 오프라인·CI 재현이 가능하다.

가장 결정적인 RED 증거는 TC-B1이다 — prefix 없는 발행 자산을 종전 코드로 추출하면 루트에 `VERSION`·`opal/`이 **둘 다 없는데도** exit 0으로 "추출 완료"를 출력했다.

**목표 시나리오 S-9는 구형 사본 대조까지 포함**했다 — `git show HEAD:`로 꺼낸 종전 코드로 같은 명령을 실행하면 `exit 1 / 체크섬 불일치`가 재현되고, 수정본은 `exit 0 / 체크섬 검증 완료`다.

## 9. 이번 태스크에서 배운 것

- **테스트 통과가 규약 정합을 뜻하지 않는다.** 계약 테스트 26/26이 GREEN인 상태에서 정적 대조가 불일치 7건을 잡았고, 그중 2건은 실제 결함이었다.
- **워커 보고를 검증하면 미해결이 드러난다.** O-5 수정은 "빈 값 거부" 가드였는데, 해당 함수는 실패 시 빈 값이 아니라 `0`을 출력한다. 실측하지 않았다면 미해결을 해결로 기록할 뻔했다.
- **이번 결함의 본질은 "조용한 성공"이다.** `install.sh`의 무결성 검증 무음 스킵, 추출 실패 후 exit 0, 모드 이상값 무음 통과, strip 무음 강등 — 같은 클래스를 넷 닫았다.
