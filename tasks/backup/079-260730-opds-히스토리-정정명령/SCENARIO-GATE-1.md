### ① 목표 달성 — 2점

**앵커 대조**: 2점 = "사용자·운영 계층에서 목표를 직접 검증".

태스크 목표는 `TASK.md:9` — "`--kind history`를 신설하여, 잘못 기재된 작업 히스토리 행을 **삭제 없이 정정**할 수 있게 한다".

- **TS-024**(`TEST-SCENARIO.md:543-558`)가 목표를 운영 계층에서 직접 검증한다 — `install-mac.sh` 배포 → **배포본 CLI**로 실 `.opal/MEMORY.json`의 078 히스토리 `stage`를 `완료·미커밋` → `완료·커밋(d7a8ce0, 447ff09)`로 정정 → `show --brief` 반영 + `git diff`가 **1행 1필드만**.
- 기대 결과가 **반증 가능한 관측값**으로 못박혀 있다 — `ok:true`·`match_count:1`·`history_count:5`·`changed:["stage"]`. 산문 "정상 동작 확인"이 아니다.
- 목표의 **부정 축**("삭제 없이")도 같은 시나리오에서 `history_count:5`·`git diff` 1행으로 동시 검증된다.
- 시나리오 문서 스스로 목표달성 시나리오임을 자각·명시한다(`:558` "왜 이것이 목표달성 시나리오인가" — 078 stale 히스토리라는 **최초 피해 사례를 신설 기능으로 실제 해소**하는 것을 목표 달성의 정의로 선언).

`scenario-gate.md:14`의 070 사건(핵심 목표 검증 시나리오가 **애초에 도출되지 않음**)이 재현되지 않았다. 목표 검증 시나리오가 존재하고, 실환경·실 SSOT·배포본이라는 가장 강한 계층에 배치되어 있다.

## 2. 작성자 판단 3건에 대한 심판

PM이 판정을 명시 요청한 지점. 세 건 모두 **형식 미충족이 아니라 근거 있는 미해당**으로 인정한다.

### (1) L3 `[SUPERVISOR]` 시나리오 부재 — **정당**

- 판정 근거가 문서에 기재돼 있다(`TEST-SCENARIO.md:22`, `:564`) — FE 변경 0건, 화면·사용자 플로우 변경 0건이라 캡틴 육안 검증 대상이 물리적으로 부존재.
- `PLAN.md:539`·§4.1이 변경 범위를 `memory_tool.py` + 참조 문서 3종 + `.opal/MEMORY.json`으로 한정하며 FE 파일이 단 한 건도 없다 — 판정과 계획이 일치한다.
- **핵심**: 축 ①은 "L3 존재"가 아니라 "**사용자·운영 계층**에서 목표를 검증하는 시나리오 존재"를 요구한다(`scenario-gate.md:20`). CLI 도구에서 그 계층은 **PM/캡틴이 실 CLI를 실행하는 지점**이며, TS-024가 정확히 그것이다. 형식 충족용 L3를 조작하는 편이 오히려 축 ①의 신호를 희석시켰을 것이다.
- `scenario-gate.md:14`가 경계한 실패는 "목표 검증 시나리오 부재"이지 "L3 칸 공백"이 아니다. 혼동 없이 처리됐다.

### (2) M2(E2E 자동화) 미해당 — **정당**

- `test-scenario-guide.md` §Step 3-b의 M2 의무 트리거는 **FE 변경 조건부**다. FE 변경 0건이므로 트리거 미성립.
- 판정 근거가 §계층·실행 방식 배치 원칙 표(`:21`)와 PM Gate 체크(`:633`)에 이중 기재돼 있다 — 누락이 아니라 판정임이 문서상 명확하다.
- 부기: M2는 `test-scenario-guide` 소관 규칙이며 scenario-gate 6축이 아니다. 본 판정에서 ①⑤⑥ 어느 축에도 감점 사유를 만들지 않는다.

### (3) TS-024를 M3(PM 직접)로 배치 — **정당. 오히려 권장 배치**

- 비가역성이 실질적이다 — `install-mac.sh`는 `~/.opal/` 전체를 덮고, 대상은 실 `.opal/MEMORY.json`이다(`PLAN.md:537`, H-10).
- `PLAN.md:621-626` Step 5(`agent: PM 직접` / `실행 방법: direct`)와 시나리오 배치가 **일치**한다 — 계획·시나리오 간 drift 없음.
- **자동 PASS 차단이 게이트 정신에 부합한다**: 목표달성 시나리오를 테스트 에이전트가 자동 통과시킬 수 있게 두면, 태스크의 유일한 채택 증거가 self-confirming으로 붕괴한다. `scenario-gate.md:79` [MUST] Producer≠Evaluator의 정신을 실행 계층으로 연장한 배치다.

**단, 실행 단계 조건 1건**(게이트 판정에는 영향 없음 — 권고): M3는 자동 게이트가 없으므로, EXECUTE 시 TS-024의 `결과`·`상세` 칸은 **실제 명령 출력을 그대로 첨부**해야 한다 — ① 응답 JSON 원문(`ok`·`match_count`·`history_count`·`changed` 4필드 가시), ② `git diff .opal/MEMORY.json` 원문, ③ `show --brief` 발췌. "확인함"류 산문 기재로 대체되면 목표 검증 축이 실행 시점에 자기선언으로 퇴화한다.
