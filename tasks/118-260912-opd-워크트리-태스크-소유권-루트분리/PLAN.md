## Approach

제안서 D-1 §11 Phase 0/Phase 1만 수행한다. Phase 2 monorepo pilot·Phase 3 확산·Phase 4 multi-repo와 `opal-pilot-*`의 태스크 생성 순서 전환은 범위 밖이므로, 제안서 §6.1의 `harness/task-process.md` 스텝 4.5 순서 재정렬은 이 태스크에서 수행하지 않고 Phase 2로 이연한다(TASK §Affected users and systems 범위 제외 항목).

집행 순서는 "실측 완결 → 발급원 신설 → 보정 제거 → 재진입 계약 → 골든표 폐기 → 문서 정합 → 회귀 증거"다. 발급원(worktree-tool metadata)을 먼저 세우는 이유는 state-tool·memory-tool·Console이 전부 그 발급값(`allocator_root`, `task_path`)을 소비하기 때문이며, 골든표 폐기를 마지막 코드 작업으로 미루는 이유는 4개 소비 스위트를 먼저 교체하지 않으면 중간 상태에서 회귀 판정 기준이 통째로 사라지기 때문이다(ANALYSIS Q4).

실측 축은 ANALYSIS가 state-tool 축(`420 passed, 3 skipped`)까지 이미 닫았으므로 재실행하지 않는다. 남은 것은 Console BE 축 하나이며, 그 미실측 원인은 cone이 아니라 `dashboard/backend/config.py:24`의 `scan_roots` 기본값 고정이다(ANALYSIS Q1 Console 행) — W-1이 이 한 축만 닫는다.

비워크트리 경로는 모든 신규 동작을 "인자·설정이 주어졌을 때만 켜지는 분기"로 설계해 보전한다. 신규 cone 키 기본값은 빈 리스트, `resolve_task_dir`의 다중 루트는 keyword-only 기본 `None`, `memory-tool`의 `pending_requests`는 신규 인자가 없으면 응답 키 자체를 만들지 않는다. 플랫폼 분기는 신설하지 않으므로 C-6은 자연 충족이다.

`code-scan search hub_root`가 반환한 6개 파일(`paths.py`, `brain_tool.py`, `test_paths.py`, `test_brain_tool.py`, `test_adapters.py`, `test_parsers.py`)과 ANALYSIS Q9의 8파일 전수를 AC-12 정리 대상 집합으로 고정한다. `code-scan depends opal/tools/state-tool/state_tool.py`는 `test_worktree_tool.py`가 state-tool에 의존함을 보여주므로, W-3(worktree-tool)과 W-4(state-tool)를 같은 실행 그룹에 두지 않는다.

**[MUST] 공유 파일 편집 규율** — 다른 세션이 같은 허브에서 태스크 117을 진행하며 `opal/tools/event-loader/event_loader.py`, `opal/core/AGENT.md`, `docs/PROJECT.md`, `docs/ARCHITECTURE.md` 등을 미커밋 수정 상태로 남겼다. `.opal/brain/pages/concept/concurrent-task-shared-file-discipline.md` §결정 내용: "`Write` 금지, `Edit` 전용 — 공유 파일에는 전체 파일을 다시 쓰는 도구를 쓰지 않는다." 해당 파일을 바꾸는 모든 Work item은 전면 재작성 금지, 헤딩·심볼 앵커 기반 `Edit` 전용, 인접 코드 미개선, 편집 직전 재-Read를 지킨다.

**[MUST]** `.opal/AGENT.md` §금지사항: "`~/.opal/` 직접 편집 금지 — 항상 프로젝트 소스를 수정한 후 install로 배포한다." 규범 문서 변경 대상은 전부 `opal/core/references/` 이하 프로젝트 소스다.

**[MUST]** `TASK.md` C-4: "파이프라인 행 상태 변경은 `state-tool`로만 수행한다. `state.json`·`test-scenario.json` 직접 편집 금지." 어떤 Work item도 이 두 파일을 변경 대상으로 갖지 않는다.
