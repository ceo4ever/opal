## Handoff

- PLAN에서 결정할 것:
  - 신규 cone 키의 이름과 기본값(예: `taskCapsuleCone: ["tasks", ".opal"]`), `validate_worktree_config`의 정확한 에러 코드.
  - `memory-index-request` 신규 파일의 이름·경로·스키마, `cmd_show`/`cmd_review`의 `pending_requests` 응답 키 형태.
  - finalize 재진입 판정의 정확한 "선언 집합"(DONE.md 회고적 학습 후보 절)의 표준 템플릿 위치 — 본 ANALYSIS는 `opal-pilot-gc` 경량 템플릿과의 관계만 확인했고 표준 CLOSE DONE 템플릿의 정확한 소유 스킬/파일은 특정하지 못함.
  - `find_project_root`를 함수 시그니처째로 분리할지, 호출자별로 다른 신규 함수(`task_root()`/명시 `allocator_root` 인자)를 호출하게 할지의 리팩터링 방식.
  - Console `resolve_task_dir`의 다중 허용 루트를 함수 인자로 받을지 호출부에서 순회할지의 인터페이스 설계.
- 착수 차단: 없음 — Q1~Q9 전 항목에 확인 사실 또는 명시된 한계가 있고, disposable fixture 실측으로 AC-1의 실체화 여부와 AC-2의 state-tool 축 새 기준선(420 passed/3 skipped/0 failed)을 이미 확보했다. Console BE 축의 새 기준선만 PLAN 단계에서 `~/workspace` 하위 fixture 또는 `scan_roots` 임시 재정의로 추가 실측이 필요하다(위 Critical assumptions 참조, 실행 자체를 막는 요인은 아니다).
