# TASK: 태스크 실행 로그 — 기록 기반 완성

## Problem

태스크 실행 로그의 기록 계층이 **자기 계약을 지키지 못하는 상태**로 남아 있다.

앞선 수행(`archive/README.md`)에서 기록 코어와 상태 계약은 동작하게 됐다. 사건이
순서 있게 쌓이고, 같은 요청 재시도가 중복을 만들지 않으며, 기록이 실패해도 작업이
멈추지 않고 복구된다. 그러나 세 가지가 비어 있고, 그중 하나는 **계약 위반을 임시
조치로 덮어둔 상태**다.

1. **마스킹이 빈 껍데기다.** `redact()`가 통과만 시킨다. 계약(`docs/run-log/CONTRACT.md`
   §8 계열)은 "마스킹된 조각은 git으로 추적한다"고 정하는데, 마스킹이 없어 추적할 수
   없다. 그래서 `.gitignore`에 기록 조각을 **한시 제외**해 둔 상태다. 이 임시 조치가
   남아 있는 동안 실행 이력은 태스크 증거로 보존되지 않는다.
2. **순번 발급이 조각 전량 스캔이다.** 사건이 쌓일수록 호출 비용이 선형 증가하고,
   4 MiB 조각 경계 전환이 구현돼 있지 않아 단일 파일이 무한히 커진다.
3. **두 시간계 해석이 미완이다.** 사건은 UTC, 기존 상태는 로컬 시각인데 변환 계약이
   코드에 없다. 실행 시간의 분 단위 투영도 없어 태스크 통계가 사람 입력에 의존한다.

이 상태로 배포하면 이력이 추적되지 않고, 기록이 커질수록 느려지며, 통계가 어긋난다.

## Proposed outcome

기록 계층이 **자기 계약을 거짓 없이 지키는 상태**가 된다.

- 비밀값이 디스크에 닿기 전에 공통 경로에서 가려지고, 그 결과 기록 조각이 계약대로
  git 추적 대상이 된다. `.gitignore` 한시 조치가 사라진다.
- 순번 발급이 파생 색인을 쓰고, 색인이 없거나 깨져도 조각에서 재구축된다. 조각이
  상한에 닿으면 다음 조각으로 원자적으로 넘어가고 닫힌 조각은 변경되지 않는다.
- 사건 시각과 기존 로컬 시각이 일관되게 해석되고, 실행 시간이 단일 원천에서 분 단위로
  자동 파생된다. 사람이 값을 손으로 넣지 않는다.
- 앞선 수행이 확보한 동작(멱등·조합 거부·복구·방어)이 하나도 깨지지 않는다.

이 지점이 **그림자 모드로 실사용 가능한 기반**이다. 강제 집행과 파이프라인 확산은
제안서가 별도 승인으로 정한 범위이며 이 태스크에 포함하지 않는다.

## Affected users and systems

- **사용자**: OPAL PM·워커 에이전트, OPAL Console에서 태스크 통계를 보는 소유자.
- **시스템**: `opal/tools/run-log-tool/`(기록 코어·CLI), `opal/tools/state-tool/`,
  `dashboard/backend/`(조용시간 설정·통계 투영), `.gitignore`.

### 포함 범위

마스킹 실동작과 추적 경계 복귀 / 런타임 색인과 재구축 / 조각 경계 원자 전환 /
두 시간계 해석과 실행 시간 분 투영 / 위 변경이 기존 동작을 깨지 않음.

### 제외 범위 — 후속 이관

| 항목 | 대응 AC | 왜 이번이 아닌가 |
|---|---|---|
| 완료 게이트 강제 집행 | AC-4·5·11·16 | **배포 후 그림자 표본 축적이 선행 조건.** 채널별 정상 완료 20건 이상은 실제 파일럿 실행에서만 나온다 |

### 기 충족 — 회귀로만 확인

앞선 수행이 닫은 **AC-1·2·3·6·7·10·15·19**는 재구현 대상이 아니다. 이번 변경이
이를 깨지 않는지만 확인한다(AC-21).

## Constraints

- C-1: `~/.opal/` 배포 파일을 직접 수정하지 않는다. 프로젝트 소스만 수정한 뒤 install로
  재배포한다. **이 태스크에서 install을 실행하지 않는다.**
- C-2: 기존 `state-tool` 테스트와 Console 동결 fixture가 회귀 없이 통과한다. 작업 전
  기준선은 `state-tool` **436 passed / 0 failed**, `run-log-tool` **36 passed**다.
- C-3: 스키마 1.0/1.1 태스크는 계속 실행 가능하다. `--run-log-mode` 미지정 경로의 바이트
  동일성을 깨지 않는다.
- C-4: 도구 의존은 상태 도구 → 기록 코어 단방향이다. 기록 코어는 `state.json`을 읽지 않는다.
- C-5: 확정된 설계 결정(`docs/run-log/TRD.md` D-1~D-9)과 계약(`docs/run-log/CONTRACT.md`)을
  바꾸지 않는다. 바꿔야 하면 구현하지 않고 blocker로 보고한다.
- C-6: 3-SSOT(`state.json`·`backlog.json`·`test-scenario.json`) 손편집 금지 — 전용 도구만 사용.
- C-7: 플랫폼별 분기를 도구 로직에 넣지 않는다. 변환 계층에만 둔다.
- C-8: 앞선 수행이 세운 I/O 방어(경계 확인·링크 추종 차단·권한 제한·예외 봉투 환원)를
  제거하거나 약화하지 않는다. 새 읽기·쓰기 경로를 만들면 **같은 방어를 적용하고 테스트로
  고정**한다.
- C-9: 계약 3자산(`CONTRACT.md` §2.2·§2.2.1·`surfaces.json`)의 오류 코드 대응은 같은 변경
  단위로 갱신한다.

## Acceptance criteria

- AC-8: segment 경계 동시 append에서 새 조각이 정확히 1개 생성되고, run 전역 순번 중복·누락이
  0건이며, 정상 호출 중 다른 호출의 pending 오탐이 0건이다.
- AC-9: 런타임 색인을 삭제·손상시킨 뒤 재구축하면 동일 순번을 이어가고, 재구축 중 append와
  워커 완료 mark가 fail-closed로 대기한다.
- AC-12: `duration_ms`와 `state.json` 분 투영이 `floor(duration_ms / 60000)`과 일치하고, 동일
  worker resume의 다중 process span이 중복 없이 합산된다. 1.2 태스크의 불일치 수동 값은
  거부된다.
- AC-13: secret fixture가 표준 로그·원본·가져오기 경로 어디에도 평문으로 남지 않는다.
  마스킹은 모든 writer가 통과하는 공통 경로 한 곳에서만 일어난다.
- AC-14: `tasks/**/run/raw/`·`tasks/**/run/.runtime/`·`.opal-task.lock`이 git 추적에서 제외되고
  **마스킹된 조각은 추적된다.** `.gitignore`의 조각 한시 제외가 제거된다.
- AC-20: legacy 로컬 시각·사건 UTC·조용시간 시간대 변환이 날짜 경계 fixture에서 일치하고,
  시간대만 다른 두 설정이 서로 다른 캐시 토큰을 만든다.
- AC-21: 기 충족 AC-1·2·3·6·7·10·15·19의 동작이 이번 변경 후에도 유지된다. 판정은 실제 실행
  출력으로 하며, 기존 테스트 파일을 수정해 통과시키지 않는다.
