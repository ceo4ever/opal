## 작업 목표

`docs/architecture-diagram/opal_framework_architecture.html`(v0.5)를 재작성하여 (1) 프레임워크의 핵심 개념인 **지식 자산 3종(코드맵·brain·MEMORY)과 환류 루프**를 1급 구조로 표현하고, (2) v0.5 이후 누적된 **실제 컴포넌트 구성과의 사실 불일치**를 실측 기반으로 복구한다.

## 배경

현행 다이어그램은 태스크 065 시점(v0.5)에 작성된 뒤 갱신되지 않았다. 그 사이 프레임워크는 코드맵 헤더 작성층(077)·매니페스트 샤딩(082·083)·메모리 JSON 전환(078)·루프 오케스트레이터(oppl)·심판 에이전트(evaluator) 등으로 확장되었으나 다이어그램에 반영되지 않았다.

또한 소유자가 지적한 구조적 결함이 있다 — 프레임워크의 차별점인 "지식이 축적되고 다음 작업이 그것을 먼저 읽는" 성질이 다이어그램에서 노드 1개 수준으로 축소되어 있어, OPAL이 **단방향 파이프라인 도구**로 오독된다.

## 확정된 설계 방향 (대화에서 합의)

소유자 승인 방향 — "박스 키우기"가 아니라 **구조 3점 교정**:

1. **지식 계층 독립 분리** — 도구(집행 수단)와 지식(축적 자산)을 갈라, `코드맵(WHAT) / brain(WHY·HOW) / MEMORY(운영 기억)` 3자산을 각각 독립 노드로 승격하고 자산별 SSOT·관리 도구·수명을 명시한다.
2. **환류 루프선 추가** — 하강 흐름 옆에 `CLOSE → ingest → 다음 세션 참조` 귀환 경로를 시각 요소로 그려 Loops를 증명한다. **최우선 항목.**
3. **참조 시점 앵커** — 각 지식 자산이 어느 계층에서 읽히는지 표시하여 "횡단 관통"을 주장에서 사실로 전환한다.

## 제약 조건

- **자기완결 HTML** — 인라인 CSS/JS 유지. 외부 스크립트·CDN 라이브러리 추가 금지(현행 Google Fonts 링크는 기존 동작 보존 차원에서 유지 허용).
- **동일 경로 덮어쓰기** — 파일명·경로를 바꾸지 않는다(기존 참조 링크 보존). 별도 백업 파일을 만들지 않는다(git 이력으로 복원 가능).
- **실측 우선** — 컴포넌트 수치·이름은 `opal/agents/`·`opal/skills/`·`opal/tools/` 실측을 SSOT로 한다. `docs/ARCHITECTURE.md`도 일부 수치가 stale하므로(예: 서브에이전트 12개 표기, `docs/ARCHITECTURE.md:39`) 문서 값을 그대로 옮기지 않는다.
- **범위 외 파생 갱신 금지** — `docs/ARCHITECTURE.md` 본문 갱신은 이 태스크 범위 밖이며, CLOSE 단계의 관련 문서 갱신 판단으로 이관한다.
- **배포 경계** — 대상 파일은 프로젝트 문서이므로 `~/.opal/` 배포와 무관하다. install 재배포 불요.
