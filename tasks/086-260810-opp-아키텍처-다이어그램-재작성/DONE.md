## 1. 무엇을 해결했나

OPAL 아키텍처 다이어그램이 **프레임워크를 단방향 파이프라인 도구로 오독시키던 구조적 결함**을 해소하고, v0.5 이후 누적된 사실 불일치 11건을 실측으로 복구했다.

소유자 지적의 핵심은 "지식 자산이 강조되지 않았다"였으나, 진단해보니 강조 부족이 아니라 **배치와 범주가 틀려 있었다**:

| 결함 | 종전 | 현재 |
|------|------|------|
| 지식 자산 지분 | 구조도 세로 스트립 1개 + 상세 L8의 노드 1개 | **L3 독립 계층 3노드** + 구조도 우측 횡단 3카드 |
| 환류 표현 | 하강 흐름만, 귀환선 0개 | **두 뷰 모두 귀환 요소** — 구조도 좌측 전체 높이 레일 / 상세 환류 밴드 + 상향 커넥터 2개 |
| 도구·자산 범주 | L8에 도구와 자산이 혼재 | **L9 집행 수단(도구 18종) ↔ L3 축적 상태(자산 3종)** 분리 + 3:3 대응 명시 |
| 지식 참조 시점 | 표기 없음 (L8 = 흐름의 끝) | 자산별 참조 시점 표기 + "흐름이 시작될 때 먼저 읽히는 상태값" 명문화 |
| 계층 번호 | 구조도·상세·모달 3중 불일치 | **정본 10계층 1종**으로 통일 |

## 2. 근본 원인 (진단 확정)

다이어그램은 태스크 065 시점(v0.5)에 만들어진 뒤 갱신되지 않았고, 그 사이 프레임워크는 코드맵 헤더 작성층(077)·매니페스트 샤딩(082·083)·메모리 JSON 전환(078)·루프 오케스트레이터(oppl)·심판 에이전트(evaluator)로 확장됐다.

더 근본적인 문제는 **지식 자산을 "산출물"로 취급한 계층 배치**였다. L8(배포 직전)에 두면 위→아래로 읽는 독자에게 "지식은 마지막에 만들어지는 것"으로 읽힌다. 실제 참조 순서는 정반대다 —

- MEMORY: 부트스트랩 Phase B 직후 `memory-tool show --brief` 브리핑 (`opal/core/references/opal-pm.md` §15)
- 코드맵: 코드 작업 디스패치 **전 무조건** 조회 (`opal/core/references/pm/dispatch-process.md:113`)
- brain: 작업·분석·설계 **착수 전** 3시점 (`opal/core/references/opal-pm.md` §14)

즉 지식은 흐름의 끝이 아니라 **시작점**이다. 이것을 L3(라우팅 앞)으로 올린 것이 이번 재작성의 축이다.

## 8. 이번 태스크에서 배운 것

### (1) 세로쓰기에 회전을 겹치면 글리프가 뒤집힌다 — 그리고 grep으로 검출되지 않는다

`writing-mode:vertical-rl`로 이미 세로쓰기가 된 요소에 "읽는 방향을 아래→위로 바꾸려고" `transform:rotate(180deg)`를 더하면, 방향이 바뀌는 게 아니라 **글자 자체가 180° 뒤집혀 판독 불가**가 된다. 같은 파일의 `.cross-node span`은 `text-orientation:mixed`만 써서 정상 렌더됐고, 레일만 이 패턴을 벗어나 결함이 됐다.

**교훈은 결함 자체가 아니라 검증 절차의 구멍이다.** 이 결함은
- 결정론 grep으로 검출 불가 (문자열·구조는 정상)
- 축소된 fullPage 스크린샷으로도 판독 불가 (34px 폭 세로 텍스트)

PM이 좌표·오버플로·모달 46/46을 전부 실측하고도 통과시켰고, 소유자가 화면에서 발견했다. **회전·세로쓰기 요소가 있으면 해당 요소를 element 단위로 확대 캡처해 판독하는 절차**가 PM Gate 렌더 검증에 필요하다.

### (2) 조용히 실패하는 코드는 브라우저 검증을 무력화한다

`openModal`이 키 부재 시 `if(!d) return;`으로 종료하므로, `data-id`↔`NODE_DATA` 키 누락은 **콘솔에 아무것도 남기지 않고 "클릭해도 반응 없음"** 으로만 나타난다. 렌더 검증만으로는 판정할 수 없어 결정론적 키 대조를 차단 게이트로 승격했다.

### (3) 하드코딩된 기대 총계는 게이트를 흉기로 만든다

PLAN 1차본이 키 총계를 43(실제 46)으로 잘못 계산해 6곳에 전파했다. 그대로 EXECUTE에 넘겼다면 워커가 "43에 맞추려고 키를 삭제"하는 방향으로 움직였을 것이다. 정정 시 총계를 **참고값으로 강등**하고 `comm -3` 양방향 일치를 유일 판정 기준으로 올렸으며, "총계를 맞추려 키를 삭제·추가하지 말라"는 `[MUST]`를 명문화했다.

### (4) 문서보다 소스가 옳다 — 이번에도 문서가 뒤처져 있었다

`docs/ARCHITECTURE.md`는 서브에이전트를 "12개"(실측 15), 독립 스킬을 "5개"(실측 8)로 적고 있고, `opal-harness.md`는 `brain-tool`을 8서브명령(실측 10)·`state-tool`을 9(실측 10)로 적고 있다. 다이어그램 수치 SSOT를 문서가 아닌 **디렉토리·frontmatter 실측**으로 고정한 판단이 유효했다.
