## §5. 핵심 설계

### 5-1. 모드 판별 테이블 확장

현재 2행 → 3행으로 확장한다. 판별 순서: AGENT.md 존재 여부 → 코드 유무. (→ D-3 §1)

```markdown
| 조건 | 모드 |
|------|------|
| `.opal/AGENT.md` 존재 | **최신화 모드** — 기존 환경을 현재 상태에 맞게 갱신 |
| `.opal/AGENT.md` 미존재 + 코드 없음 | **초기화 모드 — 신규** — 처음부터 환경 구축 |
| `.opal/AGENT.md` 미존재 + 코드 있음 | **초기화 모드 — 기존** — 소스 분석 후 2문 인터뷰 |
```

- 코드 존재 여부 판단: Phase 1-1 Step A 레이아웃 탐색 결과(config 파일 기반)를 재사용
- 최신화 판별이 최우선(기존 AGENT.md 체크 우선순위 유지) (→ D-1 `SKILL.md:56~62`)

### 5-2. 초기화(신규) 인터뷰 재설계

**시작 안내 변경**: "4개 질문을 드리겠습니다" (개발/비개발 분기에 따라 최대 4문)

**공통 질문 (Q1~Q2)**:

```
Q1/4. 이 프로젝트는 무엇을 하려는 건가요?
      → 직접 입력 (자유 서술)
      (알투가 개발/비개발 여부를 이 답변에서 자동 판단)

Q2/4. 지금 어느 단계인가요?
      a) 이제 시작 (아이디어/기획 단계)
      b) 진행 중 (이미 작업 중)
      c) 기존 프로젝트 합류
```

**개발 분기 (Q3~Q4)**:

```
Q3/4. (분석에서 파악한 기술 스택 제시)
      → 맞으면 그대로, 수정/추가하려면 알려주세요.
      (분석 결과 없으면: "어떤 기술 스택을 쓰실 건가요?")

Q4/4. 이 프로젝트에서 특별히 지켜야 할 제약이 있나요?
      a) 특정 라이브러리/프레임워크만 사용
      b) 보안/규제 요구사항 있음
      c) 없어요
      d) 직접 입력
```

**비개발 분기 (Q3~Q4)**:

```
Q3/4. 어떤 산출물을 만들어야 하나요?
      a) 기획서/PRD
      b) 보고서/제안서
      c) 가이드/매뉴얼
      d) 기타: 직접 입력해주세요

Q4/4. 누가 읽는 문서인가요?
      a) 개발팀
      b) 기획/비즈니스 팀
      c) 외부 고객/파트너
      d) 내부 전체
      e) 기타: 직접 입력
```

(→ D-3 §2, §3)


```
Q2/2. 분석 결과 외에 문서에 추가로 담아야 할 내용이 있나요?
```
