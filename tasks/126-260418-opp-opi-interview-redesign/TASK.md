# TASK: opi 인터뷰 흐름 재설계

> 작성일: 2026-04-18 | 작업 유형: 개선 | 적용 스킬: opp | 모드: interactive
> 입력: 사용자 요청
> 출력: TASK.md

## 작업 목표

`opal/skills/opal-project-init/SKILL.md`의 사용자 인터뷰 흐름을 3가지 케이스 분기 구조로 재설계하여, 모호하고 불필요하게 많은 질문을 케이스별 4문 이하로 줄인다.

## 배경

opi 실행 시 소유자에게 하는 질문이 모호하고 너무 길다는 피드백 수신.

## 배경 분석 (대화에서 도출)

**현재 문제점**:
- Q5/7 "PM으로서 어떤 관점으로 검토하면 좋을까요?" — OPAL 내부 개념을 전제한 질문. 사용자에게 의미 불명확
- Q8+2 에이전트 매핑 확인 — `opal-fe-agent`, `opal-task-agent` 등 내부 용어를 사용자에게 확인받는 구조 자체가 불필요
- Phase 2.5 방향 확인 중 "핵심만 업데이트 ({N건}만)" — N이 실제로 채워지기 전까지 의미 없음
- Phase 3 "§ 단위로 개별 승인/거부 가능" — 어떻게 하는지 안내 없음

**현재 모드 판별 구조**:
- 초기화: `.opal/AGENT.md` 미존재 → 두 케이스(신규/기존 코드에 신규 OPAL 도입)를 구분하지 않음
- 최신화: `.opal/AGENT.md` 존재

**실제 케이스**:
1. 신규 프로젝트 (코드 없음, OPAL 없음) — 목적/방향 중심 인터뷰 필요
2. 기존 프로젝트 + OPAL 신규 도입 (코드 있음, OPAL 없음) — 소스 분석 결과 확인 위주
3. 기존 프로젝트 + OPAL 최신화 (코드 있음, OPAL 있음) — 변경사항 파악, 인터뷰 최소화

## 확정된 설계 방향 (대화에서 합의)

**§1. 모드 확장 (2→3)**:
- `초기화(신규)`: 코드 없음 + OPAL 없음
- `초기화(기존)`: 코드 있음 + OPAL 없음 (소스 분석 → 확인 위주)
- `최신화`: OPAL 있음 (기존 유지)

**§2. 인터뷰 공통 흐름 (신규 기준)**:
- 공통 Q1: 이 프로젝트는 무엇을 하려는 건가요? → 목적 파악 + 개발/비개발 판단
- 공통 Q2: 지금 어느 단계인가요? (a) 이제 시작 / b) 진행 중 / c) 기존 프로젝트 합류)

**§3. 개발/비개발 분기**:
- 개발: Q3 기술 스택 확인(소스 분석 결과 제시 → 확인/보완), Q4 특별 제약
- 비개발: Q3 어떤 산출물을 만들어야 하나요?, Q4 누가 읽는 문서인가요?

**§4. 제거 항목**:
- Q5 "PM 검토 관점" → PM이 자동 판단 (AGENT.md에 자동 반영)
- Q8+2 에이전트 매핑 확인 → PM이 자동 결정, 사용자 질문 제거

**§5. 기존(코드있음) OPAL 신규 도입 케이스**:
- 소스 분석 먼저 수행 → 분석 결과 제시 + Q1(목적 확인) + Q2(보완 필요 사항) 만
