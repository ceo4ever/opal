### 현재 상태

`~/.opal/AGENT.md` 부트스트랩 섹션은 1~9단계를 동등하게 나열하고 있다.

```
1. identity.md 로드
2. identity.md 없으면 온보딩
3. 스킬 레지스트리 확인
4. 참조 문서 Read (agents.md / mcps.md / opal-harness.md 포함)
5. 모델 매핑 로드
6. 프로젝트 부트스트래퍼 자동 관리
7. PM 컨텍스트 로드
8. 프로젝트 메모리 브리핑
9. 에이전트 활성화
```

**취약점 3가지** (TASK.md 분석 결과):

1. `opal-harness.md`가 step 4의 "참조 문서" 그룹(`agents.md`, `mcps.md`와 동급)에 묶여 있어, 임의로 건너뛰어도 즉시 탐지되지 않는다.
2. 부트스트랩 완료 후 소유자에게 체크리스트를 보고하는 의무가 없어, 외부에서 누락 여부를 확인할 수 없다.
3. PM 역할 활성화(step 7) 전제로 "harness 로드 완료" 조건이 명시되어 있지 않아, harness 미로드 상태에서 PM이 활성화될 수 있다.

### 영향 범위

- `~/.opal/AGENT.md` 단독 수정 — 다른 파일로의 파급 없음
- 모든 OPAL 에이전트 세션에 즉시 적용됨 (부트스트래퍼가 이 파일을 첫 Read 대상으로 지정)
- 부트스트랩 단계 번호가 재정렬되므로, AGENT.md 내부에서 단계 번호를 직접 참조하는 표현("부트스트랩 7단계", "부트스트랩 8단계")을 함께 갱신해야 한다

### 핵심 설계

#### A. 부트스트랩 전체 강제성 경고 (신규)

부트스트랩 섹션 도입부("## 부트스트랩" 바로 아래)에 다음 경고 블록을 추가한다:

> **[CRITICAL]** 이 단계들은 순서대로 **전부** 수행해야 한다. 하나라도 건너뛰면:
> - `opal-harness.md` 미로드 → 구현 금지 원칙 무효화 → 승인 없이 파일 수정 가능
> - PM 역할 미검증 → 프로젝트 없이 PM 활성화 → 게이트 프로세스 붕괴
> 부트스트랩 완료 전 어떤 작업도 시작하지 않는다.

이 경고는 단계 번호 목록 앞에 위치하여 에이전트가 목록을 읽기 전에 먼저 인지하도록 한다.

#### B. 부트스트랩 단계 재구조화

현재 step 4에 묶인 `opal-harness.md` 로드를 독립 필수 단계로 분리한다.
새 단계 구조:

```
[MUST] 1. identity.md 로드
[MUST] 2. identity.md 없으면 온보딩
[MUST] 3. opal-harness.md 로드 ← 신규 격상 (현 step 4에서 분리)
       4. 스킬 레지스트리 확인 (기존 step 3)
       5. 참조 문서 Read — agents.md, mcps.md (opal-harness.md 제거)
       6. 모델 매핑 로드 (기존 step 5)
       7. 프로젝트 부트스트래퍼 자동 관리 (기존 step 6)
       8. PM 컨텍스트 로드 (기존 step 7) ← 전제 조건: harness 로드 완료
       9. 프로젝트 메모리 브리핑 (기존 step 8)
      10. 에이전트 활성화 (기존 step 9)
```

step 3에 `[MUST]` 태그 + 명시적 설명 추가:

> **[MUST]** `~/.opal/references/opal-harness.md`를 Read한다. 이 단계를 건너뛰면 §1 구현 금지 원칙 및 게이트 프로세스를 인지하지 못한 채 PM 역할이 활성화될 수 있다.

#### C. 부트스트랩 완료 보고 형식 추가

새 섹션 "부트스트랩 완료 보고"를 부트스트랩 섹션 하단(step 목록 직후)에 추가한다.

**보고 시점**: 세션 첫 응답 (브리핑 포함 여부와 무관)

**보고 형식** (전 단계 커버 — 소유자 부담 최소화):

```
[부트스트랩] ✅ identity  ✅ harness  ✅ registry  ✅ references  ✅ PM (ai-framework)
```

- 각 항목은 해당 단계 완료 시 ✅, 미수행 시 ❌, 해당 없음(예: PM 없는 프로젝트)은 ⬜로 표시
- 한 줄로 유지 (소유자 부담 최소화)
- 브리핑이 있을 경우 보고 블록을 브리핑 상단에 삽입
- 커버 항목: identity / harness / registry / references(agents+mcps) / model-mapping / PM
