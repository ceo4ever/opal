# PLAN: OPAL 범용 E2E 하네스 구현 (제안서 태스크 3~9)

> 입력: [TASK.md](TASK.md), [ANALYSIS.md](ANALYSIS.md) | 계약 근거: [TRD.md](TRD.md) §4·§6·§8·§10, [CONTRACT.md](CONTRACT.md), [surfaces.json](surfaces.json), [archive/backlog.json](archive/backlog.json)

## Approach

설계는 이미 끝나 있다. `TRD.md` §6이 파일·줄 단위 변경 지점을, `CONTRACT.md`가 스키마 15종·시그니처·경계·기계검증 MV-01~MV-42를 소유하고, `archive/backlog.json`의 T03~T16 14건이 그 분해이며 `covers` 합집합이 `surfaces.json` 40표면과 1:1이다(ANALYSIS Q7). 따라서 이 PLAN은 재설계하지 않고 **backlog 14건을 Work item으로 승계하면서 backlog가 비워 둔 실행 순서(`depends_on: null`)와 파일 소유권 경계만 확정한다.**

확정하는 것은 네 가지다 — (1) T03을 전 후속의 선행으로 승격, (2) `test_tool.py` `e2e` 서브파서를 확장하는 W들의 단일 소유권 순차 배치, (3) `tool-scan` 문구 강제 테스트의 선-갱신 위치, (4) AC-15 boot-time 비교의 구현 형태. 나머지 기술 결정은 TD-1~TD-19를 그대로 소비한다.

범위 밖으로 명시한다 — AC-3은 이미 충족이므로(`scripts/tests/test_console_ownership.sh` 20/20, `archive/tasks/T02-Console-프로세스-소유권/DONE.md`) Work item을 만들지 않고 회귀 방어 항목으로만 다룬다. `lib/e2e_contract.py`·`lib/scenario.py`는 C-1에 의해 어느 W의 변경 대상에도 없다.

## Release and recovery

- **적용 순서**: P1(W-1 Runtime Manager · W-2 PID 재사용 방어) → P2(W-3 driver 계약 · W-4 판정 부정 검증) → P3(W-5 agent-browser · W-6 cmux · W-7 API executor · W-8 Human executor) → P4(W-9 status/clean · W-10 hybrid) → P5(W-11 Playwright 소비자 이전) → P6(W-12 표면 전수 스위트 · W-13 기본 설치 제거) → P7(W-14 통합 검증) → P8(W-15 문서 갱신). 이 배치가 C-4(제안서 §14: Runtime Manager → Browser driver 계약 → executor → Playwright 기본 설치 제거 마지막)를 만족한다. 커밋 단위는 W 1개이며, 각 W 종료 시 해당 W의 완료 기준 연결 AC/C만 확인하고 다음 그룹으로 넘어간다.
- **검증 범위**:
  - *결정론*: `CONTRACT.md` §D.2 결정론 항목과 MV-01~MV-42. `~/.opal/.venv/bin/python -m pytest`(test-tool), `scripts/tests/test_console_ownership.sh`, vitest.
  - *회귀(C-9 기준선)*: `test-tool` 88 passed, `test_console_ownership.sh` 20/20, vitest 161 passed, `console.sh`·`install-mac.sh`에서 `pkill`·`pgrep`·`killall` 3개 문자열 grep 각각 0건. **AC-3은 이번 범위에서 새로 구현하지 않고 이 4개 지표로 방어만 한다** — W-2가 `console.sh` `stop` 판정표를 건드리므로 AC-3 회귀 위험이 있는 유일한 W이고, W-2와 W-14가 20/20을 각각 재측정한다.
  - *실제 연동*: source→installed 검증 경로는 `e2e run --target source-main` → `--target source-worktree`(worktree 2개 동시) → `--target installed`(사전 준비된 격리 `OPAL_HOME`을 `--opal-home`으로 전달, 하네스가 install을 호출하지 않음·미준비 시 입력 오류 거부, TD-9·`CONTRACT.md` §C.5) 순서다. `--opal-home`이 사용자 실제 `~/.opal`과 같은 경로면 거부된다.
  - *AC-12 clean install 회귀 판정*: 격리 `OPAL_HOME`(OS 임시 경로)에서 clean install → update → `doctor` 3단을 실행하고, W-13 적용 전후의 `doctor` 출력을 diff한다. 판정 기준은 (a) 의존성 진단에서 playwright 오탐 0건, (b) 공식 MCP 분모 문구가 playwright를 제외한 목록으로 바뀌고 미등록 경고가 0건, (c) web-to-markdown 경로와 MCP 등록이 계속 동작 — 이 3개가 D-9의 실제 관측 대상이다. Chromium이 설치되지 않았음은 install 로그에 Chromium 설치 단계가 0회 나타나는 것으로 확인한다.
- **실측 경계**: E2E run의 health gate 대기와 stale lease 회수 기준은 `CONTRACT.md` §A.7이 소유한 값을 쓰고 PLAN이 새 임계값을 만들지 않는다. `awaiting_human`의 `timeout_seconds` 경과는 `fail`이 아니라 `blocked`로 종료하고 토큰 만료 여부를 기록한다(W-8). H-2가 실현되어 가용 브라우저 후보가 0이면 AC-4·AC-5를 blocked로 남기고 재작업 대상은 후보 확보(환경) 쪽이며 driver 계약 재설계가 아니다.
- **실패 시**:
  - 산출물은 OS 임시 위치 또는 `OPAL_E2E_ARTIFACT_DIR`에만 쓰므로(C-5·TD-10) 저장소 롤백이 필요 없다. 누출된 프로세스·포트·lease는 `test-tool e2e clean --stale`로 회수한다(W-9 완료 이후 가용). 그 전 구간에서는 run이 만든 프로세스 그룹 종료만으로 회수한다.
  - 코드는 W 단위 커밋이므로 회귀 발생 시 해당 W 커밋만 되돌린다. W-13(설치 제거)은 `opal/tools/requirements.txt`·`scripts/install-mac.sh`·`scripts/install/windows.ps1`·`doctor` 4개 파일 되돌림으로 Playwright 기본 설치 상태가 그대로 복원되며, 사용자 캐시는 제거하지 않으므로 되돌림 후 재설치가 필요 없다.
  - W-2 회귀 시 `console.sh` 되돌림만으로 T02 상태(판정표 6분기)로 복귀하고, `.gitignore`의 `.oppl-run/` 항목은 독립적이라 함께 되돌릴 필요가 없다.
  - 이번 태스크는 사용자 `~/.opal` 배포를 수행하지 않는다 — 검증 종료 지점은 W-14의 AC-1~AC-16 관측 기록이며, 실제 설치본 반영은 별도 install 실행 시점이다.
