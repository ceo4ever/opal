# TASK: run-log 기록 완전성

## Problem

run-log의 `shadow`와 `active`가 기록의 강제력뿐 아니라 기록 범위까지 다른 것처럼 동작한다. 실제 `agentic + shadow` 태스크에서는 PM 의사결정과 판단 사유, 워커·게이트 생명주기, 암묵적 자동 승인 일부가 표준 JSONL에 남지 않아 기존 `AGENTIC-LOG.md`와 대화 기록을 함께 보지 않으면 중단 원인을 복원할 수 없다. 구조 검증이 통과해도 관측 가능한 사건의 누락을 발견하지 못하므로 실행 이력의 단일 원천이라는 제품 목표가 성립하지 않는다.

## Proposed outcome

`shadow`와 `active`가 관측 가능한 동일 사건 집합을 표준 run-log에 기록하고, 두 모드의 차이는 기록 증거가 완료 판정을 차단하는지 여부로 한정된다. PM 의사결정은 판단 요약·사유·근거를 남기며, 기록할 수 없는 사건이나 기록 실패도 침묵하지 않고 진단 가능한 결측으로 드러난다.

## Affected users and systems

- 영향 사용자: agentic 실행을 사후 감사·진단하는 프로젝트 소유자와 PM
- 포함: run-log 사건 생산 경로, `state-tool`의 복합 상태 전이, PM·게이트·워커 활동 기록, shadow/active 모드 계약, 검증 도구와 회귀 시나리오
- 제외: 원본 프롬프트·내부 사고 과정의 저장, 승인되지 않은 채널의 active 승격, Console 분석 화면, 기존 태스크 로그의 일괄 소급 변환

## Constraints

- C-1: `shadow`는 기록 누락·실패만으로 기존 파이프라인의 완료나 상태 전이를 차단하지 않아야 한다.
- C-2: `active`의 검증된 출처·완료 증거 게이트와 `profiles.json` 승인 경계는 약화하지 않아야 한다.
- C-3: PM 의사결정은 감사 가능한 요약·사유·근거 참조만 기록하고 원본 프롬프트, 내부 사고 과정, 비밀값은 저장하지 않아야 한다.
- C-4: 동일한 상태 변경은 모드와 기록 주체에 관계없이 같은 표준 사건 의미를 사용하고, 자동 승인처럼 한 명령에서 복수 행이 바뀌면 각 변경이 관측 가능해야 한다.
- C-5: 표준 기록은 append-only, 멱등성, 순번 연속성, 배타 락, 마스킹과 경로 방어 계약을 유지해야 한다.
- C-6: 기존 schema 1.0/1.1 태스크와 run-log 없는 태스크의 상태·통계·완료 동작은 회귀하지 않아야 한다.
- C-7: 규범 변경은 `docs/run-log/PRD.md`, `TRD.md`, `CONTRACT.md`의 책임 경계를 유지하고 동일 규칙을 여러 문서에 중복 소유시키지 않아야 한다.

## Acceptance criteria

- AC-1: `shadow`와 `active`의 표준 사건 인벤토리가 관측 가능한 실행·상태·게이트·의사결정 사건에 대해 동일하고, 모드별 차이는 완료 차단과 출처 신뢰도에만 존재한다.
- AC-2: PM의 decision·validation·retry 활동이 두 모드 모두에서 `activity` 사건으로 기록되며 판단 요약, 사유, 근거 참조를 조회할 수 있다.
- AC-3: 단계 진입 중 자동 승인된 사용자 확인 행과 진입 대상 행이 각각 독립된 `state.changed` 사건으로 기록되고 실제 `state.json` 전이와 일치한다.
- AC-4: 관측 가능한 워커 시작·중간 활동·종료와 게이트 요청·해결이 두 모드 모두 동일한 표준 사건 형태로 기록된다.
- AC-5: `shadow`에서 기록 실패 또는 관측 불가가 발생하면 실행은 계속되지만 누락 범위와 원인을 표준 진단 결과나 보관함 상태로 식별할 수 있다.
- AC-6: `active`에서는 선택된 completion profile이 요구하는 사건 증거가 부족하거나 모순되면 완료 상태 전이가 기존 계약대로 거부된다.
- AC-7: TASK 완료 보고 뒤 모델 턴이 종료된 재현 사례에서 표준 로그만으로 마지막 의사결정, 마지막 상태 전이, 관측 중단 지점을 구분할 수 있다.
- AC-8: run-log 구조 검증과 상태 대조 검증이 순번·스키마뿐 아니라 자동 승인 포함 상태 변경 누락을 검출하며, 기존 보안·멱등·동시성·legacy 회귀 검증이 통과한다.
