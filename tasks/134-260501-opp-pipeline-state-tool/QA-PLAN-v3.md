> 검토일: 2026-05-01 | 판정: **Pass**
> 검증 기준: 갭 E-1~E-6 정정 완결성 + SSOT 정합성 + EXECUTE 워커 컨텍스트 완결성

## 1. 요약

PLAN v3(1451줄)는 v2 Conditional Pass 판정 후 EXECUTE 진입 직전 PM 자가 검토에서 식별된 갭 6건(E-1~E-6)을 §2.18~§2.21 신설 및 §3 Step 7/8 보강으로 해소하였다. §2.18 에러 코드 카탈로그(22종 SSOT), §2.19 명령 인자 종합 매트릭스(9명령 × 전체 인자 + 충돌/종속 C-1~C-6), §2.20 행 구성 외부 주입 형식(--rows-spec/--rows-from 파싱 10단계 + agentic 자동 마킹), §2.21 Step 16개별 롤백 매트릭스 + 즉시 에스컬레이션 4종은 EXECUTE 워커가 추측 없이 그대로 구현 가능한 수준의 완결성을 제공한다. 모호 표현("적절히", "필요시", "상황에 따라")은 0건이며, v2 Warning-1("7개 서브 명령" 잔재)도 N-1/N-4/N-5/M-40에서 "9개"로 완전 해소되었다. 단, §2.18 에러 카탈로그에 `rows_acts_not_implemented` 코드가 미등재(§2.20.3에서 사용하는 에러)되었고, §2.19.3 `state advance`의 `--note` 인자가 TASK F-2 시그니처와 달리 매트릭스에서 누락된 점 2건은 Warning 수준의 지적이다. 두 항목 모두 EXECUTE 진행을 차단하는 수준은 아니다.

## 3. 지적 사항

### Warning-1: §2.18 에러 카탈로그에 `rows_acts_not_implemented` 미등재

**심각도**: Warning

**영향 범위**: EXECUTE 워커가 `ERROR_CODES` 상수 정의 시 이 코드 누락 위험

**내용**: §2.20.3(PLAN.md:1011)에서 `--rows-acts` 인자 명시 시 `{"ok": false, "command": "init", "error": "rows_acts_not_implemented", ...}` + exit 2를 반환하도록 명세되어 있다. 그러나 §2.18 에러 코드 카탈로그 22종 표(PLAN.md:733-756)에 이 코드가 등재되지 않았다. §2.19.1 init 인자 매트릭스(PLAN.md:791)에도 `(미구현 — exit 2 internal_error)`라고만 기재되어 있어, 해당 에러 코드의 정확한 토큰명이 인자 매트릭스에서 드러나지 않는다.

**현황**: §2.18 카탈로그 말미 "누락 0건 검증"(PLAN.md:758-761)에서 grep 기반으로 17+5=22종을 확인하였다고 선언하고 있으나, §2.20.3 신설 과정에서 `rows_acts_not_implemented`가 추가로 발생한 에러 코드임에도 카탈로그에 반영되지 않았다. 이는 카탈로그의 SSOT 선언과 자기 모순이다.

**권고**: EXECUTE 착수 전 §2.18 카탈로그에 23번째 항목으로 `rows_acts_not_implemented`를 추가하거나, §2.19.1 `--rows-acts` 행의 "에러 코드" 컬럼을 `rows_acts_not_implemented (exit 2)`로 명시. 또는 §2.20.3 응답 JSON에서 에러 코드를 `rows_acts_not_implemented` 대신 일반 `internal_error` 코드로 통일하는 결정을 PLAN에 추가.

### Warning-2: §2.19.3 `state advance`에서 `--note` 인자 누락

**심각도**: Warning

**영향 범위**: argparse 구현 시 advance에 --note 인자를 빠뜨릴 위험

**내용**: TASK.md F-2 시그니처(TASK.md:153)에 `advance <task-path> --row <N> [--note <text>]`가 명시되어 있다. 그러나 §2.19.3 `state advance` 인자 매트릭스(PLAN.md:803-810)에는 `<task-path>` + `--row` 2개만 등재되고 `--note`가 누락되었다. §2.11 G-6 매핑 표(PLAN.md:413-424)에서도 `advance --row N` 시 `--note` 인자가 언급되지 않는다.

**현황**: §2.19가 "argparse 구현 시 이 표가 SSOT"라고 선언(PLAN.md:773)했으므로, EXECUTE 워커가 이 표만 참조하면 `advance`에 `--note` 인자를 구현하지 않을 수 있다. 단, `advance`의 `--note`는 선택 인자이고 의사결정 로그 자동 기재(§2.17)에서 `advance`에 대한 트리거가 없어 실제 기능 영향은 낮다.

**권고**: §2.19.3에 `--note` 행 추가(선택 / string / null / 충돌/종속 없음 / - / §2.11 G-5 인용). 또는 EXECUTE 워커에게 "§2.19.3에 명시되지 않은 선택 인자는 TASK F-2 시그니처를 우선 기준으로 삼는다"는 명시 노트 추가.
