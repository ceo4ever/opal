# PLAN: 이벤트 로더 보안 보강(GC-004·006·011·012) + 절 단위 로딩(P3) 실험

> 입력: [TASK.md](TASK.md) | 근거: [제안서](../../docs/proposals/261001_이벤트_문서_로딩_경량화.md) §1.1·§3.4·§4.5

## Approach

두 덩어리를 한 태스크로 수행하되 코드 소유를 갈라 충돌을 막는다. (1) 보안 4건은 `event-loader`의 기존 경로를 좁히는 변경이다: 원장 override를 테스트 전용 조건으로 묶고 사용·실패를 영속 기록으로 드러내며(GC-006), 기본 매니페스트 경로를 정규화하고(GC-011), `--role-doc`을 허용 루트 안의 상한 이하 일반 파일로 제한하고(GC-004), 게이트가 설치본 기본 매니페스트가 아닌 매니페스트의 검증 결과를 통과시키지 못하게 도구 플래그와 소비자 문서·정적 검사로 막는다(GC-012). (2) P3는 별도 모듈과 선언 파일로 만들고, `--section-mode lazy`를 명시한 호출에서만 켜지는 실험 모드로 통합한다. 끄면 현재 응답·receipt·검증 결과와 바이트 단위로 같다. 대상 문서 본문은 수정하지 않는다(수정하면 끈 상태의 문서 해시가 달라진다).

측정은 구현 뒤에 한다. 로드량은 결정론 도구로 켬/끔을 같은 이벤트·같은 컨텍스트에서 비교하고, 품질 동등성은 (A) 규칙 보존 검사와 (B) 헤드리스 규칙 적용 프로브(`opal-agent`) 켬/끔 비교로 본다. 전체 파이프라인 실행(opst)은 비용·승인 경계가 있어 이번 범위에서 실행하지 않고 채택 권고의 선행 조건으로만 명시한다.

## Findings

### 직접 변경
`opal/tools/event-loader/event_loader.py`가 보안 4건의 소재다: 원장·시각 override와 쓰기 실패 처리(`_now_iso`·`_ledger_path`·`_record_legacy`·`legacy_report`), 기본 매니페스트 미정규화(`_default_manifest`·`_context`), `--role-doc` 무제한(`_call_mode`), 게이트가 검증 결과의 경계 매니페스트를 확인할 수단 부재(`verify_receipt`·`static_check`의 `_dispatch_line_violations`). P3는 새 모듈 `opal/tools/event-loader/lazy_sections.py`(선언 로드·단위 선별·목차·의존 폐포·추가 절 응답)와 이를 부르는 `event_loader.py` 통합, 매니페스트 `opal/core/references/events.json`의 `sectioning` 선언, 문서별 선언 파일 `opal/core/references/sections/citation-rules.json`·`opal/core/references/sections/design-gate.json`·`opal/core/references/sections/pm-review-gate.json`·`opal/core/references/sections/pm-process.json`이다. `state-tool event-verify`는 `opal/tools/state-tool/state_tool_parts/gates.py`·`opal/tools/state-tool/state_tool_parts/cli.py`에서 새 선택 플래그를 loader에 넘기고 `opal/tools/state-tool/tests/fixtures/state_tool_surface.json`이 인자 표면을 고정한다. 게이트 소비자는 `opal/core/references/pm/dispatch-process.md` Step 0과 `opal/agents/*/AGENT.md` 16종(하위 디스패치 3종 문단 포함)이다.

code-scan 인용: `opal/tools/event-loader/event_loader.py`는 module `event_loader`, layer `util`, domain `opal-tools`, depends `agent_sections`, exports `main`·`load_event`·`verify_receipt`·`static_check`·`measure_event`·`load_report`·`legacy_report`·`agent_index`·`compose_project_brief`·`project_brief`다. `opal/tools/state-tool/state_tool_parts/gates.py`는 module `state_tool_parts.gates`, layer `util`, domain `opal-pipeline`이며 `cmd_event_verify`가 loader를 서브프로세스로 호출한다. 새 모듈 `lazy_sections`는 layer `util`·domain `opal-tools`로 표준 라이브러리와 `agent_sections.parse_sections`만 쓰고 `event_loader`가 import한다.

### 회귀 확인
절 파서 `opal/tools/event-loader/agent_sections.py`는 변경하지 않고 재사용만 한다(펜스 인식 계약 유지). `worker.dispatch`의 계약 v2 선별·receipt 형식과 `opal/tools/event-loader/run.sh`의 호출 경로는 그대로이며, `sectioning`이 없는 이벤트와 `--section-mode`가 없는 호출의 응답·receipt는 바뀌지 않는다. `scripts/install-mac.sh`의 `install_opal_references`가 `references/` 하위를 통째로 복사하므로 새 `sections/` 디렉터리는 분기 없이 배포되는지만 확인한다(이 복사 뒤 `strip_deploy_md_recursive`가 설치본 `.md`의 변경이력 절을 제거하므로 선언은 설치본 문서에도 맞아야 한다 — H-2).

### 문서 갱신
호출 형식·계약이 서술된 곳만 바꾼다. `opal/tools/event-loader/README.md`(보안 동작·새 플래그·오류 코드·절 단위 로딩 실험 모드·"알려진 한계" 문장 제거), `opal/core/references/pm/dispatch-process.md`(Step 0의 verify 플래그와 성공 조건), `opal/agents/*/AGENT.md` 16종(진입 게이트·하위 디스패치 verify 줄과 성공 조건), `docs/proposals/261001_이벤트_문서_로딩_경량화.md`(진행 현황·GC 해소·P3 결과). 컨텍스트 주입·관측성·actor 문서는 호출 형식을 서술하지 않아 변경하지 않는다.

### 미확인 가정
H-1, H-2, H-3.

## Decisions and contracts

| 결정 | 변경 후 계약 | 선택 이유·근거 |
|---|---|---|
| D-1. 원장 override는 테스트 전용 | `OPAL_EVENT_LOADER_LEDGER`·`OPAL_EVENT_LOADER_NOW`는 환경변수 `OPAL_EVENT_LOADER_TEST_MODE=1`이 있을 때만 적용한다. 없는데 둘 중 하나가 설정돼 있으면 값을 무시하고 해당 호출의 응답 `warnings`에 `ledger_override_ignored`를 더한다. 있고 적용했으면 `ledger_override_active`를 더한다. 원장 경로는 override가 없으면 항상 설치 루트(스크립트가 설치본이면 그 설치 루트, 소스 실행이면 `~/.opal`)의 `state/event-loader/legacy-dispatch.jsonl`이며 `--deployed-root`·`OPAL_DEPLOYED_ROOT`로는 옮기지 못한다 | 호환 종료 판단 근거(원장)가 호출자 인자로 과소 집계되지 않게 한다. 기존 테스트는 `conftest.py`가 테스트 모드를 켠다 |
| D-2. 원장 무결성 기록과 보고 | 쓰기 실패(`ledger_write_failed`)·override 무시·override 적용 때마다 `{ts(실제 UTC 시각), kind, op, event}` 한 줄을 원장 옆 `legacy-dispatch.integrity.jsonl`에 남긴다. 거기도 쓸 수 없으면 `tempfile.gettempdir()`의 `opal-event-loader-integrity-<uid>.jsonl`(0600)에 남기고, 그것도 실패하면 stderr에 한 줄을 쓴다. `legacy-report`는 두 위치를 읽어 결과에 `integrity: {write_failures, override_ignored, override_active}`와 `reliable`(세 값이 모두 0이고 호출 시점에 override 환경변수가 적용·무시 상태가 아닐 때만 `true`)를 더하고, 호출 시점 override 환경변수가 있으면 `warnings`에 같은 코드를 낸다. `--since`·`--until`은 무결성 기록에도 적용한다 | AC-1. 원장이 못 쓰이는 상황에서는 원장 자체에 기록할 수 없으므로 별도 위치가 필요하다. 호환 종료 조건 1에 `reliable: true`를 더한다(README) |
| D-3. 기본 매니페스트 정규화 | `_default_manifest`는 `.resolve()`한 경로를 반환하고 `--manifest`와 같은 방식으로 정규화된 경로가 `manifest_path`로 receipt·응답에 기록된다. verify는 receipt 경로와 실행 경계 경로를 둘 다 실제 경로로 비교한다. 다른 실제 매니페스트를 가리키는 receipt는 현행대로 `stale_receipt`다 | AC-2, GC-011. 심볼릭 링크가 없는 설치에서는 값이 달라지지 않는다(C-1) |
| D-4. `--role-doc` 제한 | 경로를 `resolve()`한 뒤 `project_root`·`source_root`·`deployed_root` 중 하나의 하위여야 하고, `os.stat` 결과가 일반 파일(`S_ISREG`)이며, 크기가 1,048,576바이트 이하여야 읽는다. 읽기 전에 stat으로 판정해 FIFO·장치 파일을 열지 않는다. 위반은 현행 코드 `contract_arg_invalid`(`argument: --role-doc`)에 `cause`(`outside_allowed_roots`·`not_regular_file`·`too_large`·`unreadable`)를 더해 거부한다. verify도 같은 판정을 거친다 | AC-3, GC-004. 오류 코드를 새로 만들지 않아 기존 소비자 분기가 유지된다 |
| D-5. 설치본 기본 매니페스트 확인 | loader에 "정본 경로" 함수를 둔다: 설치본이면 `Path(__file__).resolve().parents[2]/references/events.json`, 소스 실행이면 `{source_root}/opal/core/references/events.json`이며 인자·환경변수의 영향을 받지 않는다. `verify`에 선택 플래그 `--require-default-manifest`를 더하며, 켠 호출에서 실행 경계 매니페스트가 정본과 다르면 `manifest_not_default`(`expected`·`actual` 포함)로 거부하고 성공 결과에 `manifest_default: true`를 더한다. 플래그가 없는 호출의 결과는 변하지 않는다 | AC-4, GC-012, C-1. 게이트가 도구 판정을 받게 한다. 문서 산문 확인만으로는 사본 매니페스트 통과를 막지 못한다 |
| D-6. state-tool 전달 | `state-tool event-verify`는 선택 플래그 `--require-default-manifest`를 받아 있을 때만 loader verify 명령에 넘긴다. 기존 `--manifest`·`--source-root`·`--deployed-root` 전달은 유지한다(테스트·측정용) | 제안서 §4.3. 판정은 loader가 소유한다 |
| D-7. 게이트 소비자 | PM 디스패치(`dispatch-process.md` Step 0.4), 워커 진입 게이트 16종 2~4항, 하위 디스패치 3종 문단의 verify는 `--require-default-manifest`를 포함하고, 성공 조건에 "결과 `manifest_path`가 `~/.opal/references/events.json`의 실제 경로와 같고 `manifest_default`가 `true`"를 더한다. 이 조건이 아니면 blocker다. `static-check`는(구현은 W-4, 게이트 문서 갱신과 같은 그룹) `worker.dispatch` verify 줄에 `--require-default-manifest`가 없으면 `dispatch_gate_default_manifest_missing`, `--manifest`·`--deployed-root`·`--source-root`가 있으면 `dispatch_gate_manifest_override`를 낸다 | AC-4. 인라인 게이트 문장을 유지하고(에이전트가 다른 문서를 읽기 전에 실행) 드리프트를 정적 검사로 막는 175의 방식을 따른다 |
| D-8. 절 단위 로딩 실험 모드 | `load`·`measure`에 `--section-mode lazy`와 반복 가능한 `--section-context KEY=VALUE`를 더한다. 플래그가 없으면 어떤 경로도 바뀌지 않는다. 이벤트 선언에 `sectioning`이 없거나 계약 인자(`--contract-version` 등)와 함께 쓰면 `section_mode_not_declared`·`section_mode_conflict`로 거부한다. 컨텍스트 키·값은 선언 파일의 `contexts`에 있어야 하며 아니면 `section_context_invalid`다 | AC-5, C-1. 명시한 호출에서만 켜진다 |
| D-9. 선언 위치와 형식 | 이벤트 선언 `sectioning`은 `[{"document": <required_docs의 id>, "source": "{source_root}/opal/core/references/sections/<id>.json", "deployed": "{deployed_root}/references/sections/<id>.json"}]`이다. 선언 파일은 `{"document", "unit_level", "contexts": {키: [값…]}, "sections": [{"id", "title", "load": "always"\|"conditional"\|"on_demand", "when": {키: [값…]}, "depends": [id…]}]}`다. 절 단위는 `unit_level`의 헤딩과 그 하위 전체(코드 펜스 바깥 헤딩 기준, `agent_sections.parse_sections`)이고, 첫 단위 앞의 머리말(제목·인용문·소개)은 항상 전달한다. `title`은 헤딩 원문 제목과 정확히 같아야 하고 절 id는 `^[a-z][a-z0-9-]{1,40}$`로 이벤트 안에서 유일하다. 단위 수준보다 얕은 헤딩은 첫 단위 앞에만 있어야 하고 문서의 모든 단위가 선언돼야 한다. 대상 문서(`unit_level`): `citation-rules` 2, `design-gate` 2, `pm-review-gate` 3, `pm-process` 2 | C-3. 문서 본문은 그대로 두고 선언을 사이드카로 둔다. 선언 누락이 정적 검사에서 드러나 문서가 바뀌면 선언도 갱신하게 된다 |
| D-10. 선별 규칙 | 전달 단위 = `always` + `when`이 성립한 `conditional` + 그 단위들의 `depends` 전이 폐포. `when`은 모든 키가 컨텍스트 값 집합에 속하면 성립하며, 컨텍스트에 키가 없으면(조건 불명) 성립으로 간주해 전달한다. `[MUST`가 본문에 있는 단위는 선언이 `on_demand`여도 항상 전달하고(`forced_by_must`로 기록) `static-check`가 `section_must_not_ondemand`로 보고한다. 단위는 원문 순서로 전달한다 | C-2. 필수 규칙은 지연 로딩되지 않는다. 선언 실수에도 `[MUST`가 새지 않는 도구 가드를 둔다. `[MUST` 표기가 없는 의무·금지·예외 문장은 W-3의 문서 검토가 책임진다 |
| D-11. 전달 본문 | 켠 호출의 문서 본문 = 머리말 + 목차 블록 + 전달 단위(원문 순서). 목차 블록은 미전달 단위마다 `- <id> — <제목> (<바이트>B)` 한 줄과 가져오는 방법 안내(`event-loader section --receipt <load 응답 파일> --id <id>`) 한 줄이며 미전달 단위가 없으면 목차를 만들지 않는다. 대상이 아닌 문서는 원문 그대로다 | AC-5 |
| D-12. 켠 호출의 receipt | `schema_version: 3`. 기존 필드에 `section_mode`(`mode`·`context`·문서별 `declaration_sha256`·`delivered`·`omitted`·`forced_by_must`·`unit_sha256`{id→해시}·`original_bytes`·`content_bytes`)와 `body_sha256`·`source_payload_bytes`·`response_bytes`를 더한다. 문서 항목은 `sha256`·`bytes`가 전달 내용의 값이고 `source_sha256`·`source_bytes`가 원본 값이다. `payload_bytes`는 전달 본문 합계다 | 제안서 §4.5. v2(`worker.dispatch`) receipt와 같은 source_* 관례를 쓴다 |
| D-13. 추가 절 가져오기 | 새 서브명령 `section --receipt <load 응답 파일> --id <절 id>…`. 부모 load 응답을 먼저 verify하고(실패하면 그 오류), 요청 id와 그 의존 폐포 중 부모가 아직 전달하지 않은 단위만 본문으로 돌려준다(이미 전달된 id는 `already_delivered`에 나열). 알 수 없는 id는 `section_not_found`다. 응답은 새 `load_id`·`parent_load_id`·`sections[{document,id,title,sha256,bytes,content,via}]`·`payload_bytes`·`response_bytes`·별도 receipt를 담는다. 별도 receipt는 `{schema_version: 3, kind: "section_fetch", event, manifest_path, manifest_sha256, parent: {load_id, receipt_sha256}, sections: [{document,id,sha256,bytes}], body_sha256, payload_bytes, response_bytes}`이고 부모 receipt를 수정하지 않는다 | 제안서 §4.5. 병렬 호출 충돌과 과거 기록 변경을 피하고 추가 로드량을 따로 센다 |
| D-14. 켠 호출 verify | 켠 receipt는 `--section-mode lazy`가 필요하다(없으면 `section_mode_args_missing`, 켠 플래그에 켜지 않은 receipt면 `section_mode_mismatch`). 검사: 응답 본문 해시·`body_sha256`, 기록된 컨텍스트와 현재 선언·문서로 선별을 다시 수행한 전달 내용 해시(`document_hash_mismatch`·`section_declaration_changed`), 기존 매니페스트·문서 최신성(원본 해시 기준). 추가 절 응답은 `verify --receipt <추가 절 응답> --parent-receipt <load 응답> --section-mode lazy`로 검증하며 부모 검증 → 부모 연결(`section_parent_mismatch`) → 절 해시·본문 해시(`section_hash_mismatch`) 순이다. `--parent-receipt`가 없으면 `section_parent_required`다 | AC-5. 추가로 가져온 절도 검증 대상이다 |

P1~P3 사이마다 소스 상태에서 `~/.opal/.venv/bin/python3 -m pytest opal/tools/event-loader/tests opal/tools/state-tool/tests`와 `event-loader static-check`를 통과시킨다. TEST 단계에서 `scripts/install-mac.sh`로 설치하고 설치 직후 설치본에서 `session.assistant`·`pm.activate`·`stage.plan` load, `static-check`, 켠 호출 1건을 확인한다. 설치 시각을 호환 종료 관찰 기록에 남긴다(기준 시점은 175의 `2026-10-01T15:17:22Z`를 유지한다 — 이번 변경은 구형 호출 의미를 바꾸지 않는다).
- 검증 범위: 결정론(보안 4건·선별·receipt·오류 코드·정적 검사), 회귀(기존 event-loader·state-tool 테스트 전체, 끈 호출 불변), 소비자(게이트 문서 정적 검사, `event-verify` 전달), 실제 연동(설치본 loader·state-tool로 게이트 통과 1회와 사본 매니페스트 거부 1회, `opal-agent` 프로브). opst 전체 파이프라인 실행은 하지 않는다.
- 실측 경계: 로드량은 load 호출 결과(본문 합계·응답 바이트)에서, 프로브 비용·시간은 `opal-agent` 실행 기록에서 읽고 서로 다른 열로 둔다. 시작은 프로브 에이전트 호출 시작, 종료는 최종 답 수신이며 재시도·대기 시간은 따로 적는다.
- 실패 시: 설치 전에는 소스 변경을 되돌린다. 설치 후 loader 결함이면 배포 전 보존한 `~/.opal/tools/event-loader` 사본(설치 직전 `cp -R`로 만든다 — install 스크립트는 백업을 만들지 않는다)으로 복원하거나 변경 커밋을 `git revert`한 뒤 `scripts/install-mac.sh`로 재설치하고 같은 세 load와 `static-check`를 확인한다. 게이트 문서가 새 플래그를 요구하는데 loader가 구버전이면 verify가 알 수 없는 인자로 실패하므로 loader와 문서는 한 번의 install로 함께 배포한다. 절 단위 로딩은 기본 꺼짐이라 되돌릴 때 `events.json`의 `sectioning`만 제거하면 실험 경로가 비활성이 된다.
