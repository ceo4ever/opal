# TASK: 근거 등급층 신설 + 확정/미확정 판정 + 트랙 자동 강등

> 작성일: 2026-08-21 | 작업 유형: 개선 | 적용 스킬: opds | 모드: agentic
> 입력: 사용자 요청 (캡틴 검토 대화)
> 출력: TASK.md

## 작업 목표

산출물 근거에 **등급·관할 체계**를 신설하고(`citation-rules.md` §9), 확정/미확정 판정을 **도구가 집행**하게 하여, 이미 확정된 설계를 파이프라인이 재도출하는 낭비와 근거 없는 추정이 확정으로 통과하는 구멍을 동시에 제거한다. 확정률을 트랙 판정 입력으로 삼아 `opd`→`opds` **하향 강등**을 자동화한다.

## 배경

파이프라인이 "아무것도 모르는 상태"를 전제로 설계되어 있는데, 실제 태스크는 대화에서 설계가 확정된 뒤 진입한다. 그 간극이 매 태스크마다 분석·설계 시간으로 청구된다. 캡틴이 여러 프로젝트에서 반복 체감한 문제다.

- `op-task/SKILL.md` TASK.md 템플릿의 `## 명확화 결과` 표에 **`의존 사실` 열이 이미 존재**한다.

- `harness/scenario-gate.md` §2가 이미 동일 패턴을 확립했다 — 루브릭 6축을 성격별로 쪼개 ②③④는 도구 결정론, ①⑤⑥은 평가자 판단으로 분리하고, "도구·평가자 어느 쪽도 상대방 축을 대신 판정하지 않는다"를 SSOT로 못박았다(`opal/core/references/harness/scenario-gate.md:16-27`).

## 확정된 설계 방향 (대화에서 합의)

> 각 항목의 `[결정]`/`[사실]` 구분과 근거는 본 태스크가 신설하려는 규칙을 자기적용한 것이다.

1. **[결정] 근거 등급은 AS-IS 5단계로 정의한다** — E1 실행 관측(실 DB·실제 응답·로그) > E2 현행 소스코드·통과 중 테스트 > E3 생성 코드(스키마 파생) > E4 프로젝트 문서 > E5 brain·code-map(파생 스냅샷). 등급 외는 근거로 인정하지 않는다(빌드 산출물·고아 화석·기억·추정).
2. **[결정] 단일 서열이 아니라 관할 2축으로 둔다** — AS-IS 질문(지금 어떻게 동작하는가)과 TO-BE 질문(무엇이어야 하는가)은 권위의 원천이 다르다. AS-IS 최상위인 소스코드는 TO-BE에서 최하위다. 단일 서열로 고정하면 코드가 항상 이겨 개선·정책변경 태스크가 구조적으로 불가능해진다.
3. **[결정] 등급 충돌 해소 규칙** — 같은 사실에 두 원천이 충돌하면 **그 사실이 생성된 지점에 가까운 쪽이 이긴다**. 스키마·타입 사실은 실 DB·생성 코드가 수기 도메인 모델을 이긴다. `[사실]` 근거: 실측 태스크에서 PLAN이 발견한 리스크 1건이 정확히 이 경로였다(수기 모델이 아니라 생성 코드에서 실제 컬럼 타입이 드러남) — **타 프로젝트 산출물이므로 경로 비기재, 본 문서 §배경 분석 (1) 참조**.
4. **[결정] brain은 근거가 아니라 근거로의 포인터** — E5 단독 인용을 금지하고 원천(E1~E4) 동반을 강제한다. `[사실]` 근거: `opal/core/references/opal-pm.md` §13 표가 brain을 "stale 가능(ingest/sync 시점 스냅샷)"으로 이미 규정한다.
5. **[결정] 결정은 등급 판정 대상이 아니다** — 캡틴의 결정은 근거가 없어도 확정이다(요구사항의 원천이므로). 단 캡틴이 *사실을 진술*하면 그것은 기억이므로 E1~E4 확인 대상이다. 이 구분이 없으면 새 요구사항이 "근거 없음 → 미확정"으로 강등되어 파이프라인이 멈춘다.
6. **[결정] 판정 주체는 6축으로 분리한다** — ① 인용 존재 ② 인용 유효(경로·줄 실존) ③ 등급 부여 ④ E5 단독 아님 = **도구**. ⑤ 뒷받침 충분성 ⑥ 관할 정합 = **PM 판단**. **루브릭 평가자 에이전트는 도입하지 않는다.**
7. **[결정] 평가자를 쓰지 않는 근거** — (a) `scenario-gate.md:14`가 평가자 도입 근거로 명시한 것은 "존재하지 않는 항목의 부재는 결정론으로 못 잡는다"인데, 근거 등급은 판정 대상이 표에 이미 적힌 항목이고 부재가 바로 기계 검출된다. (b) TASK 단계 상시 비용이므로 advanced 디스패치를 붙이면 캡틴이 지목한 추론 대기가 태스크 시작 지점에 새로 생긴다. (c) PM이 TASK.md를 쓰고 PLAN 워커가 반증하므로 생성자≠평가자가 이미 성립한다.
8. **[결정] PM 단독 판단도 채택하지 않는다** — 판정의 목적이 PM의 자기 추정을 걸러내는 것이므로, PM 판단에 맡기면 걸러낼 주체와 걸러질 대상이 같아진다. `[사실]` 근거: `의존 사실` 열이 이미 PM 판단에 맡겨져 있었고 결과는 4행 전부 `-` 였다 — **타 프로젝트 산출물이므로 경로 비기재, 본 문서 §배경 분석 (3) 참조**. 도구 측 미집행 근거는 `opal/tools/state-tool/state_tool.py:2225`·`:2299`.
9. **[결정] 게이트는 차단기가 아니라 라우터다** — 인용 없음은 태스크 차단이 아니라 해당 항목의 **미확정 강등**이다. 미확정이 남으면 ANALYSIS가 필요해지고, 그 결과 트랙이 `opd`로 승격된다. 기존 `--clarification-check`(차단형)과 성격이 다르므로 별 서브명령으로 둔다.
10. **[결정] 확정은 검증 면제가 아니라 재설계 면제다** — PLAN은 확정 항목마다 `유효`/`수정필요(근거)`/`사실오류(근거)` 3값 판정 의무를 진다. `사실오류`면 확정 지위를 박탈하고 정상 설계 경로로 복귀 + 캡틴 보고.
11. **[결정] 경로→등급 매핑은 1차에서 기본 패턴 세트만 둔다** — 프로젝트 관습 의존(생성 코드 경로 규약은 빌드 도구마다 다름)이므로 미매칭은 `unknown`으로 반환해 PM 판단(⑤⑥)으로 넘긴다. 프로젝트별 매핑 설정은 필요해질 때 추가한다(PRINCIPLES §2 — 사변적 추상화 금지).
12. **[결정] 산출물 형식 경량화 범위** — 결론을 상단에 집약하고, 상세는 품질 무해 범위에서 요약하고, 근거는 `경로:줄번호`(필요 시 약식 병기)로 대체한다. **소스코드 원문 붙여넣기를 금지**한다.
13. **[결정] 검증 자산은 전량 유지한다** — 시나리오 건수·목표-커버 게이트·evaluator를 축소하지 않는다. 문서 *형식*만 경량화한다.
14. **[결정] 2차 이월** — PM Gate 델타화, 트랙별 모델 레벨 차등, DONE.md 기계 생성은 본 태스크 범위에서 제외한다.
