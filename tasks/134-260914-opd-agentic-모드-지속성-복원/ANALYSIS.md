## Handoff

- PLAN에서 결정할 것: (1) `명시 플래그 > 유효 저장 mode > fail-closed 기본값` resolver의 명령명·입출력·오류 계약, (2) 기존 state를 보존하는 explicit mode override의 원자적 갱신·감사 기록, (3) 누락 mode와 malformed JSON/unknown mode를 구분하는 legacy 정책, (4) resolver→서브 하네스 load→state 전이의 순서, (5) `oppd→opwt`와 `opd↔opds`에서 effective mode를 전달하는 방식, (6) project-brief의 mode 표시 형식과 현재 baseline 실패 선행 처리, (7) AC-1~AC-7 통합 테스트와 install 검증 명령. 각 결정은 mode 축과 CLOSE·권한·비가역·트랙 사용자 선택 축을 분리해야 한다. (`opal/tools/state-tool/state_tool.py:66-89`, `opal/tools/state-tool/state_tool.py:970-1018`, `opal/skills/opal-pilot-dev/references/track-routing.md:12-18`)
- 착수 차단: 기존 `project-brief` 렌더 테스트 실패의 원인 분류 없이 해당 테스트 기대값/구현을 바로 변경하는 작업. 나머지 mode resolver·state 검증·nested/track 계약 설계는 착수 가능하다.
