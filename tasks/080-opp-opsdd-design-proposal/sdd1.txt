**SDD+TDD 하이브리드는 명세로 AI의 범위를 제한하고 테스트로 품질을 보장하는 강력한 조합입니다.** SDD가 "무엇을" 정의하면 TDD가 "잘 구현되었는지" 검증하는 구조로, AI 코딩 시대에 최적화된 방법론입니다. [app-place-tech](https://app-place-tech.com/ko/post/ai-sdd-tdd)

## 핵심 개념
```
SDD (명세 주도) → TDD (테스트 주도)
  ↓                    ↓
"올바른 것"          "잘 만들어짐"
(의도 명확화)        (품질 보장)
```

**Spec = Test Case** 철학: 명세가 곧 테스트 케이스가 되고, 테스트 실패가 명세를 보완하는 선순환. [app-place-tech](https://app-place-tech.com/ko/post/ai-sdd-tdd)

## 워크플로우
```
1. spec.md 작성 (SDD)
   → 사용자 스토리 + GIVEN/WHEN/THEN
   
2. 테스트 코드 생성 (TDD Red)
   → spec.md → pytest 자동 생성
   
3. AI 구현 (TDD Green)  
   → spec-kit /implement → 테스트 통과 코드
   
4. 리팩토링 (TDD Refactor)
   → ruff + pytest로 품질 개선
```

## 구현 예시 (실시간 채팅)
```md
# spec.md
## Acceptance Criteria
GIVEN 사용자가 채팅방 입장
WHEN 메시지 전송
THEN 1초내 다른 사용자 화면 표시
```

```python
# tests/test_chat.py (자동 생성)
def test_message_delivery():
    # spec.md에서 생성된 테스트
    send_message(user1, "Hello")
    assert receive_message(user2) == "Hello"  # Red→Green
```

## 도입 체크리스트
```
□ spec.md 템플릿 사용
□ pytest + ruff pre-commit 설정
□ spec→test 자동화 스크립트
□ CI에 SDD+TDD Quality Gate
□ 팀 명세 작성 가이드라인
```

**한 줄 요약**: SDD가 AI에게 "뭐할지" 말해주고, TDD가 "잘했는지" 확인하는 완벽한 1-2 펀치입니다. [news.hada](https://news.hada.io/topic?id=27675)

**SDD+TDD 하이브리드는 명세로 "올바른 것"을 보장하고 테스트로 "잘 만들어짐"을 검증하는 2단 조합입니다.** SDD가 전체 구조를 잡고 TDD가 각 세부 구현을 품질 보장하는 구조입니다. [news.hada](https://news.hada.io/topic?id=27675)

## 상세 워크플로우 (8단계)

### **Phase 1: 명세 정의 (SDD)**
```
1️⃣ spec.md 작성 (5-15분)
   - 사용자 스토리 + 수용기준
   - GIVEN/WHEN/THEN 형식
   
   예시: "GIVEN 채팅방 입장, WHEN 메시지 전송, THEN 1초내 표시"

2️⃣ 검증 스크립트 실행
   ```bash
   python scripts/validate-spec.py  # 필수 섹션 확인
   ✅ PASS → 다음 단계 진행
   ```

3️⃣ plan.md + tasks.md 생성
   ```bash
   /plan "WebSocket + PostgreSQL"
   /tasks  # 작업 단위 분해
   ```
```

### **Phase 2: 테스트 주도 구현 (TDD)**
```
4️⃣ 테스트 스켈레톤 생성 (Red)
   spec.md → pytest 테스트 자동생성
   
   ```python
   # tests/test_chat.py
   def test_message_delivery():  # spec.md에서 생성
       assert send_message("Hello") == "delivered"  # ❌ FAIL
   ```

5️⃣ 최소 구현 (Green)  
   AI가 테스트 통과 코드 생성
   ```bash
   /implement T001-websocket-server
   # 자동으로 Green 상태 도달
   ```

6️⃣ 리팩토링 (Refactor)
   ```bash
   ruff check --fix .
   pytest --cov=80
   ```

### **Phase 3: Quality Gate**
```
7️⃣ 전체 검증
   ```bash
   make ci  # spec + lint + test
   ```

8️⃣ PR 승인 → Merge
```

## 실제 프로젝트 타임라인 예시
```
Day 1: spec.md (15분) → validate ✅
Day 1: plan/tasks (20분) → AI 생성
Day 2-3: T001~T005 병렬 구현 (각 30분)
Day 4: 통합 테스트 + 리팩토링
Day 5: PR → CI → Deploy
```
