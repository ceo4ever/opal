# TASK: 워커 커밋 금지 주입 슬롯화 — 프레임워크 보증 경로 신설

> 작성일: 2026-08-21 | 작업 유형: 개선 | 적용 스킬: opds | 모드: agentic
> 입력: 사용자 요청
> 출력: TASK.md

## 작업 목표

하네스 §1 소유의 커밋 금지 규칙이 워커에게 **프레임워크 보증 경로로 도달**하도록, 워커 컨텍스트 주입 템플릿에 「전 워커 공통 고정」 항목을 신설하고, 프로젝트 문서에 복제된 우발 경로를 포인터로 축약한다.

## 배경

커밋 금지는 `opal/core/references/opal-harness.md` §1 Guards가 소유한 전 프로젝트 불변 규칙이다. 그러나 워커는 `[WORKER]` 마커로 부트스트랩 전체를 스킵하도록 설계되어 있어(`~/.opal/AGENT.md` §부트스트랩 §[WORKER 규칙]) 하네스 문서를 읽지 않는다. 따라서 PM의 **디스패치 주입만이 유일한 도달 경로**인데, 주입 템플릿에 해당 항목이 없다.

## 배경 분석 (대화에서 도출)

커밋 규칙이 워커에게 닿는 경로를 프레임워크 소스에서 전수 실측한 결과다.

| 계층 | 파일 | 커밋 금지 조항 | 워커 도달 |
|------|------|--------------|----------|
| 헌법 | `opal/core/references/../PRINCIPLES.md` (배포 `~/.opal/PRINCIPLES.md`) | 없음 (설계 의도 — 헌법은 짧게 유지) | — |
| 하네스 | `opal/core/references/opal-harness.md` §1 | **있음 — SSOT** | ❌ 워커는 부트스트랩 스킵으로 미독 |
| 주입 템플릿 | `opal/core/references/pm/dispatch-process.md` §워커 컨텍스트 주입 템플릿 | 없음 — 「전 워커 공통 고정」은 증분 저장·입력 축소 2건뿐 | ❌ 주입 슬롯 부재 |

| 단계 스킬 | `opal/skills/op-dev-execute/SKILL.md` §절대 금지 | 6개 항목 중 없음 — 표는 있는데 항목만 누락 | ❌ |

**핵심 판정 3건**

1. `docs/CONVENTIONS.md`의 커밋 조항은 **오배치**다. 프레임워크 규범상 CONVENTIONS.md의 정의는 「코드 컨벤션」이고(`opal/skills/opal-project-init/references/docs-guide.md:257`), 그 템플릿의 「커밋 규칙」 절은 커밋 **메시지 형식·단위**를 뜻한다(`docs-guide.md:284`). Guards를 CONVENTIONS.md에 기술하라는 규범은 프레임워크 전체에 0건이다.
2. 그 결과 이 조항은 **프로젝트마다 존재 여부가 달라지는 우발 경로**다. `opal-project-init`으로 생성된 신규 프로젝트의 CONVENTIONS.md에는 커밋 금지 조항이 없으므로, 그 프로젝트에서는 도달 경로가 실제로 0개가 된다.
3. 동일 규칙이 하네스 §1과 프로젝트 문서에 이중 서술된 상태이며, 이는 SSOT 값을 산문에 복제하면 반드시 어긋난다는 선례 교훈과 같은 형태다(`tasks/094-260815-opd-STATE-저널화/DONE.md` §교훈).

**참조 근거**

- `[MUST]` `opal/core/references/opal-harness.md` §1 커밋 규칙: "커밋은 사용자가 명시적으로 요청할 때만 수행한다. EXECUTE 완료, DONE.md 생성, 테스트 통과 후에도 자동으로 커밋하지 않는다. 완료 보고만 하고 사용자 지시를 기다린다."

- `opal/core/references/pm/dispatch-process.md:115` — "전 워커 공통 고정 2항목(증분 저장 · 입력 축소)은 ... 모든 워커 디스패치에 항상 포함한다 ... 근거 문서가 없는 운영 규율이다"

## 확정된 설계 방향 (대화에서 합의)

1. **주입 슬롯 신설이 1순위** — 워커가 부트스트랩을 스킵하므로 주입 템플릿이 유일한 전역 도달점이다. 성격(근거 문서 없는 운영 규율)이 기존 2항목과 동일하므로 같은 슬롯에 3번째로 넣는다.
2. **수정 대상은 프레임워크 소스** — `opal/core/...` / `opal/skills/...`를 수정한다. 배포본(`~/.opal/`) 직접 편집은 금지이며, 배포본을 고치면 다음 install에 덮여 사라지고 다른 프로젝트로 전파되지도 않는다.
3. **CONVENTIONS.md는 포인터로 축약** — 원문 복제를 제거하고 하네스 §1 포인터로 대체한다. 단 주입 슬롯 신설이 먼저 완료된 뒤 적용한다(현행 유일 경로를 먼저 끊으면 공백이 생긴다).
4. **permission/hook 계층은 이번 범위에서 제외** — 머신 로컬·플랫폼 전용 집행이라 프로젝트마다 달라지는 문제가 그대로 재현되며, 서브에이전트 permission 도달 여부 실측이 선행되어야 한다. 별도 태스크로 분리한다.
5. **외부 프로젝트 근거 인용 금지** — 이 개선의 발단이 된 타 프로젝트 사례의 경로·태스크 번호를 산출물에 기재하지 않고, 「프레임워크 주입 슬롯 부재」라는 구조적 사실로만 서술한다.

## 제약 조건

- **배포 경계**: `~/.opal/` 직접 편집 금지. 프레임워크 소스만 수정하고 install 재배포는 캡틴 지시 시 수행한다.
- **SSOT 단일화**: 커밋 규칙 원문은 `opal-harness.md` §1에만 존재한다. 다른 문서는 포인터만 둔다.
- **플랫폼 독립**: 특정 AI 도구 전용 permission·hook 집행 장치를 추가하지 않는다.
- **커밋 규칙**: 이 태스크 자체도 자동 커밋하지 않는다.
- **외부 프로젝트 비참조**: 발단 사례의 프로젝트명·경로·태스크 번호를 산출물에 기재하지 않는다.
- **변경이력**: 변경이력 표가 있는 파일에는 행을 추가한다. 표 일괄 제거 방침은 별도 태스크 범위다.
