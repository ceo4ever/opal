## 작업 목표

`opal/core/AGENT.md` §보고 형식(보고 형식 SSOT)에 **행동 규칙 6건 + 마크다운 어휘표 + 골격 3블록화**를 반영하여, 모든 프로젝트 알투(PM)의 보고가 읽는 즉시 행동으로 이어지도록 개정한다.

## 배경

현행 §보고 형식은 골격(🎯 결론·근거 → ▶️ 진행)과 5개 원칙만 규정한다. 실제 보고 3건을 표본 검토한 결과, 형식은 지켰으나 아래가 반복 발생했다.

- 첫 줄이 상황 서술이라 무엇을 할지 모른 채 본문을 읽어야 한다.
- 소요 시간이 없어 "지금 할지 미룰지"를 판단할 수 없다.
- `▶️` 블록에 승인 요청·정보 보고·질문이 섞여 결정 비용이 캡틴에게 전가된다.
- 마크다운 요소의 용도가 고정돼 있지 않아 같은 정보가 매번 다른 형태로 나온다.

## 확정된 설계 방향 (대화에서 합의)

- `[결정]` **B안 채택** — 원본 스킬을 community skill로 설치하지 않고, 신규 가치만 프레임워크 SSOT에 흡수한다. 근거: `.opal/AGENT.md` 「프레임워크-우선 개선 원칙」 + 토글 인프라 부재.
- `[결정]` 골격을 **2블록 → 3블록**으로 확장한다 — `## 🎯 결론·근거` / `## 📌 잔여·보류·유의` / `## ▶️ 승인 요청`.

- `[결정]` 시스템 원문은 **표(출처 열 포함)**로 기재한다. 코드펜스는 복붙 실행 명령 전용.
- `[결정]` 철회 표기는 `**정정**` 라벨을 쓴다 (취소선 미렌더).

- `[결정]` `▶️` 블록은 체크리스트(`- [ ]` 승인 필요 / `- [x]` 권고 확정)로 쓰고, **질문은 1개로 수렴**한다.

- `[결정]` `AskUserQuestion` 도구는 **선택지가 실제로 대등할 때만** 쓴다. 답이 선 사안은 체크리스트 + 텍스트 확인.
- `[사실]` 원본 스킬 문장을 복제하지 않고 규칙 아이디어만 차용하므로 MIT 고지 의무는 발생하지 않는다. 근거: 산출물에 원문 인용 0건.
- `[결정]` `owner_name` 하드코딩 83건은 **별건 태스크**로 분리한다.
