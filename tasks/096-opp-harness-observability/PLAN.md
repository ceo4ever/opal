## 2. 설계 결정: `대기 중` 처리

**현재 의미**: `대기 중` = 단계 완료 후 다음 단계 시작 전 과도기 상태  
**이번 변경 후**: Gate 단계들이 세분화됨 — QA Gate 대기 → PM Gate 대기 → 사용자 확인 대기

**결정**: `대기 중` 제거하고 Gate 단계로 대체한다.
- 근거: `대기 중`은 "어떤 Gate를 기다리는 중인가"를 표현하지 못함. Gate 세분화로 기존 역할이 `QA Gate 대기`로 대체됨.
- 기존 `완료 / 진행 중 / 블로커` 의미는 유지.
- 추가작업 상태(`추가작업중 / 추가작업완료`)는 기본 Gate 흐름과 독립된 상태이므로 그대로 유지.
- 병렬 실행 State(oppd)는 별도 상태값 체계를 사용하므로 영향 없음.

**새 상태 전이 흐름**:
```
진행 중 → QA Gate 대기 → PM Gate 대기 → 사용자 확인 대기 → 완료
완료 → 추가작업중 → 추가작업완료
      ↑___________________추가작업 반복 시___↓
```

```markdown
### 행위 주체 표시

PM은 툴 호출 직전/직후 한 줄 선언으로 행위 주체를 명시한다.

| 선언 형식 | 사용 시점 |
|----------|---------|
| `📋 알투[PM] 직접:` | PM이 직접 툴을 호출하기 직전 (Edit, Write, Read 등) |

| `⚙️ 워커 완료:` | 워커 결과 수신 직후, 결과 요약 전 |

**규칙**:
- 선언은 한 줄을 초과하지 않는다
- 기존 응답 첫 줄 표시(`📋 알투[PM]: {NNN} {태스크명} | {단계}`)는 유지된다 (대체 아닌 추가)
- PM 직접 툴 호출이 연속될 때는 매 호출 직전 선언한다
```

## 6. 리스크

### R1: `대기 중` 제거로 인한 기존 STATE.md 호환성

- **위험**: 기존 태스크의 STATE.md가 `대기 중` 상태를 가진 경우 하네스 체크가 실패할 수 있음
- **영향 범위**: 진행 중인 태스크의 세션 복원 시
- **대응**: 하네스 State Gate에서 `대기 중`을 레거시 값으로 허용하는 호환 규칙을 추가하거나, 변경이력에 "기존 STATE.md는 `대기 중` → `QA Gate 대기`로 수동 마이그레이션 권장" 안내 추가
- **판단**: 현재 진행 중인 태스크(094, 095, 096)가 있으므로, 하네스에 레거시 허용 노트 추가 권장

### R2: opsdd/opwt의 Gate 구조 불일치

- **위험**: opsdd/opwt는 Gate 구조가 달라 새 상태값 체계가 맞지 않을 수 있음
- **영향 범위**: opsdd/opwt 스킬 실행 시 State Gate 혼란
- **대응**: TASK.md 제약에서 명시적으로 제외되어 있음. opal-harness.md에 "(opsdd/opwt는 후속 태스크에서 별도 처리)" 주석 추가 권장

### R3: 행위 주체 선언의 과도한 노이즈

- **위험**: 연속 툴 호출 시 매번 선언하면 응답이 장황해짐
- **영향 범위**: 사용자 경험 (캡틴 리뷰)
- **대응**: 규칙에 "연속 동종 툴 호출 시 최초 1회 선언 후 생략 가능" 허용 조항 추가 검토. TASK.md에서는 "간결해야 한다 — 한 줄 초과 금지"만 명시하므로 연속 호출 처리는 구현 시 결정

### R4: 변경이력 누락

- **위험**: opal-harness.md, opal-harness-interactive.md 변경이력 미갱신 시 버전 추적 불가
- **대응**: 실행 체크리스트에 변경이력 갱신 항목 포함 (QA 체크리스트에도 반영됨)
