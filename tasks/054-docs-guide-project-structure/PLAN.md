#### 1. docs-guide.md 변경 설계

**변경 위치**: 56~81행 (PROJECT.md "프로젝트 구조" 섹션)

**추가할 내용**:

(a) **관점 선언 추가** — 섹션 도입부(58~59행 부근)에 관점/독자/핵심 질문 명시:
```
관점: PM 탐색 맵 — PM과 오케스트레이터가 "이 문서/폴더 어디서 찾지?"에 답하는 섹션.
```

(b) **3문서 역할 분리 테이블 추가** — "프로젝트 구조" 도입부 바로 아래에:

| 문서 | 관점 | 독자 | 핵심 질문 |
|------|------|------|----------|
| PROJECT.md "프로젝트 구조" | PM 탐색 맵 | PM, 오케스트레이터 | "이 문서 어디서 찾지?" |
| ARCHITECTURE.md "디렉토리 구조" | 기술 구조 | 개발 워커 | "코드가 어떻게 구성되어 있지?" |
| CONVENTIONS.md "네이밍 규칙" | 작성 규칙 | 코드 작성자 | "파일명을 어떻게 짓지?" |

(c) **폴더 구조맵 가이드 범위 한정** — 현재 "Phase 1에서 분석한 프로젝트 레이아웃을 기반으로 작성"만 있음. 다음을 추가:
- 폴더 구조맵은 **문서/산출물 폴더** 중심으로 작성 (PM이 탐색할 대상)
- 코드 내부 구조(모듈, 레이어)는 ARCHITECTURE.md에 기술
- 각 폴더 설명은 "여기에 어떤 종류의 산출물이 있는지" 수준 (구현 상세 X)

(d) **네이밍 규칙 가이드 범위 한정** — 현재 "PM/워커가 Glob으로 파일을 탐색할 때 활용"만 있음. 다음을 보강:
- 여기서의 네이밍 규칙은 **PM이 Glob 패턴으로 문서를 동적 탐색**하기 위한 패턴
- 코드 변수/함수/클래스 네이밍은 CONVENTIONS.md에 기술
- 파일/폴더의 범용 네이밍 규칙(kebab-case 등)도 CONVENTIONS.md 소관

(e) **작성 규칙 보강** — 기존 5개 규칙에 역할 경계 규칙 추가:
- 코드 디렉토리의 내부 구조(모듈 분해, 레이어)는 기술하지 않는다 — ARCHITECTURE.md 소관
- 네이밍의 "왜"(규칙/컨벤션)는 기술하지 않는다 — CONVENTIONS.md 소관. 여기서는 "무엇"(패턴)만 기술
