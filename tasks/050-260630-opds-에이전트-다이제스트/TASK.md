## 작업 목표

`opal/core/AGENT.md`(부트스트랩 SSOT)를 **lean core(~205줄)** 로 다이제스트한다. PM/프로젝트 전용 섹션을 Phase B 로드 문서(`opal-pm.md` 등)로 이관하고, 비런타임 메타(부트스트래퍼 자동관리·변경이력)를 정리하여 **비서 tier 매 세션 로드를 ~58% 경감**한다. 동작(부트스트랩 절차·2-tier 게이트)은 불변(회귀 0).

## 배경

태스크 049로 부트스트랩이 2-tier가 되면서 AGENT.md(493줄/~24.8k자)가 **비서 tier에서 매 세션 전량 로딩**된다. 그러나 내용의 ~58%(PM/프로젝트/설정/메타)는 비서 세션에 불필요하다. 이미 Phase B로 로드되는 `opal-pm.md`로 PM 섹션을 이관하면, PM 세션은 토큰 중립(이동)·비서 세션은 대폭 경감된다.

## 확정된 설계 방향 (대화에서 합의)

캡틴 선택: **"PM 이관 + 메타 정리"** (신규 파일 분리·제자리 압축 대비). 핵심:
1. AGENT.md = 비서 코어만 유지(~205줄).
2. PM/프로젝트 섹션 → Phase B 로드 문서(`opal-pm.md` 우선, 하네스 모드류는 `opal-harness.md` 적합 시)로 이관. **기존 커버리지 확인 후 중복 제거 병합**.
3. 부트스트래퍼 자동관리 → reference 문서(예: `references/bootstrapper-management.md`)로 이관(설치시점 가이드, 런타임 비행동).
4. 변경이력 → 최근 5개 + git 링크로 trim.
5. 교차참조(`AGENT.md §...`) 전수 grep 후 새 위치로 갱신.

## 요구사항

- [ ] **R-1 (AGENT.md lean core)**: 비서 코어 섹션(부트스트랩·정체성·핵심역할·비서/PM 상태정의·도구맵·주도성·보고형식)만 AGENT.md에 유지. **어디에**: `opal/core/AGENT.md`. **AC**: PM 이관 대상·메타 정리 대상 섹션이 AGENT.md에서 제거되고, 부트스트랩 절차·2-tier 게이트·완료보고는 보존된다.
- [ ] **R-2 (PM 섹션 이관)**: 역할전환 상세(하네스 3-way·L2·자동전환·오버라이드)·code-scan 활용·opal-brain 활용·메모리 브리핑·모델매핑 적용·프로젝트 컨텍스트를 Phase B 문서로 이관. **AC**: 각 섹션이 목적지 문서(opal-pm.md 등)에 존재하고, 기존 동일 내용과 **중복 없이 병합**된다(dedup 확인).
- [ ] **R-3 (부트스트래퍼관리 이관)**: "프로젝트 부트스트래퍼 자동 관리" 절을 reference 문서로 이관. **AC**: AGENT.md에는 1줄 포인터만 남고, 상세는 reference 문서에 존재. install 어댑터 동작은 불변.
- [ ] **R-4 (변경이력 trim)**: AGENT.md 변경이력을 최근 5개 + 전체 이력 git 링크로 축약. **AC**: 변경이력 표가 ≤5행 + "전체 이력: git log" 안내.
- [ ] **R-5 (교차참조 갱신)**: `AGENT.md §...` 형태 교차참조를 전수 grep하여 이동된 섹션은 새 위치로 갱신. **AC**: 프로젝트 전체에서 이동 섹션을 가리키는 dangling 참조 0(grep 검증).
- [ ] **R-6 (동작 불변·회귀 0)**: 부트스트랩 Eager 절차·2-tier 게이트·`//opi` 불변식·완료보고·비서 코어 정보가 손실/변형되지 않음. **AC**: 049 TS-001~004(2-phase·게이트·`//`·step0) 재실행 PASS + 비서 코어 정보 완결성 점검.

## 제약 조건

- 배포 경계: 소스(`opal/core/`)만 수정. install 재배포는 캡틴.
- **동작 불변**: 이 작업은 "이동·정리"이지 "의미 개정"이 아니다. 섹션 내용의 행동 규칙을 바꾸지 않는다.
