# TASK: OPAL 하네스 개선 — 배치 실패 감지 + 검증 체크포인트 + 폴백 반복 제약

> 작성일: 2026-04-02 | 작업 유형: 개선 | 적용 스킬: opp
> 입력: 캡틴 피드백 (하네스 실전 운용 3건 — 배치 간 패턴 감지 부재, agentic 검증 체크포인트 추상화, Guards 폴백 반복 규칙 없음)
> 출력: opal-harness.md 수정, opal-harness-agentic.md 수정

## 작업 목표

하네스의 PM 대행 품질 보증 장치를 강화한다. 3개 개선이 모두 `opal-harness.md`와 `opal-harness-agentic.md`를 건드리므로 한 태스크에서 처리한다.

## 배경

wtm 21개 URL 처리 태스크에서 발견된 하네스 수준의 3가지 공백:

1. **배치 패턴 감지 부재**: Batch 1-1의 7개 워커가 전부 동일 폴백 패턴을 반환했음에도 PM이 패턴을 인식하지 못하고 Batch 1-2, 1-3을 동일하게 디스패치 → 21회 동일 실패 반복, 1시간+ 소요. 배치 수준 집계 규칙이 없었던 것이 원인.

2. **검증 체크포인트 추상화**: agentic 하네스에 "산출물을 직접 Read하여 내용 수준까지 검증" 의무가 있으나, **무엇을** 확인할지 구체적 항목이 없어 워커 보고 텍스트만 보고 Pass 판정하는 케이스 발생. 추출 방식이 TASK.md 요구사항과 달라도 감지하지 못함.

3. **폴백 반복 제약 부재**: 하네스 §1 Guards의 자동 루핑 제약은 lint/build/test만 다룸. 워커가 동일 폴백을 반복해도 하네스 상 위반이 아니므로 PM이 정상 동작으로 간주할 근거가 됨.

## 제약 조건

- O1의 과반수 기준(50%)은 조정 가능한 임계치로 명시 (향후 오케스트레이터별 오버라이드 여지).
- O2의 미승인 폴백 = Fail 원칙은 "자율 개선 금지"가 아니라 "TASK.md 이탈 감지"임을 명시. 더 나은 방법으로의 개선은 PM이 승인하면 허용.
- O3의 폴백 1회는 허용 (URL fetch 실패 → Playwright 전환은 정상). **2회 반복**이 트리거.
- interactive 모드에서도 O1, O3 규칙이 동일하게 적용됨.
