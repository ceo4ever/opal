> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: worktree `/Volumes/Data/AIStudio/workspace/ai-framework/.opal-worktrees/task_161`, macOS. 소스 test-tool은 `bash opal/tools/test-tool/run.sh`(내부적으로 `~/.opal/.venv/bin/python`)로 실행한다. 공개 인터페이스는 stdout 단일 JSON과 process exit만 판정한다.
- 기준선: 변경 전 test-tool 전체 회귀는 23 failed·529 passed·3 skipped이며 실패는 E2E SUT 기동 계열 4개 파일이다(`evidence/baseline-test-tool-suite.txt`, PLAN §Approach).
- 격리: 결정론 시나리오는 OS 임시 폴더에 프로젝트를 만들고 `OPAL_TEST_TOOLS_GLOBAL`을 제거한 환경에서 실행한다(전역 템플릿 개입 차단). 전역 경로를 검증하는 행만 이 변수를 명시 주입한다.
- 대역 사용과 한계: S-1~S-7은 계층 명령을 임시 폴더의 stub 셸 스크립트로 대체한다. stub은 받은 argv와 호출 사실을 표식 파일에 남기고 지정 exit로 끝난다. 대역은 실행기의 분기·기록 계약만 검증하며 실제 도구 동작의 증거가 아니다. 실제 도구 동작은 S-9·S-10이 따로 확인한다.
- RED 테스트 위치: `구현 전 RED` 행은 `opal-test-agent`(red mode)가 `opal/tools/test-tool/tests/test_red_s161_unit_contract.py`에 공개 CLI 기준으로 작성하고 실패를 기록한다. 구현 워커는 이 파일의 기대 계약을 약화·삭제하지 않는다.
- 실제 도구 공급(H-1): ruff는 설치본(`/opt/homebrew/bin/ruff`, 0.15.17), pytest는 설치본(`/opt/homebrew/bin/pytest`, 9.1.0)을 쓴다. mypy는 태스크 임시 폴더에 `uv venv` 후 `uv pip install mypy`로 만든 격리 venv의 `bin`을 PATH 앞에 둔다. TS 도구는 작업본 `dashboard/frontend`에서 `npm ci`를 실행한 뒤 그 `node_modules`를 사례 프로젝트에 심볼릭 링크로 연결한다. 공급에 실패하면 해당 행은 BLOCKED이며 통과로 기록하지 않는다.
- 증거 보존: 실제 도구 실행의 stdout JSON·exit·도구 버전은 `evidence/real-tools/`, 배포본 검증은 `evidence/deploy/`에 저장한다.
- 실행 조건: S-13 직전 정식 설치는 사용자 승인 후에만 수행한다(PLAN D-11). 그 밖에는 자동 실행한다.
