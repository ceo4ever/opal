# TASK: 검증 도구 실행 정확성 복구

## Problem

test-tool unit은 설치 확인용 check 명령을 검증 명령으로 실행하며, 실행 계층이 없어도 ok=true를 반환할 수 있다 (`opal/tools/test-tool/lib/runner.py:133`). 기본 템플릿에는 --version 명령이 선언돼 있다 (`opal/templates/test-tools.yaml:49`). 변경 파일 인자는 실행기에 전달되지 않고 (`opal/tools/test-tool/test_tool.py:163`), Python 추론 lint 명령은 ruff .이다 (`opal/tools/test-tool/lib/resolver.py:142`). 그 결과 설치 확인과 실제 코드 검증의 성공·실패가 혼동된다. 요청 근거는 같은 폴더 REQUEST.md의 A1 및 공통 계약이다.

## Proposed outcome

설치 확인과 실제 검사를 구분하고, 사용자는 실제 실행한 검사의 명령·범위·결과·설정 출처를 확인한다. 검사 미실행은 통과로 소비되지 않는다. 새 실행기 대신 기존 test-tool을 보완하며 실제 도구로 정상·위반 양쪽 사례를 검증한다.

## Affected users and systems

test-tool 실행기·설정 해석·스키마·템플릿·회귀 테스트와 해당 입출력에 의존하는 스킬·에이전트·하위 문서 소비자를 포함한다. 시작 시 소비자 목록을 확정하고 영향 있음/없음 근거로 범위를 닫는다. GC 판정 문서 정합(A2), GC 빠른 완화(B), 증거 게이트 도입(C), 증분 통합(D), 과거 호출 후보 조사와 기준선 보존은 분리 작업이다. 전체 합의와 후속 범위는 REQUEST.md에 보존한다.

## Constraints

- C-1: docs/CONVENTIONS.md의 배포 경계·플랫폼 독립성·상태 도구 사용 규칙을 유지한다. 배포본 직접 수정 없이 소스 변경 후 정식 install과 배포본 검증을 수행한다.
- C-2: check는 설치 확인, install은 설치, run은 실제 검사다. run 누락 시 check를 실행 검사로 묵시 대체하지 않는다. 사용자 기존 check를 임의로 run으로 복사하지 않는다.
- C-3: 기존 러너를 재구현하거나 프로젝트 자연어 규칙 번역기·범용 캐시·LLM 추가 분할을 도입하지 않는다.
- C-4: 실행 결과 상태·사유와 의미는 test-tool 계약 한 곳에 정의한다. GC 대응 판정의 소유자는 gc-finding-schema이며 이 태스크에서 별도 판정표를 복제하지 않는다.
- C-5: 요청 변경 파일과 실제 검사 범위를 구분한다. 파일 단위 검사를 지원하지 않는 도구에 임의 인자를 붙이지 않는다.
- C-6: 검증 요구와 증거 연결은 기존 TEST-SCENARIO/test-scenario.json 소유 경계를 존중한다. PLAN Work items 열을 추가하지 않는다.
- C-7: 허브의 미커밋 변경·타 태스크 파일을 수정하거나 포함하지 않는다. 기존 사용자 설정 이관과 외부 영향 결정은 근거를 남긴다.

## Acceptance criteria

- AC-1: 코드·스킬·에이전트·하위 문서 소비자 목록에 사용 서브명령·의존 필드·이관 또는 영향 없음 근거가 있고 영향 있는 경로에서 새 계약을 확인한다.
- AC-2: 설치 확인 성공·run 누락·빈 실행이 실제 코드 검사 통과로 소비되지 않으며 검사 실패와 설치 확인 실패를 구별한다.
- AC-3: 실제 run 명령이 실행되고 명령·실행 디렉터리·설정 출처·실제 검사 범위·결과가 공개 CLI 출력 또는 연결 증거로 관측된다.
- AC-4: 전역 템플릿·추론 출력·스키마·소비자가 새 실행 계약을 사용하며, 설치 확인을 unit 검사로 실행하는 구형 경로가 남지 않는다.
- AC-5: 기존 설정과 실제 검사 명령이 check에 들어 있는 설정의 명시적 이관, run 누락, 선행 검사 실패, 범위 지원/미지원 사례가 공개 CLI 검증을 통과한다.
- AC-6: Python 추론 경로를 포함한 지원 run 명령을 고정 정상/위반 사례에서 실제 도구로 실행하여 성공·실패 양쪽을 확인하고 버전·출력을 보존한다. 문자열 검사나 mock만으로 충족하지 않는다.
- AC-7: 기존 관련 회귀 검사를 통과하며, 실패 시 미실행인 후속 계층을 통과로 보고하지 않는다.
- AC-8: 정식 install 경로로 배포 후 배포된 실행기·스키마·전역 템플릿 및 신규 셸 설정 해석을 검증하고 결과를 남긴다.
