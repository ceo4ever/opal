# TEST-SCENARIO: 검증 시간 단축 — 실호출 최소화·컨벤션 검사 경량화·판정 병렬화

> 입력: [TASK.md](TASK.md), [PLAN.md](PLAN.md) | 작성자: PM

## Setup

- 환경: macOS, 이 워크트리(`feat/OP-TASK-172`), `~/.opal/.venv/bin/python3`(`unittest`·`pytest`), `node`, `git`, `claude` CLI. 시험은 임시 폴더와 임시 git 저장소만 쓰고 이 태스크의 `state.json`·`test-scenario.json`을 수정하지 않는다.
- 공통 데이터: 설계 게이트 평가 문서는 `tasks/170-261001-opds-설계-게이트-회차-단축/run/eval-set/`의 사례 폴더를 읽기 전용으로 쓴다. 컨벤션 과거 사례는 `git worktree add --detach <임시>`로 체크아웃하고 끝나면 `git worktree remove`로 제거한다.
- 대역 사용과 한계: 사용하지 않음. 실제 에이전트 호출은 S-12·S-13에서만 하며 나머지 시나리오는 기록된 결과 파일을 입력으로 쓰는 결정론 시나리오다. 모델 판단 자체가 수용 기준인 AC-2·AC-8만 실호출을 쓴다.
- 실행 조건: 자동 실행(사람 협업 없음). 실호출은 `opal-test-agent`가 Bash로 `claude -p --agent <이름>`을 실행하고 원본 JSON 응답을 증거 파일로 저장한다. 호출이 불가능하면 `blocked`로 반환한다. S-17은 EXECUTE의 배포(W-11) 뒤에만 실행한다.
- 병렬 그룹: S-1, S-2, S-3, S-4, S-5, S-6, S-7, S-8, S-9, S-10, S-11 — 서로 선행 관계가 없고 각자 임시 폴더만 쓰며 공유 자원(포트·`~/.opal`·이 태스크 상태 파일)을 쓰지 않는다. 나머지는 순차로 실행한다.
