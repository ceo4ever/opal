**제안**: PLAN에 아래 정보 추가:
- AGENT.md의 어느 섹션(예: "## 기억과 학습" → "### 메모리 로드 우선순위") 에 어떤 내용을 추가할지 구체적인 diff 또는 마크다운 스니펫 제공
- 예:
  ```markdown
  부트스트랩 시 메모리 로드 우선순위 (context-compactor v1.0 이상):
  1. {프로젝트}/.opal/memory/archive/COMPACTED.md 존재 → 이것만 로드

  ```

**효과**: SKILL.md 작성 시 AGENT.md 수정 부분의 모호함 제거 → 실행 체크리스트 정확성 상승.

### 2. 우선 — CLASSIFY 단계의 휴리스틱/프롬프트 예시 추가 (중요도: 중간)

**현황**: §2.1 "Step 1: CLASSIFY" 에서 6가지 유형만 나열. LLM이 이를 자동으로 분류하는 방법 미명시.

**제안**: PLAN에 아래 2가지 추가:
- **휴리스틱 예시**: 각 유형을 식별하는 패턴
  - `[decision]`: "결정했다", "선택했다", "~하기로 했다", "이유는", "because"
  - `[fact]`: "API 제한", "환경에서는", "표준에 따르면"
  - 등등
- **LLM 프롬프트 템플릿**: CLASSIFY 단계에서 사용할 프롬프트의 대략적 형태
  ```
  다음 텍스트를 [decision] / [fact] / ... 중 하나로 분류하시오.
  근거: ...
  ```

**효과**: SKILL.md 작성자(또는 사용자)가 LLM을 호출할 때 무엇을 요청할지 명확함 → 일관성 있는 분류 확보.
