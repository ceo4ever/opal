# TASK: 부트스트랩 이벤트 하네스 경량화

## Problem
OPAL 프로젝트 진입 시 전역 에이전트 정의가 공통 하네스와 PM 문서를 Eager로 읽도록 지시하고 있어, 일반 인사와 비서 대화에도 프로젝트 실행 규칙 전체가 초기 컨텍스트에 올라온다 (`opal/core/AGENT.md` §부트스트랩 Phase B). 공통 하네스는 Guards뿐 아니라 모드, 워크트리, State, TASK, 디스패치, 병렬 처리, EXECUTE 규칙의 라우팅과 일부 본문까지 함께 보유한다 (`opal/core/references/opal-harness.md` §1~§10). 세부 모듈의 Lazy 로드 시점은 선언되어 있지만, 마커·세션·파일럿·단계·워커 이벤트에서 필수 원문이 실제로 로드되었는지를 일관되게 집행하는 계약이 없어 초기 지연과 규칙 누락 위험이 공존한다 (`opal/core/references/opal-harness.md` §2 모듈 구조).

## Proposed outcome
세션 부트는 최소 비서 커널과 제한된 프로젝트 메모리 브리핑까지만 수행하고, PM·파일럿·단계·워커 규칙은 표준 이벤트가 발생할 때 최신 원문을 필요한 만큼만 로드한다. 공통 하네스 산문은 실행 소유자별 기존 문서 또는 필요한 신규 문서로 이관하고, 이벤트 레지스트리와 결정론적 로더·검증 게이트가 필수 문서 로딩을 관측 가능하게 집행한다.

## Affected users and systems
영향 대상은 OPAL을 사용하는 사용자와 PM·파일럿·전문 워커·액션 에이전트이며, Claude Code·Cursor·Gemini·Codex 부트스트래퍼, 전역/프로젝트 에이전트 정의, 하네스·PM 참조 문서, 파일럿·에이전트 프롬프트, 상태·설치·검증 도구가 포함된다. OPAL과 무관한 애플리케이션 기능, 기존 태스크 112의 산출물과 소스 변경은 범위에서 제외한다.

## Constraints
- C-1: 비서와 PM의 역할 의미를 보존하면서 일반 비서, 프로젝트 인지 비서, PM 활성 상태를 구분해야 한다.
- C-2: `[WORKER]`, `[ASSISTANT]`, 무마커, `bootstrap: off`의 우선순위와 기존 안전 의미를 보존하고 표준 이벤트로 관리해야 한다. `bootstrap: off`는 설정 게이트 이후 identity·principles·memory·PM·harness를 포함한 OPAL 문서를 0건 로드하는 순수 모드이며, 후속 `worker.dispatch` 문서를 읽을 수 있는 `[WORKER]` 경로와 구분한다.
- C-3: 이벤트별 필수 문서는 단순 포인터가 아니라 실행 시점에 전문이 컨텍스트로 로드되어야 하며, 누락·오래된 해시·잘못된 이벤트는 진행을 거부해야 한다.
- C-4: 공통 하네스 본문을 복제하지 않고 각 규칙의 실행 소유 문서를 단일 SSOT로 정해야 한다.
- C-5: 플랫폼별 차이는 설치·부트스트래퍼 어댑터에만 격리하고 이벤트·하네스 로직은 플랫폼 독립적으로 유지해야 한다 (`opal/core/PRINCIPLES.md` §Core Stance).
- C-6: 프로젝트 인지 비서의 부트 메모리는 본문과 긴 작업 결과를 포함하지 않는 제한된 요약이어야 한다.
- C-7: 소스 변경은 프로젝트 저장소에서 수행하고 설치 경계를 통해 `~/.opal/` 배포본과 검증해야 한다 (`.opal/AGENT.md` §프로젝트별 추가 지침).
- C-8: 기존 dirty 변경과 태스크 112 작업본을 보존하고 이번 변경은 태스크 113 worktree에서만 수행해야 한다.
- C-9: 커밋·머지·worktree 제거와 CLOSE 진입은 사용자 명시 승인 없이는 수행하지 않아야 한다 (`opal/core/references/opal-harness.md` §1 Guards).

## Acceptance criteria
- AC-1: 일반 비서 및 프로젝트 인지 비서의 선언된 Eager 문서 payload가 현재 기준 대비 최소 70% 감소하고 30KB 이하이며, 공통 `opal-harness.md`·전체 `opal-pm.md`·전체 `docs/PROJECT.md`가 부트 로드 목록에서 제외된다.
- AC-2: 프로젝트 인지 비서는 PM을 활성화하지 않은 채 프로젝트 존재를 감지하고, 최대 3개·총 1KB 이하의 메모리 요약만 로드한다.
- AC-3: 마커와 세션 조건이 `session.disabled`, `session.worker`, `session.assistant`, `session.project` 이벤트로 결정론적으로 해석되고 우선순위 회귀 테스트를 통과한다. `session.disabled`의 이벤트 문서 payload는 0건·0 bytes다.
- AC-4: 프로젝트 작업 또는 `//` 커맨드가 `pm.activate`와 후속 파일럿·단계 이벤트를 발생시키며, 이벤트별 필수 문서가 단일 레지스트리에서 해석된다.
- AC-5: 이벤트 로더가 필수 문서 전문과 현재 해시를 반환하고, 누락 문서·stale 영수증·이벤트 불일치 시 구조화 오류로 진행을 거부한다.
- AC-6: `opal-harness.md`의 기존 산문은 실행 소유자별 문서로 이관되고, 구형 본문 잔존과 규칙 복제가 0건이며 기존 참조는 새 SSOT 또는 호환 인덱스로 연결된다.
- AC-7: `[WORKER]` 경로는 전역 부트 없이 디스패치 이벤트에 필요한 워커 규칙만 로드하고, 이벤트가 없는 워커 요청을 거부한다.
- AC-8: 파일럿·단계·워커 이벤트의 필수 로딩 계약 누락을 정적 검사가 탐지하며, 기존 파일럿 전건과 지원 플랫폼 부트스트래퍼의 회귀 테스트가 통과한다.
- AC-9: `./scripts/install-mac.sh` 배포 후 소스와 `~/.opal/`의 이벤트 레지스트리·로더·하네스 문서가 배포 정책상 허용된 차이를 제외하고 일치한다.
- AC-10: cold-start 측정 절차와 변경 전·후 Eager payload 및 실행 시간 결과가 태스크 산출물에 기록된다.
