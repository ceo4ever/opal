| # | `None` 경로 | 실측 근거 | TS 커버 |
|---|------------|----------|---------|
| 1 | `(md_dir / file_field).resolve()` 예외 | `:806-809` `except Exception: return None` | TS-035 ③ |
| 2 | `target.relative_to(memory_dir)` ValueError (경로 탈출) | `:812-815` | TS-034, TS-035 ①, TS-005, TS-036 |

**전수성 검증** — 호출부에서 `mem_file`이 `None`이 될 수 있는 경로는 위 3개가 전부다. 파생 입력도 전부 3개 중 하나로 귀착함을 확인했다:
- `file` 키 부재 / `null` → `row.get("file","")` falsy → 경로 3
- 공백만(`"   "`) → truthy → `.strip()` 후 `""` → `md_dir`로 해석 → `relative_to` ValueError → 경로 2
- `memory/` 내부 심볼릭 링크가 외부를 가리킴 → `.resolve()`가 링크를 따라감 → 경로 2 (안전측 거부)
- 백틱 감싸짐(`` `memory/x.md` ``) → `:804` strip으로 정상 해석 (None 아님)

**비-None 오판 벡터도 없다**: 해석 성공 후 `mem_file.exists()`가 True면 `memory_file_exists` 거부(디렉토리·대소문자 변형 포함 안전측). 삭제로 이어지는 유일한 조건은 "해석 성공 AND 본문 부재"뿐이다.

**가드 구조 검증 (PLAN §3.2.2 최종 코드)**:

```python
if mem_file is None:
    err("delete", "memory_file_unresolvable", file=file_field)
if mem_file.exists():
    err("delete", "memory_file_exists", path=str(mem_file))
if not ref:
    err("delete", "orphan_ref_missing")
```

`err()`가 `sys.exit(1)`(`:159-160`)이므로 조기 반환 구조다. 개정 전 `if mem_file is not None and mem_file.exists()`는 `None`을 **조용히 통과**시켰으나, 현 구조에서는 `None`이 통과 자체가 불가능하다. PLAN이 주장한 "결함 형태가 코드 구조상 재발 불가능"은 **검증되는 주장**이다 — 자기 유리한 수사가 아니다.

**결론**: TS-034(경로 탈출 + 본문 실재 = P0 최악 벡터)·TS-035(3경로 전수)가 `None` 3경로를 실제로 전수한다. **커버되지 않은 잔여 blind-삭제 벡터는 발견되지 않았다.** G-3은 실질 해소다.

## 3. 지시받은 엄격 검토 4항 — 개별 판정

### 3.1 [MUST 2] 새 고착의 정당성 — **정당하다. 단 R-13·TS-037의 사실 기술이 과장됐고, 정정 없이는 [MUST] 무변경 불변식을 위반하도록 워커를 유도한다**

**(a) 정당성 판정: 정당하다.** 4가지 실측 근거로 판단했다.

1. **"신설"이 아니다 — 선재하는 고착이다.** 현 배포 코드에서 `{active, promoted, candidate}` × 해석 불가 행은 이미 제거 불가다(`memory_tool.py:1355-1357` 상태 가드), `promote`도 이미 거부하며(`:1164-1166` `memory_file_not_found`), `cmd_update`(`:1062-1125`)는 `file` 필드를 다루지 않는다. **096은 이 클래스를 만들지도 넓히지도 않았다** — 신설된 `--orphan`의 구제 범위에 포함시키지 않았을 뿐이다.
2. **096은 이 클래스를 개선한다.** 종전에는 `review`가 아무것도 말하지 않는 **침묵 고착**이었으나, 이제 `memory_file_unresolvable`로 표면화된다(TS-005·TS-036). 진단 불가 → 진단 가능은 순개선이다.
3. **구제를 포기한 대가가 곧 P0 결함 회피다.** 해석 불가 행에 orphan 정리를 허용하는 것이 바로 G-3 결함 그 자체였다(본문이 `memory/` 밖에 실재할 수 있음 — PLAN §3.2.2 실증). 무손실 체계에서 "증거 없음"을 "부재"로 승격시키지 않는 것은 트레이드오프가 아니라 **정답**이다.
4. **실환경 도달 0건** — 본 에이전트 실측으로 확인(3행 전부 정상 경로). 즉시 처방 불요라는 PLAN 판단이 실측에 부합한다.

따라서 "고착 해소를 목표로 내걸고 새 고착을 남긴다"는 구도는 **성립하지 않는다.** gaps에 넣지 않는다.

**(b) 그러나 사실 기술이 과장됐다 — 정정 필요 (게이트 통과와 별개의 필수 조치).**

PLAN §9 R-13은 "경로 해석 불가 행은 `promote`·`delete`·`delete --orphan` **모두에게 거부되어** 여전히 도달 불가"로 쓰였고, TS-037이 이를 기대 결과("3경로 전부 거부")로 그대로 인코딩했다. **이 진술은 PLAN 자신의 §3.1.5 전이표와 모순되며, 코드 실측과도 어긋난다.**

- PLAN §3.1.5(`PLAN.md:88`): `dead / superseded` × **해석 불가** × 무플래그 `delete` → **"허용 (불변)"**
- 코드 실측(`memory_tool.py:1350-1360`): 무플래그 경로는 `status`만 검사하고 `mem_file`을 **아예 조회하지 않는다**. `dead`/`superseded` 행은 `file` 해석 가능 여부와 무관하게 제거된다. 이 3줄은 PLAN이 "문자 그대로 원본 보존" [MUST]로 잠근 부분이다.

즉 실제 고착 클래스는 5개 status 중 **3개**(`active`/`promoted`/`candidate`)에 한정된다.

**정정하지 않을 때의 구체적 위험** — §2.1 fixture 표에 `fx-traversal`의 `status`가 **미지정**이다. EXECUTE 워커가 이를 `dead`/`superseded`로 구성하면 TS-037의 무플래그 `delete` 레그는 **정상 동작인데 FAIL**한다. GREEN을 좇는 워커가 취할 다음 수는 무플래그 경로에 해석 불가 가드를 추가하는 것이며, 이는 PLAN이 [MUST]로 보존을 명령한 `else` 3줄(`:1355-1357`)과 TS-011("무플래그 `delete` 동작 완전 불변")을 정면 위반한다. iteration 1의 G-1과 **동일한 실패 형태**다 — 잘못된 시나리오 기대치가 워커를 [MUST] 위반으로 유도한다.

3. PLAN §9 R-13의 "모두에게 거부되어" 문구를 status 한정으로 정정하고, "신설 클래스"가 아니라 "**선재 클래스의 미구제 + 가시화**"로 성격을 재기술한다.

## 4. 관측 기록 (채점 대상 아님 — PM 참고)

### 4.1 [실측 지적] PLAN Step 3 완료 기준의 grep이 무관한 선재 코드를 오탐한다

PLAN §4.2 Step 3 및 §4.5 완료 기준은 `grep -c "mem_file is not None and mem_file.exists()"` == 0(G-3 결함 패턴 잔존 0)을 요구한다. 그러나 현 소스 실측 결과 이 문자열은 **정확히 1곳**에 존재하며, 그 위치는 orphan 가드가 아니라 `--with-file` 블록이다:

```
opal/tools/memory-tool/memory_tool.py:1372:                if mem_file is not None and mem_file.exists():
```

이 줄은 G-3 결함이 아니다 — 방향이 반대다(`None`이면 파일을 **삭제하지 않는다** = 안전측). 096 변경 범위에도 없다. 현 기준대로면 구현 후에도 grep이 1을 반환해 **완료 기준이 항상 미충족**이거나, 워커가 이를 맞추려 범위 밖 선재 코드를 수정해 "기존 163 회귀 0"·무플래그 경로 불변 요구와 충돌한다. 완료 기준을 `cmd_delete`의 `orphan` 분기로 범위 한정하거나(예: `--orphan` 블록 내 grep), 대상 줄 번호를 명시할 것을 권고한다.

### 4.2 `promote`의 어휘가 2분 정책에서 제외됐다

096은 "확인 불가 ≠ 부재"를 정책으로 세우고 `review`·`delete`에 `memory_file_unresolvable`를 도입했다. 그러나 `promote`(`:1164-1166`)는 해석 불가 행에 여전히 `memory_file_not_found`("부재" 어휘)를 반환한다. 거부 자체는 안전하므로 데이터 손실 위험은 없으나, PLAN이 어휘 분리 근거로 인용한 [MUST] `citation-rules.md` §7.1(영역 간 용어 일관성)의 적용 범위가 `promote`에서 끊긴다. TS-037이 promote 레그를 포함하면서 에러 코드를 명시하지 않아 이 불일치가 시나리오로도 포착되지 않는다. 범위 판단은 PM 소관 — 범위 밖으로 두더라도 PLAN §9에 명시 이월할 것을 권고한다.

### 4.3 TS-036의 fixture가 §2.1에 미등재

§2.2 TS-036 행은 "본문 부재 행 + 경로 탈출 행 공존 fixture"를 쓰는데, §2.1 사전 조건 표의 7종(`fx-missing`·`fx-intact`·`fx-empty`·`fx-matrix`·`fx-traversal`·`fx-traversal-live`·`fx-unresolvable-3`) 중 이에 해당하는 항목이 없다. §7 PM Gate 체크 "사전 조건 데이터 표(§2.1) 모든 칸 채워짐"과 어긋난다. 신규 fixture로 등재하거나, 기존 fixture 조합(`fx-missing` + `fx-traversal` 행 병합)으로 명시하면 해소된다.
