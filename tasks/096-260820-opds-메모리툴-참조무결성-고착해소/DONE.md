## 2. 핵심 설계 판단

**두 가드를 약화하지 않고 술어를 좁혔다.** 무손실 가드가 보호하는 자산은 "인덱스 행"이 아니라 "본문에 담긴 지식"이므로, 본문이 실재하지 않는 행에 한해 정리를 허용하고 본문이 실재하면 기존 가드를 그대로 유지한다.

미확정 2건을 PLAN이 실측 근거로 택일했다:

| 미확정 | 판정 | 탈락 근거 |
|--------|------|----------|
| R-2 구현 방식 | **`delete --orphan --ref`** (가드 완화형) | `promote` 플래그안 — 본문을 읽을 수 없는 행의 `--ref`는 검증 불가능한 주장이라 provenance에 거짓 졸업 이력이 남는다 / 신규 서브명령안 — "9서브명령" 리터럴이 코드·문서·테스트 7곳에 박혀 있다 |

## 3. 게이트가 잡은 P0 — 이 태스크의 최대 수확

목표-커버 게이트 iteration 1이 **PLAN 설계의 P0 결함**을 검출했다.

`_resolve_memory_file()`(`memory_tool.py:795-813`)은 3경로에서 `None`을 반환한다 — resolve 예외 / `memory/` 밖 경로 탈출 / 빈 `file`. 그런데 개정 전 가드는 `if mem_file is not None and mem_file.exists()` 형태여서 **`None`이면 조건이 거짓이라 가드를 통과해 삭제**됐다.

PLAN 워커가 실증으로 재현했고, 보고보다 심각했다 — 스키마 패턴 `^memory/[^/].*\.md$`에 `memory/../../outside.md`가 **매치**하므로 경로 탈출 행이 정상 영속되고, **본문이 디스크에 살아 있는 채 인덱스만 끊긴다.** 인덱스로도 `review`로도 다시 찾을 수 없으므로 실질적 지식 소실이다.

**무손실 가드를 정밀화하려던 변경이 새 blind 삭제 벡터를 만들 뻔한 건이다.** 게이트가 없었으면 그대로 배포됐다.

해소: 가드를 **조기 반환**(`if mem_file is None: err(...)`)으로 재구성해 `None` 통과를 구조적으로 불가능하게 만들고, `memory_file_unresolvable`을 신설해 "확인 불가 ≠ 부재"를 어휘로 분리했다. 평가자가 `None` 반환 경로가 정확히 3개임을 함수 내부 2곳 + 호출부 1곳으로 대조하고, 파생 입력 4종(키 부재·null·공백만·심볼릭 링크)도 3경로로 귀착함을 확인했다.

## 4. 근본 원인 발견 — 왜 고아 행이 생겼는가

Step 2 블로커 추적 중 실증으로 드러났다.

```
$ memory_tool.py append --kind memory --title "테스트 신규 메모리" ...
{"ok": true, "review": {"violations": [
   {"type": "memory_file_missing", "title": "테스트 신규 메모리", ...}]}}
$ ls memory/
(비어있음)
```

- `memory_tool.py`에 `memory/*.md`를 **생성하는 코드가 한 곳도 없다** (`write_text`·`open(...,'w')` grep 0건)
- `cmd_append`는 `file_field`에 **경로만 기록**한다 (`:965`)
- 즉 `append --kind memory`는 **항상 본문 없는 행을 만든다**

태스크 배경의 "인덱스 참조 10건 중 7건 본문 부재"가 이렇게 생겼다. 본문은 PM이 별도로 써야 하는데, 안 쓰면 그대로 고아가 된다. **F-001이 append 시점에 이를 즉시 표면화하는 것은 오탐이 아니라 이 기능의 최대 가치다.**

부수 효과로 정책 공백도 드러났다 — 스키마는 `file` **포인터**를 필수로 요구하지만 그 경로에 파일이 실재해야 한다는 제약은 없었고, 규범도 "인덱스 + 개별 파일"이 한 쌍이라 서술할 뿐 강제하지 않았다. 096이 `memory-learning.md:41`에 `[MUST]`를 신설해 **"본문 없는 행 = 결함으로 표면화"**를 정책으로 굳혔다.
