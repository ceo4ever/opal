### ⑤ 채택/잔존 — 1점

#### 쟁점 1 판정: "기존 무손실 가드의 잔존" 준용 해석 — **준용 자체는 타당, 다만 자기 유리한 절반만 매핑됐다**

**(a) 준용의 구조적 필요성 — 인정한다.**
`scenario-gate.md` §2 ⑤는 "교체형 목표=구형 잔존0·신형 채택"으로 정의되나, §5-1 종료조건은 "판단축(①⑤⑥) 각 ≥ 1점(0점 축 없음)"을 예외 없이 요구하며 **N/A 처리 경로를 두지 않는다**. 규칙 그대로면 비교체형 태스크는 전건 자동 FAIL이 된다. 따라서 비교체형 태스크에서 근사 축을 세우는 것은 Producer의 편법이 아니라 계약 공백에 대한 불가피한 대응이다. 준용 자체를 사유로 감점하지 않는다.

**(b) 그러나 선택된 근사축은 절반짜리다.**
교체형 ⑤는 두 방향을 함께 묻는다 — (구형) 잔존0 **AND** (신형) 채택. 본 태스크는 가드를 교체하는 것이 아니라 **술어를 좁혀 예외를 뚫는** 변경이므로, 정확한 근사는:

- **잔존 측**: 예외 밖 영역에서 기존 무손실 가드가 100% 생존하는가
- **채택 측**: 신규 경로가 의도한 조건에서만 발동하는가(과채택 없음)

Producer가 `is_adoption_scenario: true`를 부여한 4건(TS-008·TS-009·TS-011·TS-030)은 **전부 잔존 측**이다. TS-008(본문 실재 4 status 전건 거부)·TS-009(바이트 불변)·TS-011(무플래그 불변)·TS-030(promote 회귀) — 어느 하나도 신형 채택을 검증하지 않는다. 채택 측 증거는 시나리오 집합에 실재하지만(TS-006 검출→정리 왕복, TS-007 4 status 정리, TS-032 active+부재 허용, TS-021·TS-023 실환경 채택) 이 플래그가 부여되지 않아, 페이로드상 ⑤는 한쪽 날개만으로 선언됐다. 이는 R-2 AC 후단으로 어차피 의무인 음성 통제를 ⑤ 충족으로 재사용한 것에 가깝다.

**(c) 결정적 감점 — 잔존 측에 P0 공백이 실재한다.**

PLAN §3.2.2 설계 코드는 orphan 가드를 다음과 같이 규정한다:

```python
mem_file = _resolve_memory_file(str(json_path), file_field) if file_field else None
if mem_file is not None and mem_file.exists():
    err("delete", "memory_file_exists", path=str(mem_file))
```

`_resolve_memory_file()`(실측 `memory_tool.py:797-816`)은 **경로 탈출 시 `None`을 반환**한다(`target.relative_to(memory_dir)` ValueError → `return None`). 따라서 다음 3종 입력은 `mem_file is None`으로 가드를 **무조건 통과**하여 행이 제거된다:

1. `file` 값이 `memory/` 밖을 가리키는 행 (= `fx-traversal`) — 실제 본문이 존재해도 확인 없이 삭제
2. `file` 값이 빈 문자열인 행 (`if file_field else None`)
3. `.resolve()` 예외 행 (`except Exception: return None`)

이는 H-2(P0)가 정의한 실패모드 "본문이 실재하는 행까지 통과하면 살아있는 지식의 **blind 삭제 경로가 신설**된다"([MUST] `memory-learning.md:38` 위반)에 정확히 해당한다.

시나리오 집합을 전수 확인한 결과, **`--orphan`을 `fx-traversal` 행 또는 빈 `file` 행에 적용하는 시나리오는 0건이다.** TS-005는 `fx-traversal`을 다루지만 `review` 검출만 검증하고 처분 경로를 건드리지 않는다. TS-008·TS-009는 본문이 **실재하고 경로도 정상인** 행만 다룬다. 즉 무손실 가드의 잔존 검증은 "정상 경로 × 본문 실재" 축에서만 전수화됐고, **가드가 실제로 뚫리는 유일한 벡터는 미검증 상태로 남았다**.

**판정**: 준용 해석은 인정하되(0점 아님), 매핑이 잔존 측에 편중됐고 그 잔존 측마저 P0 벡터에 공백이 있다. → **1점**

## 3. 추가 검토 요구 결과 (채점 대상 아님 — 관측 기록)

### 3.1 쟁점 2 판정: H-11의 페이로드 제외 — **정당한 범위 판정. 게이트 회피 아님. 단 계약 공백을 노출한다**

**판정 근거**:

1. **범위 판정의 시점·주체가 독립적이다.** H-11 "범위 밖 — 후속 보고만" 판정은 PLAN.md(`:158`, `:1069` R-5)에서 `opal-plan-agent`가 내렸고, TEST-SCENARIO 페이로드 구성보다 선행한다. 게이트 결과를 본 뒤 사후에 만든 판정이 아니다.
2. **은폐가 없다.** H-11은 TEST-SCENARIO.md §1 리스크 가설 표에 전재됐고(`:52`, 시나리오 열 "없음"), §4 루브릭 축 커버 현황 ④행도 "H-1~H-10 전건(H-11은 PLAN이 범위 밖 판정)"으로 명시했다. 회피는 은폐를 수반하는데, 본 건은 양쪽 문서에 명문 기재됐다.
3. **TASK.md §범위 대조 결과 — 문언 일치는 아니나 판정은 정합적이다.** TASK.md §범위 "제외"의 3항(본문 5건 복원 / 타 도구 동종 검사 / 스키마 변경)에 역방향 고아는 **문언상 없다**. PLAN도 이를 인지해 "제외에 **준함**"이라는 표현을 썼다. 다만 R-1의 무엇을·AC가 "인덱스 행의 `file` 경로 실재 여부"로 방향을 명시적으로 한정하므로, 반대 방향이 포함 범위 밖이라는 결론 자체는 요구사항 문언에서 직접 도출된다.

**그러나 계약 결함을 지적한다**: `scenario-gate.md` §3 정규화 입력에는 "범위 밖으로 판정된 가설"을 표현할 필드가 없다. 선택지는 (a) 페이로드에서 누락 (b) 유지하여 확정 FAIL 둘뿐이고, (a)를 택하면 게이트는 **P2 리스크가 의식적으로 유보됐다는 사실 자체를 볼 수 없다**. 본 건은 문서 기재로 보완됐으나, 이는 도구 집행이 아니라 산문 규율에 의존한 보완이다(`PRINCIPLES.md:15` "Enforce, don't just advise" 관점에서 약하다).

> **후속 제안(본 태스크 범위 밖)**: `scenario-gate.md` §3 정규화 계약에 `out_of_scope_hypotheses[]`(사유 필수) 필드를 신설하고, test-tool이 이를 `missing` 계산에서 제외하되 출력에 명시 반환하도록 한다. 그러면 범위 유보가 도구 출력에 남아 감사 가능해진다.

### 3.2 선작성 61% 자기판정 — **결론은 수용 가능하나, 근거 수치가 문서 내부에서 검증되지 않는다**

**(a) 규칙 문언 대비**: `red-first.md` §1.6 (f) 후단은 "선작성한 시나리오가 PLAN 확정 후 보강에서 **절반 이상 수정·삭제되면**, 그 태스크는 선작성 부적격이었다는 신호다"로, 사유를 구분하지 않는 **기계적 신호**로 쓰여 있다. Producer의 "흡수는 결과가 뒤집힌 게 아니므로 부적격 신호가 아니다"는 해석은 규칙이 두지 않은 구분(흡수 vs 번복)을 도입해 문언을 좁힌 것이다. 규칙 그대로라면 신호는 **발화했다**.

**(b) 그러나 규칙의 목적 대비로는 Producer 결론이 우세하다.** (f)의 효력은 "다음 태스크의 착수 판단에 반영한다"이지 현 산출물 무효화가 아니며, Producer는 실제로 관측 데이터로 남겼다 — 규칙이 요구한 행위를 이행했다. 더 결정적인 것은 **존치 시나리오의 실질**이다: TS-024~031·TS-033은 "선작성 고유, PLAN TS 집합에 대응 없음"으로 기재됐고, 여기에 경계·부정 백본 전부(TS-024 미존재 title, TS-025 빈 인덱스, TS-028 스키마 무변경)와 유일한 L3 감독 시나리오(TS-033)가 포함된다. ⑥이 2점을 받은 근거의 상당 부분이 선작성 고유 산출물이다. 이는 §1.6이 예고한 품질 이득(095 실측: 선작성 고유 3건, PLAN 대응 0건)이 096에서 더 크게 재현됐음을 뜻한다.

**(c) [실측 지적] 61%라는 수치 자체가 문서 내에서 정합하지 않는다.**

- 보강 이력 #1(흡수)은 대상을 "선작성 **S-1**~S-6, S-14, S-16"으로, #3(수정)은 "선작성 **S-1** (실환경)"으로 기재한다 — **S-1이 흡수와 수정에 이중 계상**됐다.
- 계상 합계가 맞지 않는다: 흡수 8 + 수정 2 + 해소 1 = 11(수정·삭제) + 존치 9(TS-024~031 8건 + TS-033) = **20건**이나, 분모는 "초안 18건"이다. **2건 초과**한다.
- 존치는 사후 ID(TS-NNN)로, 수정·삭제는 초안 ID(S-NNN)로 기재돼 두 집합의 대응 관계를 문서만으로 재구성할 수 없다.

따라서 **11/18(61%)도, 대안 수치도 문서로부터 독립 검증되지 않는다.** 다음 태스크의 착수 판단에 쓰일 관측 데이터로서 이 수치는 신뢰할 수 없다.

> **제안**: 보강 이력에 초안 ID ↔ 최종 TS-ID 대응 열을 추가해 분모·분자를 재구성 가능하게 만든다. 아울러 (f) 규칙은 "수정·삭제 비율"만 세고 "존치 고유 시나리오의 기여"는 세지 않아, 본 건처럼 비율과 실질이 상반되는 사례를 판별하지 못한다 — 존치 고유 건수를 병기 지표로 추가할 것을 후속 제안한다.

### 3.3 TS-033의 L3 [SUPERVISOR] 수동 이관 — **정당하다**

**정당성 근거**:

1. **자동화 불가가 진짜다.** H-3은 "본문 부재"가 소실이 아니라 타 머신 미동기화일 수 있다고 규정한다. 도구는 **다른 머신의 파일 시스템을 관측할 수 없으므로**, "이 본문이 어딘가에 살아 있는가"는 기계 판정의 정보 자체가 부재한 명제다. 자동화 부적격 사유가 편의가 아니라 정보 부재에서 나온다.
2. **비가역성이 인간 판정을 요구한다.** 대상은 fixture가 아닌 실환경 지식 2건이고, 오판 결과는 영구 유실이다. 자동 판정에 위임할 수 없는 종류의 결정이다.
3. **역량 검증은 이관되지 않았다.** 결정적으로, **도구가 작동하는가**는 자동 검증에 남아 있다(TS-021 검출, TS-023 사본 리허설 + 원본 해시 보전). 수동으로 미룬 것은 **비가역적 실데이터 적용 결정**뿐이다. 이 분리가 정확하다 — 역량은 기계가 증명하고, 적용 여부는 사람이 결정한다.
4. **양식이 완비됐다.** [SUPERVISOR] 마커, 두 건의 실제 `summary`, "brain·docs에 대응 페이지 없음(실측)"이라는 판단 재료, (a)(b)(c) 3택 선택지를 갖춘 PM 요청 양식이 첨부됐다. 캡틴이 추가 조사 없이 결정 가능한 상태다.
5. **미결정 허용이 옳다.** "본 태스크는 결정을 강제하지 않으며, 미결정도 정상 종료 조건"은 태스크가 인간 판정에 블로킹되는 것을 막으면서 결정 사안을 표면화한다 — 올바른 범위 설정이다(PLAN §3.2.4 단계 A/B 분리와 정합).

**단서 1(관측)**: TS-033은 Pass/Fail 기준이 없는 **통지형** 항목이므로 구조상 실패할 수 없다. 그럼에도 정규화 페이로드에서 `covers_hypotheses: ["H-3"]`(P0)을 담당한다. H-3의 실질적 결정론 방전은 TS-012(provenance에 `summary` 보존)·TS-021이 수행하므로 실해는 없으나, **실패 불가 항목이 P0 가설 커버로 계상되는 구조**는 일반화하면 위험하다. ④는 본 에이전트 소관이 아니므로 채점에 반영하지 않고 관측으로만 남긴다.

**단서 2(관측)**: PLAN 내부 TS-NNN과 TEST-SCENARIO TS-NNN이 **서로 다른 번호 공간**인데 동일 표기를 쓴다(PLAN `:1016`이 이를 명시). 예 — PLAN §3.2.5 TS-009는 "`dead` + 본문 존재 → `memory_file_exists`"이나 TEST-SCENARIO TS-009는 "`active` + 본문 실재 바이트 불변"이다. EXECUTE 워커가 두 문서를 교차 참조할 때 오식별 위험이 있다. 접두 구분(예: PLAN-TS-009)을 권고한다.
