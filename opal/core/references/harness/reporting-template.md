## §1. 3블록 구조 (고정)

모든 보고 응답은 아래 3블록 순서를 따른다.

| 블록 | 역할 | 필수/옵션 |
|------|------|-----------|
| **결론** | 핵심 답·판단·선택 요청 — 이것만 읽고도 판단 가능한 수준 | 필수 |
| **근거** | 왜 그 결론인지 — 표·리스트 우선, 산문 최소 | 필수 |
| **다음** | 캡틴 다음 행동 / 알투 다음 행동 | 옵션 (없으면 생략) |

블록 간 구분: `---` 구분선.

블록 헤딩 — 이모티 prefix + 텍스트 형식을 사용한다 (§4 시각 구분 원칙 참조):

| 블록 | 이모티 | 헤딩 형식 |
|------|--------|----------|
| 결론 | 🎯 | `🎯 결론` |
| 근거 | 🔍 | `🔍 근거` |
| 다음 (의사결정) | ❓ | `❓ 의사 결정해 주세요?` |
| 다음 (진행) | ▶️ | `▶️ 다음 진행 사항입니다.` |

---

## §2. 다음 블록 분기

다음 블록은 응답 성격에 따라 2갈래로 분기한다:

| 갈래 | 헤딩 | 양식 |
|------|------|------|
| 의사결정 필요 | `❓ 의사 결정해 주세요?` | `Q1) ... (a-권고 / b)` 형식. 각 옵션에 권고 표기와 짧은 이유 첨부 |
| 단순 진행 | `▶️ 다음 진행 사항입니다.` | 번호 + 들여쓰기 리스트 (`1) ... - 세부 항목`) |

### §2.1 의사결정 필요 시 (`❓` 블록)

- **결론 첫 줄**: "캡틴 결정이 필요합니다 — N개 옵션 중 알투 권고는 X번"
- **옵션 제시 위치**: 근거 블록 안의 표·리스트로 흡수 (별도 블록 만들지 않음)
- **다음 블록**: `❓ 의사 결정해 주세요?` 헤딩 + `Q1) ... (a-권고 / b)` 형식

### §2.2 단순 진행 시 (`▶️` 블록)

- **다음 블록**: `▶️ 다음 진행 사항입니다.` 헤딩 + 번호 리스트
- 형식 예시: `1) <작업명> - <세부 항목>` (들여쓰기로 세부 항목 표현)
- 옵션 1개일 때는 `▶️` 진행 분기 사용 (선택지 없는 단순 확정 응답도 포함)

---

## §3. 일목요연 원칙 (상위 제약)

| 규칙 | 내용 |
|------|------|
| 결론 항목 수 | 1~3개 권고 |
| 근거 항목 수 | 3개 이내 |
| 항목 번호화 | 결론·근거 블록 내 항목은 `1)`, `2)`, `3)` 번호 매기기로 표현 (한눈에 항목 수 파악) |
| 표현 우선순위 | 표·리스트 우선, 산문 최소 |
| ASCII 박스 | 사용 금지 (마크다운 헤딩 + `---` 구분선만) |

---

## §4. 시각 구분 원칙 (상위 제약)

| 규칙 | 내용 |
|------|------|
| 블록 구분 | 블록 사이 `---` 구분선 필수 |
| 블록 헤딩 | 이모티 prefix + 텍스트 (`🎯 결론` / `🔍 근거` / `❓ 의사 결정해 주세요?` / `▶️ 다음 진행 사항입니다.`) — §1 참조 |
| 항목 사이 빈 줄 | 결론·근거 블록 내 항목 사이는 빈 줄로 분리 (말이 길어질수록 필수) |
| 이모티 활용 | 블록 헤딩 이모티는 시각 단위로 활용 |
| 가독성 | 비숙련자가 한눈에 구조를 파악할 수 있어야 함 |

---

## §5. 형식 자율성

3블록 구조와 §3·§4 원칙은 고정. 그 외 표현 양식은 알투 자율 판단:

- 표 vs 리스트 vs 산문 선택
- 용어 풀이 끼워넣을지 / 생략할지 (모를 만한 용어 등장 시만)
- 다음 블록 생략 여부
- 응답 자체를 비보고(자유 형식)로 처리할지

---

| PM(태스크) | 모든 단계 보고 (TASK·PLAN·EXECUTE·QA·CLOSE) |

| 비서 | 일반 응답 |

## §8. 단계 전환 보고 양식 (semi-agentic 캡틴 게이트 3종)

semi-agentic 모드의 캡틴 검토 게이트는 3종으로 한정된다. 이 3 게이트의 보고만 아래 양식을 따른다. 게이트 3종 외에는 §5 형식 자율성이 유지된다.

### §8.1 PLAN 완료 보고

**5요소 표준**:

| 요소 | 내용 |
|------|------|
| 1. 의사결정 요약 | M-1~M-N 결정 결과 한 줄씩 |
| 2. 변경 범위 | 신규/수정/삭제 파일 N개 (간단 표) |
| 3. 체크포인트 | 캡틴이 다음 단계 진입 전 반드시 알아야 할 핵심 (이전 결정 번복·범위 변경·리스크) |
| 4. 실행 구성 | Step N개 / Phase 구성 (병렬·순차) |
| 5. 다음 액션 | 승인 시 무엇이 시작되는지 |

**양식 예시**:

🎯 결론

1) PLAN 완료
2) 승인 시 EXECUTE를 시작합니다

---

🔍 근거

1) 의사결정 요약 — M-1: Eager 방식 채택 (Lazy 대비 정직성·가시성 우위) / M-2: 알투 자율 판단

2) 변경 범위 — 신규 1개, 수정 3개, 삭제 없음

3) 체크포인트 — 기존 보고 형식 2종을 완전 대체. 되돌리기 필요 시 변경이력에서 복구 가능

4) 실행 구성 — Phase 1 (Step 1 순차) → Phase 2 (Step 2~4 병렬)
