# 보고 형식 — 3블록 구조

> 출처: opal/core/AGENT.md + TASK 143
> 로드 시점: Eager 단계 (Step 6.6) — 세션 시작 시
> 역할: 알투(에이전트) 응답 형식 표준 SSOT

---

## §1. 3블록 구조 (고정)

모든 보고 응답은 아래 3블록 순서를 따른다.

| 블록 | 역할 | 필수/옵션 |
|------|------|-----------|
| **결론** | 핵심 답·판단·선택 요청 — 이것만 읽고도 판단 가능한 수준 | 필수 |
| **근거** | 왜 그 결론인지 — 표·리스트 우선, 산문 최소 | 필수 |
| **다음** | 캡틴 다음 행동 / 알투 다음 행동 | 옵션 (없으면 생략) |

블록 간 구분: `---` 구분선. 블록 헤딩: `**결론**`, `**근거**`, `**다음**`.

---

## §2. 결론 카드 — 선택 요청 시 양식

캡틴 결정이 필요한 경우:

- **결론 첫 줄**: "캡틴 결정이 필요합니다 — N개 옵션 중 알투 권고는 X번"
- **옵션 제시**: 근거 블록 안의 표·리스트로 흡수 (별도 블록 만들지 않음)
- **다음 블록**: "Q-번호로 답해주세요" 식 응답 형식 안내

---

## §3. 일목요연 원칙 (상위 제약)

| 규칙 | 내용 |
|------|------|
| 결론 길이 | 1~2줄 |
| 근거 핵심 항목 | 3개 이내 |
| 표현 우선순위 | 표·리스트 우선, 산문 최소 |
| ASCII 박스 | 사용 금지 (마크다운 헤딩 + `---` 구분선만) |

---

## §4. 시각 구분 원칙 (상위 제약)

| 규칙 | 내용 |
|------|------|
| 블록 구분 | 블록 사이 `---` 구분선 필수 |
| 블록 헤딩 | 굵은 텍스트 (`**결론**`, `**근거**`, `**다음**`) |
| 문맥 단위 | 빈 줄로 분리 |
| 가독성 | 비숙련자가 한눈에 구조를 파악할 수 있어야 함 |

---

## §5. 형식 자율성

3블록 구조와 §3·§4 원칙은 고정. 그 외 표현 양식은 알투 자율 판단:

- 표 vs 리스트 vs 산문 선택
- 용어 풀이 끼워넣을지 / 생략할지 (모를 만한 용어 등장 시만)
- 다음 블록 생략 여부
- 응답 자체를 비보고(자유 형식)로 처리할지

---

## §6. 적용 범위

| 모드 | 적용 상황 |
|------|----------|
| PM(태스크) | 모든 단계 보고 (TASK·PLAN·EXECUTE·QA·CLOSE) |
| PM(대화) | 분석·설명·검토 응답 |
| 비서 | 일반 응답 |

캡틴 게이트 3종(§8) 외에는 §5 형식 자율성이 유지된다.

---

## §7. 비보고 예시

아래 유형의 응답은 3블록 구조를 적용하지 않고 자유 형식으로 처리한다 (알투 자율 판단 — 명시 기준 아님, 방향성만).

- 단순 확인 응답 ("네", "알겠습니다", "확인했습니다")
- 단문 질문 답변 ("오늘 날짜는 2026-05-10입니다")
- 감사 표현 또는 짧은 인사
- 다음 액션이 없는 1줄 완결 응답

## §8. 단계 전환 보고 양식 (semi-agentic 캡틴 게이트 3종)

semi-agentic 모드의 캡틴 검토 게이트는 3종으로 한정된다. 이 3 게이트의 보고만 아래 양식을 따른다. 게이트 3종 외에는 §5 형식 자율성이 유지된다.

---

### §8.1 PLAN 완료 보고

**5요소 표준**:

| 요소 | 내용 |
|------|------|
| 1. 의사결정 요약 | M-1~M-N 결정 결과 한 줄씩 |
| 2. 변경 범위 | 신규/수정/삭제 파일 N개 (간단 표) |
| 3. 체크포인트 | 캡틴이 다음 단계 진입 전 반드시 알아야 할 핵심 (이전 결정 번복·범위 변경·리스크) |
| 4. 실행 구성 | Step N개 / Phase 구성 (병렬·순차) |
| 5. 다음 액션 | 승인 시 무엇이 시작되는지 |

**양식 예시**:

**결론** — PLAN 완료. 승인 시 EXECUTE를 시작합니다.

**근거**

의사결정 요약:
- M-1: Eager 방식 채택 (Lazy 대비 정직성·가시성 우위)
- M-2: 알투 자율 판단 (기준 명시 시 인지 부담 증가)

변경 범위: 신규 1개, 수정 3개, 삭제 없음.

체크포인트: 기존 보고 형식 2종을 완전 대체 — 되돌리기 필요 시 변경이력에서 복구 가능.

실행 구성: Phase 1 (Step 1 순차) → Phase 2 (Step 2~4 병렬).

**다음** — 승인하시면 EXECUTE를 시작합니다.

---

### §8.2 EXECUTE 후 사용자 확인 보고

**5요소 표준**:

| 요소 | 내용 |
|------|------|
| 1. 변경 결과 | changed_files 목록 + 각 파일 핵심 변경 1줄 |
| 2. 검증 결과 | QA 체크리스트 통과 여부 / 테스트 결과 |
| 3. 리스크 | 잔존 리스크 또는 미검증 항목 |
| 4. 잔여 작업 | 완료되지 않은 Step / 블로커 |
| 5. 다음 액션 | 확인 후 무엇이 시작되는지 |

**양식 예시**:

**결론** — EXECUTE 완료. 변경 파일 4개, QA 전 항목 통과.

**근거**

변경 결과:
- `harness/reporting-template.md` 신규 생성 — 3블록 구조 SSOT
- `AGENT.md` 수정 — Eager Step 6.6 추가, 보고 형식 섹션 대체
- `opal-harness.md` 수정 — §2 모듈 테이블 행 추가
- `opal-pm.md` 수정 — §8 신설

검증 결과: QA 체크리스트 17/17 항목 통과.

리스크: 없음.

잔여 작업: 없음.

**다음** — 확인 후 CLOSE로 진입합니다.

---

### §8.3 CLOSE 진입 보고

**5요소 표준**:

| 요소 | 내용 |
|------|------|
| 1. 완료 산출물 | 생성/수정된 파일 목록 |
| 2. QA 결과 | 기능·일관성·문서 품질 체크리스트 최종 결과 |
| 3. 잔여 미해결 | 미완료 항목 또는 Known Issue |
| 4. 후속 태스크 후보 | 파생 작업 또는 개선 아이디어 |
| 5. 확정 요청 | 캡틴에게 CLOSE 확정 요청 |

**양식 예시**:

**결론** — 태스크 143 완료. CLOSE 확정을 요청합니다.

**근거**

완료 산출물: `reporting-template.md` 신규, `AGENT.md`·`opal-harness.md`·`opal-pm.md` 수정.

QA 결과: 기능·일관성·문서 품질 전 항목 통과.

잔여 미해결: 없음.

후속 태스크 후보: install 재실행으로 `~/.opal/references/harness/`에 신규 파일 배포.

**다음** — 확정하시면 DONE.md를 생성하고 종료합니다.
