# 공통 도구 출력 계약

모든 OPAL 도구가 지키는 호출 규약이다. 개별 도구 절은 이 계약을 재서술하지 않고 자기 고유 사항만 적는다.

## 응답 형식

표준출력에 **단일 라인 JSON 객체 하나만** 출력한다. 로그·진행 표시·사람용 서술을 같은 스트림에 섞지 않는다. 호출자가 에이전트이므로 출력이 파싱 가능해야 판정이 추론이 아니라 기계 판정이 된다.

```json
{"ok": true, "command": "mark", "row_id": 5, "stage": "PLAN"}
{"ok": false, "command": "init", "error": "run_identity_missing", "message": "..."}
```

- 성공 응답은 `ok: true`와 `command`를 갖는다.
- 실패 응답은 `ok: false`, `command`, `error`를 갖는다. `message`는 선택이다.
- 추가 컨텍스트 필드는 도구가 자유롭게 더한다.

## 오류 코드

실패 응답의 `error` 값은 **안정적인 코드 식별자**다. 사람이 읽는 설명은 `message`에 넣고 `error`에 섞지 않는다. 호출자가 메시지 문자열이 아니라 코드로 분기할 수 있어야 하므로, 같은 실패 원인은 같은 코드를 유지하고 문면을 바꿀 때 코드를 바꾸지 않는다.

코드 집합이 여러 서브명령에 걸쳐 재사용되는 도구는 모듈에 **선언 목록을 두고 방출 시점에 그 목록과 대조**한다. 현재 이 패턴을 쓰는 도구는 `backlog-tool`·`brain-tool`·`git-sync-tool`·`memory-tool`·`state-tool`·`test-tool`·`tool-scan`·`worktree-tool`이며, 선언 목록을 갖지 않은 도구도 위 식별자 안정성은 지킨다. 코드별 의미는 각 도구 README가 소유한다.

## 종료 코드

성공은 `0`, 실패는 **0이 아닌 값**이다. 0이 아닌 값의 세부 분류는 도구마다 다르다 — 단일 실패 코드만 쓰는 도구와 실패 원인별로 나누는 도구가 함께 있으므로, 세부 분류는 공통 계약이 아니라 각 도구 README가 소유한다.

## 소유 경계

이 문서는 **모든 도구에 공통인 것만** 소유한다. 서브명령 인자, 사용 예시, 오류 코드별 의미, 종료 코드 세부 분류, 도구 고유 제약은 각 도구 README가 소유한다. 도구 레지스트리(도구 목록·경로·서브명령 카탈로그)는 `opal/core/references/tools.md`가 소유한다.
