## 0. 적용 범위와 상속

### 적용 범위

- 적용 대상: PM(대화) 모드에서 기획·개선 논의 중 현행(AS-IS)을 분석·보고할 때 적용한다.
- 비적용 대상: PM(태스크) 파이프라인의 분석 단계는 각 파이프라인 스킬이 규정한다.
- 본 문서가 소유하는 것: **5단계 순서**, 4축 수집 규율, 규모 분기, 자산 부재 폴백, 보고 2블록.

## 1. 진입 판정 — 규모 분기

| 판정 | 조건 | 실행 경로 |
|------|------|----------|
| **비대상** | 단일 문서·단일 조항 조회, 용어 질의 등 **현황 판단이 필요 없는** 단순 확인 | 워크플로우 미적용 — 일반 응답으로 처리 |
| 축약 | 축이 1개이지만 **현황 판단**(무엇이 현재 어떻게 되어 있는가)이 필요하고, 1단계 기존 지식만으로 근거가 충족된다 | 0 → 1 → 4 (2·3단계 생략) |
| 전개 | 축이 2개 이상이거나, 1단계 근거가 불충분해 원천 확인이 필요하다 | 0 → 1 → 2 → 3 → 4 |

- [MUST] 판정값(비대상/축약/전개)을 **0단계 좌표 선언에 노출**한다 — 머릿속 판정 금지(→ §2).
- 축약 시에도 4단계의 축 매트릭스는 생성한다 — 미수집 축은 사유와 함께 표기한다(→ §6 셀 값 규칙, §7 불변 규칙).
- 비대상은 매트릭스를 만들지 않는다. 다만 답변 중 현황 판단이 필요해지면 그 시점에 축약으로 승격한다.

## 2. 0단계 — 좌표 고정

- **입력**: 사용자 질의 원문 / `docs/PROJECT.md` 문서 레지스트리 / 프로젝트가 선언한 축 SSOT 목록.

- **행위**:
  1. **질의 경계 확정** — 무엇을 AS-IS로 볼지(대상 업무 단위·시간 경계·제외 범위)를 1~3줄로 고정한다.
  2. **축 SSOT 지목** — 정책·화면·데이터·코드 각 축의 SSOT 문서를 프로젝트가 선언한 것에서 지목한다.
     - 프레임워크는 특정 문서명을 규정하지 않는다.
  3. **[N-1 헤더 블록 우선 읽기]** 지목한 문서는 본문 통독 전에 문서 상단 헤더 블록(frontmatter·`> 출처:`·`> 역할:`·SSOT 선언 라인)을 먼저 읽는다.
     - 헤더로 **SSOT인지 파생본인지**를 판별한다.
     - 파생본이면 헤더가 가리키는 원천으로 좌표를 옮긴 뒤 수집한다.
  4. **프리로드 수행** — PM 직접 작업의 docs 프리로드를 수행한다 (→ I-1, `opal/core/references/opal-pm.md` §2).

- **산출**: **좌표 선언 블록** — 아래 3항을 **응답에 노출한다**.

```markdown
📍 좌표 — 경계: {무엇을 AS-IS로 보는가 1~3줄} | 판정: {비대상|축약|전개}
축 SSOT — 정책: {경로 또는 미보유} / 화면: {…} / 데이터: {…} / 코드: {…}
```

> [MUST] 좌표 선언은 **눈에 보이는 산출물**이다. 머릿속에서 처리하고 넘어가지 않는다.
> 근거: 실사용 관측상 산출물이 없는 단계는 생략되고, 산출물이 있는 단계는 지켜졌다. 선언을 노출해야 0단계가 집행된다(헌법 Core Stance "Enforce, don't just advise").

> [MUST] 헤더 블록만으로 SSOT/파생 판별이 불가능하면 **추정하지 않는다** — 미판별로 표기하고 §7 폴백 F-4를 적용한다 (→ `opal/core/references/harness/citation-rules.md` §0).
> [MUST] 파생/SSOT 판별은 **PM이 헤더를 직접 읽어** 수행한다 — 기존 지식(brain 페이지 등)이 "그건 파생본"이라고 말해준 것을 그대로 인용하는 것은 N-1 수행이 아니다.

## 3. 1단계 — 기존 지식 확인

- **입력**: 0단계의 질의 경계 + 축별 SSOT 경로 목록.

- **행위**:
  1. 질의 키워드로 brain을 조회한다 — 조회 흐름(후보 → 선택 → 주입)은 `opal/core/references/pm/dispatch-process.md` §Step 1.5를 따른다 (→ I-2).
  2. 동일 질의의 기존 분석 페이지에 대한 **재사용·갱신·신규 판정 결과를 소비**한다 (→ I-3, `opal/skills/opal-brain/SKILL.md` §질의 절차).
     - 판정이 **재사용**이면 해당 페이지를 답변 골격으로 삼고 2단계는 근거 재확인 범위로만 수행한다.
     - 판정이 **갱신**이면 그 페이지를 갱신 대상으로 표시해 4단계 거처 선판정에 넘긴다.
     - 판정이 **신규**이면 통상대로 2단계로 진행한다.
  3. 본 문서는 분기 조건·판정 규칙을 재기술하지 않는다 — 결과값만 받는다.

- **산출**: 기존 지식 요약(출처 페이지 경로 포함) + 재사용/갱신/신규 판정값 + 2단계로 넘길 미해소 쟁점 목록.

> brain이 없거나 분석 타입을 채택하지 않은 프로젝트에서는 §7 F-1·F-2를 적용하고 중단하지 않는다.

## 4. 2단계 — 4축 수집

- **입력**: 0단계의 축별 SSOT 경로 목록 + 1단계의 미해소 쟁점 목록.

- **행위**: 아래 4축을 각각 "지목 → 좁히기 → 구간 Read" 순으로 수집한다.

| 축 | 무엇을 지목하는가 | 어떻게 좁히는가 |
|----|------------------|----------------|
| 정책 | 업무 규칙·제약·예외 처리를 규정한 축 SSOT (프로젝트가 선언한 정책 계열 문서) | 질의 경계의 업무 용어로 grep → 매칭 조항 번호·헤딩 구간만 Read |
| 화면 | 사용자 접점·화면 정의·정보 구조를 규정한 축 SSOT | 업무 표면 식별자(→ `opal/core/references/harness/citation-rules.md` §8.7)로 화면 ID를 지목 → 해당 화면 정의 블록만 Read |
| 데이터 | 엔티티·필드·코드값·사전을 규정한 축 SSOT | 엔티티/필드명으로 grep → 해당 테이블·엔티티 정의 구간만 Read |
| 코드 | 실제 동작(실질적 SSOT) | `code-scan`으로 도메인·레이어·exports를 좁힌 뒤 해당 파일만 Read (→ I-4, Glob/Grep 직행 금지) |

- [MUST] **전체 통독 금지** — 어느 축에서도 문서·코드 전문을 컨텍스트에 올리지 않는다.
- 위치를 특정한 뒤 해당 구간만 Read한다.
- 0단계에서 확정한 4축을 넘어 임의로 축을 확장하지 않는다.

### [N-2 인용 시점 stale 재확인]

- 1단계에서 확보한 지식(brain 페이지 등)을 **근거로 인용하는 시점에** 그 인용이 가리키는 원문을 재확인한다.
- brain은 ingest 시점 스냅샷이라 stale 가능하며 코드가 SSOT다 (→ `opal/core/references/opal-pm.md` §13, `opal/core/references/harness/doc-code-mismatch.md`).
- 원문과 다르면 원문을 채택한다.
- 채택 시 발생한 차이는 4단계 갭 목록에 기재한다.

> [MUST] **신선도는 면제 사유가 아니다** — 지식 페이지의 갱신일이 오늘이어도 재확인을 생략하지 않는다.
> 갱신일이 최신이라는 것은 **ingest 시점**이 최근이라는 뜻이지 인용 대상이 그 뒤로 불변이라는 뜻이 아니다. 특히 코드 인용(`경로:줄번호`)은 줄 위치가 쉽게 밀린다.
> 예외를 두려면 그 판단 근거를 갭 목록에 기재한다 — 침묵한 생략은 위반이다.

### 읽기 전용 수집 워커 팬아웃

단일 PM 컨텍스트로 통독 불가한 규모에서는 수집만 팬아웃한다 (→ `opal/core/references/opal-pm.md` §12 예외).

- 축 단위로 1워커씩 병렬 디스패치할 수 있다.
- 디스패치 절차는 `opal/core/references/pm/dispatch-process.md`를 그대로 따른다 (→ I-7).
- **워커 권한**: 읽기 도구만 허용한다(Read/Grep/Glob/`code-scan` 조회/`brain-tool` search).
- 파일 생성·수정, 도구 쓰기 서브명령, 커밋은 금지한다.
- **반환 계약**: 축명 / 근거 인용 목록(경로:줄번호 또는 문서 §섹션) / 결측 항목 3요소만 반환한다.
- [MUST] 워커는 **판정·해석·권고를 반환하지 않는다** — 합성은 PM의 몫이다.
- 워커가 4축을 넘겨 임의 확장 수집하지 않는다.
- 축 추가가 필요하면 PM이 0단계 좌표를 갱신해 다시 지시한다.

- **산출**: 축별 근거 인용 목록 + 축별 결측 표기.

## 5. 3단계 — 정합 판정

- **입력**: 2단계의 축별 근거 인용 목록과 결측 표기.

- **행위**:
  1. 동일 쟁점에 대한 축 간 진술을 대조한다.
  2. 불일치가 있으면 `opal/core/references/harness/doc-code-mismatch.md`의 판정 기준을 적용한다 (→ I-8).
  3. 근거가 복수 계층에 걸치면 `opal/core/references/harness/citation-rules.md` §8.6대로 **병기**한다 (→ I-10).

- **판정 3분류**:

| 판정값 | 의미 |
|--------|------|
| 일치 | 축 간 진술이 같고 근거가 현행이다 |
| 불일치(코드 우선 — 문서 갱신 대상) | 축 간 진술이 다르며 코드를 SSOT로 채택한다 |
| 근거 부족(확정 불가) | 대조에 필요한 축 근거가 결측이라 판정을 유보한다 |

- **산출**: 쟁점별 판정값 + 판정 근거 인용.

> [MUST] 정합 판정·합성·보고는 **PM이 직접** 수행한다. 워커에 위임하지 않는다 (→ `opal/core/references/opal-pm.md` §12 예외).

## 6. 4단계 — 보고·환류

- **입력**: 3단계의 쟁점별 판정값 + 근거 인용 + 결측 목록.

- **행위**:
  1. 보고 레이아웃은 `opal/skills/opal-brain/SKILL.md` §답변 구조(관측 축 → 후보 레이아웃 → tie-break)로 판정한다 (→ I-11).
  2. [MUST] 본 문서는 레이아웃을 재정의하지 않는다.
  3. 선택한 레이아웃 위에 아래 **2블록**을 추가한다 — 본 문서가 소유하는 유일한 보고 구조다.

**축 매트릭스** — 행=쟁점, 열=정책·화면·데이터·코드.

| 셀 값 | 의미 | 다음 행동 |
|-------|------|----------|
| 근거 인용 | 해당 축에서 근거를 확보함 (포맷은 `opal/core/references/harness/citation-rules.md` §2) | — |
| `-` | 해당 축 미보유 — 프로젝트가 그 축 SSOT를 선언하지 않음 | 축 SSOT 신설 제안 |
| `?` | 축은 있으나 확인 실패·부분 커버·**이번 회차 미수집** | 재수집·커버리지 개선 |

> [MUST] **코드축 셀은 두 값만 허용한다** — `code-scan` 경유로 확보한 근거 인용, 또는 `?`.
> 이번 회차에 코드축을 수집하지 않았으면(축약 경로 포함) 빈칸이 아니라 `?`다. 기존 지식이 담고 있던 코드 인용을 원문 재확인 없이 옮겨 적은 것도 `?`로 표기한다(→ §4 N-2).
> 근거: 매트릭스는 매 회차 생성되는 산출물이므로, 여기에 조건을 걸면 코드축 규율(I-4·N-2)이 눈에 보이게 집행된다.

**갭 목록** — 축 간 불일치·결측·확정 필요 항목을 나열한다.

- 각 항목은 `현상 / 판정(§5 3분류) / 다음 행동` 3요소를 갖는다.

### [N-3 산출물 거처 선판정]

- 보고 산출 **전에** 이 분석 결과를 어디에 남길지 먼저 판정한다.
- 판정 없이 임의 위치에 파일을 만들지 않는다.

| 결과 성격 | 거처 | 근거 |
|----------|------|------|
| 일회성 답변 — 재사용 가치 없음 | 세션 응답만, 파일 미생성 | — |
| 설계 WHY·도메인 지식·비자명 해법 | brain 페이지 | `opal/core/references/harness/memory-learning.md` §라우팅 표 |
| 행동을 지배하는 규범으로 승격 | `docs/` 해당 문서 갱신 제안 | `opal/core/references/harness/memory-learning.md` §라우팅 표(docs=규범) |
| 진행 중 태스크의 중간 산출 | 해당 태스크 폴더 | `docs/CONVENTIONS.md` §태스크 산출물 구조 |

> [MUST] **이중 SSOT 금지** — 기존 페이지·문서가 이미 같은 내용을 담고 있으면 신규 생성이 아니라 **갱신**을 선택한다 (→ `opal/skills/opal-brain/SKILL.md` §질의 절차).

- **환류**: 갱신 대상으로 판정된 문서와 brain ingest 후보(→ `opal/core/references/opal-pm.md` §14)를 보고 말미에 다음 행동으로 제시한다.

- **산출**: 레이아웃 판정에 따른 본문 + 축 매트릭스 + 갭 목록 + 거처 판정값과 환류 제안.

## 7. 자산 부재 폴백 매트릭스

> **불변 규칙**: 결측은 침묵하지 않는다 — 축소 실행하되 결측 사유를 반드시 축 매트릭스 셀과 갭 목록에 명시한다.

| # | 결측 | 축소 동작 | 보고서 표기 |
|---|------|----------|------------|
| F-1 | brain 부재 (`.opal/brain/` 없음) | 1단계를 `docs/` 레지스트리 + 태스크 산출물 훑기로 대체하고, 재사용 판정을 생략한 채 2단계로 진행 | 갭 목록에 "과거 결정 근거 미확인 — brain 부재" |
| F-2 | term 타입 미채택 | 업무 언어 사전 대조를 생략하고 원문 표현을 그대로 사용하며, 용어 확정이 필요한 지점을 갭으로 승격 | 갭 목록에 "용어 확정 필요 — term 미채택" |
| F-3 | code-scan 미보급 (부재·매칭 0건·저커버리지) | `opal/core/references/harness/header-rules.md` §빈 결과 폴백의 분기를 그대로 적용 — 부재이면 `opal/core/references/pm/code-scan-management.md` §생성 시점을 선행한다 | 축 매트릭스 코드축 셀에 `?` + 갭 목록에 "코드축 부분 커버 — code-scan 폴백 발동" |
| F-4 | 축 SSOT 부재 (정책·화면·데이터 중 해당 축 미선언 또는 SSOT/파생 미판별) | 해당 축을 미보유로 확정하고 남은 축만으로 3단계를 수행 | 축 매트릭스 해당 열 전 셀 `-` + 갭 목록에 "축 SSOT 미선언" |
| F-5 | 기획 산출물 부재 (정책·화면·데이터 3축 전부 없음) | 코드축 단독 관측으로 축소하고, 3단계를 대조 없이 "단일 축 관측"으로 기록 | 판정값 전부 `근거 부족(확정 불가)` + 갭 목록에 "대조 불가 — 기획 산출물 부재" |

> [MUST] F-3은 분기 조건·임계값을 재정의하지 않는다 — 소유자는 `opal/core/references/harness/header-rules.md`다.
> 5행 어느 것도 동작이 중단이 아니다. 분석을 멈추는 것은 사용자가 명시적으로 요청할 때뿐이다.
