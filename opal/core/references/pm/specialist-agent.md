# 프로젝트 전문 에이전트 관리

> 출처: opal-pm.md §11
> Lazy 트리거: 전문 에이전트 디스패치 직전
> 탐색 경로: `opal/core/references/pm/specialist-agent.md`

PM이 프로젝트별 전문 에이전트를 생성하고 관리한다.

## 개념

프레임워크 전문 에이전트(`~/.opal/agents/opal-{domain}-agent/`)는 범용 도메인 지식을 제공한다. 프로젝트 전문 에이전트(`{프로젝트}/.opal/agents/opal-{domain}-agent/`)는 프레임워크 에이전트를 **상속**하고 프로젝트 전용 규칙을 **확장**한다.

```
프레임워크 에이전트 (범용):
  ~/.opal/agents/opal-be-agent/AGENT.md
  "RESTful API 설계 원칙, OWASP 방어, 레이어 구조..."

프로젝트 에이전트 (확장):
  {프로젝트}/.opal/agents/opal-be-agent/AGENT.md
  "프레임워크 에이전트를 Read하고 따른다.
   + 이 프로젝트 전용: camelCase, BaseRepository 상속 필수, 소프트 삭제..."
```

워커가 프로젝트 에이전트를 로드하면:
1. 프레임워크 에이전트 Read 지시를 따름 → 범용 전문성 로드
2. 프로젝트 전용 규칙을 추가 적용

## 프로젝트 에이전트 구조

```markdown
---
name: opal-be-agent
extends: ~/.opal/agents/opal-be-agent/AGENT.md
project: {프로젝트명}
---

# opal-be-agent — {프로젝트명} 프로젝트 확장

> 프레임워크 에이전트를 상속하고, 이 프로젝트 전용 규칙을 추가한다.

## 프레임워크 에이전트 로드

`~/.opal/agents/opal-be-agent/AGENT.md`를 Read하고 실행 프로세스·페르소나·금지 규칙을 따른다.

## 프로젝트 전용 규칙

### 확정 기준
- {프로젝트에서 확정된 규칙}

### 추가 참조 문서
- {프로젝트 전용 문서 경로}

### 추가 금지사항
- {프로젝트 전용 금지}
```

## 생성 시점

| 트리거 | PM 동작 |
|--------|---------|
| 소유자 지시 ("BE 에이전트 세팅해줘") | 코드베이스 분석 → 프로젝트 에이전트 생성 |
| opi 프로젝트 초기화 시 | 기술 스택 파악 → 필요한 에이전트 식별 → 초안 생성 제안 |
| 첫 전문 에이전트 디스패치 시 | 프로젝트 에이전트 미존재 → 생성 제안 |

## 갱신 트리거

| 트리거 | PM 동작 |
|--------|---------|
| `opal-pm.md` §5 학습 루프 — 반복 원칙 확정 | 해당 도메인 에이전트의 "확정 기준"에 추가 |
| 소유자 피드백 ("이 규칙 추가해") | 해당 에이전트의 "프로젝트 전용 규칙"에 추가 |
| 프로젝트 구조 변경 | "추가 참조 문서" 갱신 |

## 탐색 경로와 에이전트 선택

워커 디스패치 시 에이전트 파일 탐색:

```
1순위: {프로젝트}/.opal/agents/{agent-name}/AGENT.md  ← 프로젝트 확장 (있으면)
2순위: ~/.opal/agents/{agent-name}/AGENT.md            ← 프레임워크 기본 (없으면)
```

1순위가 있으면 1순위를 로드한다. 1순위 AGENT.md가 내부에서 프레임워크 에이전트를 Read하므로, 프레임워크 전문성 + 프로젝트 규칙이 합산된다.

## 루트 AGENT.md 확정 기준 분배

프로젝트 전문 에이전트 생성 시, 루트 `.opal/AGENT.md`의 확정 기준을 도메인별로 분배한다.

**분배 규칙**:
1. 루트 AGENT.md의 확정 기준을 분석하여 도메인(BE/FE/DB/공통)을 판별
2. 도메인 전용 기준 → 해당 프로젝트 전문 에이전트의 "확정 기준"으로 이동
3. 공통 기준 → 루트 AGENT.md에 유지
4. 이동된 항목은 루트 AGENT.md에서 제거하거나, "→ opal-{domain}-agent로 이관" 표시

**분배 후 역할**:

| 파일 | 내용 | 읽는 주체 |
|------|------|----------|
| 루트 `.opal/AGENT.md` | 공통 원칙 + PM 검토 기준 | PM |
| 프로젝트 전문 에이전트 | 도메인 전용 확정 기준 + 금지사항 | 워커 (자체 로드) |

**PM Gate 검토**: PM은 프로젝트 전문 에이전트의 내용을 생성/갱신 시 이미 알고 있다. PM Gate에서 도메인 규칙 위반을 확인하려면 해당 프로젝트 에이전트를 Read하여 검증한다.
