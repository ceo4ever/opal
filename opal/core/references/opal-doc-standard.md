# OPAL 문서 표준 (opal-doc-standard)

> 참조 전용 — 다른 스킬이 문서 산출물 작성/수정 시 이 규칙을 따른다.
> 탐색 경로: ~/.opal/references/opal-doc-standard.md

## 1. 언어 규칙

- 프로젝트의 CLAUDE.md 또는 코드 컨벤션 문서에 정의된 언어 규칙을 **우선** 따른다.
- 별도 규칙이 없으면: 본문 한국어, 코드/변수/필드명 영어.
- 파일명: 프로젝트 규칙 우선. 별도 규칙이 없으면 `{내용}_{버전}.{확장자}` 형식.
- 문서 형식: Markdown(.md) 기본, 필요 시 .docx/.xlsx/.pptx.
- 저장 위치: 프로젝트 구조에 맞춰 저장한다.

## 2. 문서 헤더 템플릿

모든 기술 문서는 반드시 아래 구조로 시작한다:

```markdown
# [문서 제목]

> 작성일: YYYY-MM-DD | 작성자: [작성자명] | 버전: v{X.Y}

---

## 1. 개요
[문서 목적, 대상, 범위]

## 2. 상세 내용
[본문]

## 3. 참고사항
[관련 문서, 제약사항]

---

변경이력:

| 버전 | 날짜 | 작성자 | 변경내용 |
|------|------|--------|---------|
| v1.0 | YYYY-MM-DD | [작성자명] | 초기 작성 |
```

## 3. 문서 유형별 필수 섹션

| 문서 유형 | 필수 섹션 | 비고 |
|-----------|----------|------|
| **분석서** | 개요, 분석 대상, 분석 결과, 종합 평가 | 데이터 기반 |
| **명세서** | 개요, 인증, 엔드포인트, 요청/응답, 에러, 제한사항 | API 중심 |
| **정책서** | 개요, 용어정의, 각 정책 영역, 변경이력 | 비즈니스 규칙 |
| **설계서** | 개요, 아키텍처, 상세 설계, 인터페이스, 제약사항 | 기술 중심 |
| **계획서** | 개요, 목표, 범위, 일정, 산출물, 리스크 | 작업 계획 |

## 4. 테이블 작성 규칙

- 모든 테이블에는 헤더 행과 구분선이 있어야 한다.
- 테이블 내 데이터는 좌측 정렬 기본.
- 빈 셀은 `-` 또는 `N/A`로 표시.
- 테이블이 5개 컬럼을 초과하면 분리 검토.

## 5. 버전 넘버링 규칙

### 형식: `v{Major}.{Minor}`

| 변경 수준 | 버전 변경 | 예시 | 기준 |
|-----------|----------|------|------|
| **구조적 변경** | Major 증가 | v1.0 → v2.0 | 섹션 추가/삭제, 엔티티 신규, 아키텍처 변경 |
| **내용 수정** | Minor 증가 | v1.0 → v1.1 | 기존 섹션 내용 수정, 오류 수정, 보강 |

**Major 변경** (v1.x → v2.0):
- 새로운 주요 개념이나 구조가 추가될 때
- 문서 구조(섹션) 자체가 추가되거나 대폭 변경될 때
- 기존 규칙이 근본적으로 바뀔 때

**Minor 변경** (v1.0 → v1.1):
- 기존 섹션 내 설명 보강, 테이블 데이터 추가
- 오탈자, 수치 수정
- 기존 규칙의 세부 조정

## 6. 파일 관리 프로세스

1. **기존 버전 확인** — 해당 폴더에서 동일 문서의 최신 버전을 확인한다.
2. **새 파일 생성** — 기존 파일을 절대 덮어쓰지 않는다. 새 버전은 새 파일로 생성한다.
3. **변경이력 업데이트** — 문서 하단의 변경이력 테이블에 새 버전 항목을 추가한다. 이전 버전의 변경이력도 모두 포함해야 한다.
4. **헤더 메타정보 갱신** — `> 작성일: {오늘 날짜} | 작성자: {에이전트명} | 버전: v{새 버전}`

산출물 업데이트 요청 시 주의사항:
- 반드시 최신 버전 파일을 Read로 먼저 확인
- 변경 범위를 파악하여 Major/Minor 결정
- 이전 버전의 모든 내용을 새 버전에 계승 (누락 방지)
- 변경된 부분만 정확히 수정 (관련 없는 부분 변경 금지)

## 7. 변경이력 테이블 형식

```markdown
| 버전 | 날짜 | 작성자 | 변경내용 |
|------|------|--------|---------|
| v1.0 | YYYY-MM-DD | {작성자} | 초기 작성 |
| v1.1 | YYYY-MM-DD | {작성자} | {핵심 변경 1줄 요약} |
```

변경내용은 1줄로 핵심만 기술한다. 상세 내용은 문서 본문에서 확인한다.

## 8. HTML/바이너리 파일 버전 관리

코드 내부에 변경이력 섹션이 없는 파일(HTML, 바이너리 등):
- 파일명으로 버전 관리 (예: `wireframe_v3.0.html`)
- 부분 수정은 기존 파일을 직접 Edit (Minor: 파일명 유지)
- 대규모 변경은 새 파일 생성 (Major: 새 파일명)

## 9. 작업 보고 규칙

문서 작성 완료 시 반드시 다음을 제공한다:
- 산출물 파일 경로
- 주요 변경 사항 요약 (3줄 이내)
- 관련 문서 영향 분석 (다른 문서에 영향이 있는지)
