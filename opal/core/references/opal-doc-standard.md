# OPAL 문서 표준

> 참조 전용. 실행 지시문과 OPAL이 생성하는 프로젝트 문서의 공통 기준이다.

## 1. 문서 계열

| 계열 | 대상 | 기준 |
|---|---|---|
| 실행 지시문 | SKILL, AGENT, harness, reference | 에이전트가 현재 행동을 결정하는 데 필요한 내용만 유지 |
| 프로젝트 산출물 | TASK, 분석·설계·기획·테스트·보고 문서 | 사용자가 판단하고 다음 단계가 소비할 내용만 유지 |
| 외부 납품본 | docx, pdf, xlsx 또는 명시적 스냅샷 | 사용자가 요구한 형식·버전 계약 적용 |

문서별 필수 절과 템플릿은 해당 문서를 생성하는 스킬이 소유한다. 이 표준은 모든 문서에
`개요 / 상세 / 참고사항` 같은 공통 골격을 강제하지 않는다.

## 2. 공통 작성 규칙

- 프로젝트의 `docs/PROJECT.md`와 선별된 컨벤션·도메인 문서를 우선한다.
- 별도 언어 규칙이 없으면 본문은 한국어, 코드·필드명은 영어로 쓴다.
- 같은 사실은 한 곳에만 쓰고 다른 문서는 경로와 필요한 구간을 참조한다.
- 상태, 승인, 실행 증거처럼 전용 SSOT가 있는 정보는 본문에 복제하지 않는다.
- 확인한 사실과 가정, 결정이 필요한 항목을 구분한다.
- 표는 비교·매핑에 도움이 될 때만 사용한다. 열이 많아 읽기 어려우면 내용을 줄이거나 분리한다.
- 소스 원문 인용과 비즈니스 문서의 코드 식별자 표기는 `harness/citation-rules.md`를 따른다.

## 3. 실행 지시문

문장을 지웠을 때 에이전트의 행동이나 판단이 달라지는 내용만 유지한다.

유지:

- 입력·출력 계약
- 실제 분기와 종료 조건
- 도구가 집행하지 못하는 중요한 경계
- 조건부 reference를 언제 읽는지 정하는 라우팅

제거:

- 도입 경위와 논의 과정
- 상위 문서의 규칙 재서술
- 사용 여부가 보장되지 않는 고정 MCP·스킬·도구 목록
- 일반적인 직무 상식과 과도한 persona 규칙
- 이미 guide에 있는 템플릿·체크리스트의 SKILL 복제

SKILL은 라우팅과 핵심 계약을, guide는 상세 절차와 출력 형식을 소유한다. 조건부 reference는
해당 조건에서만 읽는다.

## 4. 프로젝트 산출물

- 사용자가 판단해야 할 내용과 다음 단계의 입력만 쓴다.
- 현재 유효한 문서를 제자리에서 갱신한다.
- 변경 전 내용을 보존하기 위해 새 버전 파일을 자동 생성하지 않는다.
- 문서 내부에 변경이력 표를 기본 생성하지 않는다.
- 작업 경위는 task 산출물과 git, 단계 상태는 `state.json`, 테스트 결과·증거는
  `test-scenario.json` 등 해당 SSOT가 소유한다.
- 정책·기획 문서는 비즈니스 용어를 주어로 쓰고 코드 식별자는 필요한 근거로만 병기한다.

문서 형식에 버전이 실제 계약인 경우에는 유지한다. 예를 들어 외부 공개 규격, 사용자가 버전별
납품을 요구한 문서, 다른 도구가 특정 버전을 대조하는 산출물이 해당한다.

## 5. 이력과 버전

Markdown 문서의 이력은 git과 태스크 기록이 소유한다. SKILL, AGENT, harness, reference와
git으로 관리되는 프로젝트 산출물에는 `변경이력`, `Changelog`, `history`, `revisions` 등 이름과
무관하게 수기 누적 이력 절을 만들지 않는다.

문서 상단 버전이나 frontmatter `version`도 소비자가 있을 때만 둔다. 단순히 수정 횟수를 나타내는
버전은 만들지 않는다. 외부 납품본의 파일명·헤더 버전은 사용자 요구나 배포 계약이 있을 때만 쓴다.

## 6. 파일 형식

원본은 Markdown 또는 해당 구조 데이터의 원래 형식을 사용한다. docx, pdf, xlsx 변환본은 사용자가
요청했거나 실제 전달 경로에서 필요할 때만 만든다. 변환본이 원본 역할을 대체하지 않도록 원본 경로와
생성 기준을 함께 관리한다.

## 7. 완료 보고

문서 작성·수정 후 다음만 보고한다.

- 산출물 경로
- 사용자가 판단할 핵심 변경
- 함께 갱신해야 할 다른 문서나 남은 불일치
