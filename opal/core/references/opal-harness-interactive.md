# opal-harness-interactive.md

> interactive 모드(기본) 전용 하네스. 공통 하네스(opal-harness.md)와 함께 로드한다.

---

## 1. 단계 게이트

각 단계 완료 시 사용자에게 보고하고 승인을 받는다.

| 응답 | 동작 |
|------|------|
| "확인", "다음", "승인" | 다음 단계 진행 |
| 피드백/수정 요청 | 현재 단계 수정 후 재보고 |
| "중단", "보류" | 산출물 저장 후 대기 |

## 2. QA Gate

단계 완료 후 QA 에이전트를 호출하여 산출물을 검증한다.

| 오케스트레이터 도메인 | QA 스킬 (qa_skill) | QA 에이전트 | 비고 |
|---------------------|-------------------|------------|------|
| dev (opd/opds/opdw) | op-dev-qa | opal-task-qa-agent | |
| 범용 (opp) | op-task-qa | opal-task-qa-agent | |
| SDD (opsdd) | op-task-qa (SPEC/REVIEW/DESIGN Phase) / op-dev-qa (EXECUTE-LOOP Phase) | opal-task-qa-agent | Phase별 QA 스킬이 다름 |
| 기획 산출물 (opwt) | op-task-qa | opal-task-qa-agent | 기획 문서 검증 |

각 오케스트레이터 SKILL.md에서 QA 스킬명을 명시한다.
탐색 경로: `{프로젝트}/.opal/skills/{qa-skill}/SKILL.md` -> `~/.opal/skills/{qa-skill}/SKILL.md`

**QA Gate 완료 즉시 — State Gate**:
진행 현황 테이블에서 QA Gate 행 → ✅, 바로 이어지는 State Gate 행 → ✅로 갱신한다.
미갱신 시 PM이 즉시 갱신한다. 갱신 확인 후 Artifact Gate로 진입한다.
Fail 시: §5 Gate Fail 공통 처리 참조.

## 2.5 Artifact Gate

QA Gate 완료 후 PM Gate 진입 전, 필수 산출물 파일의 존재 여부를 확인한다.

**게이트 진입 조건**: QA Gate + State Gate 완료 후 자동 실행

**자가 점검 프롬프트**:
> "QA 산출물 파일이 존재하는가?"
> 1. 현재 단계의 필수 산출물 파일명을 확인한다 (하네스 §2 QA 산출물 표준 파일명 또는 SKILL.md 참조)
> 2. 파일이 `tasks/{NNN}-{name}/` 경로에 실제로 존재하는지 확인한다
> 3. 파일이 존재하고 비어 있지 않은지 확인한다

| 확인 결과 | 동작 |
|----------|------|
| 산출물 파일 존재 + 내용 있음 | Artifact Gate 통과 |
| 산출물 파일 미존재 | QA 에이전트 재소환 → 산출물 생성 후 재확인 |
| 산출물 파일 존재하나 비어 있음 | QA 에이전트 재소환 → 산출물 재생성 후 재확인 |

**차단 원칙**: 필수 산출물이 확인되지 않으면 PM Gate 및 DONE.md 생성 단계로 진입하지 않는다.

**Artifact Gate 완료 즉시 — State Gate**:
진행 현황 테이블에서 Artifact Gate 행 → ✅, 바로 이어지는 State Gate 행 → ✅로 갱신한다.
미갱신 시 PM이 즉시 갱신한다. 갱신 확인 후 PM Gate로 진입한다.
Fail 시: §5 Gate Fail 공통 처리 참조.

## 3. PM Gate

`.opal/AGENT.md`가 존재하면 PM 검토 기준으로 산출물을 검토한다.
상세: `opal-pm.md` §4 "PM 검토 게이트" 참조.
AGENT.md 미존재 시 스킵.

**PM Gate 완료 즉시 — State Gate**:
진행 현황 테이블에서 PM Gate 행 → ✅, 바로 이어지는 State Gate 행 → ✅로 갱신한다.
미갱신 시 PM이 즉시 갱신한다. 갱신 확인 후 사용자 확인으로 진입한다.
Fail 시: §5 Gate Fail 공통 처리 참조.

---

### 체크리스트 갱신 상태 확인 (모든 PM Gate 공통)

PM Gate에서 체크리스트 갱신 상태를 반드시 확인한다. QA 에이전트가 1차 갱신을 수행하므로, PM은 갱신 결과를 **확인**하는 역할이다.

**PLAN PM Gate 시**:
1. TASK.md 요구사항 체크박스 갱신 상태를 확인한다
2. 미갱신 항목이 있으면 QA 에이전트(op-task-qa 또는 op-dev-qa)를 재소환하여 갱신하게 한다
3. PM이 직접 체크박스를 갱신하지 않는다

**EXECUTE PM Gate 시**:
1. PLAN.md §3 실행 체크리스트 갱신 상태를 확인한다
2. PLAN.md §4 QA 체크리스트 갱신 상태를 확인한다
3. 미갱신 항목이 있으면 QA 에이전트를 재소환하여 갱신하게 한다
4. **모든 체크리스트가 갱신 완료된 후에만** DONE.md 생성으로 진행한다

> **QA 에이전트 미발동 시**: PM Gate에서 미갱신을 감지하면 이 시점에서 QA 에이전트를 소환하여 갱신한다.

## 4. 체크리스트 검증 게이트

EXECUTE 완료 후, PLAN.md 실행 체크리스트 갱신을 2단계로 보장한다.

**1차 책임 — 워커(서브에이전트)**:
- EXECUTE 중 각 Step 완료 시 PLAN.md 실행 체크박스 즉시 갱신 (`- [ ]` → `- [x]`)

**1차 갱신 — QA 에이전트**:
- QA 수행 시 해당 시점의 체크리스트를 Read하고 검증 통과 항목을 `[x]`로 갱신

**2차 확인 — 오케스트레이터(PM)**:
- PM Gate에서 체크리스트 갱신 상태를 확인한다 (§3 "체크리스트 갱신 상태 확인" 참조)
- 미갱신 항목 발견 시: QA 에이전트를 재소환하여 갱신 (PM 직접 갱신 금지)
- **체크리스트 완전 갱신 확인 후에만** DONE.md / 완료 보고로 진행

## 5. Gate Fail 공통 처리

Gate 통과 실패 시 아래 절차를 따른다. 각 Gate 섹션의 "Fail 시 §5 참조"는 이 섹션을 가리킨다.

### PM 즉시 처리 (사용자 개입 불필요)

| Gate | Fail 원인 | PM 처리 |
|------|----------|---------|
| State Gate | 진행 현황 테이블 미갱신 | PM이 즉시 해당 행 갱신 → State Gate 재확인 |

### 재소환·재지시 처리

| Gate | Fail 원인 | PM 처리 | 최대 재시도 |
|------|----------|---------|-----------|
| QA Gate | 산출물 품질 기준 미달 | 워커 재지시 | 1회 |
| Artifact Gate | 산출물 파일 미존재/비어있음 | QA 에이전트 재소환 | 1회 |
| PM Gate | 체크리스트 미갱신 | QA 에이전트 재소환 | 1회 |

### 사용자 에스컬레이션 조건

재시도 한계 초과 또는 아래 조건에 해당하면 즉시 사용자에게 보고한다:

- QA Gate 재지시 후 재실패
- Artifact Gate 재소환 후 산출물 미생성
- PM Gate 재소환 후 체크리스트 여전히 미갱신
- 설계/아키텍처 수준 문제 감지 (즉시 에스컬레이션, 재시도 없음)

에스컬레이션 보고 형식:
> `❌ Gate Fail: {Gate명}` — {실패 원인} / 재시도 {N}회 / {판단 필요 내용}

### 순서 강제 원칙

진행 현황 테이블에서 현재 행보다 앞 행이 ✅ 또는 `-`가 아니면 현재 행을 진행할 수 없다.

| 앞 행 상태 | 현재 행 진입 |
|----------|------------|
| ✅ 또는 - | 가능 |
| ⬜ 또는 🔄 | **불가** — 앞 행 완료 후 진입 |
| ❌ | **불가** — 에스컬레이션 해소 후 진입 |
