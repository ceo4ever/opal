# opal-pilot-project-loop

목표·계약·백로그가 실행 결과에 따라 계속 바뀌는 프로젝트를, 반복(수렴 루프)으로 완주시키는 스킬. 별칭 `oppl`.

## 개요

`//oppl`을 호출하면 먼저 설계를 확정하는 "설계 수렴 루프"(PRD/TRD/계약/백로그를 만들고, 문제가 발견되면 다시 다듬는 과정을 반복)를 거치고, 이어서 백로그의 각 작업을 완료할 때까지 반복하는 "실행 수렴 루프"를 진행합니다. 매 회전마다 목표 달성 여부를 도구(백로그 상태·테스트 결과)로 판정하며, 사람의 주관적 판단으로 종료를 결정하지 않습니다.

## 언제 쓰나

- 처음부터 요구사항을 다 확정할 수 없고, 구현 결과를 보면서 계획을 계속 조정해야 하는 프로젝트일 때
- 안정성 목표, 실험적 품질 개선, 탐색형 제품처럼 "해보고 나서 다음을 정하는" 성격의 프로젝트일 때

> 반대로 한 번의 설계 승인으로 목표·계약·완료조건을 잠글 수 있는 프로젝트라면 `oppb`를 사용하세요. 단순히 파일 수가 많거나 기술적으로 어렵다는 이유만으로는 이 스킬을 선택하지 않습니다.

## 사용법

```
//oppl {요청 내용}                  # 기본 — 설계 확정까지 사용자 검토, 이후 실행은 자동 진행
//oppl --interactive {요청 내용}    # 실행 중 각 작업마다 사용자 승인
//oppl --agentic {요청 내용}        # 설계 확정까지도 자동 진행 (완료 승인만 사용자가 함)
```

`docs/PROJECT.md`가 없는 프로젝트에서 호출하면 프로젝트 초기 설정을 먼저 자동으로 실행합니다.

## 파이프라인

**Loop 1 — 설계 수렴** (PRD/TRD/CONTRACT/백로그 4요소가 확정될 때까지 반복)

1. 인터뷰로 목표·범위·제약·완료기준을 명확히 하고, 사용자 대면 프로젝트면 여정 지도를 작성합니다.
2. PRD → TRD → CONTRACT(인터페이스 계약)를 순서대로 작성합니다.
3. 작업(백로그)을 얇은 단위로 쪼개 등록합니다.
4. 설계 전체를 검토해, 미해결 이슈가 있으면 다시 다듬고, 없으면 사용자에게 최종 확정을 요청합니다. 확정되면 PRD/TRD/CONTRACT이 `docs/`로 승격되고 Loop 2로 넘어갑니다.

**Loop 2 — 실행 수렴** (백로그의 모든 작업이 완료될 때까지 반복)

1. 우선순위와 의존성에 따라 다음 작업을 하나 선택합니다.
2. 선택된 작업은 내부적으로 "명세 작성 → 테스트 시나리오 작성 → 명세 검토 → 구현 → 테스트 → 규칙 검사 → 마무리" 파이프라인을 자율로 완주합니다. 명세 검토는 구현 전에, 실제 테스트는 구현 후에 각각 별도로 수행합니다(이중 검증).
3. 모든 작업이 끝나고 회귀도 없으면 종료하고, 남은 작업이 있으면 다시 다음 작업을 선택합니다.

## 산출물

```
tasks/{번호}-oppl-{프로젝트명}/
├── TASK.md · STATE.md · DONE.md
├── PRD.md · TRD.md · CONTRACT.md · USER_JOURNEY.md*   (* 사용자 대면 프로젝트만, 설계 확정 후 docs/로 승격)
├── BACKLOG.md            # 백로그 현황 (자동 생성 미러)
└── tasks/
    └── T{NN}-{작업명}/    { PLAN.md, test-scenario.json, QA-SPEC.md, DONE.md }
```

## 관련 스킬

- **opal-planning-agent / opal-plan-agent** — Loop 1에서 PRD/TRD/CONTRACT를 실제로 작성합니다.
- **opal-fe-agent / opal-be-agent / opal-db-agent** — Loop 2에서 각 작업 영역(FE/BE/DB)의 구현을 담당합니다.
- **opal-brain (opbr)** — 프로젝트에 브레인이 설정되어 있으면, 완료 시 설계 결정과 산출물이 브레인에 누적됩니다.

## FAQ

### 설계가 계속 바뀌면 무한정 반복되나요?
아닙니다. 반복 횟수 상한, 예산, 무진전(더 이상 나아지지 않는 상태) 감지 등 여러 종료 조건이 있어 한계에 도달하면 자동으로 진행을 멈추고 사용자에게 알립니다.

### Loop 2에서 새로운 작업이 필요해지면 어떻게 하나요?
진행 중 범위 확장이 발견되면 백로그에 새 작업을 추가할 수 있습니다. WBS를 다시 통째로 쓰는 대신 백로그를 계속 살아있는 상태로 유지합니다.

### 계약(CONTRACT.md)이 실행 중 바뀔 수 있나요?
내부 조정 수준이면 자동으로 반영되지만, 외부에 노출되는 계약 변경은 항상 사용자 승인을 거칩니다.

### 병렬로 여러 작업을 진행할 수 있나요?
네, 서로 의존하지 않는 작업은 병렬로 진행할 수 있습니다. 다만 계약이 확정된 뒤에만 FE/BE를 병렬로 진행하며, 병렬로 진행한 작업들은 반드시 통합 검증 작업을 거칩니다.
