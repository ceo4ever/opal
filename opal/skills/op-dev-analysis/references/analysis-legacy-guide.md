# Legacy ANALYSIS 작성 가이드

> `template: sdlc-v2`가 없는 TASK에서 기존 `ANALYSIS.md`도 없을 때만 읽는다. 기존 ANALYSIS가 있으면 재작성하지 않는다.

기존 state/pipeline gate가 소비하는 절 이름과 표 헤더를 유지한다. 내용은 TASK 재개에 필요한 만큼만 채우며 신규 sdlc-v2 절을 섞지 않는다.

```markdown
# ANALYSIS: {제목}

## 확정 입력 판정

| 항목 | 판정 | 근거 |
|---|---|---|
| {TASK의 결정 또는 사실} | 해당없음(결정) / 유효(대조 확인) / 수정필요 / 사실오류 | {근거} |

## 0. 참조 문서

| # | 유형 | 문서/사이트 | 경로/URL | 참조 이유 |
|---|---|---|---|---|

## 1. 기존 코드 분석

### 1.1 관련 파일 목록

| 영역 | 경로 | 역할 | 변경 유형 | 근거(줄번호) |
|---|---|---|---|---|

## 2. 외부 조사 결과

## 3. 영향 범위

## 4. 핵심 발견 사항

## 5. 제약/리스크

## 6. 기술 컨텍스트

## 7. 지정 분석 질문 Q1~QN 답변

## 8. 다음 단계 입력 — PLAN이 재조사 없이 쓸 수 있는 확정값

| 항목 | 확정값 | 근거 |
|---|---|---|

### PLAN 결정 필요

| 항목 | 쟁점 | 근거 |
|---|---|---|
```

PM이 주입한 프로젝트 문서와 runtime capability만 사용한다. 프로젝트 전체 기술 스택이나 도구 목록을 채우지 않는다.
