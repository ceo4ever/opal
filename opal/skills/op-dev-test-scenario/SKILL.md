# op-dev-test-scenario — 테스트 시나리오 작성

## 실행 컨텍스트

- **호출자**: `opal-pilot-dev` STEP 3.5 — 오케스트레이터(PM + 사용자 페어)가 직접 수행 (워커 디스패치 없음)
- **작성자**: PM + 사용자 페어 — self-confirming 방지를 위해 PLAN 워커(opal-plan-agent)와 다른 작성자가 수행한다
- **입력**: `tasks/{NNN}-{태스크명}/TASK.md` + `PLAN.md` (§ 리스크 가설 표 필수)
- **출력**: `tasks/{NNN}-{태스크명}/TEST-SCENARIO.md`
- **목표-커버리지 게이트 규칙 SSOT**: `opal/core/references/harness/scenario-gate.md` — 루브릭 6축(①목표달성~⑥경계/부정)·판정 주체 분리·정규화 계약·종료조건 3종은 이 문서가 SSOT다.

## 페르소나

```
Read ~/.opal/skills/op-dev-test-scenario/personas/qa-engineer.md
```

페르소나 파일이 없으면 다음 역할을 따른다:
- 시니어 QA 엔지니어
- 기능·경계값·통합 관점에서 빈틈 없이 시나리오를 도출한다
- 설계 빈틈을 발견하면 즉시 피드백한다

## 프로세스

### Step 1. 테스트 시나리오 가이드 로딩

```
Read ~/.opal/skills/op-dev-test-scenario/references/test-scenario-guide.md
```

가이드에 따라 컨텍스트 확인 → 도구 사전 결정 → 시나리오 도출 → 작성 → 설계 검증을 순서대로 수행한다.

### Step 2. TEST-SCENARIO.md 작성

가이드의 프로세스(Step 1~5)를 따라 시나리오를 도출하고 아래 통일 형식으로 작성한다.

## 시나리오 작성 체크리스트

TEST-SCENARIO.md 작성 후 자체 검증한다:

- [ ] PLAN.md §리스크 가설 표를 Read하여 H-N 목록을 확인했는가
- [ ] §1 리스크 가설 표에 H-N 가설이 모두 기재되었는가 (컬럼 6종: ID/변경 단위/계약/영향/계층/시나리오)
- [ ] §2.1 사전 조건 데이터 표의 모든 칸이 채워졌는가 (테이블/식별자/상태/출처)
- [ ] §2.2 시나리오별 데이터 흐름에 Given/When/Then 3필드가 모두 작성되었는가
- [ ] 모든 시나리오에 L1/L2/L3 계층이 명시되었는가
- [ ] test-scenario-guide.md 계층 결정 규칙 표를 적용하여 계층을 결정했는가
- [ ] mock/patch/MagicMock 등 시나리오 본문에 없는가 (grep 확인 — 존재 시 PM Gate FAIL)
- [ ] §4 AC ↔ 가설 ↔ 계층 ↔ 시나리오 매핑 표가 완전한가 (미매핑 시나리오 없음)
- [ ] L3 [SUPERVISOR] 마커가 있는 시나리오가 있으면 PM 표준 요청 양식을 첨부했는가
- [ ] op-dev-execute 워커 담당 필드(실행 명령)와 opal-test-agent 담당 필드(결과/상세)는 비워두었는가
- [ ] FE 변경(화면/컴포넌트·인증/인가·외부 API)이 포함된 경우 L2/M2 시나리오가 최소 1건 작성되었는가? (`test-scenario-guide.md` §Step 3-b M2 의무 트리거 참조)

## 완료 후 동작

TEST-SCENARIO.md 작성이 완료되면 State Gate를 수행하고 사용자에게 보고한다. 사용자 승인 = EXECUTE 시작 허가.

**보고 형식**:
```
TEST-SCENARIO 완료: tasks/{NNN}-{태스크명}/TEST-SCENARIO.md
승인 시 EXECUTE 단계를 진행합니다.
```
