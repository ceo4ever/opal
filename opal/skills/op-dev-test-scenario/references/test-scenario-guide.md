# TEST-SCENARIO.md 작성 가이드

> **실행 컨텍스트**: 이 가이드는 `opal-pilot-dev` STEP 3.5에서 알투(PM) + 캡틴 페어가 직접 읽고 따른다.
> PLAN 완료 후, EXECUTE 전에 오케스트레이터가 이 가이드를 읽고 TEST-SCENARIO.md를 작성한다.
> 작성된 TEST-SCENARIO.md는 사용자 검토 게이트를 거친 후, EXECUTE 단계에서 실행 명령이 채워지고, TEST 단계에서 opal-test-agent가 결과를 채운다.

---

## 목적

TEST-SCENARIO.md는 두 가지 역할을 수행한다:

1. **리스크 가설 기반 시나리오 설계** — PLAN.md §리스크 가설 표에서 H-N 가설을 읽어 검증 시나리오를 도출. self-confirming 방지를 위해 PLAN 작성자(opal-plan-agent)와 다른 작성자가 수행.
2. **TDD red-green 연결** — EXECUTE 워커가 시나리오 실행 명령을 채우고, L1/L2 PASS = 구현 완료 기준으로 삼는다.

---

## 작성 프로세스

### Step 1: PLAN 가설 표 Read

PLAN.md §리스크 가설 표를 Read하여 H-N 목록을 파악한다:
- 변경 단위 (F-NNN 또는 파일)
- 깨질 수 있는 계약 (함수 반환 계약 / DB 제약 / API 계약)
- 운영 영향 (P0/P1/P2)
- 검증 계층 권고 (L1/L2/L3)
- 시나리오 후보 (S-N 후보)

가설 없이 시나리오를 도출하면 "당연한 시나리오"만 생산된다 — PLAN.md 가설 표가 누락되었으면 PLAN 단계로 되돌아간다.

### Step 2: 데이터 설계

TEST-SCENARIO.md §2를 작성한다:

**§2.1 사전 조건 데이터** — 각 시나리오 실행 전 DB에 존재해야 하는 레코드:
- 테이블명, 식별자, 상태, 출처(fixture/seed/수동)
- 빈 칸 없이 모두 채워야 한다 — 빈 칸 = PM Gate FAIL

**§2.2 시나리오별 데이터 흐름** — Given/When/Then 3필드:
- Given (read): 시나리오 실행 전 사전 데이터 상태
- When (CUD/호출): 실행하는 조작 (Create/Update/Delete 또는 API 호출)
- Then (re-read): 조작 후 검증할 데이터 상태

### Step 3: 계층 결정

아래 계층 결정 규칙 표를 적용하여 각 가설의 시나리오 계층을 결정한다:

**계층 결정 규칙 표:**

| 변경 영역 | L1 의무 | L2 의무 | L3 의무 |
|----------|---------|---------|---------|
| DB 스키마/마이그레이션 | 단위 CRUD | FK/NOT NULL 제약 re-read | 해당 없음 |
| API 엔드포인트 | 요청/응답 계약 | 인증·권한 흐름 | 해당 없음 |
| 비즈니스 로직 | 함수 단위 정상/경계 | 서비스 계층 흐름 | 해당 없음 |
| 병렬/동시성 | 해당 없음 | 동시 요청 시나리오 | 수동 부하 테스트 |
| FE 화면/컴포넌트 | 렌더링 단위 | API 연동 흐름 | 사용자 시각 확인 [SUPERVISOR] |
| 인증/인가 | 토큰 발급 단위 | 세션 흐름 | 수동 로그인 [SUPERVISOR] |
| 외부 API 연동 | mock 없이 stub 사용 | 실 API 호출 흐름 | 해당 없음 |

계층 결정 원칙:
- 가설 N건 → 시나리오 N건 이상 (정량 미달 = 당연한 시나리오 누락 의심)
- L3는 FE 사용자 확인 또는 수동 부하 테스트 등 자동화 불가 항목에 한정
- L3가 없으면 §3에 L3 섹션을 생략하거나 "해당 없음" 명시

### Step 3-b: 실행 방식 결정 (M1/M2/M3)

각 시나리오에 검증 깊이(L1/L2/L3)와 별도로 **실행 방식**을 명시한다.

| 코드 | 정의 | 실행 주체 | 자가 점검 가능 |
|------|------|---------|-------------|
| **M1. 테스트 도구** | pytest/vitest/jest 등 표준 단위·통합 테스트 도구 — Bash 단발 실행 | EXECUTE 워커 자가 + opal-test-agent 최종 | ✓ |
| **M2. E2E 자동화** | cmux browser / playwright / cypress 등 브라우저·외부 시스템 자동화 도구 — 시나리오 스크립트 실행 | EXECUTE 워커 자가(가능 시) + opal-test-agent 최종 | △ (도구 환경 준비 필요) |
| **M3. 사용자 협업** | 자동화 불가 또는 자동화 우회 의사결정 — PM 표준 양식으로 캡틴 요청 | [SUPERVISOR] 캡틴 수동 | ✗ |

**변경 영역 7종 × M1/M2/M3 매핑 표:**

| 변경 영역 | M1 도구 예 | M2 E2E 예 | M3 사용자 예 |
|----------|----------|----------|------------|
| DB 스키마/마이그레이션 | pytest + 실 DB | (해당 없음) | (해당 없음) |
| API 엔드포인트 | pytest + httpx | playwright API / cmux | (해당 없음) |
| 비즈니스 로직 | pytest/vitest | (해당 없음) | (해당 없음) |
| 병렬/동시성 | pytest + asyncio | 부하 도구(locust 등) | 캡틴 모니터 확인 |
| FE 화면/컴포넌트 | vitest + RTL | **cmux browser / playwright** | **캡틴 화면 시각 확인** |
| 인증/인가 | pytest | playwright 로그인 흐름 | **캡틴 실 매체 로그인** |
| 외부 API 연동 | pytest + stub | playwright/cmux 실 API | (해당 없음) |

**검증 깊이 × 실행 방식 가능 조합:**

```
              M1. 테스트 도구  M2. E2E 자동화  M3. 사용자 협업
L1 기능 단위        ✓               —               —
L2 프로세스 통합     ✓               ✓               —
L3 사용자 협업       —               (옵션)          ✓
```

→ 시나리오마다 (L, M) 두 코드 모두 명시한다 (예: `L2/M1` = 실 DB 통합 / `L2/M2` = cmux E2E / `L3/M3` = 캡틴 협업).

### Step 4: 시나리오 본문 작성

각 시나리오에 대해 TEST-SCENARIO.md 통일 형식 §3을 작성한다:

**L1 시나리오 작성 요령**:
- 계층: L1 명시
- 가설 매핑: 연결된 H-N 명시
- 조건: 입력값, 사전 상태, 환경 구체적으로 기재
- 기대 결과: 검증 가능한 성공 기준 (예: "반환값 타입이 List[dict]이고 len >= 1")
- 도구: `.opal/test-tools.yaml` 또는 프로젝트 설정에서 결정 (vitest/pytest 등)
- 실행 명령/결과/상세: 비워둠 (EXECUTE 워커 / opal-test-agent가 채움)
- 실행 방식: M1 (테스트 도구) — pytest/vitest 도구명 명시

**L2 시나리오 작성 요령**:
- 계층: L2 명시
- 실 DB read → CUD → re-read 사이클 필수
- 트랜잭션 롤백 없이 실 데이터 확인
- 실행 방식: M1 (도구) 또는 M2 (E2E 자동화) 선택 — 변경 영역 × M 매핑 표 참조

**L3 시나리오 작성 요령**:
- 계층: L3 명시
- `[SUPERVISOR]` 마커를 시나리오 제목에 붙임
- 실행자 필드: "[SUPERVISOR] — 캡틴 수동 확인 필요"
- 결과/상세: 비워둠 (캡틴이 수동 확인 후 기록)
- 실행 방식: M3 (사용자 협업) 기본. M2 자동화 시도가 가능하면 옵션으로 병기.

> **mock 금지 룰**
>
> 시나리오 본문에 `mock`/`patch`/`MagicMock`/`unittest.mock` 등 사용 금지.
> 위반 시 PM Gate FAIL (grep 자동 감지).
> 대안: 실 fixture / factory / seed 데이터 사용.

### Step 5: AC ↔ 가설 ↔ 계층 ↔ 시나리오 4열 매핑 표 완성

TEST-SCENARIO.md §4 매핑 표를 완성한다:

| AC ID | 가설 ID | 검증 계층 | 시나리오 | 비고 |
|-------|---------|---------|---------|------|
| F-N AC (a) | H-N | L1/L2/L3 | S-N | 설명 |

매핑 완전성 검증:
- 모든 AC에 가설 ID 연결 (미연결 = 가설 누락)
- 모든 H-N 가설에 시나리오 연결 (미연결 = 시나리오 누락)
- 모든 시나리오에 계층 명시 (미명시 = 계층 결정 미완)
