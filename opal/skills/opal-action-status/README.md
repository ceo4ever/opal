# opal-action-status

루프 액션 에이전트의 진행 현황을 자동으로 탐지해 한 번에 정리 보고하는 읽기 전용 스킬입니다.

## 개요

`opal-action-monitor` 도구를 호출해 현재 실행 중이거나 최근 실행된 루프 액션 에이전트 태스크의 상태를 조회하고, 필요하면 상위 루프의 백로그(`backlog.json`)와 결합하여 하나의 해석 보고로 보여줍니다. 파일을 쓰거나 상태를 바꾸지 않는 순수 조회 스킬입니다.

## 트리거

- `opas`
- `opal-action-status`
- "액션 에이전트 현황"
- "루프 진행 상황"
- "모니터 현황"
- alias: `opas`

## 사용법

| 호출 | 동작 |
|------|------|
| `//opas` | 태스크 폴더를 지정하지 않으면 현재 위치에서 가장 최신 루프 액션 태스크를 자동으로 찾아 보고합니다 |
| `//opas {태스크폴더}` | 지정한 태스크 폴더를 대상으로 현황을 보고합니다 |

## 동작 흐름

1. **인자 파싱**: 태스크 폴더가 주어졌으면 그대로 대상으로 삼고, 없으면 자동 탐지합니다.
   - 먼저 현재 위치에서 위로 올라가며 `backlog.json`을 가진 루프 루트를 찾고, 그 하위의 `tasks/T*/.oppl-run/` 중 가장 최근 것을 채택합니다.
   - 루프 루트를 못 찾으면 현재 위치 하위의 `tasks/**/.oppl-run/`을 최대 깊이 3까지 훑어 가장 최근 것을 채택합니다.
   - 후보가 여러 개면 최신 것을 채택하되, 상위 후보 목록(최대 10개)도 함께 보여줍니다.
   - 아무것도 찾지 못하면 `//opas <태스크폴더>`로 직접 지정하라고 안내하고 종료합니다.
2. **현황 조회**: `opal-action-monitor --json`을 호출해 대상 태스크의 단계별 상태를 가져옵니다. 조회에 실패하면 오류를 그대로 안내하고 종료합니다.
3. **백로그 결합**: 대상 태스크의 상위에 `backlog.json`이 있으면 `backlog-tool show`를 함께 호출해 루프 전체 진행 상황을 결합합니다. 없으면 이 단계는 자연스럽게 생략됩니다.
4. **해석 보고**: 아래 형식으로 한 번에 정리해 보여줍니다.
   - 대상 태스크 폴더와 생성 시각
   - 전체 blocked 여부 경고(있을 때)
   - 단계별 상태 표(단계, 축, 상태, 경과 시간, 최근 이벤트, 비용)
   - 최근 journal 이벤트 요약
   - (있으면) 루프 전체 백로그 진행 요약
   - 상태에 따른 다음 액션 제안 (예: 실행 중이면 watch 권고, 실패면 err.log 확인 권고, blocked면 사람 확인 필요)
   - 지속 관측이 필요할 때 쓸 수 있는 `--watch` 명령 1줄 안내
5. 이 스킬 자체는 실시간으로 상주하지 않습니다. 계속 지켜보려면 안내된 `--watch` 명령을 터미널에서 직접 실행합니다.

## 산출물

파일을 생성하거나 수정하지 않습니다. 대화 응답으로 현황 보고를 보여주는 것이 전부입니다.

## FAQ

### 여러 루프 액션 태스크가 동시에 진행 중이면 어떻게 되나요
최신 것을 자동으로 채택하되, 다른 후보들의 목록도 함께 보여주므로 다른 태스크를 보고 싶으면 그 경로를 지정해서 다시 호출하면 됩니다.

### 지금은 oppl 파이프라인만 지원하나요
현재는 `.oppl-run/` 관측 규약을 따르는 oppl 루프 액션 에이전트만 대상입니다. 다만 "폴더에 `.oppl-run/`이 있으면 렌더한다"는 범용 원칙으로 설계되어 있어, 다른 파이프라인이 같은 규약을 따르면 스킬 수정 없이 자연히 확장됩니다.
