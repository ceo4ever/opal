# opal-workspace-sync

워크스페이스 안의 여러 git 저장소를 한 번에 안전하게 최신화하는 스킬입니다.

## 개요

워크스페이스 직속 자식 git 저장소들(그리고 프로젝트 root 저장소)을 순회하며, 깨끗하고 fast-forward 가능한 저장소만 자동으로 `pull`합니다. 문제가 있는 저장소(변경사항이 남아있거나, 원격과 갈라졌거나, detached 상태이거나, upstream이 없거나, fetch에 실패한 경우)는 건드리지 않고 skip한 뒤 보고서에 정리하고, 사용자 승인을 받은 조치만 실행합니다.

## 트리거

- `opal-workspace-sync`
- `opws`
- "워크스페이스 동기화"
- "저장소 일괄 pull"
- "일괄 pull"
- alias: `opws`

## 사용법

| 호출 | 동작 |
|------|------|
| `//opws` | 현재 프로젝트(또는 지정한 경로) 아래 `workspace` 폴더나 단일 git 루트를 자동으로 찾아 동기화합니다 |
| `//opws {경로}` | 지정한 경로를 대상으로 동기화합니다 |

경로 판별 규칙: `<경로>/workspace`가 있으면 그 워크스페이스를 대상으로 삼고, `<경로>/.git`도 있으면 그 프로젝트 root 저장소도 함께 포함합니다. `workspace` 폴더가 없고 `<경로>` 자체가 git 저장소면 그 저장소 하나만 대상이 됩니다. 둘 다 아니면 워크스페이스 경로를 직접 물어봅니다.

## 동작 흐름

1. **대상 결정**: 위 경로 판별 규칙에 따라 순회 대상(그리고 필요하면 root 저장소)을 확정합니다. 워크스페이스에 선언 파일(`.opal/workspace.json`)이 있으면 이후 단계에서 선언과 디스크 상태를 대조합니다.
2. **동기화 실행**: `git-sync-tool`로 확정된 경로를 순회하며 각 저장소를 `git pull --ff-only`로 최신화합니다. 순회는 직속 자식 1단계까지만 합니다(재귀하지 않습니다).
3. **보고서 렌더**: 결과를 5개 섹션으로 정리해 보여줍니다.
   - 요약 헤더 (전체/최신화/skip/실패/이미 최신 건수, root 포함 여부)
   - 최신화된 저장소 목록 (이전→새 커밋, 커밋 수)
   - skip된 저장소 목록 (사유별 그룹핑: dirty/diverged/detached/no-upstream)
   - 실패한 저장소 목록 (fetch-failed 및 추정 원인)
   - (선언 파일이 있을 때) 선언과 디스크 상태 대조 결과 — 선언됐지만 아직 클론되지 않음, 디스크엔 있지만 선언에 없음, 다른 저장소가 clone되어 있음, 원격 좌표를 확인할 수 없음, 선언대로 존재하지 않도록 되어 있는 저장소가 실제로 존재함 등
4. **조치 제안**: 문제 저장소마다 사유에 맞는 제안 조치(예: dirty → stash 후 pull/수동 검토, no-upstream → upstream 설정 후 재시도, not-cloned → clone)를 나열합니다. 문제 저장소가 없으면 이 단계와 다음 단계는 생략됩니다.
5. **승인 게이트**: 제안된 조치 중 사용자가 승인한 것만 실행합니다. 승인 없이는 stash·rebase·merge·commit·push 등 어떤 변경 작업도 자동으로 실행되지 않습니다. clone이 필요한 경우 접속 방식(SSH/HTTPS)은 세션당 한 번만 확인합니다.

## 산출물

이 스킬 자체는 별도 파일을 생성하지 않습니다. 승인된 조치에 따라 대상 git 저장소가 `pull`되거나(커밋 히스토리 갱신), 새 저장소가 clone됩니다. 선언 파일 초안을 처음 만들 때는 `.opal/workspace.json`이 생성됩니다(항상 미리보기 후 승인을 거칩니다).

## FAQ

### 변경사항이 남아있는 저장소는 어떻게 되나요
자동으로 건드리지 않고 skip 처리한 뒤 "dirty"로 보고합니다. stash 후 pull, 커밋 후 pull, 수동 검토 중 승인한 조치만 실행합니다.

### 선언 파일이 없어도 사용할 수 있나요
네. 선언 파일이 없으면 기존과 동일하게 디스크에 있는 저장소만 순회해 동기화합니다. 선언 파일을 새로 만들고 싶으면 초안을 미리 보여준 뒤 승인을 받아 생성합니다.

### 프로젝트 root 저장소도 함께 최신화되나요
`<경로>/workspace`를 대상으로 잡을 때 `<경로>/.git`도 있으면 root 저장소로 함께 포함되어 결과 목록 맨 앞에 나타납니다.
