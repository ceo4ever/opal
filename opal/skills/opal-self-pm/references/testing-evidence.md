# 테스트와 실행 증거

## 테스트 선정

대상 프로젝트의 PROJECT 문서가 연결한 테스트 지침·사용자 흐름·구성과 실제 테스트 설정·기존 테스트를 확인한다. 변경한 동작과 완료 기준에 맞춰 단위·통합·E2E 검증을 선정하고, 어떤 기준을 무엇으로 확인할지 TASK.md 또는 필요한 검증 문서에 기록한다. OPAL 저장소의 테스트 명령을 다른 프로젝트에 그대로 적용하지 않는다.

## E2E 스킬 적용 검토

**[MUST]** 매 작업에서 `opal-e2e`를 통한 테스트 수행을 검토한다. 프로젝트 로컬 스킬 또는 설치본 `~/.opal/skills/opal-e2e/SKILL.md`를 읽고 대상 프로젝트의 기존 여정·실행 환경과 대조한다. 스킬이 없으면 검색한 위치·부재와 가능한 대체 검증을 기록한다. 설치를 자동으로 수행하지 않는다.

- 사용자 흐름·화면·API 연동·여러 구성요소를 거치는 동작에 영향을 주면 관련 여정을 선정해 실행한다. 기존 여정으로 확인할 수 없으면 스킬의 `author` 계약에 따라 필요한 여정·단언을 준비한다.
- 실행 대상(source-main/source-worktree/installed)은 검증하려는 실제 변경과 맞춰 선택하고, `run`의 실제 stdout JSON·process exit·run ID·run_json_path를 증거로 남긴다. 최종 판정은 스킬이 호출한 test-tool 결과를 그대로 사용한다.
- 문서만 변경되어 실행 동작에 영향이 없는 등 E2E가 적합하지 않으면 `미실행 / 변경 영향에 근거한 이유 / 대체 검증 / 미검증 범위`를 남긴다. 막연한 "불필요"로 끝내지 않는다.
- 실행이 필요한데 서버·계정·데이터·도구가 없어 못 하면 `차단`으로 기록한다. 미실행을 pass나 영향 없음으로 바꾸지 않는다. 필요한 외부 쓰기·승인은 해당 스킬의 권한 경계를 따른다.
- 이전 실행 증거를 인용하면 새 실행과 구분하고 대상 버전·범위·환경이 여전히 유효한지 확인한다. 여정 승격 등 E2E 자산 관리는 해당 스킬의 계약을 따른다.

## 실행 증거

**[MUST]** 테스트마다 다음을 실제 실행 시점에 남긴다. "통과했다"는 요약만으로 증거를 대신하지 않는다.

| 항목 | 보존할 내용 |
|---|---|
| 재현 조건 | 실행 시각·작업 디렉터리·대상 버전/작업본·환경·전제조건·입력 또는 fixture |
| 실행 | 실제 명령·옵션 또는 스킬 호출 입력, 사용한 도구·스킬 |
| 기대와 관측 | 확인할 완료 기준·기대 결과, 실제 결과·exit code·pass/fail/blocked/미실행 구분 |
| 증거 | stdout/stderr, 테스트 리포트, 필요한 스크린샷·trace·응답 및 E2E run JSON의 지속 가능한 경로 |
| 실패와 재실행 | 실패 증거, 수정 내용, 별도 재실행 증거. 성공 결과로 이전 실패를 덮어쓰지 않음 |

증거는 태스크 폴더의 `evidence/` 또는 테스트 도구가 소유한 지속 저장소에 보관한다. 임시 경로만 남기거나 도구 정리로 유일한 증거를 삭제하지 않는다. 비밀값·개인정보는 마스킹하고 필요한 출력만 보존한다. 전체 증거를 여러 문서에 복제하지 않고 DONE.md 및 self-pm-tool의 `validation`에 경로를 연결하며 run-log `activity(kind=validation)`의 `refs`로 같은 증거를 참조한다.

## 완료 판단

선정한 테스트 결과와 E2E 검토 근거, 증거 파일의 존재·열람 가능성을 확인한다. 실패·차단·미검증 범위는 DONE.md에 남기고 해결되지 않은 필수 검증을 성공으로 보고하지 않는다. 문서·스킬 변경은 관련 구조 검사와 명령 동작 확인을 증거로 남기며, 도구 실행 검증과 독립 에이전트의 실제 스킬 수행 검증을 구분한다.
