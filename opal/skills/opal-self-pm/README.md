# opal-self-pm

정해진 태스크 파이프라인을 밟는 대신, PM이 사용자와 대화하며 질문을 하나씩 던지고 직접 조사·작성·수정까지 수행하는 대화형 작업 루프입니다.

## 개요

일반적인 태스크 진행 방식(분석 → 계획 → 실행 → 검증의 정해진 단계)이 맞지 않는, 범위가 아직 불확실하거나 대화하면서 하나씩 결정해 나가야 하는 작업에 씁니다. PM이 사용자에게 질문을 한 개씩만 던지고, 답변을 받을 때마다 필요한 자료를 조회·정리한 뒤 다음 질문으로 넘어갑니다. 충분히 결정되면 작업 범위를 계약 형태로 정리해 승인을 받고, 그 뒤에야 실제 작업(조회·작성·수정·검증)에 들어갑니다.

작업이 끝나기 전에는 기획·설계·프로젝트 문서·컨벤션·보안·brain·memory·code-scan 이렇게 여덟 영역 모두에 대해 "이번 변경이 영향을 주는지"를 빠짐없이 판정하고, 사용자의 최종 확인을 받은 뒤에만 종료를 선언합니다.

## 트리거

- `//oppm` 또는 `//opal-self-pm` 명시 호출
- "대화하면서 직접 해줘", "하나씩 질문하며 PM이 처리해줘" 같은 발화

## 사용법

```
//oppm <하고 싶은 작업을 자연어로>
```

특정 진행 중인 태스크 폴더 안에서 호출하면 그 태스크를 기준으로 작업하고, 그렇지 않으면 프로젝트 루트를 기준으로 작업합니다.

## 동작 흐름

1. **질문 단계 (한 개씩)**: PM이 매 턴 결정해야 할 사항을 하나씩만 묻습니다. 각 질문에는 항상 다음 다섯 가지가 함께 제시됩니다.
   - 지금 결정해야 하는 한 가지
   - 고를 수 있는 선택지(또는 자유 응답 범위)
   - PM의 권고 답안
   - 그 권고를 하는 이유와 다른 선택지 대비 trade-off
   - 이 답변에 따라 달라지는 다음 조사·작업
   답변을 받으면 필요한 자료를 조회·정리하고, 이미 답한 질문은 다시 묻지 않으며, 다음 질문으로 넘어갑니다.
2. **작업 계약 확정**: 결정이 충분히 쌓이면, 목표와 완료 조건·포함 및 제외 범위·변경 대상·확정된 결정과 남은 가정·검증 방법·예상되는 문서 영향, 이렇게 6개 항목을 한 번에 정리해 제시하고 승인을 받습니다. **승인 전에는 어떤 파일도 쓰지 않습니다.**
3. **PM 작업·검증**: 승인받은 계약 안에서 PM이 직접 조회·작성·수정합니다. 보안·컨벤션 등 독립적인 검증이 필요하면 별도 검증 스킬을 호출해서 진행하며, PM이 자기 작업을 스스로 채점하지 않습니다. 계약에 없던 변경이나 사용자의 새로운 결정이 필요한 지점이 나오면, 그 자리에서 멈추고 다시 1단계(질문 단계)로 돌아갑니다.
4. **지식·산출물 동기화**: 완료 직전, 아래 8개 영역 모두를 "반영함(update)" 또는 "반영할 필요 없음(no-op) + 그 근거"로 판정합니다. 근거 없이 그냥 건너뛰는 것은 허용되지 않습니다.

   | 영역 | 확인 대상 |
   |------|-----------|
   | 기획 | 기획서·정책서·사용자 흐름 문서 |
   | 설계 | 아키텍처·인터페이스·데이터 모델 문서 |
   | 프로젝트 문서 | `docs/PROJECT.md`의 컴포넌트·문서 목록 |
   | 컨벤션 | `docs/CONVENTIONS.md` |
   | 보안 | `docs/SECURITY.md` (또는 기본 보안 기준) |
   | brain | 프로젝트의 결정 이유 기록소(`.opal/brain/`, 있는 경우만) |
   | memory | 다음 세션이 알아야 할 주의사항·후속 작업 |
   | code-scan | 변경된 코드 파일의 메타 정보(`@header`) 최신화 여부 |

5. **사용자 최종 확인**: 6개 항목 계약이 어떻게 이행됐는지와 8영역 판정 결과를 사용자에게 제시하고 확인을 받습니다. **사용자가 확인하기 전에는 "완료했다"고 먼저 선언하지 않습니다.** 수정 의견이 있으면 다시 질문 단계로 돌아갑니다.
6. **종료**: 최종 확인을 받은 뒤에만 작업을 마칩니다.

## 산출물

- 사용자와 합의한 계약 범위 안에서 실제로 변경된 파일들(문서·코드 등, 작업 내용에 따라 다름)
- 8영역 지식 동기화 판정 결과(어느 영역을 반영했고, 어느 영역은 왜 반영하지 않았는지)
- 이 스킬은 정해진 산출물 템플릿(TASK.md, PLAN.md 같은 파이프라인 문서)을 만들지 않습니다 — 대화와 실제 작업 결과물이 곧 산출물입니다.

## FAQ

### 일반 태스크 파이프라인과 뭐가 다른가요?
정해진 단계(분석→계획→실행→검증)를 순서대로 밟는 대신, 질문 하나에 답하고 조사하는 것을 반복하면서 범위를 그때그때 정해 나갑니다. 별도 워커에게 작업을 위임하지 않고 PM이 직접 조회·작성·수정합니다.

### 작업 중간에 계획에 없던 게 필요해지면 어떻게 되나요?
그 자리에서 작업을 멈추고 다시 질문 단계로 돌아가 새로 결정한 뒤, 계약을 다시 승인받고 이어갑니다.

### 완료 보고 전에 확인해야 할 게 많나요?
기획·설계·프로젝트 문서·컨벤션·보안·brain·memory·code-scan 8개 영역을 모두 확인합니다. 관련 없어 보인다고 그냥 넘어가지 않고, 관련 없다면 그 이유를 명시해서 남깁니다.

### 외부 패키지 설치나 배포도 이 스킬이 알아서 하나요?
아니요. 외부 스킬·패키지 설치, 프로젝트 밖 시스템에 대한 쓰기, 되돌릴 수 없는 변경, 커밋·푸시·배포 같은 것은 이 스킬이 임의로 진행하지 않고 별도 승인 절차를 따릅니다.
