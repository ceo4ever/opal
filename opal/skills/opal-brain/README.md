# opal-brain

프로젝트의 "왜(WHY)"와 "어떻게(HOW)"를 마크다운 위키로 누적해 두고, 필요할 때 질의해서 답을 얻는 지식 관리 스킬. 별칭 `opbr`.

## 개요

`//opbr`은 코드·문서·태스크 기록에서 지식을 뽑아 프로젝트 전용 위키(`.opal/brain/`)에 쌓아 둡니다. 코드는 "무엇을 하는지(WHAT)"는 잘 보여주지만 "왜 그렇게 설계했는지(WHY)"는 잘 남지 않는데, 이 위키가 그 설계 배경과 맥락을 사람이 읽을 수 있는 형태로 보존합니다. init(초기화) · ingest(누적) · query(질의) · lint(정비) 네 가지 모드로 동작합니다.

## 언제 쓰나

- 프로젝트에 지식 위키를 처음 만들고 싶을 때 (`init`)
- 코드·문서·완료된 태스크의 핵심 결정을 위키에 기록해 두고 싶을 때 (`ingest`)
- "이 모듈이 왜 이렇게 설계됐지?" 같은 질문에 근거를 찾아 답을 받고 싶을 때 (`query`)
- 위키에 고아 페이지, 깨진 링크, 오래된 내용이 없는지 점검하고 싶을 때 (`lint`)

## 사용법

```
//opbr init                         # 프로젝트당 1회 — 위키 골격 생성 + 핵심 엔티티 시드
//opbr ingest <소스>                # 코드/문서/태스크/외부 URL 등 하나를 누적
//opbr ingest --all                 # docs·스킬·참조 문서 등을 일괄 누적
//opbr ask "질문"                   # 대화형으로 질의 (후보 페이지를 직접 선택)
//opbr query --read-only "질의"     # 비대화형 질의 (콘솔·자동화용, JSON 응답)
//opbr lint                         # 위키 무결성 점검
```

모드를 지정하지 않고 그냥 `//opbr ...`로 말하면, 의도를 판별해 가장 적합한 모드로 안내합니다.

## 파이프라인

**init** — 코드 분석 결과를 바탕으로 어떤 종류의 페이지(entity/concept/flow/synthesis 등)를 쓸지, 어떤 모듈을 핵심 엔티티로 먼저 문서화할지 제안받고 확인한 뒤, 위키 골격을 만들고 핵심 모듈들의 엔티티 페이지를 작성합니다.

**ingest** — 소스 종류(내부 코드/내부 문서/태스크/외부 URL/파일)에 따라 처리 방식이 다릅니다. 내부 코드·문서는 본문을 그대로 복사하지 않고 요약과 원본 위치(포인터)만 남기며, 원본이 계속 최신 정보의 기준(SSOT)입니다. 외부 소스만 원본을 별도로 저장합니다. 아직 실재하지 않는 지식(예정된 개선, 미확정 설계 등)은 등록하지 않습니다.

**query** — 질문과 관련된 페이지 후보를 먼저 찾아 제시하고, 선택된 페이지만 실제로 읽어 답을 만듭니다(전체 위키를 한꺼번에 불러오지 않습니다). 답변이 새로운 통찰을 담고 있으면 별도 페이지(synthesis)로 저장할지 제안받습니다.

**lint** — 위키 전체를 점검해 고아 페이지, 오래된 내용, 깨진 링크, 출처 없는 주장, 서로 모순되는 내용 등을 찾아 목록으로 보여주고, 정비를 진행할지 확인받습니다.

## 산출물

```
.opal/brain/
├── pages/
│   ├── entity/       # 모듈·컴포넌트 단위 지식 (WHAT/WHY/HOW)
│   ├── concept/       # 문서·정책 등에서 뽑은 개념 요약
│   ├── flow/           # 오케스트레이터·파일럿 등 흐름 지식
│   └── synthesis/      # 질의에서 파생된 분석 결과 (사용자 승인 시 저장)
├── index.md            # 전체 페이지 맵
└── log.md              # init/ingest/query/lint 작업 이력
```

프로젝트 성격에 따라 업무 용어를 담는 `term` 페이지 타입이 추가로 채택될 수 있습니다.

## 관련 스킬

- **op-brain-ingest** — `opgc`·`oppd`·`oppl` 등 다른 파일럿이 완료(CLOSE) 시점에 이 스킬을 통해 산출물을 브레인에 자동으로 누적합니다.
- **오케스트레이터 스킬 전반** — 브레인이 초기화된 프로젝트에서는 각 파일럿 완료 시 자동으로 지식이 쌓이며, `opbr query`로 그 지식을 다시 꺼내 쓸 수 있습니다.

## FAQ

### 브레인이 아직 없는 프로젝트에서 ingest나 query를 하면 어떻게 되나요?
오류 없이 "먼저 `//opbr init`을 실행해 달라"는 안내만 받고 아무 작업도 하지 않습니다(no-op).

### 위키가 코드와 어긋나면 어떤 게 맞나요?
코드가 항상 기준(SSOT)입니다. 위키는 코드 시점의 스냅샷이라 오래될 수 있으므로, 질의 시에는 위키 내용뿐 아니라 근거가 된 원본(코드·문서)까지 함께 확인합니다.

### 위키에서 코드를 거꾸로 고칠 수 있나요?
아니요. 코드→위키 단방향으로만 지식이 흐르며, 위키 내용으로 코드나 원본 문서를 역으로 수정하는 것은 금지되어 있습니다.

### `ingest --all`은 비용이 많이 드나요?
프로젝트의 문서·스킬·참조 문서를 일괄로 요약하는 작업이라 시간과 비용이 들 수 있어, 실행 전에 항상 확인을 받습니다.

### query 결과가 마음에 들면 어떻게 보존하나요?
새로운 통찰이 담긴 답변이면 `synthesis` 페이지로 저장할지 물어봅니다. 승인하면 이후 같은 주제의 질문에서 재사용됩니다.
