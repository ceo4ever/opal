# docs 문서 작성 가이드

> opi 스킬에서 프로젝트 문서를 작성할 때 참조하는 구조/내용 지침.
> 이 가이드는 템플릿이 아니다. 에이전트가 프로젝트를 분석하고 이 구조에 맞춰 직접 작성한다.

---

## docs/PROJECT.md — 프로젝트 정의 (모든 프로젝트 필수)

프로젝트의 WHAT(무엇을)과 WHY(왜)를 정의하는 단일 진실 원천(SSOT).
프로젝트 문서 테이블을 통해 모든 문서의 허브 역할을 한다.

### 구조

```markdown
# {프로젝트명}

> {프로젝트 한 줄 설명}

## 프로젝트 개요

| 항목 | 값 |
|------|-----|
| 프로젝트명 | {프로젝트명} |
| 도메인 | {도메인} |
| 현재 Phase | {현재 진행 단계} |

## 프로젝트 원칙

{이 프로젝트에서 모든 작업이 지켜야 할 핵심 원칙}
{사용자과 대화에서 도출. 3~5개 권장}

예:
- 소상공인이 5분 안에 첫 결과를 받을 수 있어야 한다
- 크롤링 실패해도 사용자 경험이 끊기면 안 된다
- 모든 컴포넌트는 프로젝트 간 재사용 가능해야 한다

## 프로젝트 기준

{품질, 우선순위, 의사결정 기준}

예:
- UX 단순성 > 기능 풍부함
- 데이터 정합성 > 처리 속도
- 코드 가독성 > 성능 최적화

## 기술 스택 (개발 프로젝트만)

| 레이어 | 기술 |
|--------|------|
| Backend | {예: FastAPI 0.115, Python 3.12} |
| Frontend | {예: Next.js 15, React 19, shadcn/ui} |
| Database | {예: PostgreSQL 16} |
| 기타 | {예: Claude API, Crawl4AI} |

## 프로젝트 설정

프로젝트별 커스텀 경로 등을 정의한다. 생략 시 기본값 적용.
에이전트(PM)가 부트스트랩에서 이 설정을 읽고 모든 작업에 적용한다.

| 항목 | 경로 | 기본값 |
|------|------|--------|
| 태스크 폴더 | {예: `work/tasks/`} | `tasks/` |

- 사용자이 별도 지정하지 않으면 이 섹션을 생략한다 (기본값 적용)
- 에이전트가 opi 인터뷰에서 "특별한 폴더 설정이 있나요?" 같이 묻지 않는다 — 사용자이 직접 요청할 때만 설정

## 프로젝트 문서

| 문서 | 설명 | 용도 | 참조 시점 |
|------|------|------|----------|
| `.opal/AGENT.md` | PM 프로필 | PM 역할 및 검토 기준 | 부트스트랩 시 자동 |
```

### 작성 규칙

- **프로젝트 개요**: 사실 기반으로 작성. 추측 금지.
- **프로젝트 원칙**: 사용자과 대화에서 명시적으로 도출된 것만. 에이전트가 임의로 추가하지 않는다.
- **프로젝트 기준**: 트레이드오프 상황에서의 판단 기준. "A > B" 형식 권장.
- **기술 스택**: 일반 프로젝트에서는 이 섹션을 생략한다.
- **프로젝트 문서 테이블**: 프로젝트 허브. 모든 등록된 문서의 레지스트리.

### 문서 등록 프로토콜

문서를 생성하는 모든 스킬(opi, otp-doc 등)은 작성 완료 후:

1. 사용자에게 확인: "이 문서를 프로젝트 문서로 등록할까요?"
2. 용도 인터뷰: "이 문서의 용도는 무엇인가요? 어떤 작업에서 참조하면 좋을까요?"
3. 사용자 승인 시 PROJECT.md 문서 테이블에 등록
4. 등록되지 않은 문서는 다른 스킬이 참조하지 않음

**참조 시점 표준값**:

| 값 | 의미 |
|---|------|
| 부트스트랩 시 자동 | 매 세션 시작 시 에이전트가 자동 Read |
| 개발 작업 시 항상 | otp 디스패치 시 항상 워커에게 전달 |
| 개발 작업 시 | otp 디스패치 시 관련 있으면 워커에게 전달 |
| BE 작업 시 | 백엔드 관련 작업에서 워커에게 전달 |
| FE 작업 시 | 프론트엔드 관련 작업에서 워커에게 전달 |
| 요청 시 | 사용자이나 스킬이 명시적으로 요청할 때만 |

## 새 기능 추가 가이드

{이 프로젝트에서 새 도메인/서비스/API를 추가하려면 아래 순서를 따른다}

### 새 API 추가 절차 (실제 파일 경로 기반)

1. **커맨드 정의**: `domain/{서비스}/command/{기능}Command.{확장자}` 생성
2. **도메인 서비스**: `domain/{서비스}/service/{도메인}Service.{확장자}` 에 메서드 추가
