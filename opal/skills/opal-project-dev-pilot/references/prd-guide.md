# PRD 작성 가이드

> opal-project-dev-pilot Phase 1에서 PRD를 작성할 때 참조하는 구조/내용 지침.
> 알투가 프로젝트를 분석하고 사용자과 대화하여 직접 작성한다.

---

## 작성 전 준비

다음 문서를 반드시 Read한다:
- `docs/PROJECT.md` — 프로젝트 목적, 원칙, 기준
- `docs/ARCHITECTURE.md` — 기술 스택, 시스템 구성 (있으면)
- `.opal/AGENT.md` — PM 전문 역할, 검토 기준

---

## PRD 구조

```markdown
# PRD: {프로젝트명}

> 작성일: YYYY-MM-DD | 상태: 초안 / PM 검수 완료 / 사용자 확정

## 1. 개요

### 목적
{이 제품이 해결하려는 문제}

### 범위
{이번 버전에서 다루는 범위 / 다루지 않는 범위}

### 대상 사용자
{주요 사용자 그룹}

## 2. 사용자 정의 (페르소나)

### 페르소나 1: {이름}
- 역할: {누구인가}
- 목표: {무엇을 달성하려 하는가}
- 어려움: {현재 어떤 불편이 있는가}
- 기술 수준: {초급/중급/고급}

## 3. 기능 요구사항

### Must (필수)

| ID | 유저 스토리 | 수용 기준 |
|----|-----------|----------|
| F-001 | {역할}로서 {기능}을 원한다. 왜냐하면 {이유} | - {조건 1}<br>- {조건 2} |

### Should (권장)

| ID | 유저 스토리 | 수용 기준 |
|----|-----------|----------|

### Could (선택)

| ID | 유저 스토리 | 수용 기준 |
|----|-----------|----------|

### Won't (이번 버전 제외)

| ID | 유저 스토리 | 제외 이유 |
|----|-----------|----------|

## 4. 화면 흐름

### 주요 시나리오

{사용자가 제품을 사용하는 핵심 흐름을 단계별로 기술}

1. {첫 화면}
2. {사용자 액션}
3. {결과 화면}

### 화면 목록

| 화면 | 설명 | 주요 기능 |
|------|------|----------|

## 5. 비기능 요구사항

| 항목 | 요구사항 | 기준 |
|------|---------|------|
| 성능 | {예: 페이지 로드 시간} | {예: 3초 이내} |
| 보안 | {예: 인증 방식} | {예: JWT + HTTPS} |
| 접근성 | {예: WCAG 준수} | {예: AA 레벨} |
| 호환성 | {예: 브라우저 지원} | {예: Chrome, Safari, Firefox} |

## 6. 제약 조건

- {기술적 제약}
- {일정 제약}
- {비용 제약}
```

## 사용자 인터뷰 포인트

PRD 작성을 위해 사용자에게 확인할 핵심 질문 (PROJECT.md에서 파악 안 된 것만):

1. **주요 사용자는 누구인가?** — 기술 수준, 사용 환경
2. **핵심 기능 3~5개는?** — Must에 해당하는 것
3. **사용자의 메인 시나리오는?** — 앱을 열고 → 뭘 하고 → 결과를 얻는 흐름
4. **이번 버전에서 안 할 것은?** — Won't 명확화
5. **성능/보안 기대치는?** — 비기능 요구사항

---

## PM 검수 체크리스트

PRD 작성 후 사용자에게 넘기기 전, 아래를 1:1 대조한다:

- [ ] 모든 Must 기능에 유저 스토리 + 수용 기준이 있는가
- [ ] 우선순위가 명확하고 Must가 과다하지 않은가 (Must 5~8개 적정)
- [ ] 비기능 요구사항이 구체적 수치로 명시되었는가
- [ ] 화면 흐름이 주요 시나리오를 커버하는가
- [ ] docs/PROJECT.md의 프로젝트 원칙과 부합하는가
- [ ] 기술 실현 가능성이 검토되었는가 (ARCHITECTURE.md 참조)
- [ ] Won't 항목에 제외 이유가 명시되었는가
