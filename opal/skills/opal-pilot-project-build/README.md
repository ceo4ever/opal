# opal-pilot-project-build

이미 확정된 실행 계약을 여러 작업 단위(capability)로 나눠 거의 무인으로 완성하는 프로젝트 빌드 스킬. 별칭 `oppb`.

## 개요

`//oppb`를 호출하면 목표·범위·완료조건을 담은 실행 계약 문서(`INTENT.md`) 하나를 사용자와 함께 확정한 뒤, 그 계약을 여러 개의 독립적인 capability(기능 단위) 미니 작업으로 나눠 자동으로 병렬 실행합니다. 사용자가 실제로 개입하는 시점은 여섯 번뿐이며, 그 사이 진행 상황(스케줄·예산·격리·증거 수집)은 모두 자동으로 관리됩니다.

## 언제 쓰나

- 한 번의 설계 승인으로 목표·계약·완료조건을 잠글 수 있고, 이후 변경은 예외로만 처리해도 되는 프로젝트일 때
- 여러 기능(capability)을 병렬로 무인 실행하고 싶을 때
- 이미 프로젝트 문서가 충분히 갖춰져 있어 PRD·TRD를 새로 쓸 필요가 없을 때

> 실행 증거에 따라 목표·계약이 계속 바뀌어야 하는 프로젝트라면 `oppl`을, 제품 명세(PRD·TRD) 작성부터 필요하다면 `oppd`(또는 `opwt`로 명세를 먼저 만든 뒤 `oppb`)를 사용하세요. 단일 태스크 규모라면 `opd`/`opds`가 더 적합합니다. 이 네 파일럿은 서로 대체 관계가 아니라 병존하는 선택지입니다.

## 사용법

```
//oppb {요청 내용}                  # 기본 — 계약 확정까지 사용자 검토, 이후 자동 진행
//oppb --interactive {요청 내용}    # 모든 단계 사용자 승인
//oppb --agentic {요청 내용}        # 계약 확정까지도 자동 진행 (최종 승인만 사용자가 함)
```

`docs/PROJECT.md`가 없는 프로젝트(그린필드)에서 호출하면 프로젝트 초기 설정을 먼저 자동으로 실행합니다.

**PRD·TRD를 새로 만들지 않습니다** — 기존 프로젝트에 관련 문서가 이미 충분하면 그 문서만 참조하고, 실행 계약은 `INTENT.md` 하나로만 확정합니다. 재사용할 제품 명세가 꼭 필요하다고 판단될 때만 예외적으로 PRD를 추가로 작성합니다.

## 파이프라인

1. **P0 (진입)** — 프로젝트 컨텍스트를 확인하고 태스크를 준비합니다.
2. **P1 (INTENT)** — 목표·제외 범위·완료조건·비가역 제약·예산을 담은 `INTENT.md`를 작성합니다. **사용자 게이트 ①**: 이 내용을 승인받습니다.
3. **P2 (설계 & 분할)** — 프로젝트를 독립적인 capability 단위로 나누고, 각 단위의 의존관계·완료조건을 기계적으로 검증합니다. 중대한 신규 기술 결정이 있을 때만 **사용자 게이트 ②**를 거칩니다.
4. **P3 (무인 실행)** — 준비된 capability들을 스케줄에 따라 순서·병렬로 실행합니다. 이 구간은 설계상 사람이 재촉하거나 개입하지 않는 무인 구간입니다. 기능 범위나 외부 계약이 바뀌어야 하는 경우에만 **사용자 게이트 ③**이 열립니다.
5. **P4 (검증)** — 통합·보안·컨벤션을 전체적으로 재검증하고, `INTENT.md`의 완료조건이 실제로 충족됐는지 판정합니다. 비가역 작업이나 예산 초과가 있으면 **사용자 게이트 ④**가 열립니다.
6. **P5 (병합·지식화·종료)** — 최종 결과를 프로젝트 원본에 병합하고, 지식(브레인·메모리)에 정확히 한 번 반영한 뒤 완료 문서를 만듭니다. 귀속되지 않은 변경이 있으면 **사용자 게이트 ⑤**, 최종 병합·종료는 **사용자 게이트 ⑥**을 거칩니다.

## 산출물

```
tasks/{번호}-oppb-{프로젝트명}/
├── TASK.md · STATE.md
├── INTENT.md            # 유일한 실행 계약 문서
├── PROJECT-DESIGN.md    # P2 설계·분할 근거
└── DONE.md              # 완료조건 판정·증거 목록 포함
```

미니 작업(capability) 단위로는 별도의 태스크 폴더·`TASK.md`·`DONE.md`를 만들지 않습니다 — 진행 상황은 내부 작업 그래프로만 추적되며, 상시 남는 산출물은 실행 기록과 증거 파일뿐입니다.

## 관련 스킬

- **opal-capability-agent** — 미니 작업 하나를 실제로 구현·검증하는 유일한 실행 담당자입니다.
- **opal-evaluator-agent** — P2 설계 검토와 P4 완료조건 판정을 맡습니다.
- **opal-plan-agent** — P2 설계 초안을 작성합니다.

## FAQ

### PRD/TRD가 자동으로 만들어지나요?
아니요. 기존 문서가 충분하면 새로 만들지 않는 것이 기본 원칙입니다. 재사용할 명세가 필요하다고 확인된 경우에만 예외적으로 만듭니다.

### 실행 중에 사용자가 계속 확인해야 하나요?
아니요. P3(무인 실행) 구간은 설계상 사람이 개입하지 않으며, 문제가 생겨도 자동 재시도나 자체 분류로 처리하려 시도합니다. 정말 판단이 필요한 경우에만 여섯 개의 게이트 중 하나가 열립니다.

### 브레인·메모리에는 언제 반영되나요?
프로젝트 전체가 끝나고 최종 병합이 완료된 후 P5에서 정확히 한 번만 반영됩니다. 미니 작업이 끝날 때마다 반영하지 않습니다.

### `--wt`(worktree) 없이도 되나요?
네, 프로젝트 전체가 worktree 하나를 사용하며, 미니 작업마다 별도의 worktree나 branch를 만들지 않습니다.
