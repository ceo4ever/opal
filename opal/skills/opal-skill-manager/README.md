# opal-skill-manager

OPAL 커뮤니티 스킬을 검색·설치·삭제·업데이트 확인하는 스킬입니다.

## 개요

[skills.sh](https://skills.sh/) (vercel-labs/skills) 생태계에서 스킬을 검색하고, 후보를 안전성·적합성 기준으로 비교해 추천한 뒤, `git clone` → 복사 방식(clone-copy)으로 `~/.opal/community-skills/`에 설치합니다. 설치된 스킬은 목록 조회, 삭제, 업데이트 확인도 이 스킬로 처리합니다.

- alias: `osm`

## 사용법

| 요청 | 동작 |
|------|------|
| "○○ 관련 스킬 찾아줘" | 스킬 검색 (설치 여부 대조 → 필요 시 생태계 검색) |
| "스킬 설치해줘" | 검색 결과 후보를 비교·추천 후 승인을 받아 설치 |
| "설치된 스킬 목록" | 벤더별로 그룹핑한 설치 목록 표시 |
| "스킬 삭제해줘" | 지정한 벤더/스킬명을 확인 후 삭제 |
| "이 스킬 최신 상태야?" | 업스트림 커밋과 대조해 업데이트 필요 여부 확인 |

## 동작 흐름

### 스킬 검색

1. 먼저 이미 설치된 스킬과 대조합니다(Exact Match / Partial Match / No Match 3등급). 정확히 일치하는 설치된 스킬이 있으면 그 정보를 안내하고 종료합니다(외부 검색을 다시 하지 않습니다).
2. 일치하는 것이 없으면 `npx skills find`로 생태계를 검색해 후보를 최대 3개까지 선별합니다.
3. 적합한 후보가 없으면 `opal-skill-creator`로 새 스킬 생성을 위임합니다.

### 스킬 설치 (clone-copy)

1. 후보별로 임시 디렉토리에 `git clone --depth 1`로 내려받습니다(clone 자체는 설치가 아닙니다).
2. 위험 패턴 스캔(`scan-risk`)과 라이선스 확인(LICENSE 파일)을 거쳐 SAFE/CAUTION/RISKY/UNKNOWN으로 판정합니다. RISKY 후보는 추천에서 제외됩니다.
3. 남은 후보를 목적 적합성, 출력 형식 호환, 유지 활동, 부수효과 범위 4가지 기준으로 비교해 추천 후보 1개를 정합니다.
4. 추천 후보와 추천 사유, 탈락 사유를 보여주고 사용자 승인을 받은 뒤에만 `~/.opal/community-skills/{vendor}/{basename}/`로 복사하고 설치 이력을 기록합니다.

### 설치된 스킬 목록

`~/.opal/community-skills/` 아래를 벤더별로 그룹핑해 보여주고, 등록된 메타데이터와 대조합니다.

### 스킬 삭제

삭제 대상(벤더/스킬명)을 확인한 뒤 해당 디렉토리를 삭제하고, 설치 이력에서도 제거합니다.

### 업데이트 확인

대상 스킬의 원격 저장소 최신 커밋과 설치 시점에 기록해 둔 커밋을 비교해, 다르면 재설치를 제안합니다.

### `//` 커맨드로 미설치 스킬을 바로 부른 경우

라이선스가 확인된 스킬은 별도 동의 없이 자동으로 설치·실행됩니다. 라이선스가 확인되지 않은(Unknown) 스킬만 설치 전 확인을 거칩니다.

## 산출물

- `~/.opal/community-skills/{vendor}/{basename}/`: 설치된 커뮤니티 스킬 파일 일체
- `~/.opal/community-skills/user-registry.json`: 사용자 설치 이력(설치/삭제 시 갱신)

## FAQ

### `~/.opal/references/community-skills-registry.json`도 이 스킬이 수정하나요
아니요. 이 파일은 OPAL 배포 시 덮어써지는 프레임워크 카탈로그이므로, 설치·삭제 시 절대 수정하지 않습니다. 사용자 설치 이력은 별도의 `user-registry.json`에만 기록합니다.

### 라이선스가 확인되지 않은 스킬도 설치할 수 있나요
설치 전 "라이선스 미확인 — proceed at your own risk" 확인을 거치며, 기본값은 거부입니다. 승인하면 설치가 진행됩니다.

### 여러 벤더에 같은 이름의 스킬이 있으면 어떻게 되나요
후보 목록(vendor별 이름·저장소·라이선스·설치 여부)을 보여주고, `vendor/skill` 형식의 정식 이름으로 다시 요청하도록 안내합니다. 자동으로 하나를 고르지 않습니다.
