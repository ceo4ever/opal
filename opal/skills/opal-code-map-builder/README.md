# opal-code-map-builder

프로젝트 코드의 `@header` 메타데이터를 어디에 기록할지 확정하고, 필요하면 그 기록을 담는 코드 맵 자산을 구축·정비해 주는 스킬입니다.

## 개요

프로젝트마다 코드 파일의 메타 정보(`@header`: 모듈명, 계층, 도메인, 설명, exports 등)를 소스 파일에 직접 넣을지, 소스와 분리된 별도 매니페스트 파일에 넣을지 선택해야 합니다. 이 스킬은 그 선택을 소유자에게 물어 확정하고, `code-scan`이라는 도구를 통해 실제 설정 파일과 매니페스트 자산을 만들고 정비합니다. 판정과 실제 기록은 `code-scan` 도구가 담당하고, 이 스킬은 소유자의 선택을 도구에 전달하고 절차 순서를 지키는 역할을 합니다.

## 트리거

- `//opcmb` 또는 `//opal-code-map-builder` 명시 호출
- "코드 맵", "code-map", "헤더 자산" 등의 발화

## 사용법

```
//opcmb
```

호출하면 현재 프로젝트의 설정 상태를 자동으로 감지해서 처음 설정하는 것인지(init), 이미 설정된 자산을 정비하는 것인지(update)를 판별하고 알맞은 단계부터 시작합니다.

## 동작 흐름

### 최초 설정이 안 되어 있는 경우 (init)

1. **헤더 기록 방식 선택**: `@header`를 어디에 기록할지 두 가지 중 하나를 확정합니다.

   | 값 | 의미 |
   |----|------|
   | `inline` | 소스 파일에 직접 `@header` 주석을 남깁니다 (소스 편집이 자유로운 저장소에 권장) |
   | `manifest` | 소스는 건드리지 않고 `.opal/code-map/` 아래 별도 파일에 기록합니다 (소스 편집이 제한된 저장소용) |

   - `inline`을 선택하면 여기서 끝납니다. 아직 헤더가 없는 파일 목록을 보여주고, 이후 각 파일을 수정할 때 자연스럽게 헤더를 채워 나가면 됩니다.
   - `manifest`를 선택하면 다음 단계로 진행합니다.

2. **초안 자동 생성**: 프로젝트 구조를 스캔해 `.opal/code-map/index.json` 초안을 만듭니다. 이 초안은 자동 추론 결과이며 아직 확정된 것이 아닙니다.
3. **소유자 리뷰**: 초안에 담긴 폴더 범위, 계층 규칙(어떤 폴더가 어떤 계층인지), 도메인 구분을 사용자에게 제시하고 확인을 받습니다. 초안이 비워둔 항목(계층 규칙, 도메인 구분 등)은 이 자리에서 직접 채워 확정합니다.
4. **확정 전환**: 소유자 확인이 끝나면 초안 상태(`draft`)를 확정 상태(`reviewed`)로 바꿉니다. 승인 없이는 이 전환이 일어나지 않습니다.
5. **골격 생성**: 확정된 범위와 규칙에 따라 실제 매니페스트 파일들의 골격을 만듭니다. 골격에는 파일 목록 같은 구조 정보만 채워지고, 각 파일의 설명·exports 등은 이후 그 파일을 수정하는 시점에 채워집니다.
6. **정합성 확인 + 완료 보고**: 매니페스트가 실제 소스 구조와 어긋나지 않는지 확인하고, 남은 미기입 항목 수와 함께 결과를 보고합니다. 아직 내용이 다 채워지지 않은 "골격 완료" 상태도 정상 종료로 취급됩니다.

### 이미 설정이 되어 있는 경우 (update)

새 폴더가 추가되었거나 구조가 크게 바뀌었을 때, 골격 생성과 정합성 확인 두 단계만 다시 수행해 매니페스트를 최신 상태로 정비합니다. 이미 확정된 범위·규칙 자체를 바꿔야 한다면 그 사실을 보고하고 소유자 확인을 다시 받습니다.

## 산출물

- `manifest` 방식을 선택한 경우: `.opal/code-scan.json`(설정 파일), `.opal/code-map/index.json`(전체 매니페스트 색인), `.opal/code-map/{범위}/*.json`(패키지별 매니페스트 골격)
- `inline` 방식을 선택한 경우: 별도 자산 파일 없이, 아직 헤더가 없는 파일 목록만 안내합니다.

## FAQ

### 두 방식을 나중에 섞어서 쓸 수 있나요?
아니요. 헤더 기록 방식은 프로젝트 전체에 하나만 적용되며, 두 방식을 동시에 쓰는 경로는 만들지 않습니다. 이미 확정한 방식을 바꾸려면 다시 사용자 확인을 거쳐야 합니다.

### 매니페스트에 내용을 다 채워야 완료로 보나요?
아니요. 골격만 만들어진 "기입 대기" 상태도 정상적인 완료입니다. 세부 설명은 실제로 그 파일을 수정할 때 함께 채워지도록 설계되어 있습니다.

### 도메인이나 폴더 범위 구분은 자동으로 되나요?
초안은 자동으로 만들어지지만, 도메인 경계나 포함/제외 범위 같은 판단이 필요한 값은 이 스킬이 임의로 정하지 않고 항상 소유자가 리뷰 단계에서 직접 확정합니다.
